# W190-A — ARM64 via qemu-user: design + confined spike

**Date:** 2026-11-11. **Scope:** Step 1 design (`docs/ARM64.md`) and Step 2
spike — run an aarch64 hello binary under `qemu-aarch64` **inside** a
Landlock + seccomp sandbox and record exactly what had to be widened.
**Read-only** on `/home/Qui/Projects/gaten`; all scratch under
`.cache/w190a/` (removed at the end); **no product code changed, no commit.**
Owner-approved: ARM64 via qemu-user (user-mode only).

Host: Arch Linux, kernel `7.2.11-arch1-1`, x86_64. `sudo` requires a password;
`qemu-user` was **not** installed and was **not** installed (see §1).

## 3. Sandbox spike

The arm64 profile cannot use `acos_sandbox::confine` as-is: `confine` installs
seccomp (which **denies `execve`**) before the session worker, and the transport
must `execve` qemu. The spike therefore splits the layers exactly as the design
proposes:

1. `prctl(PR_SET_NO_NEW_PRIVS)`,
2. a **Landlock** ruleset (RO roots + single RW session root),
3. `execve(qemu-aarch64)`,
4. an **`LD_PRELOAD`** constructor (`libw190_guard.so`) installs the ACOS
   seccomp deny filter **after** the exec, before qemu `main`.

Artifacts (spike-only, C; the product reuses the audited
`acos-sandbox` filter):

| file | role | sha256 |
|---|---|---|
| `w190_launch.c` → `w190_launch` | NNP + Landlock + exec | `c491c2bc8e719f8fca574bc057ae484cf3051d98bd164b2894d41061ee2e4c4c` |
| `w190_guard.c` → `libw190_guard.so` | seccomp via `libseccomp` (default ALLOW, 55 deny rules, socket→AF_UNIX, clone→no namespace flags, clone3→ENOSYS) | `9a5b7bbee562f2a4ac6383057fa09378d5f78b027ed20d29721e0bff7806db42` |

Landlock roots used: RO `.cache/w190a` (guest + guard), `/usr`, `/lib`,
`/lib64`, `/proc`, `/dev`; RW `.cache/w190a/scratch`. The out-of-root secret
lives in `.cache/w190a-private/`.

### 3.2 What the evidence shows

| check | unsandboxed | sandboxed | conclusion |
|---|---|---|---|
| aarch64 guest runs under qemu-user | ✅ | ✅ | transport works inside the sandbox |
| threads (clone/futex) | ✅ `thread_ret=42` | ✅ `thread_ret=42` | TCG threads survive the filter |
| Landlock denies outside path | read ok | `outside_read=-1` | path confinement active |
| Landlock denies `/etc/hostname` | — | pre-exec `EACCES` | ruleset active before exec |
| seccomp denies host `ptrace` | `ENOSYS` | `errno=13 EACCES` | filter active **inside qemu** |
| seccomp denies host `unshare` | `EINVAL(22)` | `errno=13 EACCES` | filter active |
| guest `setuid` | `EPERM(1)` | `errno=13 EACCES` | guest syscall reaches the host filter |

**No new seccomp allowance was needed.** The full deny list (execve, ptrace,
unshare, setuid, mount, …) is compatible with the static aarch64 + TCG path;
`mmap`/`mprotect(PROT_EXEC)`, `clone`/`clone3→ENOSYS`, `futex` and `prctl` were
already allowed by the native profile. The only widening is **structural** —
deferred seccomp install (post-`execve`) and the added Landlock RO roots
(`/usr`, `/lib`, `/lib64`, `/proc`, `/dev`, guest sysroot). The x86_64 path is
untouched.

## 4. bionic sysroot finding

The NDK sysroot has **no** `libc.so`/`libm.so`/`libdl.so`/`liblog.so` and **no
`linker64`** for `aarch64-linux-android` (only `libc.a`, `libm.a`, `libdl.a`,
`libc++_shared.so`). No NDK/sysroot/bionic tree exists under the repo `.cache`.
So dynamic APK `.so` that need the *real* Android loader require a bionic
sysroot from (1) the attached arm64 device `ZA222WGJPP` (world-readable
`/system/bin/linker64` + `/system/lib64/*.so`, no root), or (2) an arm64 system
image (~1.5 GB, needs authorisation). If the cross-built runtime uses
`acos-native-loader`'s own ELF loader + bionic shims, `linker64` is **not**
required. See `docs/ARM64.md` §3.
