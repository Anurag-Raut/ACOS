# W194-A — cross-built aarch64 runtime under qemu-user (option B), first real arm64 `.so` load

**Date:** 2026-11-11. **Scope:** roadmap W193-A + W194-A (`docs/ARM64.md` §6),
option **B** (cross-build the runtime, JNI stays in-process). **Base:** committed
HEAD `1d87eaa`. Worktree `.cache/wt-w194a`, target dir `.cache/target-w194a`,
`CARGO_PROFILE_DEV_DEBUG=0`, `CARGO_BUILD_JOBS=2`; every run through
`tools/guarded.sh`. **No commit.** The x86_64 path is unchanged (all deltas are
`cfg`-gated).

Host: Arch Linux x86_64, kernel 7.2.11-arch1-1, 60 GiB RAM. Toolchain:
`rustc 1.90.0` (targets added: `aarch64-linux-android`,
`aarch64-unknown-linux-gnu`, `aarch64-unknown-linux-musl`), NDK
`27.1.12297006` (`aarch64-linux-android34-clang`), `qemu-aarch64 11.1.3`
(`.cache/qemu-user`), bionic sysroot `.cache/bionic-arm64` (device pull,
W192-A).

---

## 1. Target choice

| target | C deps (`freetype`, `zlib`, `sqlite3`) | linker/sysroot | chosen |
|---|---|---|---|
| `aarch64-linux-android` | NDK clang (**works**, `cc` uses NDK) | NDK clang + bionic stubs; guest `.so` ABI matches | **yes** |
| `aarch64-unknown-linux-gnu` | needs a gnu aarch64 sysroot (absent; no `zig`) | unavailable | no |
| `aarch64-unknown-linux-musl` | `libz-sys` wants `aarch64-linux-musl-gcc` (absent) | — | no |

`acos-vm` pulls `acos-render` (freetype/zlib) and `acos-sqlite` (vendored C),
so a C cross-compiler is mandatory; the NDK one is the only one present.
`aarch64-linux-android` is also the only target whose host libc *is* bionic,
which is what `acos-native-loader`'s shim table expects.

## 2. Cross-build fixes (all `cfg`-gated; x86_64 unchanged)

| file | change | why |
|---|---|---|
| `acos-sandbox/src/linux/seccomp.rs` | `AUDIT_ARCH` is now per-target (`AUDIT_ARCH_X86_64` unchanged; `AUDIT_ARCH_AARCH64 = 0xC000_00B7`, riscv64 too); `SYS_KEXEC_FILE_LOAD = 294` on arm64; `ioperm`/`iopl`/`modify_ldt` only on x86 | seccomp arch check + per-arch syscall numbers |
| `acos-sandbox/src/linux/mod.rs` | `RlimitResource` alias (`c_int` on bionic, `__rlimit_resource_t` on glibc); `close_range` via `SYS_close_range` on Android | bionic libc crate types/APIs differ |
| `acos-native-loader/src/bionic/host.rs` (**new**) | non-Android: `pub use ::libc::*`; Android: adds bionic declarations `__errno`, `environ`, `pthread_once*`, `pthread_getname_np`, `abs/labs/rand/srand/drand48/lrand48/mrand48`, `mremap`, `dup3` | the `libc` crate's Android module omits symbols bionic exports |
| `bionic/{mod,engine_gaps,shims,pthread}.rs` | `use crate::bionic::host as libc;`; `SendMap` for `pthread_attr_t` (bionic embeds `*mut c_void`); `pthread_once` arg shape per target | compile/link on aarch64 |
| `bionic/mod.rs` | glibc-fortify `__printf_chk`/`__fprintf_chk`/`__vprintf_chk`/`__vfprintf_chk` are aborting traps on Android; `__xpg_strerror_r` (glibc) ⇄ `__gnu_strerror_r` (bionic) pair mapped per target | link: bionic has neither the fortify quartet nor `__xpg_strerror_r` |
| `acos-native-loader/src/{elf,error,loader}.rs` | `EM_AARCH64`, `HOST_ELF_MACHINE`/`HOST_ABI_NAME`; loader accepts the **host** machine instead of hard-coded `EM_X86_64`; `rt` aliases map the shared relocation semantics to the host numbers; `R_AARCH64_{ABS64,COPY,GLOB_DAT,JUMP_SLOT,RELATIVE,TLS_*,IRELATIVE}` | W194-A: an aarch64 runtime must map aarch64 objects; same code then loads them in-process |
| `pthread.rs` (shim) | `extern "C" fn()`, not `Option<…>`, is glibc's `pthread_once` signature in libc 0.2.191 | host API shape |

Linker note: **use `aarch64-linux-android34-clang`**, not API 29. The API-29
stub `libc.so` has no `close_range`, and `linux/seccomp.rs` forwards it; the
API-34 stub does. The binary is `for Android 34`, run against the API-34
device sysroot.

### 3.1 Real arm64 `.so` through `acos-native-loader` (W194-A step)

Probe (scratch example, deleted afterwards) built with the aarch64 runtime,
running under `qemu-aarch64 -L .cache/bionic-arm64`; `Loader` in strict
missing-symbol mode with `require_confinement = false` (test config):

```
LOAD_OK  fixtures/build/apps/hello-jni-jni/arm64-v8a/libhellojni.so
SYMBOL JNI_OnLoad                                           = 0x7f8480abac74
SYMBOL Java_dev_acos_fixtures_hellojni_MainActivity_add     = 0x7f8480aba9ec
SYMBOL Java_dev_acos_fixtures_hellojni_MainActivity_stringFromJNI = 0x7f8480aba9d8
CALL add(2,3) = 5
exit=0
```

The mapped aarch64 `.text` **executes in-process**: the real JNI thunk
`Java_…_MainActivity_add(env, thiz, 2, 3)` returns `5`. Relocations actually
applied are `R_AARCH64_RELATIVE` ×6 and `R_AARCH64_JUMP_SLOT` ×3
(`__cxa_finalize`, `__cxa_atexit`, `__register_atfork`, all satisfied by the
bionic shim table).

RN fixture libraries (`fixtures/build/apps/work-rn/variant-arm64/lib/arm64-v8a`)
all reach `LOAD_OK` too (relocations + constructors, strict policy):

| library | load | notes |
|---|---|---|
| `libhellojni.so` | ✅ | JNI thunk called → 5 |
| `libjsi.so` | ✅ | no JNI exports |
| `libhermes.so` | ✅ | no JNI exports |
| `libfbjni.so` | ✅ | `JNI_OnLoad` exported |
| `libreactnative.so` | ✅ (load) | `JNI_OnLoad` exported; **`unload` SIGSEGVs** (first blocker) |

`libreactnative.so` load-only run exits 0; the crash happens only in
`Loader::unload` (`SIGSEGV code 1 SEGV_MAPERR` inside the qemu process), so it
is a teardown/TLS-unmap issue, not a relocation/constructor failure.

## 4. First blockers (in the order hit) and status

1. **`AUDIT_ARCH_X86_64` + x86-only syscall numbers** in seccomp — fixed.
2. **`libc` Android gaps** (`__errno_location`, `environ`, `pthread_once`,
   `abs`, `mremap`, …) — fixed via `bionic::host`.
3. **glibc fortify/`__xpg_strerror_r`** symbols absent on bionic — fixed
   (aborting traps / `__gnu_strerror_r` pairing).
4. **Linker API 29 has no `close_range`** — use NDK API-34 clang.
5. **`WRONG_ABI` hard-coded `EM_X86_64`** in the loader — fixed:
   `HOST_ELF_MACHINE` accepts the host machine (still x86_64 on the product
   host, so `arm64_library_is_reported_as_wrong_abi` stays green).
6. **`UNSUPPORTED_RELOCATION 1027`** (AArch64 `RELATIVE`) — fixed; the
   `RELATIVE`/`GLOB_DAT`/`JUMP_SLOT`/`ABS64`/`COPY`/TLS/`IRELATIVE` apply logic
   is shared, only the type numbers are per-arch (`rt` aliases).
7. **Remaining (open):** `Loader::unload` on `libreactnative.so` segfaults;
   `acos-jni`'s JNI ABI trampoline and the bionic `setjmp`/`longjmp` shims are
   still x86_64-only (non-x86 targets take the documented structured trap —
   W192-A design), so `System.loadLibrary`-driven JNI callbacks are not yet
   runnable on aarch64; `acos-jni/tests/flutter_hello.rs` is x86_64-only and
   blocks an android `--all-targets` check.
