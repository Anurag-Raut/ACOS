## 1. S2 — guest `/system` path translation escapes the boot tree

`translate_guest_system_path` strips `/system/` and then does
`boot.join(rest)` / `boot.join("etc").join(etc)` / `boot.join("fonts").join(font)`
with the guest-controlled `rest`. `Path::join` does not normalise:

* `fopen("/system/../../etc/passwd")` → `boot/../../etc/passwd` → `is_file()`
  true → the host opens `/etc/passwd`;
* `fopen("/system//etc/passwd")` → `rest = "/etc/passwd"` is absolute, so
  `boot.join(rest)` **discards `boot`** entirely.

The C shim then passes the translated string straight to `fopen`
(`csrc/stdio_shims.c:118`). This turns a convenience mapping into a traversal /
arbitrary-file-read primitive for guest native code. Whether it is reachable
depends on the confinement around the native harness (Landlock would still gate
the final `open`), but the translation's own contract — "never invents a file
outside the extraction" — is broken, and it defeats any caller that relies on
the mapping to keep guest reads inside the boot tree.

**Repro (host, no sandbox needed).** `ACOS_BOOT_DIR=$(mktemp -d)` then call the
exported `translate_guest_system_path("/system/../etc/passwd")` from a unit test
or via `acos_translate_guest_path`; it returns `/etc/passwd`.
**Patch:** `results/audit/patches/121A_guest_system_path_and_timerfd.patch`
(rejects any non-`Normal` component; unit test added).

## 2. S3 — `timerfd_settime` dereferences an invalid guest pointer

```rust
let r = libc::timerfd_settime(fd, flags, new_value, old_value);
if !new_value.is_null() {                       // engine_gaps.rs:137
    let v = (*new_value).it_value;              // :138  (unconditional)
```

`TIMER_TRACE` is `false`, so the *intent* is inert, but the dereference is
outside the trace guard. A guest passing a non-null, unmapped `new_value` makes
libc return `EFAULT` and then ACOS dereferences the same bad pointer → host
SIGSEGV. In a confined process this is self-DoS; in an in-process embedder it is
a crash of the host.
**Patch:** same patch (guard the dereference with `TIMER_TRACE`; invalid-pointer
test added).

## 3. S3 — `ALooper` fd leak on partial creation

`make_looper` (`ndk_looper.rs:128`) creates both `epoll_create1` and `eventfd`;
only the both-succeeded path uses them. When one fails, `alooper_prepare`
(`:176-190`) calls `unsupported(...)` and returns NULL, and neither descriptor is
closed — the successful one leaks. `Looper` has no `Drop`, so nothing reclaims
it later either.
**Patch:** `results/audit/patches/121A_alooper_fd_leak.patch` closes the
surviving fd in the failure branch (no double-close: the error path returns
before use).

## 4. S3 — unbounded `ALooper` posted-frame queue

`post_frame_callback` (`ndk_looper.rs:408`) `push_back`s a `PostedFrame` for
every guest `AChoreographer_postFrameCallback`; the queue (`posted`, `:81`) is
drained only by `pollOnce`/`pollAll`. A guest that posts in a loop without
polling grows a `VecDeque` without bound (memory DoS). A cap (drop-oldest with a
diagnostic counter) is the natural fix, but it changes frame-delivery semantics
on a latency-sensitive engine path, so it is left documented rather than patched.

## 5. S3 — pthread side-table destroy race (use-after-free)

`mutex_ptr`/`cond_ptr`/`rwlock_ptr`/`attr_ptr` (`pthread.rs:166-196`) take the
map lock, insert a `Box<T>`, and return `as_mut()` **after the guard is
dropped**. The caller then uses the raw pointer in a separate `libc::pthread_*`
call. `pthread_mutex_destroy` (`:214`), `pthread_cond_destroy` (`:257`) and
`pthread_attr_destroy` (`:313`) `remove` the box under the same lock, freeing
the heap object. A guest that destroys a mutex/attr while another thread is
inside `lock`/`unlock`/`setdetachstate` races to a use-after-free. Requires a
guest race, so S3; a correct fix needs the operations to run while the table
lock is held (or per-object Arc), which is a larger refactor.

## 6. S3 — unbounded pthread handle tables

The same functions lazily insert for **any** guest address (the static-initialiser
path is intentional), so a guest loop calling `pthread_mutex_lock(<new addr>)`
or `pthread_cond_wait` on ever-new addresses grows host memory without limit and
without eviction. Bionic's contract is on the caller, but the shim runs in the
same process as the guest, so a hostile guest can OOM the host. Documented; a
cap needs a policy decision (the current design deliberately supports
static-initialiser addresses that `_destroy` may never be called for).

## 7. S3 — crafted boot-cache frame overflows into a slice panic

`decode_boot_payload` (`session_pool.rs:231`) reads `snap_len`/`img_len` as
**full `u64`s** (`:295`, `:305`) and then tests `bytes.len() < pos + snap_len`
(`:297`) / `bytes.len() != pos + img_len` (`:307`). In release the addition
wraps; in every profile the following slice (`bytes[pos..pos + snap_len]`,
`:300`) panics. The module doc promises "a corrupt cache file is a clean `Err`
and the caller falls back to a boot" — this path panics `acos launch`/`acos
serve` before the checksum-free decode can return.

**Repro sketch.** With a warm cache dir, rewrite the entry's framed payload so
the 8-byte snapshot-length field is `0xFFFF_FFFF_FFFF_FFFF`; the FNV payload
checksum is trivially recomputable, and `decode_boot_payload` panics with
"range end index … out of range". (The file's outer CRC is FNV, so an
accidental corruption is caught earlier; a writer of the cache can always pass.)
**Not patched:** `session_pool.rs` is off-limits this round. Fix is
`checked_add`/`usize::try_from` and comparing against `bytes.len() - pos`.

## 8. S3 — boot-image `dex_paths` re-open has no containment check

`BootImage::from_bytes` (`snapshot.rs:233`) iterates the decoded
`SerializedBootImage.dex_paths` and calls `acos_dex::shared_dex(Path::new(path))`
(`:243`), which `std::fs::read`s and parses the file (`acos-dex/src/cache.rs:96`).
The paths are arbitrary strings from the untrusted cache payload; nothing checks
that they live under `data.boot_dir` (which is present in the same struct). A
poisoned cache entry therefore makes the host open/parse an arbitrary file as
DEX. The module's trust model says the cache is not a boundary, and the same-user
threat means this is defence-in-depth — but the check is cheap and absent.
**Fix (documented):** after decode, require every `dex_paths` entry to be
`canonicalize(path).starts_with(canonicalize(boot_dir))`. Not patched because
`snapshot.rs` is shared with concurrent agents and the change touches a
hot/validated path.

## 9. S4 — cache authenticity / cross-user poisoning

`image_key` is FNV-1a over the boot-classpath definition and file
path/size/mtime (`boot_image_cache.rs:262`); `decode` verifies only magic,
format, key, ACOS version, length and an FNV payload checksum (`:431`). This is
corruption detection, not authenticity. `ensure_private_dir` (`:527`) creates
the dir, then tightens mode to `0700` if any group/other bit is set — but it
does not check the directory **owner**, does not reject a symlinked root, and
`create_dir_all` follows symlinks. Practical exposure:

* normal default `~/.cache/acos` (0700, owner-checked by the kernel) → only the
  same user can write, i.e. no privilege boundary is crossed;
* `ACOS_CACHE_DIR`/`XDG_CACHE_HOME` pointing at a shared or attacker-created
  directory → another local user with write access can pre-seed an entry under
  the (non-secret, metadata-only) key and cause arbitrary `dex_paths` (finding
  8) and arbitrary borsh class/method tables to be installed.

Recommendation: require `st_uid == geteuid()` and reject a symlinked root before
`create_dir_all`. Documented (small, but not patched to keep the native-loader
acceptance self-contained).

## 10. Honest negative — no borsh allocation bomb

The review brief asked specifically about `BootImage::from_bytes` borsh decoding
of untrusted files. borsh 1.8.1 decodes `Vec<T>`/`HashMap` with
`Vec::with_capacity(hint::cautious::<T>(len))`
(`borsh-1.8.1/src/de/mod.rs:415`), where `cautious` caps the hint at
`4096 / size_of::<T>()` (`src/de/hint.rs:2`). A 4-byte `u32::MAX` length prefix
therefore does **not** allocate exabytes; the element loop then hits EOF and
returns `Err`. The outer cache layer independently caps the file at 64 MiB
(`boot_image_cache.rs:49`). Remaining exposure is bounded decode amplification
(small on-disk empty collections expand to in-memory structs), not a bomb.

## 11. S4 — Landlock ancestor-search widening (device nodes still fail closed)

The committed range changed `add_path_rule` to `fstat` the opened `O_PATH` fd and
mask `DIRECTORY_ONLY_RIGHTS` for non-directories (so `/dev/urandom`, `/dev/null`
rule adds no longer `EINVAL`), and re-uses `handled_fs(abi)` for read-write
roots. The working tree (W120-A, uncommitted) additionally grants
`EXECUTE`-only on every ancestor of each granted path (`landlock.rs:142,185-205`).
Review result:

* device-node rules **still fail closed**: masked to
  `EXECUTE|READ_FILE` (`:250-256`), `READ_DIR`/write/remove are never granted on
  a non-directory;
* the ancestor grant is search only — no `READ_DIR`, `READ_FILE`, write or
  `IOCTL_DEV` is widened, so a guest gains traversal but not listing or content
  (the new `confine.rs` `list_outside` denial asserts exactly this);
* the `direct` `HashSet<&Path>` / `seen` dedup bound the rule count by path
  depth; no unbounded growth.

Net: intended minimal widening, not a fail-open. Severity S4 (it does grant
search on `/`, `/proc`, etc.; harmless without a content right).
