## SECURITY

### S1 (S3) — `jni_NewDirectByteBuffer` unchecked host-pointer read (new `unsafe`)
`crates/acos-jni/src/jni.rs:2584-2586`:

```rust
// SAFETY: the JNI contract says `address` points at `capacity` readable bytes …
let bytes = unsafe { std::slice::from_raw_parts(address as *const u8, capacity as usize) };
```

`address`/`capacity` come from the guest JNI call. This is new since W121A
(the W156-A Flutter semantics fix, `7755818`) and is the only *new* `from_raw_parts`
in the crate. Soundness rests entirely on the JNI caller contract; a hostile
guest native can pass an unmapped address or an absurd capacity and fault the
host in the confined child (self-DoS) — or crash an in-process embedder that
hosts the VM. `native_mem_write` then copies those bytes into a synthetic
region, so a crash is the main exposure.

**Fix.** Clamp `capacity` to `acos_vm::natives::native_mem::cap_bytes()` and
reject before dereferencing; ideally validate the range against a known mapping
or catch `SIGSEGV` at the shim boundary. At minimum record the DoS as accepted
in the module's trust model.

### S2 (S4) — `sem_word` unchecked `&'static AtomicI32`
`crates/acos-native-loader/src/bionic/shims.rs:654-666`. `check_sem` rejects
null and misalignment but not an unmapped or one-byte page, so `sem_trywait`/
`sem_post` on a bad guest address is UB rather than `EINVAL`. The `'static`
return also lets a reference escape the guest object's lifetime (relies on the
guest keeping `sem_t` alive). Introduced with the Flutter semaphore shims
(W126-A/W130-A).

**Fix.** Track live guest mappings (the loader already knows the diagnostic
mapping) and check membership+length; or hold the reference only for the
duration of the operation instead of returning `'static`.

### S3 (S4) — guest-controlled `pthread` stack attributes
`crates/acos-native-loader/src/bionic/pthread.rs:427-435`: `pthread_attr_getstack`
returns the real host stack pointer for a `pthread_t`, and `pthread_attr_setstack`
writes a guest `(base, len)` into the attr. A later `pthread_create` using that
attr could run on a guest-chosen address. Because the harness is a single
confined process this is guest self-corruption, but it is new unsafe and should
be either validated (a sane length, an address inside the loader's own mappings)
or documented.

The remaining **new `unsafe`** in `acos-jni`/`acos-native-loader` was reviewed
and is sound:
`dispatch.rs::call_guest_abi` (bounds are self-consistent: `base` has ≥ `n`
words, `x` is exactly 8, stack copy reads within `n`; ABI-contract comment
present), `flutter_session.rs` `unsafe impl Send` + `JNI_OnLoad` transmute +
`alooper_prepare`/`pollonce`, `load.rs` `JNI_OnLoad` transmute + `set_vm`/
`&mut *vm`, `jni.rs` `FromReflectedMethod/Field`/`ToReflectedMethod/Field`
(operate on VM-owned handle ids), `engine_gaps.rs` (W121-A timerfd test),
`ndk_looper.rs` (W121-A fd close), `pthread.rs` `zeroed()` boxes/`pthread_equal`,
`shims.rs` `sem_getvalue`/`abs_timeout`.

### E1 (S4) — `ACOS_*` knobs that weaken protection
No knob disables Landlock, seccomp, namespaces, or `require_confinement`
(`crates/acos-runtime/src/native_bridge.rs:12` sets it as a compile-time
default; the MCP re-execs a confined child when
`!confinement_active()` — `crates/acos-mcp/src/session_backend.rs:961`). The
safety-relevant knobs, all opt-in and documented, are:

* **limb/limit widening:** `ACOS_HOST_RSS_MAX`, `ACOS_WALL_MAX_SECS`
  (`crates/acos-vm/src/limits.rs:53`), `ACOS_NATIVE_MEM_MAX`
  (`native_mem.rs`), `ACOS_MAX_OPEN_FDS`, `ACOS_MAX_BYTES_WRITTEN` (`vfs.rs`).
* **root/source redirection:** `ACOS_ALLOWED_ROOTS` (MCP readable roots —
  widenable to `/`, `crates/acos-mcp/src/server.rs:118`,
  `crates/acos-cli/src/serve.rs:300`), `ACOS_BOOT_DIR`, `ACOS_CACHE_DIR`,
  `ACOS_SESSION_ROOT`, `ACOS_RUNTIME_DIR`, `ACOS_SESSION_SOCKET`.
* **code loading into the confined child:** `ACOS_FLUTTER_LIB_DIR`,
  `ACOS_FLUTTER_DRIVER_DEX`, `ACOS_RN_DRIVER_DEX`, `ACOS_FLUTTER_SCRATCH`,
  `ACOS_RN_SCRATCH`.
* **test integrity:** `ACOS_RENDER_SKIP_GOLDEN`
  (`crates/acos-render/tests/text_metrics_parity.rs:196`,
  `text_coverage.rs:293`), `ACOS_REQUIRE_FIXTURES` (strengthens).
* **boot cache:** `ACOS_NO_BOOT_CACHE`, `ACOS_BOOT_CACHE_NO_IMAGE`
  (`session_pool.rs:1247`), `ACOS_BOOT_CACHE_DEX_TABLES`.

**Fix.** Keep `require_confinement` non-overridable (it is); document the
root-redirection knobs' trust requirement (their directories must be
same-user, `0700`) and reject world/group-writable roots in `ensure_private_dir`.

### Boot-cache loader (W160-A) — crafted cache **cannot** read arbitrary host files
The brief's key concern is answered by reading the decode path. `map0`
(`crates/acos-vm/src/natives/fwk_m2_filechannel.rs:205`) records
`Vfs::fd_file_guest_path(fd)` — the **guest** path (e.g.
`/system/fonts/Roboto-Regular.ttf`), not a host path. On restore,
`Vm::restore` calls `vfs.read_mapped_region(&source.path, …)`
(`crates/acos-vm/src/snapshot.rs:1821`), which goes through
`Vfs::open` → `normalize_guest` + `target` + `safe_path` canonical containment
(`crates/acos-vm/src/vfs.rs:786`). A crafted `source.path` such as
`/system/../../etc/passwd` normalises to `/etc/passwd`, which `target()` maps to
`ENOENT`; a path outside `/system`, `/apex/...`, `/data/...` is denied. The
`length` is checked against `native_mem::cap_bytes()`, and `hash`/`file_size`/
`file_mtime` must all match or the restore returns `SnapshotMismatch` → cache
miss → cold boot. The only unvalidated field is `offset` (a huge offset yields a
short/zero-filled `pread`, whose hash then fails), so the path is fail-closed.

Also fixed since W121A:
* **#7** `decode_boot_payload` now uses a `take(pos, n)` closure with
  `checked_add` + `end <= bytes.len()` (`session_pool.rs:257-305`); no wrap or
  slice panic on a crafted length.
* **#8** `BootImage::from_bytes` canonicalises every `dex_paths` entry and
  rejects it unless it `starts_with(boot_root)` (`snapshot.rs:283-291`).
* **Landlock** gained no widening beyond W120-A's search-only ancestor grant;
  device nodes stay `EXECUTE|READ_FILE`, and `list_outside` is asserted denied
  (`crates/acos-sandbox/tests/confine.rs:100-107`). No new seccomp scope.

### VM invariant
`crates/acos-vm/src/lib.rs:11` keeps `#![forbid(unsafe_code)]`; there is no
`allow(unsafe_code)` anywhere in the crate. `src/natives/unsafe.rs` is the
`sun.misc.Unsafe` **API** module and contains **zero** `unsafe` keywords.

## CORRECTNESS

### C1 (S3) — shared-tree contamination and mixed-wave provenance
The V1 record was produced from `20663b3` **plus an uncommitted W160-A patch**
(`BENCHMARKS.md §9.2`), while `main` advanced through W152/W155/W157/W158/W159;
the patch and the whole wave set were then committed in `42f6d44`. The
benchmark's own `before` binary `built_at` `b845c69` predates W152/W155/W157
(`results/bench/w160a-region-source.json` notes), so its −11.8 % launch delta is
"indicative", not a clean A/B. Additional cross-subsystem sweeps that make
`git bisect`/blame unreliable:

* `edfddba` (RN pixels) also edits PMS (`acos-services/src/pms.rs`,
  `pms_hello_views.golden`).
* `82a0462` (RN bridge) also edits the AIDL generator/tables and
  `acos-services` declared/registry.
* `992f3a9` (VM annotation cache) also edits `acos-framework-natives/src/res/*`.
* `629b737`'s subject says "**W163-A in progress**".

**Fix.** Land wave work in one subsystem-scoped commit; for benchmark runs,
commit the code first and record the exact commit in the artefact's `commit`
field (as §9 already tries to, but the "built_from" is an uncommitted patch).

### C2 (S4) — nondeterminism
The frame count is monotonic/racy (the reason for H3), and the latency rows were
sampled at `loadavg1 1.99` with other agents building and running. The table
discloses this ("noisy rows … host load, not code"), but the H3/H4 weakenings are
direct consequences. Prefer `before/after` deltas over absolute counts and pin
the host in the method record (already partly done).

### C3 (S4) — CI fixture coverage
See H5. `ACOS_REQUIRE_FIXTURES` is honoured by `have_fixture`, but the default
`cargo test` still skips, and `verify-all.sh` does not run the newest product
targets. `STATUS.md:230-236` correctly states the rule; the script does not
enforce it for the new tests.

### C4 (S4) — `rn_pixels.rs` / `vsync_natives.rs` bare skips
`crates/acos-runtime/tests/rn_pixels.rs:115` (missing APK) and
`crates/acos-runtime/tests/vsync_natives.rs:49,102,134` (missing `javac`/`d8`/
