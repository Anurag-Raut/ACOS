## 1. Item 1 — the saved per-step tree **is** the tree the assertion evaluated

**The W28 claim is not reproducible and is contradicted by W28's own artifacts.**
`results/art-runtime/evidence/W28-artifacts/gaten-release-tap/tree/{1,2,3}.json`
(written 00:59:29–00:59:31Z, i.e. during W28, after its 00:58Z report) each hold
**160 nodes**; `tree/1.json` contains `text: "Recently looked up"`. The debug
run's trees hold 128 nodes with the app's onboarding text. A `DecorView`-only
tree does not exist in any W28 `tree/*.json`. The report's "one `DecorView`
node" is the *root* of a pretty-printed 445 KB file (its children are ~1.8 MB
into the file, deeply indented), not the whole file.

**Why a divergence is structurally impossible on this path** (code read, not
inferred):

1. `acos-verify::executor` `wait_for` calls `backend.refresh()`, keeps
   `observation: SessionObservation`, and evaluates
   `observation.tree.find_one(&wait.selector)` (executor.rs:700-716). The
   passing step stores `exec.observation = Some(last)`.
2. The artifact writer is handed **that same `observation`** and calls
   `artifacts::write_tree(dir, seq, &observation.tree)` (executor.rs:339-342).
   One object, two uses: no re-probe, no re-serialisation.
3. On ART, `refresh()` = `ArtSession::request_tree()` → `{"cmd":"tree"}` →
   `absorb(reply)`, which parses the reply's tree into `CachedFrame.tree` and
   returns it as the observation (`engine/art.rs`). `UiTree.truncated` is read
   from the reply (`engine/mod.rs:993`).
4. `acos-art launch --interactive` binds one `ACOSPROBE` sample to one C1
   capture in the same reply (`launch.rs` `interactive_serve`, `"tree"` arm),
   and `wait_for_settled_observation` requires the probe sample to be taken
   *after* the newest stored frame.

W31 re-ran the release row with an extra frame-bound `assert_text` for the same
selector (`scenarios/w31-gaten-release-evidence.yaml`). Both selector steps
cite `tree/1.json` and `assert_text` records `matched_node_ids: ["n27_"]`;
`tree/1.json` contains `n27_` and the exact text. **No fix was needed for the
tree/assertion identity.**

**The real defect found in the same artifacts (fixed).** The interactive probe
capped a window at 160 nodes *silently*: `appendViewJson` returned at the cap
and the reply carried `{"nodes":[…]}` with no `truncated` field, so
`UiTree.truncated` was `false` for a tree that had stopped at exactly 160 nodes
(Gaten home screen: 160/160/160 in W25/W28/W31). A saved tree claimed
completeness it did not have.

* `LaunchMain`: `PROBE_NODE_BUDGET = 160`; the walk sets `truncated` when a
  child is skipped at the cap; the probe line now carries
  `"node_budget":160,"truncated":bool`.
* The engine copies the flag into `UiTree` (no code change needed there);
  `tree/1.json` now says `truncated: true` for the same 160-node tree.
* **Test with teeth**: `crates/acos-art/tests/w31_tree_evidence.rs`
  * `saved_wait_for_and_assert_text_trees_contain_the_matched_node` — for the
    real W31 artifacts: each selector step's evidence path is the tree bound to
    its own `frame_seq`, `frame.frame_seq` matches, the exact text is present,
    and every `matched_node_ids` id resolves in that file;
  * `a_decor_only_saved_tree_is_rejected` — the shape W28 described fails the
    same checker (`no node whose text …`);
  * `a_tree_at_the_node_budget_must_be_marked_truncated` — 160 nodes with
    `truncated:false` is rejected; the same tree with `truncated:true` passes.

## 3. Item 3 — the Activity token: root cause (no code change; spans services)

`LaunchMain` builds the launch transaction itself and marshals it
(`buildScheduleTransactionRequest` → `pushToPeer(3, txn)`). `obtainItem`
deliberately passes **`null` for every `IBinder` parameter**:

```java
if (t == IBinder.class) {
    // `Parcel.marshall()` refuses a parcel that carries binder objects …
    v = null;
}
```
`LaunchActivityItem.obtain(…, IBinder activityToken, …)` therefore gets
`null` → `ActivityClientRecord.token == null` → `Activity.attach(…, token)` sets
`Activity.mToken = null` → every later callback reports token `0x0`:
`IWindowSession`-independent `finishActivity` (W27), and
`IActivityClientController.activityResumed`/`activityIdle` (W28). The host side
confirms the mechanism: `atms.rs` decodes the token with `binder_u64(...)`
(`Value::Binder(None) -> 0`) and looks it up against an `ActivityRecord` it only
ever creates for its fixture token `0xabc` (`FIXTURE_ACTIVITY_TOKEN`), which the
real launcher never uses.

**Fix design (two parts, neither faked):**

* **A (acos-art, mine, next action):** deliver the `ClientTransaction`
  **in-process** — call `IApplicationThread.scheduleTransaction(ClientTransaction)`
  on the `ApplicationThread` object the guest already holds (reflection), instead
  of marshalling bytes — and pass a real `new android.os.Binder()` as
  `LaunchActivityItem`'s `activityToken`. The token then survives into
  `Activity.mToken`, so `finish()`/`activityResumed`/`activityIdle` carry one
  stable binder id instead of 0.
* **B (acos-services, W32, request in §7):** the host ATMS must know that id.
  Add `AtmsState::adopt_activity(token: u64, activity: &str)` and call it on the
  first `activityResumed`/`activityIdle` whose token is unknown while the
  process is attached (replacing/renaming the `FIXTURE_ACTIVITY_TOKEN` record,
  with a `Debug` log line); `finish_activity` then succeeds for an adopted
  token and marks it finished. Without B, A only changes `0x0` to a non-zero
  unknown token — still an error, so A alone is not shipped.

## 7. Requests (precise; owner = W32 for services)

**R1 (item 2, the only thing between PARTIAL and DONE).** In
`crates/acos-services/src/pms.rs::AppInfo::from_manifest`, replace the
hand-computed flag block (`const FLAG_HARDWARE_ACCELERATED/HAS_CODE/EXTRACT_NATIVE_LIBS`
and the `let mut flags = …` at ~lines 196-225) with:

```rust
// acos-apk owns the PackageParser transcription (`parseBaseApplication`,
// android-14.0.0_r75): hasCode/extractNativeLibs/allowBackup/supportsRtl/
// usesCleartextTraffic (targetSdk default)/largeHeap/debuggable/vmSafeMode.

```

`acos-art` reads `installed.app.flags`, clears `FLAG_HARDWARE_ACCELERATED`

then: counter `0x30800046`, Gaten debug `0x38808046`, Gaten release `0x30408044`
(the new acos-apk tests pin them). The `ACOSLAUNCH_APP_FLAGS` seam can be deleted
after this lands; until then it is the only way to run the truthful value.

**R2 (item 3, design in §3).** `crates/acos-services/src/atms.rs`:
`pub fn adopt_activity(&mut self, token: u64, activity: &str)`; adopt an unknown
token on the first `activityResumed`/`activityIdle` after the process is
attached (replace the `FIXTURE_ACTIVITY_TOKEN` record; keep it out of the
fixture lifecycle tests), log `ActivityManagerAdopt token=…`, and let
`finish_activity` succeed for an adopted token. Then W31's part A (in-process
`scheduleTransaction` + a real `new Binder()` token) makes finish/resume/idle
resolve together.

**R3 (cosmetic, item 1).** Nothing in `acos-verify`: the tree writer is already
correct. If a reviewer wants the truncation visible in the artifact name too,
