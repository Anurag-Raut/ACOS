## 1. What changed

### 1.1 Screen-space bounds for selectors and assertions

`EngineBackend`'s probe reader (`crates/acos-cli/src/engine/mod.rs`,
`ui_tree_from_json`) now stores the probe's **`bounds_on_screen`** in
`UiNode.bounds` when present, and falls back to the window-local `bounds` for a
probe that predates the field. Every `Selector::bounds`, `assert_text`/
`assert_visible` bounds comparison and tap-point resolution therefore uses the
display-space rectangle the reference scenarios use. W17 measured every failing
bounds case as exactly +128 px in y (the status-bar inset); the four W15
scenarios now match their reference bounds.

### 1.2 Tap points use screen bounds, translated once by the measured window origin

The live input channel's transform is **window-local** (W10/I2 measured a tap at
`(176,303)` for the counter's Increment button). Resolving a tap from screen
bounds and sending it unchanged missed the button (count stayed 0). `ArtSession`
now measures `(dx,dy) = bounds_on_screen - bounds` from the probe tree (the
decor root gives the window origin, normally `(0,128)`) and subtracts it in
`ArtSession::tap`. The engine keeps speaking screen coordinates; the backend
owns the one translation to the channel convention. This also fixes
`tap_text` (it resolves a screen-space node and calls the same `tap`).

Verified with explicit taps: y=303 (window-local) increments; y=431 (screen
centre) does not; after the fix the selector tap sends 303 and `v2-art-counter`
passes 11/11.

### 1.3 The richer node fields reach selectors and assertions

* `UiNode` now carries `hint` and `selected` (plus the existing
  `content_desc`/`checked`); the engine maps `hint`, `content_description`/
  `content_desc`, `checked` and `selected` from the probe.
* `Selector` gained `hint`; selector `text` matches `node.text` **or**
  `node.hint`, so a hint-only EditText can be selected by text as well as by
  `hint`/`content_desc`.
* `assert_text` matches the expected text against `node.text` **or**
  `node.hint`; its diff/error reports both (`expected text …, got text … /
  hint …`).
* `StateAssertion` gained `selected`; `assert_state` checks it alongside
  `visible/enabled/focused/clickable/scrollable/checked`.
* The protocol JSON Schemas were regenerated with
  `UPDATE_SCHEMA=1 cargo test -p acos-protocol`; the protocol tests that build
  these structs were updated for the new fields.
* Provenance is unchanged: this is all **guest-asserted tree** data (S8), and
  untrusted runs still fail closed with `INSUFFICIENT_HOST_EVIDENCE`.

### 1.4 `wait_for` polls a fresh tree until the condition or the timeout

Old behaviour: one `observe()` (cached frame) and an immediate
`ELEMENT_NOT_FOUND` — W17 saw ~1 ms for a 15 s request. New `Backend::refresh()`
is a re-traversal seam; `EngineBackend::Session` implements it with
`session.frame()` (live `tree` command, tree + PNG of that completed frame).
`wait_for`:

* attempts immediately, then polls until the selector matches (and the node is
  visible when `require_visible`); it returns on the first satisfying sample;
* backs off 25/50/100/200/400/800/1000 ms (capped at 1 s) so a long timeout does
  not exhaust the guest's C1 buffer pool;
* on deadline returns **status `timeout` / `TIMEOUT`** with details
  `{timeout_ms, elapsed_ms, polls, require_visible, selector, last_frame_seq}`;
  never a pass and never an immediate "not found";
* still fails immediately on a backend error (a broken traversal is not hidden).

Tests with teeth (`crates/acos-verify/tests/scenarios.rs`): a condition that
never appears is a `TIMEOUT` with `elapsed_ms >= timeout_ms` and ≥2 polls; a
condition that appears on poll 2 returns `pass` after 2 polls, well before a
4 s timeout.
