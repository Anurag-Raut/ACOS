## 3. Changes

1. **The stop waited out the launcher's memory watchdog, not the guest.**
   `MemoryWatchdog::drop` set `stop` and joined a sampler thread that was
   sleeping `POLL_INTERVAL = 50 ms`, so every `acos-art` exit (and the host's
   `wait_for_exit`, and therefore every reset stop) paid up to 50 ms of dead
   time: measured p50 57 ms of the 60 ms stop, reproduced by tracing the
   launcher's own `kill_guest` (0.16 ms), evidence write (0.09 ms) and
   post-serve teardown (11 ms). The sampler now sleeps on a channel
   (`recv_timeout(POLL_INTERVAL)`) and the `Drop` closes it, so it wakes at once:
   `crates/acos-art/src/watchdog.rs:110` (`wake` field), `:125` (channel),
   `:170` (wake-aware wait), `:237` (`Drop` closes it). Sampling cadence and the
   trip behaviour are unchanged; only the join stops waiting out the sleep.
2. **The process-group proof is asked of the kernel, not `/proc`.** After the
   child is reaped, `shutdown` now uses `kill(-pgid, 0)` (`ESRCH` = the group,
   zombies included, is empty) instead of reading `/proc/<pid>/stat` for every
   process on the host. The `/proc` scan still runs, but **only when the kernel
   says a member exists** — then it names the survivors for the SIGKILL/grace
   path and the structured `PROCESS_TREE_DIRTY` error. This is not weaker: the
   kernel check is atomic and cannot miss a process whose `stat` read failed,
   and the scan is still the proof whenever the answer is not a clear `ESRCH`.
   `crates/acos-cli/src/engine/art.rs:1793` (method), `:2468` (function), used at
   `shutdown` (`:1724`). New test
   `kernel_group_check_agrees_with_the_scan` (`:2972`) asserts live → not empty,
   killed + reaped → empty and agrees with the `/proc` scan.
3. **Reset phase trace (inert, env-gated).** `DM6_RESET_TRACE` now also records
   one `reset` line (`stop_ms`, `relaunch_ms`, `bind_ms`, `engine_total_ms`,
   `unix_ms`) at `crates/acos-cli/src/engine/art.rs:2209`. Unset ⇒ no work, no
   reply change, no control-flow change; consistent with the existing D-M6 sink.

Not changed: the 150 ms quiet window, the capture, the ready/`activity-resumed`
signal, the tree reply, what reset returns (`state_reset`, `data_cleared`,
`isolation:"fresh-guest-process"`, a settled bound frame), and the launcher's
run-dir teardown/evidence ordering.

## 6. What remains above 300 ms, and why

Reset p50 is ~510 ms = stop 13 + relaunch/readiness ~201 + strict bind ~291.

* **Strict bind ~291 ms (57 %).** 257 ms is the 150 ms quiet window plus the
  real first-frame ramp (the last C1 store lands ~106 ms after `activity-resumed`
  even with O3's traversal-gated ready). It is the settle that assertions rely
  on, so it must not be shortened or skipped. Removing the pixel **capture**
  (~34 ms) from a tree-only bind is P3a/P1 territory (a pixel-free cached frame)
  and was not done here.
* **Relaunch + readiness ~200 ms (39 %).** Fresh `acos-art` + bwrap + ART boot
  image + framework + resume. Persisting this needs the zygote/shared-image
  track (Z) or B3's opt-in shared boot image; nothing here can safely persist.
* **Stop 13 ms (2.5 %).** Close write + launcher exit + kernel group check.
* **End-to-end +189 ms** is the second strict tree read the M6 verifier performs
  after reset; reset already returned a settled bound frame, so a strict assert
  after reset is valid without that read. Reusing a still-fresh bound tree for a
  strict read is P3b/P1's invalidation work, not reset's.
* Identified but **not kept**: suppressing the launcher's final pretty-printed
  JSON on the interactive path measured reset **491.8** instead of 510.5 (and
  stop 13 in both), but it changes an `acos-art` CLI output path and needs its
  own gate; it is a ~19 ms option for a future task, not part of this diff.

Inspecting the guest further (probe cadence, event-driven first-frame signal) is
P3/P1; the reset work here is the stop/exit path, and it is now 13 ms.
