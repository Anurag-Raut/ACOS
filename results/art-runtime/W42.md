## 1. What the image actually sends on Activity destroy (measured)

A small driver (`.cache/w42/drive.py`) speaks the launcher's interactive protocol directly so the
host's own stderr is visible (`ACOS_WMS_TRACE=1 ACOSC1_TRACE=1`), taps `message` → types `Hello` →
taps `send` → taps `finish` and captures after Back. Raw lines:
`results/art-runtime/evidence/W42-destroy-trace.txt`.

```
ACOSWMS enter code=4 (remove) avail=24
ACOSC1 destroy handle=0x11 layers=3 buffers=1 retained=1 fds=5
ACOSWMS destroy-layer window=0x100000019 surface=0x1005 layer=0x11 dropped=3
ACOSWMS remove-layer window=0x100000019 dropped=Some(3)
```

* **The destroy is `IWindowSession.remove` (code 4)**, not a `SurfaceControl`-level transaction:
  every composer state in the surrounding transactions has `reparent=None` and no
  `eBufferChanged`-to-null (8 of 8 logged). One window = **3 layers** on this image (the window
  surface the WMS created, the BLAST child that holds the pixels, one more child) and **1 memfd**.
* The client does send visibility flags: `what=0x48` (`eFlagsChanged|eAlphaChanged`) with
  `flags=0x1 mask=0x1` (`eLayerHidden`) for its own surface controls, and `flags=0x2`
  (`eLayerOpaque`) on the window surface at destroy. Hiding is therefore a real signal too — but it
  arrives on layers that carry no pixels, so it alone does not fix a stale composite.
* The composite around the destroy: before `layer3 + layer6(z=2, Second's BLAST child)`, after
  `layer3 + layer8` (both Main). The destroyed layer is gone from the composite.

## 5. Residuals

**5.1 `Destroy from Uncreated` (pre-existing, not this fix).** The guest's stock
`DestroyActivityItem` reaches `IActivityClientController.activityDestroyed` after `finishActivity`
already removed the ATMS record, so ATMS answers `SERVICE_ILLEGAL_STATE` (`illegal transition
Destroy from Uncreated`). It is in the pre-W42 run as well, `Second.onDestroy` runs, and the frame is
correct; the owner is the ATMS/guest delivery path (W38), not the compositor.

**5.2 Two BLAST children under one window surface.** After Back the composite draws `layer3` (the
window's first BLAST child, still holding Main's last frame) plus `layer8` (the child created on
re-resume), both `z=1` at the same placement; the tie-break on layer id puts `layer8` on top and the
frame is correct. Stock destroys the old BLAST surface when the client re-creates it; ACOS has no
signal for that (`SurfaceControl` release is only visible as `reparent(null)`, which this path does
not send). A future `finishDrawing`/`createSurface` pairing could retire the older child. Not
evidence-affecting today (both children show the same Activity).

**5.3 `eReparent`-to-null is decoded but not exercised live.** The decoder reads the second nullable
`SurfaceControl` and treats a null parent on a WMS-placed layer as destroy; the multi-activity
destroy path does not send it (measured). The unit row pins the decode.
