# W48 — a validated ART heap seam, and a bench runner that cannot fill the disk

**Verdicts.**
**Item A (heap configuration seam): ACCEPTED.** The six `dalvik.vm.heap*` values
are no longer compile-time constants. `ACOS_ART_HEAPSTARTSIZE`,
`ACOS_ART_HEAPGROWTHLIMIT`, `ACOS_ART_HEAPSIZE`, `ACOS_ART_HEAPMINFREE`,
`ACOS_ART_HEAPMAXFREE` and `ACOS_ART_HEAPTARGETUTILIZATION` are parsed,
range-checked, ordered (`start ≤ growthlimit ≤ heapsize`) and written into the
property table ART's `AndroidRuntime` turns into `-Xms`/`-Xmx`/
`-XX:HeapGrowthLimit=`/… An invalid value is a structured
`INVALID_HEAP_CONFIG` **before any guest exists**; there is no silent default, and
the defaults are byte-identical to the stock table (enforced by a test that
compares the launch table to `Props::android34().to_string()`). The resolved
values are recorded in the session's own metadata. Two guarded runs of
`scenarios/v2-art-counter.yaml` (the ART counter scenario; the dispatch's
`scenarios/v2-counter.yaml` does not exist in this tree) both **pass 11/11 steps**;
`resources.json` peak RSS 86 MiB in both. **No M11 claim is made.**
**Item B (disk preflight + pruning): ACCEPTED.** Both harnesses refuse to start
under `ACOS_BENCH_MIN_FREE_GB` (default 40) with a non-zero `HOST_DISK_FULL`
exit, and delete each rep's bulky artifacts once its row is recorded. A tiny
`bench-d2 --quick` run shrank from **950 MB kept to 1.4 MB pruned**; a tiny
`bench-n art 1` run from **1.1 MB to 208 KB** (that harness's artifacts are
smaller because its seeded `/data` is thin today). Pruning keeps the two session
records inside `art-frames/`, so a pruned row still names its heap configuration.
**Evidence scope:** debug binaries for the two heap rows (labelled; not
verdict-eligible), release binaries for the harness experiments, N=1, one ART
acquisition per run. No PREVIEW evidence, nothing simulated.

## 1. Item A — the heap seam

### 1.1 What ART actually reads

`.cache/aosp/base/core/jni/AndroidRuntime.cpp:831-839`:

```c
parseRuntimeOption("dalvik.vm.heapstartsize",       heapstartsizeOptsBuf, "-Xms", "4m");
parseRuntimeOption("dalvik.vm.heapsize",            heapsizeOptsBuf,     "-Xmx", "16m");
parseRuntimeOption("dalvik.vm.heapgrowthlimit",     heapgrowthlimitOptsBuf, "-XX:HeapGrowthLimit=");
parseRuntimeOption("dalvik.vm.heapminfree",         heapminfreeOptsBuf,     "-XX:HeapMinFree=");
parseRuntimeOption("dalvik.vm.heapmaxfree",         heapmaxfreeOptsBuf,     "-XX:HeapMaxFree=");
parseRuntimeOption("dalvik.vm.heaptargetutilization", heaptargetutilizationOptsBuf,
                                                        "-XX:HeapTargetUtilization=");
```

On a device those come from `build.prop`. ACOS serves its own table
(`crates/acos-art/src/props.rs`, `acos.properties` → the shim's
`__system_property_get`), so the heap configuration used to be a literal in the
source and could not be varied without a rebuild. That is the seam this item
opens.

### 1.2 The seam

`crates/acos-art/src/props.rs`:

* `HeapSize::parse(var, "<int>[kmg]")` — decimal digits plus an optional
  lowercase binary multiplier (`k`=2^10, `m`=2^20, `g`=2^30), checked-multiplied
  into bytes. Refused: empty, whitespace, uppercase `K/M/G`, fractional,
  sign-prefixed, `0x`, double suffix, > u64.
* `HeapUtilization::parse` — a plain decimal strictly inside `(0,1)`.
  Refused: `0`, `1`, `1.5`, `.5`, `0.`, `abc`, `0.75.1`.
* `HeapConfig::from_env()` resolves the six variables over the stock defaults
  (`DEFAULT_HEAP*` consts, which `Props::android34()` now also uses, so the two
  cannot drift), then `validate()` enforces `start ≤ growthlimit ≤ heapsize`.
  An ordering error names the variable the caller actually set, so blaming a
  stock default cannot send the reader to the wrong place.
* `HeapConfigError` is typed (variable, verbatim value, what was expected);
  `Props::for_launch()` maps it to `Error::InvalidHeapConfig`, whose `Display`
  starts with `INVALID_HEAP_CONFIG:`.
* `Props::for_launch()` is now the only table the launch paths serve:
  `ArtRoot::ensure_data`, `launch::launch`, `session::session`, `app::render_app`,
  `launcher::run`, and `acos-art props print|write`. Validation therefore happens
  before the sandbox is built and before any guest process exists.
* `effective_heap_json()` + `HeapConfig::to_json()` record the effective
  property text, the byte values, and which variables were overridden.

### 1.3 Where the effective values are recorded

| record | written by | content |
|---|---|---|
| `<artifacts>/art-frames/session-exit.json` → `heap` | `launch::write_session_exit` | prop text + bytes + `overridden` |
| `<artifacts>/art-frames/live-session.json` → `heap` | `launch::write_session_evidence` (interactive route) | same |
| `acos-art launch --json` → `heap` | `LaunchResult.heap` | same |
| `acos-art session --json` → `heap` | `SessionReport.heap` | same |

`session-exit.json` is written next to the frames in the **verify artifacts
directory**, so the record travels with `resources.json`/`verdict.json`/`repro.*`
and `engine.json` points at its path. `acos verify`'s `resources.json` and
`repro.json` are owned by W46 (`crates/acos-verify`, `crates/acos-protocol`) and
were not touched: the heap block is in the ART session's record, not injected into
a protocol schema this task does not own. A future acos-cli change can copy
`heap` into `engine.json`'s `session_exit` projection the way it already copies
`code`/`stage`/`cgroup` — one field, no new measurement.

### 1.4 Behaviour on a bad value (verified, not just tested)

```
$ ACOS_ART_HEAPGROWTHLIMIT=64x acos-art props print
acos-art: INVALID_HEAP_CONFIG: ACOS_ART_HEAPGROWTHLIMIT="64x": expected <int>[kmg]:
          decimal digits with an optional lowercase multiplier (k=1024, m=1024^2,
          g=1024^3), e.g. 512k, 8m, 2g                      # rc=2

$ ACOS_ART_HEAPSIZE=16m acos-art props print
acos-art: INVALID_HEAP_CONFIG: ACOS_ART_HEAPSIZE="16m": heapgrowthlimit 192m
          must be <= heapsize 16m; the configured pair is inconsistent   # rc=2

$ ACOS_ART_HEAPTARGETUTILIZATION=75 acos-art props print
acos-art: INVALID_HEAP_CONFIG: ACOS_ART_HEAPTARGETUTILIZATION="75": expected a
          decimal strictly between 0 and 1, e.g. 0.75; 75 is outside (0,1)   # rc=2
```

Through `acos verify --engine art` the same refusal surfaces in the envelope's
error message and in the CLI's stderr line (`acos-art: INVALID_HEAP_CONFIG: …`),
classified `INTERNAL`/harness by the CLI's existing "session exited before its
ready line" rule. The launch refusal itself is structured and named; mapping it
to a dedicated protocol code (e.g. `INVALID_CONFIG`) belongs to
`crates/acos-protocol`+`crates/acos-cli` (W46) and was deliberately not done here.

and no such claim is made. Measuring that needs the N=10 suite with per-job

## 2. Item B — disk preflight and pruning

### 2.1 Preflight

`tools/art-runtime/bench-d2.sh` and `tools/art-runtime/bench-n.sh` now share the
same contract (each implemented locally; `benchlib.py` is W45's and was not
edited):

* `ACOS_BENCH_MIN_FREE_GB` (default **40**) is compared with the free space on
  the filesystem holding `$OUT`, measured with `df -Pk`. Unreadable free space is
  a warning, not a refusal (a missing answer must not block a run; the same rule
  `launch::disk_full_for_run` already follows).
* Too little space: `HOST_DISK_FULL: … refuses to run: N GiB free … below
  ACOS_BENCH_MIN_FREE_GB=40 GiB.` and **exit 6**, before the build and again
  before the first ART run (bench-d2), before the first cohort (bench-n).
* Verified: `ACOS_BENCH_MIN_FREE_GB=100000` → both scripts exit **6** with that
  message and start nothing; the normal path prints
  `disk preflight ok: 156 GiB free on … (>= 40 GiB)`.

### 2.2 Pruning

* **bench-d2**: after each rep's sample/row is parsed (`lat-*`, `cohort-N*-rep*`,
  `suite-*`), `prune_artifacts()` deletes every `frames/`, `tree/`, `logs/`,
  `live-frames/`, `screenshots/`, `session*/` directory at any depth, plus every
  `*.png` and `tree-*.json`. Kept: `verdict.json`, `resources.json`, `steps/`,
  `repro.*`, `events.jsonl`, `engine.json`, the host record (`run.json`,
  `stdout.raw`) and — important for item A — the **two session records inside
  `art-frames/`**: `session-exit.json` (exit/signal/stage facts *and the effective
  heap configuration*) and `live-session.json`. Everything else in `art-frames/`
  is the live frame buffer and goes. It prints the bytes freed per rep. (The
  first version of this prune deleted `art-frames/` whole and would have destroyed
  the heap record of every benchmark row — caught in the tiny run below, which is
  why the final run asserts the file is still there:
  `results/art-runtime/evidence/W48/pruned-rep/session-exit.json`.)
* **bench-n**: after each rep's `summary.json` exists, `prune_rep()` removes
  `agent-*/out`, `agent-*/data`, `agent-*/session-root`, PNGs and
  frames/tree/logs dirs; `summary.json`, `samples.jsonl`, `compare.json` and the
  per-agent `stdout/stderr/rc/verified/wall` stay. Prints the freed size.
* `ACOS_BENCH_KEEP_ARTIFACTS=1` disables pruning in both (bench-d2 prints a
  startup notice; bench-n prints a per-rep notice).

### 2.4 What is still not bounded

Pruning bounds a *successful* run. It does not bound a run that is killed
mid-rep (`timeout`, OOM, Ctrl-C): the rep's artifacts survive, which is intended
— they are the failure evidence. Two consecutive such runs are the reason the
preflight is a hard gate and not a warning.

## 5. Smallest next actions

1. **Measure, don't assume, the heap effect.** Run the N=10 suite through
   `tools/mem-breakdown.sh`-style per-job integrals at 8m/192m vs 4m/64m and
   compare `job_gib_min`; until then the seam is capability, not evidence of an
   M11 change.
2. **One protocol code for the refusal.** `INVALID_HEAP_CONFIG` currently reaches
   a caller as `INTERNAL` + message text; a `ProtocolError` code (W46) would let
   a harness classify it without matching prose.
3. **Bound the killed-run case.** A `trap` in the harnesses that prunes a
   half-written rep would close the last unbounded path (the failure evidence for
   that rep would need to be copied out first).
