# P5 — one full agent verification loop: 2.21 s p50, 48 % of it a Button ripple

Time box: 60 min, started 2026-11-12T15:08Z. **Diagnosis only.** No production
code change: the harness is new (`evidence/P5/p5_loop.py`), and the traces are
the existing env-gated hooks (`P3_TRACE`, `DM5_TRACE`, `DM6_RESET_TRACE`), inert
when unset. Nothing under `crates/` was touched.

## 1. Result

On a held `acos serve` ART session (HEAD `195f9b0`, release, one counter.apk
session), **one launch → inspect → tap → observe → assert → reset loop costs
2,210.6 ms p50 / 2,280.8 ms p95 (n=21 measured tasks, 21/21 verified, 0 false
passes)**. A second cohort with 5 concurrent sessions in one serve measured
**2,216.0 ms p50 / 3,250.0 ms p95 (n=25, 25/25 verified)**.

The loop is not dominated by IPC, JSON or file paths:

| rank | cost | p50 per loop | share | owner |
|---|---|---:|---:|---|
| 1 | **real Android ripple** after the counter tap, before the UI is quiet | **865.6 ms** | **38.8 %** | P1 (fast/strict, ack) |
| 2 | **fixed 150 ms quiet windows** (polled every 15 ms) | **859.6 ms** | **38.5 %** | P1 / P3 follow-up / P4 |
| 3 | **frame capture** (buffer clone + PNG + write + md5) ×6 | **203.9 ms** | **9.1 %** | P3 follow-up / P2 |
| 4 | reset relaunch: guest stop + fresh ART boot + framework + Activity | **258.8 ms** | **11.6 %** | P4 / Z track |
| 5 | IPC + JSON (7 request/reply pairs, 3.8–4.1 KiB trees) | **17.6 ms** | **0.8 %** | — |
| 6 | screenshot file read + client write | **2.3 ms** | **0.1 %** | P2 |

The tap alone (`acos_tap {id:"inc"}`) is **1,075.1 ms p50**: ~20 ms delivery,
~846–866 ms of RippleDrawable frames that keep resetting the quiet window, 150 ms
quiet, and 32.9 ms capture. That is W59's cause reproduced under the current
HEAD after O1/O2/O3. The tree verbs are the P3 split reproduced (151 ms settle +
34 ms capture each); `reset` adds a 256 ms bind because its first-frame ramp is
still animating when the bind starts.

**Throughput** (definition in §6): N=1 **0.4219 verified tasks/s** and
**136.8 verified tasks/GiB-min** (291.7 on net anon+shmem); N=5 **1.599
verified tasks/s** and **188.0 verified tasks/GiB-min** (219.4 net). These are
not comparable to the D2 13-step `62.84` row.

## 2. Method

* Build: `CARGO_TARGET_DIR=.cache/p5-target tools/guarded.sh --mem 8G --time 900
  -- cargo build --release -j 6 -p acos-cli -p acos-art` (1m11s, HEAD `195f9b0`).
  Binary sha256 `dd1c5ced8946c3a9b3179914f0cc2b7d2285526247262f25d18f823347b19937`.
* Harness: `results/art-runtime/evidence/P5/p5_loop.py`, reusing
  `tools/art-runtime/d2_warm.py`'s `Serve`, `WarmSampler`, `descendants` and
  `tools/art-runtime/agent_loop.py`'s `Daemon` (real transport: newline JSON on
  a unix socket), plus `tools/benchlib.py` for stats, provenance and the cgroup
  integral. The server is `acos serve --engine art --max-sessions 8`.
* Loop per task, exactly the six requested steps (7 requests):
  1. `acos_launch {apk}`,
  2. `acos_observe_tree` (inspect),
  3. `acos_tap {id:"inc"}`,
  4. `acos_observe {tree:true,text:true}` then `acos_observe {png:true,
     screenshot:<path>}` (two requests: see §5 item 8),
  5. `acos_observe_tree` + the bench's client-side assertion (`count` text `1`,
     same rule as `agent_loop.py::evaluate_assert`),
  6. `acos_reset`.
  A task is **verified** only when inspect text is `0`, the tap succeeded, the
  post-tap tree says `1`, the screenshot file is non-empty, and reset reports
  `state_reset` + `data_cleared` with a newer frame. Acknowledgements alone are
  never a pass (0 false passes).
* Runs, both under `run-exclusive.sh --task P5` + `guarded.sh --mem 8G --time
  900`, never overlapping P6/P1 (the lock serialises them):
  * N=1: 1 held session, 22 loops, first discarded ⇒ **21 measured tasks**,
    49.78 s cohort wall.
  * N=5: 5 held sessions in one serve, 6 loops each, first of each discarded ⇒
    **25 measured tasks**, 15.64 s cohort wall.
* Per-request wall is the client round trip; the launcher/engine phase split
  comes from the existing trace events (`art.tree` carries `settle_us` /
  `capture_us`; `art.capture_*` its sub-phases; `cli.art_cmd_wait` the launcher
  wait; `DM6` the stop). Traces are deduplicated because P3 and DM5 both trace
  some phases. I/O is `/proc/<pid>/io` deltas over the serve process tree, and
  PNG bytes are the files actually written. **Phase attribution uses N=1 only**:
  with 5 sessions in flight the single append-only trace cannot be assigned to
  one request by time window, so N=5 reports client wall + cgroup only.
* Host: N=1 load1 6.15 → 4.15, MemAvailable 46.38 → 47.57 GiB; N=5 load1
  2.52 → 1.96, MemAvailable 47.69 → 47.63 GiB. Peak guarded-cgroup memory
  316.4 MiB (N=1) and 829.7 MiB (N=5), far under the 8 G guard. Scratch was
  `.cache/p5-n1`, `.cache/p5-n5`, `.cache/p5-target` only, removed at the end.
* Raw data: `results/art-runtime/evidence/P5/loop-n1.json` (per-task rows, all
  steps, trace events), `loop-n5.json` (traces stripped for size; note in file),
  `p3.trace`, `dm5.trace`, `dm6.trace`, `commands.txt`, `p5_loop.py`.

## 3. Per-step table (N=1, n=21, p50 / p95 ms)

"settle" is `wait_for_settled_observation`; "capture" is the C1 capture that
the verb performs; "guest/real" is guest-side work (delivery, ripple, boot).

| # | step | request | p50 | p95 | settle | capture | guest/real | residual |
|---|---|---|---:|---:|---:|---:|---:|---:|
| 1 | launch | `acos_launch` | 0.25 | 0.40 | — | — | — | 0.25 (re-launch on a live session: no guest work) |
| 2 | inspect | `acos_observe_tree` | 190.64 | 192.77 | **151.13** | **34.20** | — | 5.3 |
| 3 | tap | `acos_tap {id:"inc"}` | **1075.12** | **1086.60** | 150.0 (quiet) | **32.86** | **888.6** (delivery + ripple) | 0.05 |
| 4a | observe tree+text | `acos_observe {tree,text}` | 190.47 | 196.19 | **151.08** | **34.37** | — | 5.0 |
| 4b | observe png | `acos_observe {png,screenshot}` | 36.56 | 50.17 | — | **33.4** | — | 3.2 (1.15 read + 1.11 write) |
| 5 | assert | `acos_observe_tree` | 190.41 | 202.55 | **151.07** | **34.19** | — | 5.2 |
| 6 | reset | `acos_reset` | 552.66 | 567.42 | **256.30** | **34.87** | **258.8** (69.5 stop + 189.3 relaunch) | — |
| | **loop** | 7 requests | **2210.57** | **2280.77** | 709.6 | 204.0 | 1147.4 | — |

Capture internals (median per capture, from `art.capture_*`): buffer clone /
composite **12.1 ms**, PNG encode **8.0 ms**, PNG write **1.7 ms**, `md5sum`
over the PNG **11.3 ms**; the engine then streams the same PNG again to bind
its SHA-256. The screenshot adds `png_read` 1.15 ms + client `serve_shot_write`
1.11 ms.

Everything in the "residual" column is serve dispatch, socket read/reply write,
`acos-art` command write, reply JSON parse and tree→`UiTree` parse: 17.6 ms of
2,230.7 ms for the whole loop (0.8 %). `tree_json` is 0.09 ms and the reply is
3.8–4.1 KiB in, 5.0–5.8 KiB out; the client's loop measurement adds 5.2 ms
p50 over the sum of the request walls.

## 4. Category attribution (per loop p50, from the trace, n=21)

| category | ms | share | what is inside |
|---|---:|---:|---|
| **real Android work (guest)** | **1077.8** | **48.3 %** | Button ripple frame stream + delivery (~888.6); reset's fresh ART/framework/Activity boot (~189.3) |
| **polling / fixed waits** | **859.6** | **38.5 %** | four 150 ms quiet windows (inspect, tap, observe, assert) = 600; reset bind 256.3 of which 150 quiet + 106 ramp extension; 15 ms poll quantum |
| **capture / serialisation** | **203.9** | **9.1 %** | 6 captures: clone 72.6, PNG encode 48.0, PNG write 10.2, md5 67.8, misc 5.3 |
| guest stop / teardown | 69.5 | 3.1 % | `close` → reaped → group proven empty (DM6 `stop_ms`, p50 69.5, p95 86.0) |
| IPC + JSON | 17.6 | 0.8 % | 7 client↔serve + 7 serve↔`acos-art` round trips, tree parse/serialise |
| screenshot file round trip | 2.3 | 0.1 % | read the PNG, write the caller's copy |

Counted IPC hops per loop (all measured, none estimated):

* 7 client → serve requests + 7 replies (14 socket messages);
* 7 serve → `acos-art` command lines + 7 replies (14 pipe messages), plus
  `logs` + `tree` inside reset (4 more);
* 1 command + 1 reply per verb on the launcher→guest channel, 21 gesture/input
  acks, and **~45 probe lines** (`ACOSPROBE`, 3.8 KiB each, 50 ms cadence);
  21 of them land during the 1.07 s tap.

File I/O per loop, measured from `/proc/<pid>/io` over the serve tree and from
the files on disk:

* **writes ≈ 66.8 MB**: 7 PNGs of 9,545,882 B — 5 captures (inspect, tap,
  observe, assert, reset bind) + the launcher's screenshot + the client's copy;
* **reads ≈ 162 MB**: each tree capture reads the 9.5 MB C1 buffer, then
  `md5sum` reads a 9.5 MB PNG, then `FrameArtifact::bind` streams it again for
  SHA-256; the screenshot adds one `read_png`;
* **~6,200 read syscalls and ~1,000 write syscalls per loop**, most of them the
  two whole-file hashes done in 16 KiB chunks (596 reads per tree request).
  Each capture also spawns an `md5sum` process (6 per loop).

Fixed waits, with file:line:

| wait | value | file:line |
|---|---:|---|
| quiet window | 150 ms | `crates/acos-art/src/launch.rs:1978` |
| settle poll sleep | 15 ms | `crates/acos-art/src/launch.rs:2050` |
| live probe cadence | 50 ms | `crates/acos-art/guest/java/dev/acos/art/LaunchMain.java:641` |
| launch ready gate poll | 10 ms | `crates/acos-art/src/launch.rs:2132` |
| resume watcher polls | 5 ms | `LaunchMain.java:1219, 1259, 1362` |
| stop wait | blocking `wait_for_exit`, no poll quantum | `crates/acos-cli/src/engine/art.rs:1786` |
| client recovery settle | 250 ms poll (not entered: no `NO_FRESH_FRAME` in 46 tasks) | `crates/acos-cli/src/engine/art.rs:87, 1490` |

Re-initialisation: only `reset` rebuilds anything — a new `acos-art` launcher,
a new guest, ART runtime + boot image, framework boot, `Application.onCreate`
and Activity launch (~189 ms, plus 69.5 ms stop). Nothing is rebuilt per request
except the 9.5 MB capture buffer clone and the `UiTree` (0.015 ms). The probe
thread is already per-session; the PNG encoder is stateless.

## 5. Avoidable costs, ranked (measured basis, owner marked)

| # | cost | measured now | expected saving / loop | risk | owner |
|---|---|---|---:|---|---|
| 1 | **Strict tap waits for the ripple, then observe settles again** | tap 1075.1 + observe 190.5 | **187 ms** strict (merge tap+observe: one settle + one capture + 2 hops); **~1.04 s** in fast mode (ack ≤30 ms, fast observe ≈5–10 ms) | medium–high: fast evidence must be labelled and never used for assertions; strict stays default | **P1** |
| 2 | **Fast tree**: no quiet window on navigation/inspect | 151 ms per tree verb | **302 ms** for inspect + observe only (assert must stay strict); 453 ms if assert is allowed a strict read of the same tree | medium–high: invalidation rule (`probe.at_ms >= last_store_at_ms`, newer than last input) must hold | **P1** (mode) + **P3 follow-up** (event probe) |
| 3 | **Reset binds a full tree** (`reset` → `tree`) | 256.3 settle + 34.9 capture = 291.2 | **291 ms** (return after resumed/ready; prove the post-reset screen in the next request, never claim it from readiness alone) | low–medium: must not report "reset complete" without a bound frame unless the reply says so | **P4** |
| 4 | **Duplicate tree on the same idle frame** (observe, then assert re-requests) | 190.4 | **190 ms** with a freshness-checked cache (same `frame_seq`, no input since) | low–medium: refuse on any generation/input change; never reuse a fast tree for a strict assert | **P3 follow-up** |
| 5 | **Tree requests capture pixels they do not use** | 34.3 per tree verb ×4 | **137 ms** + 4 fewer 9.5 MB writes, 4 fewer `md5sum`s, 4 fewer 9.5 MB bind reads | low–medium: `observe_tree` never returned pixels; keep frame identity from C1 metadata | **P3 follow-up** |
| 6 | Screenshot keeps `md5sum`, disk round trip and PNG | 36.6 | **~15 ms** (in-process hash, raw path, no client copy) | low | **P2** |
| 7 | Reset tears the guest down and boots ART again | 258.8 (69.5 stop + 189.3 boot) | stop ~60 ms is P4; the 189 ms boot needs a zygote/shared boot image | architectural | **P4** / Z track |
| 8 | `acos_observe {tree:true,png:true}` **silently drops the PNG** | 2 requests (227 ms) to get both | 1 redundant capture + 2 hops ≈ 36 ms, and an API that does not lie | low (API gap) | **P2/P3** |
| 9 | Probe polling: ~45 full walks + 3.8 KiB JSON/session/s, discarded unless a request is open | <1 ms CPU at 12 nodes, but competes with draws | event-driven dirty flag + wakeup; matters for big trees | low–medium | **P3 follow-up** |

If every non-guest item above landed, the loop would be ~1.08 s (mostly the
ripple); with P1's fast mode it is bounded by delivery + one capture (~50 ms).

## 6. Throughput, same definition as the existing bench

Definition (cited, not invented):

* **verified task** = the loop above passed all six checks (`pass` count; 0
  false passes). Same client-side assertion rule as
  `tools/art-runtime/agent_loop.py::evaluate_assert`.
* **GiB-min** = `tools/benchlib.py::sample_integral` (line 686) over the
  guarded job cgroup's `memory.current` sampled every 100 ms by
  `d2_warm.WarmSampler` — the same code and the same M11 formula
  (`verified_good / Σ job_gib_min`) as `results/bench/d2-*.md`, Q1 and W29.
  "net" is the W45/W52 rule: the sampler process's own anon+shmem is charged
  back out.

| N | verified / measured | cohort wall | loop p50 / p95 | tasks/s | cgroup peak | GiB-min | **tasks/GiB-min** | net anon+shmem GiB-min | tasks/GiB-min (net) |
|---:|---|---:|---|---:|---:|---:|---:|---:|---:|
| 1 | 21 / 21 | 49.78 s | 2210.6 / 2280.8 ms | **0.4219** | 316.4 MiB | 0.15355 | **136.76** | 0.071997 | **291.68** |
| 5 | 25 / 25 | 15.64 s | 2216.0 / 3250.0 ms | **1.599** | 829.7 MiB | 0.13295 | **188.04** | 0.113949 | **219.40** |

Read this carefully: the N=1 denominator is the **held session for the whole
49.8 s**, so it charges ~7.31 MiB-min per task (N=5: 5.32). At N=5 the fixed
daemon cost is amortised and the memory is 829.7 MiB for 5 sessions
(~166 MiB/session), but CPU contention stretches the tail (p95 3.25 s vs
2.28 s). The legacy/D2 `62.84 verified tasks/GiB-min` row is a different
workload (13-step verify, N=10) and **must not be set against these numbers**;
the right comparison is the same loop re-run after P1/P2/P4 land.

A hard ceiling from this run: 2.21 s per task per held session = 0.45 tasks/s
per agent, whatever the CPU has spare.

## 7. What is verified and what is not

Verified: one held `acos serve` ART session, 21 measured loops (plus 1
warm-up), every step's wall and phase split on one clock, 21/21 fresh and
complete (12 nodes, 4 text nodes, `count` 0→1, non-empty 1080×2209 PNG,
`state_reset` + `data_cleared` + newer frame_seq), 0 false passes; a second
cohort of 5 sessions in one serve, 25/25 verified; I/O counted from `/proc` and
from the PNG files; no survivors (serve rc −15 after the harness teardown, no
process left with the scratch path); host under limits; traces inert when unset;
the same numbers reproduce the P3 tree split (151 + 34 ms) and the W59 tap cause
(ripple), on the O1/O2/O3-optimised HEAD.

Not verified: the form-validation app and any app without a ripple (W59 measured
the form tap at 295 ms; the loop total there would be ~1.45 s, not 2.21 s);
trees larger than 12 nodes; the strict vs fast comparison (P1 is not merged in
this checkout — this is the **current strict path**); N=10; the exact split of
the 189 ms relaunch (D-M6 owns it); whether a freshness-checked tree cache can
be strict (it needs P1's flag shape); GPU/CPU attribution of the ripple frames.
