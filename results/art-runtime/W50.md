# W50 — `acos serve` drives real ART by default

UTC stamps (required by the dispatch): **start 2026-11-12T04:42:40Z**,

## 1. Problem and result

W49 measured the daemon/MCP path agents actually use (`acos serve`) and found it
ran `SessionBackend`/`AgentSession` (the frozen Rust VM) with no engine
selector. `acos_launch` ignored `engine`, so every app died in the Rust VM
(`BadParcelableException`) and no agent could reach a verdict through the
socket. W49's functional gates were FAIL and it could not measure real ART at
all.

W50 wires the **existing ART session machinery** behind the same socket:
`crates/acos-cli/src/engine/art.rs` (`ArtSession`, one `acos-art launch
--interactive` guest, the line-JSON tree/tap/frames protocol) — the exact
machinery `acos verify --engine art` already drives — is now what
`acos_launch` starts by default. No new runtime was written.

Measured on the W49 fixed agent loop (`launch → tree → tap → tree → type → key
→ screenshot → assert → logs → reset`) over the real Unix socket:

| gate | W49 | W50 |
|---|---|---|
| `runtime:tree_reached` | FAIL | **PASS** |
| `runtime:task_reaches_verdict` | FAIL | **PASS** (39/40 tasks) |
| `task:round_trips<=12` | NOT_MEASURED | **PASS** (8 round-trips to verdict) |
| `counter:tree_payload<=64KiB` | NOT_MEASURED | **PASS** (4,101 B) |
| verb p95 < 500 ms | PASS on error paths only | 13/18 PASS, 4 EXCLUDED, `counter:tap` FAIL (1,141 ms) |
| overall | FAIL | FAIL (one real latency gate: ART input settle) |

The remaining overall FAIL is a **real measurement**, not a broken path: every
input on ART costs the guest's own settle window (tap p50 1,117 ms), which the
500 ms warm gate inherited from the Rust VM's no-op input path cannot meet.
Nothing was relaxed to make it pass.

## 2. Design

**Engine selection is explicit and never guesses.**
`crates/acos-cli/src/engine/serve.rs::ServeEngine` multiplexes every session
tool call:

* `acos_launch` with no `engine` → **ART** (the daemon default) unless the
  request is a Flutter/RN/native-child launch (`native|flutter|rn: true`), which
  stays on the confined native-child route because the ART launcher cannot drive
  a native closure in this build; an explicit `engine: "art"` on such an APK is
  a structured `UNSUPPORTED_BACKEND` (`engine.art.native-closure`), never a
  silent switch to another route.
* `engine: "rust-vm"` → the legacy `acos_mcp::SessionBackend` (frozen Rust VM).
  Every reply (success **and** error) is relabelled `engine: "rust-vm, frozen"`,
  `engine_frozen: true`, with a note saying it is not real ART.
* `engine: <anything else>` or a non-string → `UNSUPPORTED_BACKEND` with
  `supported_engines: ["art","rust-vm"]`, `fallback_used: false`.
* `acos serve --engine art|rust-vm` sets the daemon default (default `art`); an
  unknown value refuses to start (`exit 2`).
* A session id held by ART cannot be addressed with `engine: "rust-vm"`
  (`SESSION_BUSY`); a non-launch verb on an id that was never launched is
  `SESSION_NOT_FOUND` (the pre-W50 behaviour silently created a dead Rust VM
  session).

**One ART guest per serve session.** `SessionRegistry` holds
`session_id -> Arc<HeldArtSession>` with `Mutex<ArtSession>` per session (two
connections addressing one id serialise). `acos_launch` on a live session with
the same APK is the daemon's point: it hands back the bound live frame
(`relaunch: false`) instead of booting a second guest; a different APK is
`INVALID_ARGUMENT` with the hint to `acos_destroy` first. `--max-sessions`
caps live guests (ART + legacy) with `RESOURCE_LIMIT`.

**Reset is the engine's honest reset:** `ArtSession::reset` stops the guest
(dropping its whole process group and proving it empty), launches the same APK
in a fresh `acos-art` process with empty app-data, and keeps the frame sequence
monotonic, so the frame after a reset is provably newer (`frame_seq` 1→9 in the
smoke, `previous_frame_seq` reported). It is **not** the app's Reset button.

**Teardown.** `acos_destroy` calls `ArtSession::teardown`, which closes the
guest, `SIGKILL`s its process group and reports `process_group`, `survivors`,
`verified`; a survivor is an error (`PROCESS_TREE_DIRTY`), never a quiet pass.
`acos serve` closes every ART guest on exit. W50 also sets
`PR_SET_PDEATHSIG=SIGKILL` on the `acos-art` child (`engine/art.rs`), so a
SIGKILLed daemon cannot leave a guest behind (the guest already carries the
same parent-death signal inside `acos-art`).

**Verbs.** `acos_launch`, `acos_observe_tree`, `acos_observe` (frame/screenshot,
PNG written host-side), `acos_tap` (by `id`, `text`, or `x`/`y`; window-local
offset from the probe's multi-window map), `acos_text`, `acos_key` (numeric
keycode or symbolic name), `acos_assert` (**new**, server-side assertion over
the live tree, one round trip instead of two), `acos_logs`, `acos_status`,
`acos_reset`, `acos_destroy`, `acos_action` (tap/key/text alias), plus
`ping`/`session_list`. Anything else is `UNSUPPORTED_BACKEND`. `acos_swipe` is
`UNSUPPORTED_BACKEND` naming `input.swipe` — the ART protocol has no swipe and
nothing pretends otherwise.

**Labels on every reply** (result or error `details`, same wording as
`verify`'s provenance): `engine` (`art` | `rust-vm, frozen` | `native-child`),
`engine_frozen`, `trust` (`trusted` | `untrusted`, from the request's optional
`trust`), `evidence_label` (`host-pixel` for a reply that carries host-observed
pixels, `guest-asserted` for the guest's tree/logs/acks, `none` for status),
and an `evidence` map `{frame: host-observed, tree: guest-asserted, logs:
guest-asserted, input_acks: guest-asserted, state_change: host-observed}`.
`state_changed` is the engine's own pixel-hash + tree-signature comparison, not
a guest claim. On an untrusted session `acos_assert` fails closed with
`INSUFFICIENT_HOST_EVIDENCE`.

**Typing requires a focused editable view.** `acos_text` on an ART session
first looks for a focused `*EditText`/`*AutoCompleteTextView` in the live tree;
with none it returns `UNSUPPORTED_BACKEND` (`text.input`). This is a measured
correctness fix, not a convenience: sending raw key events into a window with no
editable focus delivers them to whatever view the window focuses next. Measured
on the counter fixture: `tap inc → type "1" → key ENTER` focused the Increment
**Button** and the ENTER clicked it, leaving the counter at **2** while the W49
script asserts **1** (`probe2` in the run log). With the guard, the same loop
verifies count == 1 (19/20 samples, the 20th lost to the guest death below).

## 6. Controls and cost decomposition

`ping` p50 0.01 ms (transport floor), control `tree` p50 230.4 ms, frame-only
p50 80.7 ms— so a tree is ~230 ms of guest traversal + serialization, a
screenshot ~81 ms of capture + PNG write, and `tap` adds ~890 ms of input
dispatch + the guest's settle window on top of the frame cost. `reset` ~690 ms
(kill + fresh process + ready + traversal). The counter tap gate fails by
2.3×; the same op on the form app (tap into an EditText) is 276 ms because the
guest settles on changed pixels quickly.

## 7. Findings and remaining gaps (honest list)

1. **`counter:tap` fails the 500 ms gate (1,117 ms p50).** Real ART input settle
   (guest waits for a new buffer generation + new probe sample + changed pixels)
   dominates. W34 already shortened the guest window to 3 s and added host-side
   recovery; the *strong* path is still ~1.1 s for a changing tap. Smallest next
   action: measure whether the guest's settle window (not the engine) is the
   cost on this fixture; do not relax the gate.
2. **`counter:type` is unsupported by design.** The counter fixture has nothing
   to type into, and injecting raw keys focuses the Increment Button (measured
   count 1→2 when ENTER follows). The W49 script's `type` step is meaningless on
   that app; the honest answer is `UNSUPPORTED_BACKEND`. The form app types
   normally (268 ms p50, 20/20).
3. **A dead ART guest is not classified, and `acos_launch` can return the cached
   frame of a dead session.** In the validated run, 1/40 rows (counter run 2,
   iteration 5) hit `INTERNAL: the ART session stdin is closed` for 7 verbs
   after the guest vanished between two iterations; `launch` had answered 0.2 ms
   from the cached tree first. Run 1 lost 4/44 rows the same way (all clustered
   in 50 s, no exit record, `GUEST_EXITED: status signal 9 (SIGKILL)` on the
   replacement guest during reset). The host was not idle (three sibling agents
   running ART suites/builds), but the lock was ours during both windows and no
   exit record was written, so the cause is **not named**. Smallest next action
   (not done here — it would need another validated run): add
   `ArtSession::is_alive()` (`stdin.is_some() && child.try_wait()==Ok(None)`),
   make `acos_launch` on a dead session relaunch (or return `GUEST_EXITED`
   naming the lost guest) instead of serving a cached frame, and have the
   launcher write an exit record on SIGKILL where it can.
4. **`benchlib.py` has no `GUEST_EXITED` entry**, so a real W46 code is counted
   `unclassified` and fails schema validation (`benchlib.py` is read-only for
   W50; owner: W51 / bench owner). Run 1's JSON is kept for this reason.
5. **No dedicated screenshot verb.** `acos_observe {png:true, screenshot:path}`
   is the capture path (one round trip); the harness gap
   `serve-screenshot-verb-missing` is therefore still accurate. `acos_assert`
   now exists server-side, so `serve-assert-verb-missing` in `agent_loop.py`'s
   unconditional gap list is stale — the fixed script still uses
   `acos_observe_tree` + client-side compare exactly as W49 specified.
6. **No swipe / environment / rotation on ART.** `acos_swipe` is a structured
   `UNSUPPORTED_BACKEND`; there is no `set_*` verb and no rotate.
7. **Flutter/RN/native APKs cannot use the ART engine yet** (`native-closure`
   unsupported); they keep the confined native-child route via
   `engine: "rust-vm"` and are labelled `native-child`, not `rust-vm, frozen`.
8. **Trust is a label, not a guard, on serve.** `trust: "untrusted"` labels the
   replies and makes `acos_assert` fail closed, but the full `TrustGuard`
   (region assertions, log-only evidence refusal) is a verify-path wrapper that
   serve does not install. Serve is peer-credential checked (SO_PEERCRED) and
   root-scoped, but untrusted APKs still need the verify path's guard.
9. **`session_list`/artifacts grow per session.** Frame mirrors live under
   `$ACOS_RUNTIME_DIR/art-sessions/<session>/art-frames` and are not pruned by
   `acos_destroy` (they are evidence). A long-lived daemon with many sessions
   will accumulate them; the runtime dir is removed by the caller/harness today.
10. **`acos-art` API asks (engine owners, described here per the dispatch):**
    (a) a liveness/`status` command on the interactive protocol (or a
    launcher-written exit record when it is SIGKILLed) so a lost guest is
    `GUEST_EXITED` with a stage instead of `INTERNAL`; (b) guest-side
    `type_text` should itself refuse when no editable view has focus (today the
    host guard in `engine/serve.rs` does); (c) a swipe/touch-move command if
    input parity needs it.
