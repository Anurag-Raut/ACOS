# W56 — the cleanup suite's leak scan killed other agents' guests (scoped ownership)

**Verdict.** Confirmed and **fixed** in `crates/acos-art/tests/cleanup.rs`. Every scan,
assertion and kill is now scoped to the processes *this test* started (ancestry from the
launcher pid it spawned + this test's private data/scratch roots), and the kill path
re-derives ownership so a scan bug cannot reach `kill` for a foreign pid. Teeth kept and
demonstrated three ways (stand-in leak, real-ART A/B, real-ART positive). Proven with a
**concurrent run**: a held real ART session from another process kept the same
`(pid, starttime)` while the whole `acos-art` suite ran green.

## 1. Root cause confirmation

The suite scanned the **whole host** and treated "an ART-looking process that appeared
after my snapshot" as *this test's* leak:

* `scan_procs()` (`cleanup.rs:167`) walked all of `/proc` for
  `dalvikvm64|bwrap|acos-art|SessionMain`;
* `new_procs(&before)` = that set minus a pre-spawn snapshot (`:225`) — no relationship to
  the test's own launcher;
* `wait_until_clean(&before, 3 s)` polled it to empty (`:248`), so on a shared host it
  either timed out or returned a foreign run;
* `reap(&leaked)` then `SIGKILL`ed every entry (`:259`);
* `guest_crash_still_removes_the_run_root` did the same thing directly: it killed every
  **new `dalvikvm64`** on the host (`for g in &guests { kill(g.pid, SIGKILL) }`).

That is exactly W52 r2: 12 of its N=10 benchmark guests died from signal 9 inside one
3 ms window (`results/art-runtime/W52.md` §4), and W53 saw the mirror-image failure —
its two leak tests reporting another agent's live `acos-art launch --out
.cache/w30-suite/…` as a leak (`W53.md` §2.3 B2/B3). The narrow fix W53 applied (match
`comm` only) removed a compile-command false positive but could not remove the host-wide
scope, and it **lost a real guest**: on the `launch`/`app` route ART sets `comm` to the
*package* (`comm=fixtures.counter`) while the binary path stays in `cmdline`, so such a
leaked guest was invisible to the scan (§2.3). Both defects are fixed.

## 2. The fix (all in `crates/acos-art/tests/cleanup.rs`)

### 2.1 `Scope` — ownership from evidence only this test can produce

```rust
struct Scope { roots: Vec<(u32, u64)>, markers: Vec<String> }   // (pid, starttime)
```

* `own_run(&scratch, &data)` registers **markers**: the test's private `/data` copy
  (`<scratch>/data`) and its scratch dir. The launcher names it (`--data …`), bwrap binds
  it (`--ro-bind <data>/system /system`), so both are identifiable from their first
  millisecond and, crucially, **after the launcher is gone** (bwrap reparented → ancestry
  dead, argv still names the run).
* `add_root(pid)` registers a process the test spawned, as `(pid, starttime)`.
* `owned()` = fresh `/proc` scan → candidates that match the ART pattern **and** are
  (a) a registered root, (b) name a marker in `cmd`/`cwd`, or (c) are a child of an owned
  pid — iterated to a fixpoint. A process that started before the earliest root cannot be
  its descendant, so pid reuse cannot inherit a dead test's ownership.
* `procs()` / `wait_until_clean(within)` / `foreign(before)` replace
  `new_procs`/`wait_until_clean`; `foreign()` **reports** (never asserts on, never
  signals) the ART-looking processes that appeared and are not ours — the diagnostic that
  would have explained W52 r2 and W53 B2/B3 in one line.
* **`reap(&self, procs)` re-derives `owned()` and refuses anything else**, printing
  `cleanup: NOT killing pid=… — it is not this test's process`. Second safety layer: even
  if a survivor list is wrong, a foreign pid cannot be signalled.
* `Reaper` now keeps `Option<Child>` so a spawn's pid is available for `add_root` and its
  output can still be collected (`wait_with_output`), i.e. no test lost its leak-proofing
  when it stopped using `Command::output()`.

### 2.2 Scan predicate

`comm` **or** `cmd` may name a pattern again (W53's `comm`-only narrowing is no longer
needed: a foreign `cargo build -p acos-art` is not a descendant of this test's launcher and
does not name its scratch path, so it cannot be owned). This is what makes a leaked
`launch`-route guest visible at all (§2.3). The bwrap rule (a `bwrap` must name a repo path)
is unchanged.

### 2.3 Call sites

| test | before | now |
|---|---|---|
| `render_app_leaves_no_processes_or_scratch_behind` | host-wide scan after `status()` | `Scope` root = spawned launcher pid; `scope.wait_until_clean` |
| `sigkill_of_the_launcher_takes_the_guest_and_bwrap_with_it` | `new_procs(&before)` for the guest and for the victims list | `scope.procs()`; survivors + `reap` scoped |
| `guest_crash_still_removes_the_run_root` | **SIGKILLed every new `dalvikvm64` on the host** | SIGKILLs only `scope.procs().filter(is_guest)` |
| `r1_watchdog_reports_host_memory_limit_and_leaves_no_orphans` | host-wide scan after `output()` | spawn → `add_root` → `wait_with_output`; scoped scan |
| `log_spam_keeps_the_launcher_peak_rss_under_256_mib` | host-wide scan | scoped |
| `guest_cannot_overwrite_boot_art_or_the_classpath`, janitor | no scan / no kill | unchanged (they never scanned or killed) |

Diagnostic knob **`ACOS_CLEANUP_OWNERSHIP=host`** widens *detection* back to the old
host-wide predicate for the A/B evidence; `reap` ignores it (it always uses `owned()`), so
a diagnostic run cannot signal anyone.

## 3. Teeth (a real leak is still caught)

**3.1 New test `leak_scan_is_scoped_to_this_tests_own_processes`** (no ART needed,
deterministic, ~1 s): three stand-ins named `dalvikvm64` (a copy of `/bin/sleep`):
`own_marker` (no root, only this test's data path in `cwd` — the *leaked guest whose
launcher is gone*), `own_root` (a registered root, neutral cwd — the ancestry case) and
`foreign` (neither). It asserts the scan owns exactly the first two, ignores the third,
and then — **handed the full host-wide list, as the old code did** — `reap` kills the two
and leaves the foreign process alive (`evidence/W56/W56-teeth.txt`).

**3.2 Real-ART A/B** (same held session as §4, `ACOS_CLEANUP_OWNERSHIP=host`, one test):
the old predicate **fails** naming the background run —

```
cleanup: NOT killing pid=676223 comm=ixtures.counter — it is not this test's process
SIGKILL of the launcher (pid 680905) left 8 process(es) of this run alive after 3 s …
  pid=676217 bwrap … pid=676219 bwrap … pid=676223 comm=ixtures.counter
  cmd=/system/apex/com.android.art/bin/dalvikvm64 -cp /data/app/launch-guest/classes.dex …
test result: FAILED. 0 passed; 1 failed
```

and **no foreign pid was signalled** (`reap` refused all 7 externals + the harness)
— `evidence/W56/W56-ab-host-wide.txt`. So: the old predicate really does turn another
run into "this test's leak" (that is the false failure *and* the kill), and the new kill
path cannot act on it.

**3.3 Real-ART positive.** In the default (scoped) mode the same suite finds *its own*
guest on every session test (`assert!(!guests.is_empty())` in the SIGKILL and crash tests
is satisfied from `scope.procs()`), kills only it, and its survivors list is empty — the
scoped scan is not blind, it is selective.

**No product change is needed for this finding.** The one product observation worth

(`fixtures.counter`), so any *external* tool that identifies guests by `comm ==
"dalvikvm64"` (e.g. `bench-d2.sh:473`, `load-repro.sh:169`, and `leakcheck.sh`'s pattern
list) is blind to `launch`-route guests; they should also match the
`/system/apex/com.android.art/bin/dalvikvm64` path in `cmdline`. `cleanup.rs` now does.

## 7. Residuals

1. `ACOS_CLEANUP_OWNERSHIP=host` is a diagnostic hatch in a safety suite. It is scan-only
   by construction (`reap` re-derives ownership) and documented in the file; if a reviewer
   prefers no hatch at all, the A/B can be re-run from a scratch copy of the file instead.
2. `Scope::owned()` costs one `/proc` scan per poll (25–50 ms) and one `readlink` per
   candidate; the suite's wall time is unchanged within noise (cleanup 14.78–14.91 s across
   the two proof runs).
3. `foreign()` reporting is included in failure messages only; a future run on a busy host
   will now *explain* the noise instead of failing on it.
