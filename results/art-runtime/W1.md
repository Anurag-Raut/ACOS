## 1. What was wrong (P4c §5, confirmed in the tree)

`WmsService::call` matched five scalar `IWindowManager` methods and sent everything else to
`UNSUPPORTED_ANDROID_API` — `openSession` included. `WmsState::open_session()` existed, and
`acos-wm` implemented `addToDisplayAsUser`/`relayout`/`finishDrawing`, but the session
binder it returns is an **`acos-wm` id**, not a host binder: `registry.rs` listed
`android.view.IWindowSession` in `NOT_OWNED` and installed no node. So even a successful
`openSession` reply would have been a handle the peer could not route.

Two host-level obstacles sat behind that, both fixed here:

* `ServiceHost::transact_inner` rejected **any** descriptor in `NOT_OWNED` before dispatch,
  so a component that *had* installed a real node (the `window` service) could never be
  reached through the host — that is why `acos-binder-peer` carries a private
  `direct_dispatch` workaround (peer.rs:560). The ownership table is now a marker that only
  applies when there is **no** node: `entries` or a dynamic binder for that binder id wins.
* `binder_for_descriptor` only knew statically registered entries and aux binders, so a
  dynamic node (this session) could not be named.

## 4. The `SurfaceControl` part of `relayout` (exactly what is and is not real)

The image's `relayout` reply is **not** a bare optional: `readInt() != 0` then
`SurfaceControl.readFromParcel` (`String8 mName`, `int mWidth`, `int mHeight`, presence int,
then `nativeReadFromParcel` → one 8-byte handle; `SurfaceControl.java` `writeToParcel`). ACOS
therefore writes the **exact structural shape**, present, using the `acos-wm`
`SurfaceControlInfo` the compositor already produces (`Surface(name=<pkg>/<activity>)`, the
window size, a synthetic layer handle the guest's ACOS native accepts).

What that handle is **not**: a SurfaceFlinger layer. Nothing applies a
`SurfaceControl$Transaction` to it, `finishDrawing`'s transaction is discarded, and no buffer
the app queues ever reaches the screen — pixels still come from the ACOS renderer
(`render-app`, P3c). The missing pieces, for **W-R** (surface/vsync architecture, not
designed here):

1. a server-side `SurfaceControl`/layer object with a lifetime (create/`release`, reparent,
   buffer state) that the parcel handle resolves to;
2. a `SurfaceControl$Transaction` applier (the native op buffer `finishDrawing` and
   `relayout`'s post-draw transaction carry) and the `syncInputTransactions`/sync-group
   channel the (now-null) `out Bundle` would carry the SyncSeqId on;
3. the frame-clock half: `Choreographer` → `DisplayEventReceiver` →
   `ISurfaceComposer.createDisplayEventConnection`/`BitTube` (P4c §5.2 — that wall is
   *before* any relayout, in `ViewRootImpl`'s constructor);
4. a buffer queue from the app's `Canvas`/`Surface` to the compositor, so
   `finishDrawing` can publish.

Until then `finishDrawing` is recorded and `frames_published` stays 0 — the same rule the VM
path follows.

## 7. Limits / not done

* No ART run (task constraint), so §5 is a prediction from the code, not evidence. The
  `--until window-added` rung and the `SurfaceFlinger` wall are the next run's business.
* `IWindowManager` is still listed in `NOT_OWNED` (`acos-wm`): its node now wins over the
  marker, which is what the peer's private workaround did; removing the entry is a
  follow-up cleanup that would touch the runtime's ownership reporting.
* `SurfaceControl`, vsync/`Choreographer`, buffer queue: **not designed here** (§4 list).
* `region`/`Transaction`/`OnBackInvokedCallbackInfo` bodies are skipped rather than decoded:
  each is a native payload that no ACOS component consumes yet.
* One process, one session node: `openSession` allocates a new `acos-wm` session record per
  call but answers the same host node (a device returns a new `Session` binder). Observable
  only if two window roots in one process were driven concurrently.
