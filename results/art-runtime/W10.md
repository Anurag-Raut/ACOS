## 2. Design — the smallest control channel

No new process, socket or protocol family. The engine keeps speaking the
line-JSON protocol it already had (`tree`, `screenshot`, `tap`, `close`); it now
spawns **`acos-art launch --apk … --until activity-resumed`** with
`ACOSLAUNCH_INTERACTIVE=1` instead of `acos-art session`:

* **Guest → host tree**: `LaunchMain` starts a daemon probe thread after
  `activity-resumed`. Every 50 ms it posts a `Runnable` to the **main** looper
  that walks the decor view with getters only and prints one `ACOSPROBE {json}`
  line (id/class/text/window-local bounds/visibility/flags, 160-node budget).
  The launcher's stdout drain parses those lines live into `ProbeState`; a
  partial line is never parsed. The probe also prints an
  `ACOSPROBE-STALL main-thread | …` stack when the main thread has not run a
  sample for 2 s — that is how the frame-slot wall was named
  (`Surface.nativeLockCanvas` ← `drawSoftware`).
* **Taps**: the launcher holds the exact `InputHost` the window session uses
  (`registry::install_with_handles`). New `InputHost::tap/key` publish the same
  I2 `InputChannel` `InputMessage`s and collect the guest's `FINISHED` acks.
  No coordinates are hard-coded: the engine resolves the selector from the live
  tree (W9/I2's coordinate space is `getLocationInWindow`).
* **Frames/screenshots**: `SurfaceState` now keeps a monotonic store counter
  (`latest_generation`) and exposes `capture_latest()` — the ACOS **C1 buffer
  capture** (pixels read through C1's own dup of the guest memfd). The launcher
  writes a PNG and reports `frame_seq` (session capture sequence),
  `buffer_generation`, producer `frame_number`, `capture_source`.
* **Binding rule** (found by a failing run, not by design): a frame can land
  before the click runs, and the tree probe can see the post-click state before
  the post-click frame is stored. One run returned tree `0` with pixels `1`, so
  the executor's own `state_change` assertion failed the tap — correctly. A tap
  reply is now only sent when: C1 generation advanced, a probe sample was taken
  **after** the last store, no new store for 150 ms (settled), **and** the
  pixels differ from the session's previous capture.
* **Teardown**: `close` kills the guest's process group and its cgroup; the
  engine's existing teardown then verifies the whole process group is empty.

`reset` is deliberately not implemented on this backend (the real guest has no
shell-like reset command). `scenarios/v2-art-counter.yaml` now taps the app's
own **Reset** control; the engine reports `reset: false` and `key: false`
(window focus still needs the IME `EditorInfo` codec, I2 §5).

## 3. The wall this milestone hit, and the fix (measured)

`Surface.lockCanvas → nativeLockCanvas` blocked on the **5th** draw. Evidence
chain:

1. `ACOSPROBE-STALL` main-thread stack = `Surface.nativeLockCanvas →
   ViewRootImpl.drawSoftware → performTraversals` (blocked in `dequeueBuffer`).
2. The block appears after **exactly** `2 + getMaxAcquiredBufferCount`
   C1-stored frames: with the old constant 2 it blocked at generation 4; with
   the env override 8 it blocked at 10; with 12 at 14. That is BLAST's
   `getMaxBufferCountLocked = maxDequeued(2) + maxAcquired`.
3. The pool is consumed because **no buffer is ever reused**: with
   `ACOSART_HW_VERBOSE`, 10 `allocate:` lines for 10 stored frames in every
   run. C1's `onReleaseBuffer`/`onTransactionCompleted` deliveries arrive
   (`reverse_failed=0`) but the image's BLAST does not return the slot; W9's
   "4 allocations for 6 queue numbers" was a property of the pre-tap phase, not
   reuse under a live session. Hypothesis ledger §6.

Fix used for this milestone: **`compositor_client::getMaxAcquiredBufferCount`
answers `DEFAULT_MAX_ACQUIRED_BUFFERS = 24`** (pool 26 buffers, ~247 MiB at
1080×2209) instead of `MIN_UNDEQUEUED_BUFFERS = 2`, overridable with
`ACOS_MAX_ACQUIRED_BUFFERS` (1–64). `SurfaceState.max_acquired_buffers` uses
the same value so the callback arguments agree. **This file is outside the
packet's OWN list and is flagged prominently**: it is a memory/pipeline-depth
policy change, not a security change; the honest fix is the BLAST release path
(§7). Side effect measured: peak launcher RSS 87 MiB, guest cgroup peak 116 MiB
for the passing run; worst case if every slot is allocated is ~250 MiB per
session, still inside the scenario's 512 MiB budget.

## 7. Residuals and the next wall

1. **Next wall (precise)**: the image's BLAST never returns a producer slot to
   its pool when C1 has no presentation (`allocate` count == stored-frame count
   in every run), so a session's frame budget is `2 + getMaxAcquiredBufferCount`.
   The W10 fix is a pool-depth constant (24 → 26 buffers ≈ 247 MiB worst case),
   not the real fix. The real fix is the release path (the
   `ReleaseBufferCallback`/`onTransactionCompleted` contract BLAST uses on API
   34), in `acos-services`/`acos-binder-peer` territory; it also removes the
   memory cost and lets long agent sessions run unbounded.
2. **`compositor_client.rs` is outside this packet's OWN list**; the one-line
   default (plus env override) is flagged for integrator review. `tests/display_events.rs`
   and `tests/surface_client.rs` were updated to the constant instead of the
   literal 2.
3. `key` remains unsupported (window focus needs the IME `EditorInfo` codec,
   I2 §5); `reset` is the app's Reset control.
4. The launcher's PNG writer uses zlib stored blocks (valid, uncompressed,
   ~9.5 MB/frame). Evidence was losslessly re-encoded for the bundle; a real
   compressor would need a `png`/`flate2` dependency in `acos-art/Cargo.toml`
   (integrator-owned) — request, not blocking.
5. `md5sum` is shelled out for the PNG hash (same precedent as
   `app.rs::md5_file`); a bundled hash would remove the host tool dependency.
6. The `ACOSPROBE-STALL` probe and `ACOSLAUNCH_GUEST_STDERR_FILE` tee are
   diagnostics; they never touch app state.
7. `launch.rs` grew by ~900 lines (protocol loop, settle rule, PNG writer,
   diagnostics) — above the packet's rough 600-line threshold, but it is an
   extension of the existing launch seam (no new subsystem, process, socket, or
   security tradeoff). If the integrator prefers, the PNG writer and probe
   parser can move to a new module with a `lib.rs` declaration.
8. Pre-existing red tests unchanged: `negative_verify::broken_fixtures_never_false_pass`,
   `session::launch_counter_reports_the_honest_stage_ladder`,
   `session::warm_boot_cache_reaches_first_frame_on_every_launch` (Rust-VM launch
   path, `BadParcelableException … unread size: 796`); not touched by W10.
