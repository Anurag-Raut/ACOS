## 2. What changed and why

* **`crates/acos-services/src/ime_wire.rs` (new)** — the `IInputMethodManager`
  service as a dynamic `raw_transact` node:
  * `startInputOrWindowGainedFocus`: decodes the image request in order
    (`int, strongInterface, strongBinder, 3×int, writeTypedObject(EditorInfo),
    strongInterface, strongInterface, 2×int, writeTypedObject(ImeOnBackInvokedDispatcher)`)
    and writes `writeNoException` + presence + a real
    `InputBindResult.NO_IME` (result 6, no session/channel, request sequence).
  * `showSoftInput`/`hideSoftInput` (the sibling calls a focused `EditText`
    makes): decode the image `ImeTracker$Token` (binder + string8) and
    `ResultReceiver` typed object, answer `false`.
  * every other `IInputMethodManager` method delegates to the generic
    `Value` codec + `crate::ime::ImeService` (no behaviour change).
  * `EditorInfo` decoding is **image-exact**, including the conditional
    `AutofillId` tail, `Bundle`, `SurroundingText`, `LocaleList` and
    `contentMimeTypes`; `Spanned` `CharSequence`s (the `EditText`'s
    `mInitialSurroundingText` is a `SpannableStringBuilder`) are decoded with
    the image's span id → payload table. Unknown span/parcelable classes are a
    structured `UNSUPPORTED_*`.
  * `ACOS_IME_DUMP=<path>` writes the request bytes (the two replay fixtures).
* **`crates/acos-services/src/registry.rs`** — register the IME manager with
  `register_dynamic_named` so the host routes it to `raw_transact`.
* **`crates/acos-services/src/input_dispatch.rs`** — `FOCUS(true)` by default;
  `inject_text`/`type_text` + `text_strokes` (US/QWERTY → keyCode/metaState);
  `ChannelError::Io` for a character with no key (before publishing anything).
* **`crates/acos-services/src/input_channel.rs`** — `InputPublisher::key_stroke`
  (explicit `metaState`/`deviceId`; text uses `VIRTUAL_KEYBOARD`).
* **`crates/acos-cli/src/engine/art.rs`** — `key`/`type_text` capabilities are
  true; `type_text` sends `{"cmd":"type_text","text":…}`; protocol doc updated.
* **`crates/acos-art/src/launch.rs`** — **outside the OWN list, minimal and
  flagged**: the `"type_text"` protocol command (parses `text`, calls
  `InputHost::type_text`, then the existing settle/frame binding used by
  `tap`/`key`).
* **`crates/acos-services/src/lib.rs`** — **integrator-owned, one line,
  flagged**: `pub mod ime_wire;`.
* Tests/evidence/notebook: `crates/acos-services/tests/{ime_wire,input_dispatch}.rs`,
  `tests/fixtures/w13_ime_{start_input,text_input}.bin`,
  `results/art-runtime/evidence/W13-*`, `docs/IMAGE_ABI_NOTEBOOK.md`.

**Requested integrator edits**: (a) keep the `pub mod ime_wire;` line; (b)
review/keep the `acos-art/src/launch.rs` `type_text` command; (c) the curated
`android.view.inputmethod.ImeTracker$Token` spec in
`crates/acos-services/src/parcelable.rs` is the **tag** shape
`[FieldOp::Int, FieldOp::Str16]` and does not match the image
(`binder + string8`); the ART path no longer uses it (raw codec), but the
Rust-VM/other users still do.

## 6. Residuals

1. **Next wall (precise)**: typed characters do not resolve in the guest.
   `KeyEvent.getUnicodeChar()` → `KeyCharacterMap.load(mDeviceId)` →
   `InputManager.getInputDevice(-1)`: the reply is ACOS's VM-shaped
   `KeyCharacterMap` (`[int 4][string8 "Generic"]`) rather than the image's
   native KCM parcel, and `tools/art-sysroot.sh` does not export
   `/system/usr/keychars` (it exports `bin,etc,framework,lib,lib64`). Result:
   the map has no keys, `getUnicodeChar` returns 0, `TextView` acknowledges but
   does not insert. The key events themselves are delivered and acked.
2. `type_text` is ASCII / US-QWERTY only; a character with no US key is a
   structured error and publishes nothing (unit-tested).
3. Two adjacent files were edited outside the OWN list and are flagged:
   `crates/acos-art/src/launch.rs` (the `type_text` protocol command) and
   `crates/acos-services/src/lib.rs` (the one-line module declaration).
4. **Adjacent race (found, not fixed)**: an `EditText` tap sent immediately
   after the ready tree is followed by a guest SIGABRT (134) on
   `text-input.apk`; the same tap after the interactive driver's tree/settle
   succeeds. Repro and the two timings are in `W13-tap-crash.txt`. Another
   agent should treat this as the first item for `type_text` live work; it is
   independent of the counter key path and the milestone.
5. Pre-existing unrelated wall still visible in every run:
   `handleApplicationWtf` has no `ApplicationErrorReport$ParcelableCrashInfo`
   codec (from `TrafficStats.init` in `handleBindApplication`); it does not
   affect focus/input.
