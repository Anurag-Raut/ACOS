## 2. What changed and why

* **`tools/art-sysroot.sh`** — export `/system/usr` (keychars/keylayout/idc)
  with the rest of `/system`; extraction now also triggers when
  `system/usr/keychars` is missing. The sysroot digest changed:
  `MANIFEST.txt` `bcbad21f…` → `e29f8845…`, `READY` `3027594b…` → `162d0d82…`;
  stock `Virtual.kcm` sha256 `6356265e…`, `Generic.kcm` `8bb3a930…`
  (`evidence/W16-sysroot-digest.txt`).
* **`crates/acos-services/src/keychars.rs` (new)** — parse the stock KCM text
  with the stock parser semantics (modifier combinations, `push_front`
  behaviour order, default `number`, `fallback`/`replace`, escapes,
  `'\n' fallback ENTER`); build the image's **native** `KeyCharacterMap`
  parcel (`deviceId, hasMap, raw NUL-terminated cstring, type, overlay, keys,
  remap tables`). Resolution order: `ACOS_KEYCHARS_DIR`, `ACOS_ART_SYSROOT`,
  the productised/feasibility `.cache` sysroots, `/system`. A missing stock map
  produces an honest `hasMap=false` payload (no keys), never a guessed layout.
* **`crates/acos-services/src/misc.rs`** — the synthetic `InputDevice(-1)` now
  carries `Virtual.kcm` (touchscreen `0` carries `Generic.kcm`), the KCM
  payload is the native parcel, the touchscreen no longer claims
  `SOURCE_KEYBOARD`, and the reply field order matches the **image's**
  `InputDevice(Parcel)` (no `mDeviceBus`, no smooth-scroll boolean; the r75 tag
  has both and is wrong for this image). `ACOS_W16_TRACE=1` logs id/KCM/reply
  sizes (opt-in diagnostics).
* **`crates/acos-services/src/parcelable.rs`** — `FieldOp::Raw`: write an
  opaque payload verbatim (the KCM native bytes) and read it by walking the
  self-describing KCM layout (so the replay oracle can decode a captured
  `InputDevice` reply). The KCM spec is now `[Raw]`; the InputDevice prefix is
  corrected to the image order.
* **`crates/acos-services/src/lib.rs`** — **integrator-owned, one flagged
  line**: `pub mod keychars;`.
* **`crates/acos-art/src/launch.rs`** — publish the resolved sysroot's
  `system/usr/keychars` as `ACOS_KEYCHARS_DIR` (so an explicit `--sysroot` is
  honoured by the services).
* **`crates/acos-binder-peer/native/binder_driver.c`** — **flagged adjacent
  fixes (not in the OWN list; both required by the OUTCOME and reported here)**:
  1. `reader_main`: receive buffer `sizeof(fhdr) + E3G_MAX_FRAME + 64` instead
     of 4096 (the host contract is `HEADER_SIZE + MAX_FRAME`). A 4 KiB buffer
     truncated the 6712-byte KCM reply and silently killed the reader.
  2. `initAndroidRuntime`: after publishing `AndroidRuntime::mJavaVM`, install
     `androidSetCreateThreadFunc(javaCreateThreadEtc)` from the image, exactly
     as `AndroidRuntime::startReg` does; unattached libbinder pool threads were
     aborting `JavaBBinder::onTransact` when autofill answered its
     `IResultReceiver` after a tap.
* **Tests/evidence/scenario/notebook** —
  `crates/acos-services/tests/keychars_stock.rs`, `misc`/`keychars`/`parcelable`
  tests, `scenarios/w16-text-input.yaml`, `results/art-runtime/evidence/W16-*`,
  `docs/IMAGE_ABI_NOTEBOOK.md` (W16 section).

No `Cargo.toml`, `STATUS.md` or `OPERATING_DIRECTIVES.md` changes. No
`git add -A`, no commit, no push.

## 6. Residuals

1. `type_text` remains ASCII/US-QWERTY (`text_strokes`); a character with no
   stock key is a structured error before anything is published. Non-US layouts
   are now possible from the sysroot (`qwerty*.kcm`) but selecting a locale
   layout is a separate task.
2. The native KCM parcel is built on demand (`getInputDevice`) from the stock
   text file; the map content is not cached per device beyond the parse. Cost is
   a 15 KB parse once per process, a ~6.7 KB reply per device query.
3. Two **flagged adjacent** files outside the OWN list were edited:
   `crates/acos-binder-peer/native/binder_driver.c` (frame buffer + Java thread
   shell — both are the first error of an OUTCOME) and the one-line
   `pub mod keychars;` in `crates/acos-services/src/lib.rs`.
4. The image-vs-tag `InputDevice` mismatch (`mDeviceBus`/smooth-scroll) is now
   recorded in the notebook; any other agent adding fields must check the image
   dex, not the r75 tag.
5. Pre-existing, unrelated: `handleApplicationWtf` has no
   `ApplicationErrorReport$ParcelableCrashInfo` codec (from `TrafficStats.init`)
   — it appears in every run and does not affect text/input.
6. The earlier `cargo test` invocation failed at **link time** with lld
   `std::system_error: Resource temporarily unavailable` when many test binaries
   linked in parallel (host contention, not code); rerun with `-j 2` is green.
   Recorded so it is not mistaken for a test failure.
