# S3 — bwrap hardening adopted in `Sandbox::command` (flags + argv test)

Status: **implementer**, hard checkpoint 45 min, **nothing committed**. Owner files:
`crates/acos-art/src/lib.rs` (only the `SANDBOX_FLAGS` constant, the three-line push in
`Sandbox::command`, and one new unit test) and this file. Nothing else was touched;
`launch.rs`/`session.rs`/`app.rs`/guest tree belong to P4b-r. Every ART/cargo run went through
`tools/guarded.sh --mem 4G --time 300`; scratch is `.cache/s3/`, never `/tmp`.

Closes item 1 of `results/art-runtime/S1-sandbox-review.md` §5 (the flag half), using the flag set
`results/art-runtime/S2.md` measured as ART-safe. Item 2 (per-run `/data`) is **not** implemented —
see §5 for the exact change.

## 0. What changed

`crates/acos-art/src/lib.rs`

1. New `const SANDBOX_FLAGS: &[&str]` (above `pub struct Sandbox`) with the rationale comment.
2. In `Sandbox::command`, immediately after `let mut a: Vec<OsString> = Vec::new();` and **before**
   the first mount (`--tmpfs /`):

   ```rust
   for f in SANDBOX_FLAGS { a.push((*f).into()); }
   a.push("--tmpfs".into());
   ```

3. New test `tests::sandbox_argv_hardens_before_first_mount` (+ a 7-line `scratch_dir` helper).

The flag list and order are S2's "adopt verbatim" list, unchanged:

```
--unshare-pid --unshare-net --unshare-ipc --unshare-uts --unshare-cgroup-try
--die-with-parent --clearenv --cap-drop ALL
```

Nothing else in the argv moved: the mount sequence, `--proc /proc` (now *after* `--unshare-pid`, as
required), the `--setenv` list, the `--` exec tail, and the `ACOS_ART_DEBUG_ARGV` path are all
positionally identical. `--clearenv` sits before every `--setenv`, which is what makes the guest
environment exactly the explicit list below — bwrap applies options in order.

Deliberately **not** adopted (S2 measured or reasoned them out): `--unshare-user` (bwrap already
creates an unprivileged userns), `--disable-userns` and `--new-session` (untested against ART; a
nested-userns denial fails closed with an unexpected errno), `PR_SET_NO_NEW_PRIVS` in `pre_exec`
(already `1` inside — no-op, and that `pre_exec` lives in P4b-r's files anyway).

## 1. The guest environment under `--clearenv`

variable *names*, incl. `DISPLAY`, `WAYLAND_DISPLAY`, `DBUS_SESSION_BUS_ADDRESS`, `SSH_*`,
`*_API_KEY`, `PI_*`, `PASEO_*` — S2 §4).

`PATH`, `HOME`, `TMPDIR`, `LANG` are gone. That is safe here because every program the guest runs is

linker uses `ld.config.txt`, not `LD_LIBRARY_PATH`. Empirically confirmed by the corpus and the
render below rather than argued.

### 2.1 The orphan check

`.cache/s3/orphan.sh` starts a real long-lived guest (`acos-art session --apk …/counter.apk`) in its
own session (`setsid`, so `guarded.sh`'s process-group cleanup cannot mask a survivor), waits for the
`dalvikvm64` guest to be up, `kill -9`s the launcher, waits 3 s, and compares `pgrep -f dalvikvm64`
against the pre-trial set (other agents' guests were running on this host and are excluded, not
killed):

```
launcher pid 2069341
guest up after 1 x 0.5s: [… 2069350 2069354 2069355]
bwrap:  2069350 bwrap --unshare-pid --unshare-net --unshare-ipc --unshare-uts
        --unshare-cgroup-try --die-with-parent --clearenv --cap-drop ALL --tmpfs / …
SIGKILLed launcher 2069341
dalvikvm64 after:  []          bwrap after: []
PASS: no orphan guest (and no bwrap) left after launcher SIGKILL
```

This is S2's trial `hard kill=B` reproduced one level up, at the launcher: with `--die-with-parent`
the supervisor dies with its parent and takes the guest with it. (S2's `plain` trial had bwrap and the
guest both survive; the launcher's `PR_SET_PDEATHSIG` is cleared by bwrap's credential changes, so
before this change `acos-art` had *no* orphan protection at all.)

Residual: `--die-with-parent` covers the launcher dying. A `SIGKILL` of the *supervisor itself* is
covered too (S2 6a). It does not cover a stuck supervisor, which is a cgroup/timeout problem, not a
namespace one.

## 3. What this closes, and what it does not

Closed (S2's measured table, now in the product argv): host PID list + `kill` reachability (2a, 2g),
TCP/UDP/loopback/internet + every abstract AF_UNIX socket incl. X11/D-Bus (3a–3c), ~125 inherited
env names (4), orphan survival (6a, 6b).

Still open, unchanged by flags:

- **Writable `/data`** (S2 item 5): guest can create/overwrite/truncate anything under `/data`,
  `/linkerconfig`, `/dev/socket`, incl. `img/x86_64/boot.art` and `system/environ/classpath` which the
  host reads back. §5.
- No seccomp filter and no Landlock in this route (S1 §5 items 5–6). `--unshare-*` is namespace
  isolation, not syscall isolation.
- Memory: nothing in the argv bounds it. `session`/`app`/`launch` now log
  `guards rss_max=2048MiB rlimit_data=2560MiB stream_cap=8MiB log_cap=50000` (R1 + watchdog), and the
  `run` path relies on `tools/guarded.sh`; there is still no mandatory cgroup created by `acos-art`
  itself (S1 §5 item 3).
- `/sys` and `/etc/passwd` are still `--ro-bind`ed from the host (S1 §5 item 11).

## 4. Two behavioural notes worth knowing

- `--unshare-pid` makes bwrap PID 1 of the guest pidns, so it reaps orphans *inside* the sandbox and
  forwards signals. Nothing in ART depends on being PID > 1 on this route (the corpus and the render
  are unchanged), but `getpid()` values are now small and non-host — a guest that recorded a pid
  across invocations would see a different number.
- `--unshare-net` removes *only* the network namespace. Both guest↔host transports are **path**
  sockets (`/dev/socket/logdw`, `/data/acos-launch.sock`) and are unaffected; the shim→logd path still
  delivers the same entries (corpus `logs` counts identical to f2, render logd 968 entries).

## 5. Per-run `/data` (S1 §5 item 2): NOT done — the exact change

Assessment: **not cheap**, and it collides with files P4b-r owns this checkpoint. Today one host tree
`<data>` is shared by every route and every run:

```
--bind <data>/linkerconfig /linkerconfig   # rw   (lib.rs:712-714)
--bind <data>            /data             # rw, whole tree (lib.rs:715-717)
--bind <data>/shim/libartshim.so -> /data/shim/libartshim.so        ro
--bind <data>/socket -> /dev/socket                                  rw
--bind <image dir>    -> /data/img                                   rw (with_image / build-image)
```

Three of those mounts must stay writable **for the host's own staging steps**, which is why a blanket
`--ro-bind` is wrong and why the fix is a per-run tree, not a flag:

1. `ensure_linkerconfig` runs the image's `linkerconfig --target /linkerconfig` **through the same
   builder** (`lib.rs:243-263`), so `/linkerconfig` must be writable during that call.
2. `ensure_classpath_env` runs `derive_classpath` through the same builder and it writes
   `/data/system/environ/classpath` (`lib.rs:351-357`) — the very file S1 wants read-only for the guest.
3. `build-image` runs `dex2oat64` with `sb.rw_bind(out, "/data/img")` and writes
   `boot.art`/`boot.oat` there (`main.rs:519,539-550`); `with_image` then re-binds the same dir rw for
   `run`/`app` (`launcher.rs:172-188`).

Meanwhile the guest legitimately needs these writable at run time: `/data/dalvik-cache`,
`/data/misc/apexdata/com.android.art/dalvik-cache`, `/data/tmp`, `/data/local/tmp`,
`/data/session/<id>/{out,socket}`, `/data/out/...`, plus `/dev/socket` for logd.

So the change is a **per-run data root**, one per invocation, with the shared inputs mounted read-only
*inside* it. Concretely, in `lib.rs`:

1. Add to `Sandbox` a `rw_roots: Vec<String>` (guest dirs that may stay rw) — default
   `["/data/dalvik-cache", "/data/misc/apexdata", "/data/tmp", "/data/local/tmp"]`, plus whatever the
   route adds (`/data/session/<id>`, `/data/out`, `/data/app` for the cached guest).
2. Add `Sandbox::staging(bool)` (default `false`). When `true` the builder keeps today's argv exactly —
   this is the mode `ensure_linkerconfig`, `ensure_classpath_env` and `build-image` use, so nothing
   their staging writes is blocked.
3. In normal mode, replace the single `--bind <data> /data` with:

   ```
   --dir /data
   --ro-bind <data>/system/environ /data/system/environ   # BOOTCLASSPATH input
   --ro-bind <data>/acos.properties /data/acos.properties
   --ro-bind <data>/apex-info-list.xml /data/apex-info-list.xml
   --ro-bind <image dir> /data/img                        # boot.art (read-only for runs)
   --ro-bind <data>/app    /data/app                      # cached guest dex/libs, host-staged
   --ro-bind <data>/shim   /data/shim
   --ro-bind <data>/linkerconfig /linkerconfig            # ro unless linkerconfig is being regenerated
   --bind <data>/dalvik-cache /data/dalvik-cache          # per-run or shared, see below
   --bind <data>/misc     /data/misc
   --bind <data>/tmp      /data/tmp
   --bind <data>/socket   /dev/socket                     # path socket only
   --bind <run>/session/<id> /data/session/<id>           # per-run writable dir
   --bind <run>/out       /data/out
   ```
   (`--ro-bind` of a file is fine; `--dir` before the child binds because `/data` is a fresh tmpfs now,
   not a bind of the host tree.)
4. `ArtRoot` gains `fn run_dir(&self, id: &str) -> PathBuf` (`.cache/art/runs/<id>` or
   `<data>/runs/<id>`) and the routes (`launcher.rs`, `app.rs`, `session.rs`, `launch.rs`) pass it
   through — **that is the part P4b-r owns today**, and it is why this was left alone.
5. Decide `dalvik-cache`: sharing it across runs is what makes the corpus fast (warm), and it is the
   one subtree where a guest can poison a later run. Accept it (documented, `mmap`-checked) or move it
   under the run dir and eat the cold start. Measurement needed either way.

Effort: **M (~1 day)** as S1 estimated, because of (4) and the warm-cache trade-off in (5), not because
of the argv. It also needs a re-run of the corpus/patch timing, and it must land with an adversarial
test that tries `boot.art` and `classpath` overwrite from the guest (S1 §5 item 14) — otherwise the
change cannot be shown to have worked.

Until then the residual exposure from S2 item 5 stands, with the same interim rule as S1: run only
APKs the user built or fully trusts, and never with `ACOS_ART_DATA` outside the repo cache.
