## 1. Landlock in the guest: deferred install of the existing policy

### 1.1 Where the policy lives, and where it is applied

The ART guest is a **bionic** process: a glibc Rust `cdylib` cannot be preloaded (S5 §2.1), so the
only in-guest hook is the freestanding preload constructor. S5 deferred Landlock because
`acos-sandbox`'s builder was private and copying it into `acos-art` would create two Landlock
policies. S6 removes that blocker instead of duplicating it:

| layer | file | role |
|---|---|---|
| policy | `crates/acos-sandbox/src/linux/landlock.rs::plan()` + exports `landlock_abi()`, `landlock_guest_plan()` | the ABI-dependent handled mask, the read-only mask and the read-write mask — the same constants `restrict()` uses in-process |
| plan transport | `crates/acos-art/src/landlock.rs::write_plan()` | writes `<data>/seccomp/landlock.plan`, which every filtered run already binds read-only at `/data/seccomp` |
| applier | `crates/acos-art/src/seccomp_guest.c::apply_landlock()` | raw `landlock_create_ruleset` → `landlock_add_rule` → `landlock_restrict_self`, in the constructor, **before** the seccomp install |
| enforcement of the evidence | `landlock::require_from_log()` + `seccomp::require_guard()` + the `launcher.rs` hook | a run without `OK landlock=active` on a Landlock kernel is refused |

The plan is line-oriented text (`acos-landlock 1`, `abi N`, `handled <hex>`, `ro|rw <hex> <path>`) so
the freestanding stub needs no libc allocator or parser runtime. Paths are **guest** paths, opened by
the guest after bwrap's mounts. Missing roots are skipped (`ENOENT`), never widened — the same
behaviour as `acos-sandbox::restrict()`; `skipped=N` is in the evidence line.

### 1.2 What the ruleset actually restricts

* `handled_access_fs` = the full ABI mask (all write-class rights, `REFER`, `TRUNCATE`, and on ABI ≥ 5
  `IOCTL_DEV`). A handled-but-not-granted right is denied by the kernel.
* read-only: `/` — the guest's *own* mount view. ART needs `/system`, `/apex`, `/data/system`,
  `/data/app`, `/data/img`, `/linkerconfig`, `/proc`, `/sys`, `/dev`; bwrap already removed every
  host path outside that view, so the read roots do not need a per-directory list.
* read-write: only the per-run `/data` binds (`dalvik-cache`, `misc`, `tmp`, `out`, `task`,
  `app-data`, `session`), `/dev/socket` (logd) and the device nodes a process writes
  (`null`, `zero`, `full`, `random`, `urandom`, `tty`). Everything else in the guest is
  write-denied even where DAC would allow it.

Evidence line in a normal render (all 15 roots present):

```
OK landlock=active abi=10 rules=15 skipped=0
OK guard=active insns=83
```

In the no-ART probe (no shim, so `/dev/socket` is not bound): `rules=14 skipped=1`.

### 1.3 Fail closed, with exactly one documented fallback

* Host kernel has Landlock (`acos_sandbox::landlock_abi() == Some(_)`, here **10**) ⇒ the plan is
  mandatory. Missing plan, unreadable/unknown format, `create_ruleset`/`add_rule`/`restrict_self`
  failure, or a constructor that exits before logging `OK landlock=active` ⇒ the guest exits **126**
  and the run is refused (`LANDLOCK_UNAVAILABLE` in the structured `SECCOMP_UNAVAILABLE` family —
  the layer ships in the same guard bundle, so it uses the same error channel rather than adding a
  new variant to a file this checkpoint does not own). Proven by
  `missing_plan_fails_closed_on_a_landlock_kernel`: deleting the plan makes the guard log
  `ERR landlock=plan-missing`, no guest code runs, `require_from_log`/`require_guard` both error.
  *Superseded 2026-11-11 (E1 error-contract cleanup):* Landlock now has its own
  `acos_art::Error::LandlockUnavailable` variant, so the code `LANDLOCK_UNAVAILABLE` is no longer
  reported through `SECCOMP_UNAVAILABLE`. The S6 text is kept as the record of that checkpoint.
* Kernel has no Landlock (pre-5.13 or LSM absent) ⇒ no plan is written; the applier logs
  `SKIP landlock=kernel-unsupported`, which is the only accepted absence, and the run proceeds on
  the S2–S4 view (its write surface is already per-run). The report says "inactive", never "applied".

Scopes (ABI ≥ 6 signal/abstract-UNIX confinement) are deliberately **not** enabled for the guest:
bionic installs its own handlers after constructors, and the pid namespace plus the seccomp
`kill`/`tkill` denial already bound signalling. Recorded as a residual (§5).

## 2. Denial audit: which deny-listed syscalls a normal run actually hits

### 2.1 Method (why not strace/tracefs)

There is no unprivileged seccomp audit channel here: `SECCOMP_FILTER_FLAG_LOG`/the audit log need
`CAP_SYS_ADMIN`, a bwrap userns has none (S5 §2.3), `strace`/`bpftrace` are not installed, and the
host user cannot ptrace a guest in a child userns. S6 therefore uses the **KILL-variant audit**: the
same filter with `SECCOMP_RET_KILL_PROCESS` instead of `RET_ERRNO|EACCES` for a chosen set of
syscalls. A run that completes normally then proves none of those syscalls was attempted (a single
attempt dies of `SIGSYS`). Bisecting the 57-syscall deny list attributes the denial to one number:

```bash
# ACOS_ART_SECCOMP_AUDIT=kill           -> every deny-listed syscall is fatal
# ACOS_ART_SECCOMP_AUDIT=kill:101,157   -> only these numbers are fatal
ACOS_ART_SECCOMP_AUDIT=kill:<subset> tools/guarded.sh --mem 6G --time 90 -- \
  ./target/debug/acos-art render-app --apk fixtures/build/apps/counter.apk --out <dir>
ACOS_ART_SECCOMP_AUDIT=kill:<subset> tools/guarded.sh --mem 6G --time 90 -- \
  ./target/debug/acos-art launch --apk fixtures/build/apps/counter.apk \
    --until application-created --out <dir>
```

The audit action is part of the artefact hash, so production (`EACCES`) and audit (`KILL`) blobs can
never alias in the guard cache. Production is unchanged: `ACOS_ART_SECCOMP_AUDIT` unset ⇒ `EACCES`.

### 2.2 Result: exactly one expected denial, zero unexpected

| run | whole-list kill | bisect | verdict |
|---|---|---|---|
| `render-app` (counter.apk) | `SIGSYS`, rc 1 | **323 = `userfaultfd`** | expected: ART's GC probes userfaultfd mode and falls back on `EACCES` |
| `launch --until application-created` | no exit (rc 124 under the 90 s guard) | **323 = `userfaultfd`** | same expected denial; the hang is the W4 launch issue in §5.1 |

All other 56 deny-listed syscalls (the list has 57 distinct numbers) (`ptrace`, `mount`/`umount2`, `unshare`/`setns`, the new mount API,
`bpf`, `perf_event_open`, `keyctl`, module ops, `*set*id`/`capset`, pidfd family, `kill`/`tkill`,
`io_uring_*`, `process_vm_*`, `open_by_handle_at`, `syslog`, `acct`, `swap*`, `quotactl`,
`lookup_dcookie`, `userfaultfd`'s peers, `AF_INET`/`AF_NETLINK` sockets via the socket check) were
**never attempted** in either run. There are **zero unexpected denials**.

`clone3` is not a denial of an attempted escape: it returns `ENOSYS` by policy so bionic falls back to
the filtered `clone`; the audit confirms it as a designed non-fatal answer, not a kill.

### 2.3 Landlock denials in a normal run

Landlock has no audit channel without `CAP_SYS_ADMIN` in the initial user namespace, so "attempted
and denied" writes cannot be enumerated by the kernel. What S6 establishes instead:

1. The applied ruleset (paths + masks) is in the run's evidence, so the *policy* is recorded exactly.
2. The ruleset only leaves **write-class** rights un-granted: `READ_FILE`/`READ_DIR`/`EXECUTE` on `/`
   means no read in the guest's own view can be Landlock-denied, so the open question reduces to
   "does a normal run write outside the rw roots?".
3. A refused write-open returns `EACCES` to the guest and is not retried silently; the probe in §3
   proves that shape, and both normal runs (render md5/SSIM identical, launch `outcome=ok`, logd
   behaviour normal) show no such failure. Therefore: **no Landlock denial is needed or observed in a
   normal render-app or LaunchMain run**.
4. The escape corpus in §3 enumerates the denials the layer *does* produce for the attack paths, with
   errno and responsible layer:

| attack (guest) | result | layer |
|---|---|---|
| write `/data/out/…`, `/data/tmp/…` | **WRITTEN** | rw grant |
| write `/data/pwn` (tmpfs root) | `EACCES` | Landlock |
| write `/data/local/tmp/pwn` | `EACCES` | Landlock |
| write `/etc/pwn` | `EACCES` | Landlock |
| write `/data/system/environ/pwn` | `EROFS` | read-only bind (before Landlock) |
| write `/linkerconfig/pwn` | `EROFS` | read-only bind (before Landlock) |
| read host `$HOME/…` | `ENOENT` | mount view |
| read `/etc/hostname` | `ENOENT` | mount view |
| read `/proc/1/root/home/Qui/.bashrc` | `EACCES` | kernel ptrace check (S2) |
| visible pids in `/proc` | **2** (host: ~660) | pid namespace |
| `ptrace(PTRACE_TRACEME)` | `EACCES` | seccomp |
| `userfaultfd` | `EACCES` | seccomp (the audited expected denial) |
| `socket(AF_INET)` | `EACCES` | seccomp socket check |
| `socket(AF_UNIX)` | allowed | by design |

## 3. Adversarial corpus (`crates/acos-art/tests/sandbox_s6.rs`)

Five tests, all running the attack **inside the real guest argv** (`Sandbox::command`, per-run
`/data`, the same preloaded guard) under a proven cgroup scope. One guest at a time
(`static Mutex<()>`), each bomb bounded by the scope and by a wall-clock bound; the host's
`MemAvailable` is sampled before/after.

| test | assertion | measured |
|---|---|---|
| `escape_corpus_is_denied_in_the_real_guest` | every row of the table above; `OK landlock=active` + `OK guard=active`; `require_guard`/`require_from_log` both accept | pass, probe exit 0 |
| `missing_plan_fails_closed_on_a_landlock_kernel` | plan removed ⇒ `ERR landlock=plan-missing`, no guest marker, non-zero exit, both guard checks refuse | pass |
| `fork_bomb_in_the_guest_stays_under_pids_max` | scope never exceeds `pids.max=32`; no survivor after `cgroup.kill` | **max 32** (probe's `fork` stopped at 29, `EAGAIN`), 0 survivors |
| `memory_bomb_in_the_guest_is_oom_killed_at_the_cap` | 1 MiB/touch loop under `memory.max=128 MiB`: OOM kill (or allocator refusal) at the cap, peak ≤ 256 MiB, non-zero exit, host floor `MemAvailable > 8 GiB` sampled throughout, 0 survivors | **`oom_kills=1`, peak 128 MiB**, host min 32.2 GiB, 0 survivors |
| `userfaultfd_is_denied_and_expected_in_a_normal_run` | 323 stays denied; futex/mmap/mprotect/memfd_create/clone stay allowed | pass |

The fork bomb produced `fork stopped at 29 (errno=11)` — the kernel's `pids.max` accounting includes
ART-side threads in real runs, so the guest's own count stops a little below the cap; the scope count
(processes + threads) is what the test asserts, and it never exceeded 32.

## 5. Residuals, blockers, and what is *not* covered

1. **`launch` hangs when the guest dies before its milestone (W4's area, not changed here).**
   Two independent triggers: (a) the mandatory-Landlock fail-closed path (plan removed ⇒ guard exits
   126), and (b) the whole-list KILL audit filter. In both cases `launch --until …` does not return;
   it ran into the outer 90 s/400 s guard (rc 124) instead of surfacing a structured error, and left
   its per-run root behind. A guest that dies from a denied syscall must make the route fail fast. The
   `run`/`render-app`/`session` routes already do (they returned in the same experiment). Reported for
   W4; not edited here.
2. **LaunchMain currently stops at `NO_ACTIVITY_RESUMED`.** At HEAD (`ea99a0c`, W4's in-flight
   surface/ATMS work) `--until activity-resumed` returns `outcome=crash, code=NO_ACTIVITY_RESUMED,
   application_created=true, activity_launched=false`, with `LOG_ALWAYS_FATAL`/`ISurfaceComposer`
   placeholders in the log — the known W4 wall, reproduced identically twice. The S6 audit therefore
   uses `--until application-created` (ActivityThread.main + Application.onCreate), which is `ok`.
   This is not a Landlock effect: with Landlock disabled the run does not get further.
3. **No kernel audit channel for denials.** Seccomp denials are attributed by the KILL-variant bisect
   (§2); Landlock denials cannot be enumerated kernel-side without `CAP_SYS_ADMIN` in the initial
   namespace. The evidence is the applied ruleset + identical outputs + the probe corpus, not a
   per-path kernel log. A `SECCOMP_RET_USER_NOTIF` supervisor in the launcher (listener fd handed over
   before the exec) remains the proper attribution fix for seccomp, and would be the only way to get a
   per-syscall/per-path log for landlock *and* seccomp in one place.
4. **The evidence file is guest-writable** (`<run>/out/seccomp.log`): it proves what the constructor
   installed and reports, not a tamper-proof audit trail (S5 residual 4, unchanged).
5. **Landlock scopes (ABI ≥ 6) are off for the guest**: signal and abstract-UNIX-socket confinement
   would be defence in depth, but bionic's own handler setup and the binder-over-`/dev/socket` path
   make it unsafe to enable without a dedicated test matrix. `kill`/`tkill` stay seccomp-denied and the
   pid namespace bounds signalling (S2).
6. **`IOCTL_DEV` is handled.** ioctls are granted only on the rw device list (`/dev/null`, `/dev/zero`,
   `/dev/*random`, `/dev/full`, `/dev/tty`); an ioctl on any other device node would be `EACCES`. No
   ART path needed one in the corpus, render or launch runs; a future device (e.g. `/dev/binder` under
   a different transport) must be added to `READ_WRITE_ROOTS` explicitly — this is the intended
   "deny by default" behaviour.
7. **`execve` remains allowed in the guest** (S5 residual 5) and the new image inherits the ruleset and
   filter, so it still cannot leave the run root or the namespace view.
8. **Guard artefacts are shared per data dir, not per run.** The plan blob is content-identical for
   every run and the audit action is in the hash, so runs cannot mix blobs; a run does not re-verify
   the blob's hash at exec time (it reads whatever `<data>/seccomp` holds, as S5 already did).
9. **Memory bomb outcome is "bounded", not always "SIGKILL", and the host assertion is an absolute floor.** At 128 MiB with 1 MiB chunks the memcg
   OOM killer fires (`oom_kills=1`); with 8 MiB chunks the allocator could instead get `ENOMEM` first
   (charge failure). The test accepts both because both are the cap refusing memory, and asserts the
   peak, the non-successful exit and the host's `MemAvailable`. The first host assertion compared
   endpoints (before/after < 512 MiB) and flaked once because this host is shared with other agents
   building concurrently; it is now an absolute floor (`min MemAvailable > 8 GiB`, sampled during the
   bomb) plus the exact in-scope peak, which is the claim that matters.
