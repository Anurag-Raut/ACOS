**Verdicts.**
**Task: ACCEPTED** for the OUTCOME. The 1.7x swing in `job GiB.min` for one
binary is explained by measurement scope, not by the product: `tools/run-suite.sh`
integrates `memory.current` of the **suite runner's** cgroup, which (a) does not

## 1. Why the same binary gave 4.01 and 2.37 GiB·min

Four defects, all in the *measurement*, ranked by size. Evidence: the cgroup
topology probe (`.cache/w41/probe-out.txt` transcript in the ledger below) and
the per-component samples in `results/bench/mem-W41-*.json`.

### 1.1 The guest is not in the job cgroup (largest)

`tools/guarded.sh` puts the runner in a transient scope
`run-p<jobpid>-i<inv>.scope`. `acos-art` then creates the guest with
`systemd-run --user --scope`, which lands as a **sibling** scope in `app.slice`:

```
acos        (job)   .../app.slice/run-p3855427-i8055567.scope
bwrap       (guest) .../app.slice/run-p3855923-i8086200.scope   <-- not a child
acos-art, dalvikvm64/.formvalidation (guest) same sibling scope
```

`run-suite.sh` samples `cgroup_path()` = `/proc/self/cgroup` = the **job** scope
only. So its `job_gib_min` is the *host-side* runner (python 24 MiB, `acos`
84 MiB PSS, `acos-art` 60 MiB) plus whatever page cache those processes touched —
and **none of the guest's ~110 MiB**. W34's "memory per task" figure was measuring
the wrong cgroup.

### 1.2 Shared page cache is charged to whoever faults it in first

cgroup v2 charges file pages to the cgroup that first brings them in; the 860 MiB
ART sysroot, the 60–100 MB debug binaries, extracted DEX under `ACOS_ART_DATA` and
the PNG/verdict writes all land in the job scope. Measured composition of a T07
job (p50, GiB·min): anon 0.0260, **file 0.0141** (33 % of `job_all`), shmem 0.0033,
kernel 0.0010. For T02 file is 29 %; for T01 13 %. Whether those pages are charged
to *this* job depends on whether another live cgroup already owns them, so the
same binary swings. The controlled test (prewarm the read-only inputs from outside
the job scope, §4.3) moves T07 `job_all` by **−18.7 %** and `file` by −16 %.

### 1.3 The job scope lives for the whole suite and accumulates

`run-suite.sh` creates **one** guarded scope for all 22 variants. Page cache is
never given back, so `memory.current` grows monotonically across the suite
(W34 §7 records 321 → 1 591 MiB), and *every* variant's integral is charged the
current high-water mark × its wall. Consequences, measured per task in a fresh
scope vs the same task inside the suite's scope (run-suite numbers from W34):

| task | run-suite (suite scope) | mem-breakdown (fresh scope) | ratio |
|---|---:|---:|---:|
| T01 | 0.0033–0.0079 | 0.000637 | 5–12x |
| T02 | 0.0177 | 0.015302 | 1.16x |
| T07 | 0.0889–0.3306 | 0.024783 | 3.6–13x |

The same-binary pair `suite-W34-before1` (4.0086) / `before2` (2.3694) differed
because the charged-cache high-water differed (cold sysroot vs pages already owned
by another agent's live cgroup, plus reclaim under the disk-full window), while
the wall was identical (244.2 s vs 245.1 s). 1.7x is exactly this.

### 1.4 Sampling gaps and the sampler's own memory

`run_one()` samples only while the child is alive, has no closing sample, never
samples between variants, and the 100 ms trapezoid under-reads peaks on 1 s tasks
(T01 gets 10–13 points). The runner python (24 MiB anon) is inside the scope it
measures for the whole run; at T07 scale that is **0.0045 GiB·min = 14.7 %** of
`job_resident`. `mem-breakdown.sh` reports `sampler_overhead_gib_min` and
`job_resident_excl_sampler_gib_min` for this reason.

Not a cause: other agents' *processes* are never in the job scope (per-run
systemd scope). They matter only indirectly (they own the shared page cache and
they raise load, which raised `queue_wait_s` up to 274 s in this session).

## 2. The stable measurement: `tools/mem-breakdown.sh`

New tool (only file written outside `results/`). It samples every 100 ms, for one
task, in one fresh guarded scope:

* the **job cgroup** (`/proc/self/cgroup`): `memory.current` + `memory.stat`
  (`anon, file, shmem, kernel, kernel_stack, sock, slab, pagetables, pgfault,
  pgmajfault, workingset_refault_file`);
* **every guest cgroup the run creates**, discovered from the launcher's own
  `<run>/cgroup` evidence file and (before that file exists) from
  `dalvikvm*/bwrap` processes whose **ppid chain leads to this process** —
  other users of bwrap on the host (flatpak) are explicitly excluded;
* **per-process PSS/RSS** (smaps_rollup) every 3rd tick, classified as
  guest-app / guest-dalvikvm / acos-art-launcher / acos-host / bwrap /
  sampler-python;
* a **closing sample** after the child exits, so teardown has two points.

It reports three denominators and never sums across types:

| field | meaning |
|---|---|
| `scope_gib_min_runner_formula` | job scope only — reproduces today's run-suite number |
| `job_gib_min_all_cgroups` | job + guest scopes, `memory.current` (the advisor's v2 formula, fixed) |
| `job_resident_no_file_gib_min` | job + guest, `Σ(anon+shmem+kernel+sock)` — **the page-cache-free per-task cost; this is the metric to gate M11 on** |

plus `components{}` (GiB·min and peak for each stat key, file split into
incl/excl shmem), `phase{}` (boot / launch / steps / teardown, windows from
`art-frames/session-timing.json` + `verdict.steps[]`, one-sample precision),
`pss_peak_mib_by_class`, `pss_at_peak_tick`, `guest_series[]` (per guest cgroup),
and `--aggregate` mode which emits `benchlib.stats` groups (spread, bootstrap CI).

**Commands (one ART run per lock acquisition):**

```bash
# one rep, fresh scope (repeat N times for N samples)
tools/art-runtime/run-exclusive.sh --task W41-T07-1 -- \
  tools/guarded.sh --mem 8G --time 900 -- \
  tools/mem-breakdown.sh --task T07 --reps 1 --label baseline \
    --acos .cache/w41/bin/acos --acos-art .cache/w41/bin/acos-art \
    --out results/bench/mem-W41-T07-baseline-r1.json
# group stats + CI over all json
tools/mem-breakdown.sh --aggregate results/bench/mem-W41-*.json
```

`--env K=V` (repeatable) is the experiment seam; `--reps` loops inside one scope
(not used for the numbers below: a job is one scope).

**Pinned binaries.** `target/debug` is rebuilt by other agents mid-run (and was
half-written during the ENOSPC window), so all accepted reps used copies:
`acos` sha256 `581b289f…15 8ce7`, `acos-art` sha256 `eef97f18…dabd2` (both
`target/debug`, 2026-11-12T03:21Z, **debug profile — not verdict-eligible**).
