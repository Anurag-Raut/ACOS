## 1. What changed

### 1.1 `SurfaceControlInfo` can name a real compositor (codec)

`crates/acos-wm/src/codec.rs` gained two optional fields:

```rust
pub struct SurfaceControlInfo {
    pub name: String, pub width: i32, pub height: i32, pub handle: Option<u64>,
    pub client: Option<BinderId>,       // W5: real ISurfaceComposerClient
    pub layer_binder: Option<BinderId>, // W5: CreateSurfaceResult.binder
}
```

`write_to_parcel` writes them when present and falls back to W3's
`placeholder_binder(handle)` otherwise (the insets leashes keep exactly their W3
behaviour); `read_from_parcel` reads them back so the byte-exact re-encode tests
still hold.

### 1.2 One layer-allocation path in C1

`SurfaceState::create_layer(name, w, h, format, flags, parent)` was extracted from
the `createSurface` arms; `createSurface` and the window-surface binding both use
it. Bounded pool unchanged (16 handles, exhaustion is a structured `BAD_REQUEST`).

### 1.3 `relayout` binds the window surface (the gate-1 fix)

`WmsState::bind_surface_layer(&mut SurfaceControlInfo, &SurfaceState)` maps the
`acos-wm` synthetic `surface_handle` (`0x1000 + n`) to a C1 layer once per window
and rewrites the control's `client`/`layer_binder`/`handle`. `registry::install`
now installs the compositor first (`compositor_client::install_full`) and hands the
shared `SurfaceState` to `WindowSessionService::with_compositor`. A host without a
compositor keeps the W3 placeholder body (the `Option` is the switch, tested).

### 1.4 Two C1 reply bugs the guest exposed (not visible to in-process tests)

1. **`CreateSurfaceResult`'s binder was copied, not written.** C1 built the body in
   a scratch `Parcel`, `marshall`ed it, and copied the bytes into the reply. The
   reply Parcel therefore had no object-table entry for the binder:
   `Parcel: Attempt to read object from Parcel … at offset 12 that is not in the
   object list`, and `SurfaceComposerClient::createSurface` failed with
   `UNKNOWN_ERROR`. Fixed with `write_aidl_parcelable`: measure in a scratch
   parcel, then write the fields **through the reply parcel's own writers** (the
   binder is written by `write_strong_binder`, so the object table is right).
   In-process `acos-parcel` tests could not see this because their reader does not
   do libbinder's DPOS check.
2. **`FrameTimelineInfo`'s size word counts itself.** The image's
   `Transaction::apply` writes size word `28` for the 24-byte field set
   (`int64 vsyncId, int32 inputEventId, int64 startTimeNanos, bool`). The decoder
   skipped the raw word, so every real `setTransactionState` was four bytes late
   and read the layer's `flat_binder_object` flags as the binder type
   (`NotABinder { type: 0x13 }` at the object's flags word). The decoder now tries
   both interpretations and keeps the one that consumes the parcel exactly
   (`read_transaction_state_body`). A regression test patches a hand-built parcel
   to the image shape and requires `transaction_id` + `data_avail() == 0`.

### 1.5 Two missing stock registrations (W4's class of wall)

After the compositor wall moved, the looper died in
`PhoneWindow.preparePanel` → `KeyCharacterMap.load` → `InputDevice.<init>` →
`nativeReadFromParcel`. `register_android_view_InputDevice` and
`register_android_view_KeyCharacterMap` were missing from `LaunchMain`'s allowlist;
both are stock exported `libandroid_runtime` entry points (`nm -D`), added with
the framework stack that needs them.

### 1.6 Opt-in diagnostics kept for the next slice

`ACOS_W5_DUMP` (transaction bytes/positions), `ACOS_W5_BUF` (buffer store and
`finishDrawing` body), `ACOS_W5_TAIL`/`ACOS_W5_LS`/`ACOS_W5_BD` (field-position
tracing), and `ACOSLAUNCH_HOLD_MS` (keep the guest's real looper alive N ms after
`activity-resumed`, then print a read-only `ViewRootImpl` state probe). Nothing is
printed unless the variable is set.

## 3. The live `ViewRootImpl` probe (the finding of this slice)

`ACOSLAUNCH_HOLD_MS=2000` (keeps the real looper running after the resume marker,
which the watcher's `quit()` otherwise stops before the first traversal draws):

```text
ACOSLAUNCH MARK viewroot-probe surface_valid=true
  surface=Surface(name=null)/@0x918de63
  view_visibility=8        <-- View.GONE
  first=false display_state=2 renderer=null blast_queue=null
  dirty=Rect(0, 0 - 1080, 2209) layout_requested=false
ACOSW5 finishDrawing transaction bytes=1 has_gralloc_buffer=false
ACOSHWC[gralloc]: software gralloc shim loaded (1 fd / 9 ints)   (no allocate line)
```

`surface_valid=true` says BLAST's `mSurface.transferFrom(blastSurface)` worked:
the surface the traversal would draw into is real. (The probe's
`mBlastBufferQueue` read came back `null`, which is a probe artefact, not a
missing queue — the `createSurface` at service call 73 can only come from
`updateBlastSurfaceIfNeeded()`'s live `BLASTBufferQueue`; the reflective field
lookup is the thing to fix if the next agent relies on that line.)

`view_visibility=8` is `View.GONE`. `ViewRootImpl.getHostVisibility()` is:

```java
return (mAppVisible || mForceDecorViewVisibility) ? mView.getVisibility() : View.GONE;
```

and `mAppVisible` is only set by `IWindow.dispatchAppVisibility(true)` (or the
deprecated `windowVisibilityChanged`), which the real WMS sends right after the
add. ACOS's `acos-wm` already queues `WmCallback::DispatchAppVisibility { visible:
true }` (`crates/acos-wm/src/wms.rs:337`) and the codec exists
(`crates/acos-wm/src/callbacks.rs`, `IWINDOW_DESCRIPTOR` + code 7, oneway), but
**nothing delivers `IWindow` callbacks**: the `android.view.IWindow` node is not
implemented and `addToDisplayAsUser` never turns the queue into a reverse
transaction. So `performDraw` takes `cancelDraw = !isViewVisible`, nothing ever
calls `drawSoftware` → `Surface.lockCanvas` → `queueBuffer`, and the frame path
stops before its first buffer.

A first attempt at delivering the queue from `WindowSessionService` (encoding each
`WmCallback::to_parcel()`, returning it from `drain_raw_deliveries`) made the guest
**hang** (`outcome=timeout`), so it was reverted rather than shipped half-working;
that experiment is the next task, with §5.1 as the pass/fail.

## 5. The next wall, precisely

### 5.1 `IWindow` callbacks are never delivered → `getHostVisibility()` is GONE

- `mAppVisible` never becomes true because `IWindow.dispatchAppVisibility(true)`
  (code 7) is not sent. The callback is already queued by `acos-wm`, and the
  codec (`to_parcel`, oneway, interface token) exists.
- Everything after it is already in place: `surface_valid=true`, real BLAST queue,
  real gralloc shim preloaded, `ViewRootImpl` on screen state 2 (`STATE_ON`),
  software renderer (`renderer=null` is the expected software path).
- Pass/fail for the next task: after delivery, the probe must show
  `view_visibility=0`, a `ACOSHWC[gralloc]: allocate: 1080x2209 …` line, and a
  `setTransactionState` parcel containing `GB01`.

Caveats to keep (measured, not guessed):

1. **W5's first delivery attempt hung the guest.** The queue flush was called from
   `raw_transact` for both add and relayout and returned through
   `drain_raw_deliveries`; the run timed out with two `finishDrawing` calls and no
   resume marker. Do not ship that shape; start by delivering **only**
   `dispatchAppVisibility` for the window, after `addToDisplayAsUser`'s reply, and
   verify the peer's delivery frame ordering (the peer drains the host queue after
   the call, `acos-binder-peer/src/peer.rs:365`). `resized(reportDraw=true)` is the
   second callback needed for the draw (queued by `relayout`), and the measured
   order is visibility → focus → insets.
2. **The three/four `setTransactionState` failures that remain are the insets
   *leashes*, not the window.** Their `surface` binder is W3's
   `0x0100100{2,3,4}` placeholder (the `acos-wm` leash handles), their layer ids
   are the synthetic `0x1002`-class ones, and they carry no `GB01`. The framework
   logs and continues (W4 §4). They will need the same "bind the leash to a real
   layer" treatment before insets animations are honest, but they do not gate the
   first frame.
3. `finishDrawing`'s `SurfaceControl$Transaction` body is read as an opaque byte
   array and dropped. If the buffer ever arrives through that path it will need its
   own decoder (it is a *different* flatten from `setTransactionState`); today it
   is 1 byte, i.e. empty, which is why dropping it is honest for now.
4. `launch --until activity-resumed` stops the looper in the watcher (`quit()`)
   right after the marker, before the first traversal draws. `ACOSLAUNCH_HOLD_MS`
   is the only way to observe the frame path at this stop point; a dedicated
   `--until first-frame` would be better than an env knob.
