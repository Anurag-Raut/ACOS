## 1. What was implemented

### 1.1 `--concurrency N` (`tools/run-suite.sh`, `tools/benchlib.py`)

* Per round the runner schedules the 22 variant runs (11 good + 11 wrong twins; T05 is
  `UNSUPPORTED_EXPRESSION`) through a `ThreadPoolExecutor(max_workers=N)`. Every run
  calls `run_round()` → `run_measured()` → `guarded.sh` (a NEW transient systemd scope)
  → `benchlib.py sample-scope` inside that scope. The W45 per-run contract is unchanged.
* **Shared `ACOS_ART_DATA` is filtered by launcher-pid ownership.** Under the suite-level
  ART lock all runs share one `--data` tree (`<data>/runs/<launcher-pid>-<seq>/cgroup`).
  `ScopeSampler.discover()` now accepts an evidence file only when its directory pid
  (`<pid>-<seq>`) is a descendant of *this* sampler; otherwise it would charge another
  concurrent run's guest (a systematic double count). Unit test with teeth:
  `test_concurrent_shared_data_evidence_is_owner_filtered`.
* **Job-scope registry (host cross-check only).** Each sampler writes its job cgroup to
  `<artifacts>/<stamp>/_registry/r<round>/<label>-<pid>.job` before spawning the child.
  The host monitor uses it to close the ~100 ms discovery gap for the job cgroup; guest
  scopes are still discovered **independently** by the process-tree scan, so a mutated
  sampler that drops a guest is caught.

### 1.2 Denominator and the host-level alternative

* **Primary (gate):** for each run, `Σ (anon+shmem bytes)/2^30 × Δt/60` over
  job + every guest cgroup, sampler `RssAnon+RssShmem` subtracted. Peer denominators
  (`resident`, `job_all_incl_file`, `scope_runner_formula`, `infra_file_cache`) are
  still recorded with `gate_uses: false`.
* **Round denominator:** the sum of the per-run primary integrals over that round's wall
  window (`per_run_sum_gib_min`). `M11 = verified_good / mean(round denominator)`; the
  median of the per-round M11 is also reported.
* **Host-level alternative:** `benchlib.HostScopeMonitor` runs in the suite process
  (outside every job scope), discovers the union of all descendant job scopes and their
  sibling guest scopes every 100 ms, samples `memory.stat` anon+shmem, integrates the
  union over the same window, and subtracts the same sum of sampler charges. This is
  independent of the per-run guest discovery (it only reuses the job registry, never a
  per-run guest list).
* **Agreement is a measurement gate.** `benchlib.scope_agreement()` compares the two;
  a relative difference > 5 % fails the run (`verdict_vs_bar: SCOPE_MISMATCH`, exit 1).
  The mutant in `tools/tests/test-run-suite.sh` case F delegates to the real sampler and
  deletes one label's guest from the JSON: the host integral still sees it and the run is
  rejected (`F exit 1`, `per-run < host`, `SCOPE_MISMATCH`).
* `false_pass > 0` still zeroes M11. `gate_eligible` requires N=10, 3 rounds, release,
  scope check ok, no false pass, no host-gate contamination, and agreement within noise.
  The pass rule is the requested one: **PASS only if CI95 low ≥ bar × (1 + noise)**, the
  round spread ≤ 15 %, the scope check is clean and false_pass is 0.

## 3. Bar comparability — the 24.4 bar's inputs are NOT anon+shmem/warm

The bar is derived in `results/art-runtime/ADVISOR-benchmarks-top10.md` item 3 as

```
((206 MiB core / 10) + 112.1 MiB marginal) / 1024 × (19 s / 60)
  = 0.0410 GiB·min/task  =>  24.4 tasks/GiB·min
```

Checking the legacy rows it names (BENCHMARKS.md §3, citations in
`docs/reference/ACVM_INVENTORY.md` §2):

| input | legacy row | actual type / state | same as our primary? |
|---|---|---|---|
| 206.0 MiB | bare core (W1 diet), `iter/W1.md` §5 | **workset 206.0** / anon 203.4 / `memory.current` 285.7, settled 60 s | **no** (BENCHMARKS §3 says anon+shmem; the cited row is workset) |
| 112.1 MiB | marginal N=5→10 (v5), `EXPERIMENTS.md` §v6 | **`memory.current`** (paired ws 99.3), warm | **no** (different type) |
| 19 s | U2 dev loop, install-bound | **`adb install -r` portion = 74–81 % of the loop**, warm | **no** (not a whole-task wall; a warm install component) |

So the legacy inputs are **not** anon+shmem warm throughout: the core is workset, the
marginal is `memory.current`, and the wall is an install component. A bar built from
those numbers cannot gate a cold-process per-task anon+shmem integral.

**Finding: the M11 row is `NOT_COMPARABLE` to 24.4.** For information only (never a
verdict), 62.84 / 24.4 = **2.58×** the bar and the CI low 45.45 / 25.62 = **1.77×**.
If one substituted the ws marginal 99.3 for the current 112.1, the same arithmetic
gives 26.97, still a mixed ws/anon+shmem construction — no pure anon+shmem bar exists
in the legacy record. Do not read the 2.58× as a D2 PASS.
