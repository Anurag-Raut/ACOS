# S4 — private per-run `/data`: shared inputs read-only, per-run root removed on exit

Status: **implementer**, hard checkpoint 60 min (overran; measured work is below), **nothing
committed**. Owner files only: `crates/acos-art/src/{lib,launcher,app,session,launch,main}.rs`,
`crates/acos-art/tests/cleanup.rs`, one pattern line in `tools/art-runtime/leakcheck.sh`, this file.
`crates/acos-services` (W1) and `research/` (T0) untouched. Every ART/cargo run went through
`tools/guarded.sh --mem 4G --time 300` (6 G for the cleanup suite), one ART guest at a time, scratch
under `.cache/s4/` and `.cache/h1-tests/` — never `/tmp`.

Closes S3 §5 (per-run `/data`, S1 §5 item 2) and H1 §2 (session scratch never removed). Implements the
replacement mount block S3 predicted, with two deliberate deviations (per-session `/data/session/<id>`,
and a short run-dir id for `sun_path`) described in §1.4.

## 1. The design as landed

### 1.1 Every run gets its own writable root

`ArtRoot::new_run_dir(tag)` creates `<data>/runs/<pid>-<seq>/` with
`dalvik-cache/x86_64`, `misc/apexdata/com.android.art/dalvik-cache/x86_64`, `tmp`, `out`, `task`,
`socket`, `session`, `app-data`, plus an `owner` file (`pid=`, `start=` = `/proc/self/stat` starttime,
`tag=`). `RunDir::drop` removes the tree; the routes hold it until they return, so *every* exit path
of a route (ok, guest error, timeout, watchdog kill, spawn error) removes it — see §2.3/§2.4.

### 1.2 Shared inputs are read-only in the guest

In a run, `<data>` itself is no longer bound. The argv now has (verified from
`ACOS_ART_DEBUG_ARGV=1`):

```
--ro-bind <data>/linkerconfig /linkerconfig          # was: --bind  (regenerated only in staging)
--dir /data
--ro-bind <data>/system            /data/system       # BOOTCLASSPATH input (system/environ)
--ro-bind <data>/app               /data/app          # staged guest dex/libs + APKs
--ro-bind <data>/overlay           /data/overlay      # static-RRO idmaps
--ro-bind <data>/lib               /data/lib          # binder driver shim
--ro-bind <data>/shim              /data/shim
--ro-bind <data>/apex-info-list.xml /data/apex-info-list.xml
--ro-bind <data>/acos.properties   /data/acos.properties
--bind    <run>/dalvik-cache /data/dalvik-cache      # per-run (see §3.2)
--bind    <run>/misc         /data/misc
--bind    <run>/tmp          /data/tmp
--bind    <run>/out          /data/out
--bind    <run>/task         /data/task
--bind    <run>/app-data     /data/app-data
--dir     /data/session                              # route binds /data/session/<id>
...
--ro-bind <image dir> /data/img                      # was: --bind; the boot image is an input
```

`/dev/socket` is the run's own socket dir (`<run>/socket`, or `<run>/socket` for a session); the old
shared `<data>/socket` is not visible.

### 1.3 Staging mode (host-side build steps only)

`Sandbox::staging(true)` keeps today's argv exactly (`--bind <data>/linkerconfig`, `--bind <data>
/data`, `--bind <image> /data/img`) and is used **only** by:

* `build-image` (`dex2oat64` writes `boot.art`/`boot.oat`),
* `ensure_linkerconfig` (`linkerconfig --target /linkerconfig`),
* `ensure_classpath_env` (`derive_classpath` writes `/data/system/environ/classpath`),
* `sandbox_tool` (`idmap2` writes `/data/overlay`).

No APK/DEX run uses it; `run`, `verify`, `render-app`, `session`, `launch` all pass a run root. A unit
test asserts both directions (run ⇒ no shared `<data>` bind; staging ⇒ shared bind and no `runs/`).

### 1.4 Two deviations from S3 §5, both forced

1. **Session dir = run root.** S3 proposed `--bind <run>/session/<id> /data/session/<id>`. Simpler and
   equivalent: the session's run root *is* its session dir, bound at `/data/session/<id>` and at
   `/dev/socket` (for `logdw`). `/data/session` stays a plain empty temp dir in the guest.
2. **Short run-dir id `<pid>-<seq>`** (not `tag-pid-nanos`). The logd/importer sockets live inside the
   run root and `sun_path` is 108 bytes: a long id made a deep `--data` dir fail at `bind()` with
   `path must be shorter than SUN_LEN` (found by the suite, not in review). The tag is kept in `owner`.

### 1.5 The janitor (the SIGKILL case)

`--die-with-parent` (S3) kills bwrap + guest when the launcher dies, but no process is left to remove
the host directory. `ArtRoot::sweep_stale_runs` runs on every `ensure_data` (i.e. at startup of every
route) and as `acos-art janitor`:

* a run dir is **live** while its `owner` pid exists *and* `/proc/<pid>/stat` starttime matches
  (pid reuse cannot keep a leak alive; the same identity rule as `leakcheck.sh`),
* a dead-owner dir is removed once it is older than `ACOS_ART_RUN_TTL_SECS` (default 1800 s),
* the TTL covers the create-then-write-owner window of a concurrent run.

### 2.1 The canary (S1 §5 item 14, S2 item 5a)

The test compiles a canary DEX with `javac` + the SDK's `d8` (skips with a reason if the Android SDK is
absent), seeds a private `<data>` copy, and runs it through the real `run` route **with a real boot
image** (`--image .cache/art-exp/data/img`), so `/data/img/x86_64/boot.art` really is in the guest's
view. The canary *reads* each input first (proving visibility), then tries to append one byte:

```
READ /data/img/x86_64/boot.art
READ /data/system/environ/classpath
READ /data/acos.properties
READ /data/shim/libartshim.so
READ /data/app/guest/classes.dex
READ /linkerconfig/ld.config.txt
DENIED /data/img/x86_64/boot.art FileNotFoundException        (EROFS surface of a ro bind)
DENIED /data/system/environ/classpath FileNotFoundException
DENIED /data/acos.properties FileNotFoundException
DENIED /data/shim/libartshim.so FileNotFoundException
DENIED /data/app/guest/classes.dex FileNotFoundException
DENIED /linkerconfig/ld.config.txt FileNotFoundException
acos-art: outcome=ok code=- exit=Some(0) signal=None wall=152ms
```

The test asserts `READ <p>` and `DENIED <p>` for every input, no `WROTE <p>`, **and** that the host
md5s are unchanged afterwards (`boot.art 5a223bca034212dce69cd655a94124c2`, `classpath
0cd1e169a230def2b1b915f6fa2b2095` — same before and after). That is the S2 canary (which *did* write)
now failing to modify host files.

### 2.2 The oracle is still the oracle

Corpus and render are byte-identical, not "close": the same 28 result rows on the ten stable fields,
the same `frame.png` md5, the same structural 8/8 / tree 12/12, `fatal_logs 0`. The change is a mount
change, so anything else would have been a regression.

### 2.3 Guest crash

`guest_crash_still_removes_the_run_root` starts a real `session`, waits for the guest to appear,
`SIGKILL`s the *guest* (not the launcher), lets the session end (its wall-clock budget is 8 s; a
session whose guest dies does not end early — pre-existing relay behaviour, unchanged here), then
asserts: launcher exited, no surviving `dalvikvm64`/`bwrap`, **and** `<data>/runs` is empty.

### 2.4 Launcher SIGKILL and the janitor

The extended SIGKILL test first asserts the opposite of a leak-free run: the kill *does* leave the run
root (that is what `--die-with-parent` cannot clean), then runs `acos-art janitor` with
`ACOS_ART_RUN_TTL_SECS=0` and asserts `<data>/runs` is empty. `janitor_reaps_stale_runs_and_keeps_live_ones`
covers the rest of the policy directly:

| run dir | owner | age | after default sweep (TTL 30 min) | after TTL=0 |
|---|---|---|---|---|
| `stale` | pid 999999 (dead) | 2 h | **removed** | – |
| `no-owner` | none | 2 h | **removed** | – |
| `dead-fresh` | dead pid | now | kept (run may be mid-setup) | **removed** |
| `live` | the test's own pid+starttime | 2 h | **kept** | **kept** |

## 3. Startup latency, before vs after (measured, not guessed)

Control = the **same source at HEAD** (stashed `crates/acos-art`, rebuilt release, verified byte-for-byte
restored afterwards), not an older binary. Two traps were hit and are worth recording:

* `target/release/acos-art` from 15:54 is **not** a valid baseline: it showed a phantom +85 ms.
* The phantom decomposes exactly: `MemoryWatchdog::Drop` joins a sampler thread that sleeps
  `POLL_INTERVAL = 50 ms`, so every current-HEAD command pays up to 50 ms at exit — the 15:54 binary
  predates it (`acos-art janitor` on an empty data dir: 1 ms before-copy vs 51 ms current build, no
  S4 code involved).

Medians via `tools/guarded.sh` (what acceptance uses), `run 01_hello`, n=15:

| variant | process wall | guest+spawn (`wall_ms`) |
|---|---|---|
| HEAD (shared rw `<data>`) | **583 ms** | 61 ms |
| S4, per-run root, cold dalvik-cache | **583 ms** | 61 ms |
| S4 + `ACOS_ART_DALVIK_CACHE=shared` (warm) | **583 ms** | 61 ms |

`render-app counter.apk`, n=5: HEAD **684 ms** / S4 **683 ms** (guest 162 ms both).

**Warm dalvik-cache trade-off — measured, and it is zero here.** The per-run cache is created empty and
stays empty: after a full run, the run root holds only `owner` and `task/00_classes.dex`
(`dalvik-cache` and `misc/…/dalvik-cache` are 0-byte directories). These routes pass the boot image and
`-cp`; ART neither reads nor writes `/data/dalvik-cache` for them, so sharing it could only have been a
poisoning surface, never a speed-up on this corpus. The `shared` variant is kept only as a
measured-and-documented escape hatch. Cost of the whole change on the measured path: **±0 ms** (the
run root is 9 `mkdir`s, one 10 KB dex copy and one `rm -rf`).

## 4. What this closes, and what it does not

Closed: S3 §3's "writable `/data`" item (guest can no longer create/overwrite/truncate
`img/x86_64/boot.art`, `system/environ/classpath`, `acos.properties`, `shim/*`, `app/*`,
`linkerconfig/*` — only its own run root), and H1 §2 (a `session` no longer leaves
`<data>/session/<id>` behind; `<data>/session` is not used by new runs at all).

Behaviour changes worth knowing:

* `<data>/app-data` is now per-run: Android app data no longer persists between runs (nothing in the
  product depended on it; `launch` still creates a fresh per-package dir).
* A session's `--out` artefacts are copied out before the tree is removed; the session dir itself is
  gone afterwards. `ACOS_ART_KEEP_SESSION=1` (session) / `ACOS_ART_KEEP_RUN=1` (any route) keep it.
* `/data/task` is per-run (was shared and grew one file per corpus program per invocation).
* The pre-S4 `<data>/session/*` scratch H1 found (3.0 MB of dead session dirs) was removed during this
  checkpoint; nothing creates it any more.
* `ACOS_ART_RUN_TTL_SECS` (default 1800) tunes the janitor; `ACOS_ART_DALVIK_CACHE=shared` restores the
  old warm-cache mount (documented as poisonable; not for untrusted APKs).

Still open (unchanged by S4):

* **SIGKILL of the launcher leaves the run root for up to the TTL.** The next `acos-art` invocation
  reaps it, but a host that never runs `acos-art` again keeps a dead tree (bounded: one per killed
  launcher, no processes/sockets inside). A mandatory per-run cgroup with `KillMode` would make this
  immediate (S1 §5 item 3).
* No seccomp and no Landlock on this route (S1 §5 items 5–6): the guest is confined by *mounts*, not by
  syscall filtering. It can still read every shared input, and it can still write anything inside its
  own run root (including its dalvik-cache — now only its own run can be poisoned).
* `/sys` and `/etc/passwd` are still `--ro-bind`ed from the host (S1 §5 item 11).
* `leakcheck.sh` still audits processes/sockets/memfds/scopes/dirs, not file contents; the canary test is
  the content-level check, and it is now in `cargo test`.
