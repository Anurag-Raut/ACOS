UTC stamps (required by the dispatch): **start 2026-11-12T05:37:13Z**,
**45-minute stamp 2026-11-12T06:21:51Z**, end stamp at the bottom. No commit, no

Worked through the three items in their priority order. Items 1 and 2 are fixed

## 2. Item 1 — root cause of the W50 dead guest, and the fix

### 2.1 Root cause (from W50's own artefacts, now named)

W50 §7 item 3 described the symptom honestly but could not name the cause. The
recorded steps of the two failing rows do name it:

```
counter   run 2 iter 4  reset 249 ms  INTERNAL
  "LIVE_FRAME_UNAVAILABLE: the ART session ended before its ready line (no live
   frame exists): startup: acos-art session exited; stderr tail: …guards rss_max=…"
counter   run 2 iter 5  tree/tap/tree/key/screenshot/assert/logs  INTERNAL
  "the ART session stdin is closed"                              (7 verbs, 0.01 ms each)
form-validation run 1 iter 10  reset 227 ms  GUEST_EXITED (status signal: 9 SIGKILL)
form-validation run 1 iter 11  same seven verbs, same "stdin is closed"
```

The death happens **inside `ArtSession::reset`**, not in the guest between
iterations:

1. `reset` sets `self.closed = true`, calls `shutdown()` (which sets
   `stdin = None` and kills the old group), then `ArtSession::start(...)` for the
   replacement guest.
2. In those rows the **replacement** `acos-art` died before its ready line
   (one row is explicit: `GUEST_EXITED … status signal: 9 (SIGKILL)`; the other
   lost the launcher before it wrote `session-exit.json`, so W46's
   `classify_session_exit` returned `None` and the error surfaced as `INTERNAL`).
3. `reset` returned `Err` **after** poisoning `self`: still closed, still
   `stdin = None`, **still holding the old guest's cached frame**, and still
   registered in `ServeEngine`'s map.
4. Every later verb hit `command_raw`'s `stdin.is_none()` branch → `INTERNAL:
   the ART session stdin is closed` in 0.01 ms, and `acos_launch` on the held
   session returned `ensure_bound_tree()` → **the dead guest's cached tree**.

So the "one unclassified guest death" was a *harness state* defect, not a
mystery guest crash: the trigger was the replacement launcher's death, and the
stale frame was served because nothing checked the child and nothing invalidated
the cache. The cause of *that* death (SIGKILL of the fresh launcher, host
loadavg 3.2 with sibling ART suites) is still not named — the launcher wrote no
exit record and both W50 scratch directories were pruned, so there is no logcat
for it. What is fixed is that the next occurrence can never be served as a live
frame, and it now carries its signal/exit code and `session-exit.json` path.

### 2.2 The fix

`crates/acos-cli/src/engine/art.rs`

* `ArtSession::liveness(&mut self) -> Option<GuestExit>` — never blocks; reaps
  the child once, and reports `{state, exit_code, signal}`. A host-closed
  session is dead even if its pid lingers.
* `ArtSession::invalidate_frame()` — drops `cached` and returns the discarded
  frame's identity `(seq, md5, captured_at)`, so it can be *reported* but never
  handed over.
* `ArtSession::start` removes a stale `session-exit.json` from the artifacts
  directory before spawning: `reset` and a serve relaunch reuse that directory,
  and a record left by a *previous* guest must not classify the new one (the
  W46 hazard made concrete by the W55 relaunch path).
* `reset` no longer poisons: a failed `shutdown`, a failed replacement `start`
  or a failed first traversal all `invalidate_frame()` and leave a session whose
  `liveness()` says exactly why. Close stays idempotent, so the daemon can drop
  it.
* `session_lost` → `session_lost_mut`: a lost launcher with **no**
  `session-exit.json` is classified from the child's own `ExitStatus`
  (`failure::classify_child_exit`, the W53 patch the orchestrator extended my
  ownership to apply). A dead write (`EPIPE`) is classified the same way; it is
  no longer `INTERNAL`. `HostDiskFull` keeps its own code.
* The `stdin.is_none()` "stdin is closed" branch is classified from the same
  evidence instead of returning a bare `INTERNAL`.

`crates/acos-cli/src/engine/serve.rs`

* `call_art` starts with `session.liveness()` **before** any trust rule and
  before any verb. On death: `guest_exit_envelope` invalidates the frame,
  classifies the code (`session-exit.json` → else child status → else
  `GUEST_EXITED`), and returns the details `{verb, guest_exit, session_exit,
  session_exit_path, discarded_frame: {…, served: false}, launch_hint}` with a
  hint to relaunch.
* `launch_art` on a held session checks liveness **before** serving the bound
  tree. If dead: the held session is removed, torn down (best effort, proves the
  group), and the same APK is started in a fresh guest. The reply carries
  `replaced_guest` (with the discarded frame and the exit facts) and
  `relaunch: false` / `isolation: fresh-guest-process`.
* `list_sessions` reports `live: false`, `mode: "dead"`, `frame_seq: 0` and
  `guest_exit` for a dead session. It keeps its slot (and counts against
  `--max-sessions`) until it is relaunched or destroyed: dropping it silently
  would hide a dead guest from the operator.

## 3. Item 2 — the trust guard on serve

`trust::TrustGuard` refuses exactly two channels on an untrusted run:
`observe` (the UI tree) and `logs_since` (guest logs), with
`INSUFFICIENT_HOST_EVIDENCE`; it still allows `capture` (host pixels), `input`
(host-injected; a selector only navigates) and lifecycle. Serve now maps the
same channels through one pure function, `trust_refusal(trust, tool, args)`:

| TrustGuard channel | serve verb(s) | untrusted result |
|---|---|---|
| `observe` | `acos_observe_tree`, `acos_assert`, `acos_observe {tree|text:true}` | `INSUFFICIENT_HOST_EVIDENCE`, `assertion: UNTRUSTED_TREE_ASSERTION` |
| `logs_since` | `acos_logs` | `INSUFFICIENT_HOST_EVIDENCE`, `assertion: UNTRUSTED_LOG_ASSERTION` |
| `capture` | `acos_observe {tree:false,text:false}` (frame/screenshot) | **allowed** (`evidence_label: host-pixel`) |
| `input` | `acos_tap`, `acos_key`, `acos_text`, `acos_action` | **allowed** (host-injected; tree use is navigation only) |
| lifecycle | `acos_launch/destroy/reset/status` | allowed |

Test: `w55_dead_guest::untrusted_serve_applies_the_trust_guard` asserts the
refusals (including that the refusal names the assertion class), the allowed
frame-only capture and tap, and that the **same verbs succeed on a trusted
session** (the guard is the trust level, not the verb). `w50`'s
`acos_assert`-only guard is subsumed and still passes.

### 4.3 Conclusion and why no serve-side change was made

* The settle wait is **0–25 ms**, not the cost. The guest's `FINISHED` ack
  arrives *after* the post-tap frame is already settled and captured, so
  "return as soon as the settled state is observed (next frame + stable tree)"
  returns at the ack, i.e. at the same 1.1 s. Implementing it would relabel the
  cost, not remove it.
* The "no change" bound is unchanged and honest: a delivered tap the guest
  cannot settle still costs the guest's 3 s window plus the engine's recovery
  polls, and the reply says `state_changed: false` from the host's own
  pixel-hash + tree-signature comparison (W34), never a guest claim. The
  documented bound lives in `DEFAULT_FRAME_WAIT_SECS` /
  `DEFAULT_SETTLE_NOCHANGE_POLLS` and is unchanged by W55.
* No frame is returned before it exists: the reply's `frame.frame_seq` is the
  post-input frame, `frame_seq_before → frame_seq_after` shows the advance, and
  `state_changed` is computed from that pair.

Smallest next action (guest owner — `acos-services` input / `acos-art`):
split the ack from the post-tap relayout, or measure the stage inside the guest.
The measured shape says the **app's synchronous traversal after the click** is
inside the ack window: the counter's click changes a `TextView` (relayout),
the form's tap only moves focus. A guest-side per-stage timer in the tap reply
(`inject_ms`, `dispatch_ms`, `ack_ms`) plus acking `FINISHED` before the
traversal would prove it and is the only route to the 500 ms gate that does not
fake the evidence.

## 8. Remaining gaps (honest list)

1. **`counter:tap` 1,136 ms p50 still fails the 500 ms gate.** Measured cause:
   the guest's input ack (1,115–1,141 ms), not the settle window (§4.2). Needs a
   guest-side stage timer and ack-vs-traversal split in `acos-services` input /
   `acos-art`; serve cannot shorten it without lying about delivery.
2. **Why the replacement launcher was SIGKILLed during W50's reset is still
   unnamed.** The two W50 scratch dirs were pruned, so no `session-exit.json`,
   `live-session.json` or logcat survives. The next occurrence now classifies
   itself and keeps the frame discarded; run the bench with `--keep-scratch`
   when hunting it.
3. **`acos-art` API asks** (per the dispatch, described not changed):
   (a) a per-stage input timing block in the tap reply (`inject_ms`,
   `dispatch_ms`, `ack_ms`) — the measurement in §4.2 says the ack *is* the tap
   cost, and only the guest can split it; (b) `reset` should fail without leaving
   the caller's session closed-but-alive (today the CLI compensates); (c) the
   launcher could ack `FINISHED` before the post-click traversal if the framework
   allows it — that is the only route to the gate.
4. **`ErrorCode::GuestExited.class()` is `Harness`** in `acos-protocol` (owned
   elsewhere), so `GUEST_EXITED` is still counted as an unclassified/harness
   class by consumers that key on the class (W50 §7 item 4 also notes
   `benchlib.py` has no `GUEST_EXITED` entry). W55's run has 0 such rows, so
   this did not affect the numbers; the code and its `guest_exit`/`session_exit`
   details are what W55 guarantees, not the class label.
5. **`launch` on a dead session discards the old artifacts' frame mirror** only
   as evidence; frames stay under `$ACOS_RUNTIME_DIR/art-sessions/<id>/art-frames`
   and are not pruned (unchanged from W50, item 9 there).
6. **Trust on serve is now the TrustGuard rule set, not the wrapper.** Serve
   still does not install a `TrustGuard` object (it has no `Backend` on that
   path); the mapping is one pure function with tests, and any future change in
   `trust.rs` must be mirrored there. Named as the residual coupling.
7. **`counter:type` remains `UNSUPPORTED_BACKEND`** by design (no editable view);
   unchanged from W50.
8. **`acos_reset` on a dead session returns `GUEST_EXITED`; it does not relaunch.**
   `acos_launch` is the relaunch primitive (it replaces the guest and says so);
   making two verbs silently respawn would hide where the new guest came from.
   An agent that wants "start over" after a death calls `acos_launch`, which is
   also the documented hint in the error.
