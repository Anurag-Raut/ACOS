## 1. What was wrong

Verified against a fresh form-validation run (artifacts `.cache/shot2/r/`), and
reproduced from this run's own artifacts:

* the live tree root is `com.android.internal.policy.DecorView [0,128,1080,2337]`
  — **display** coordinates (`View.getLocationOnScreen`);
* the dialog card `android:id/parentPanel` is `[70,1018][1010,1447]` — display;
* `frames/<seq>.png` is **1080x2209** and starts at display `y=128`:
  PNG `(70,890)` = display `(70,1018)`;
* nothing in the frame metadata, the tree artifact, the step result or the
  verdict named that offset. An agent (or a scenario author) that crops the PNG
  at a tree bound is 128 px off, and a region assertion written in PNG pixels
  passes while checking the wrong rows — a **silent** false pass if the rows
  happen to look alike.

The separation itself is correct and AOSP-shaped: ACOS composites the display's
application area (it has no SystemUI layers for the status/navigation bars — they
are insets, not surfaces), so the PNG legitimately excludes them. What was
missing was the metadata that makes the separation legible.

## 3. The contract

### 3.1 Decision

There are exactly **two** pixel spaces, and every coordinate belongs to one:

| space | origin | used by |
|---|---|---|
| **display** | logical display top-left `[0,0]`; size from `display:` in the scenario (1080x2400 reference) | UI-tree bounds, `tap` `x`/`y`, `assert_region` `x/y/w/h`, `assert_screenshot.region_masks` |
| **frame** | the PNG's pixel `(0,0)`, published as `FrameMeta.display_origin` | the PNG bytes, region `hash`es, `equals_png` baselines, screenshot comparison |

* A frame **must** publish `display_origin` + `display_size` when it does not
  cover the whole display. Absent `display_origin` means identity (a
  full-display frame, the AOSP `screencap` case).
* `assert_region` takes **display** pixels and converts with the frame's
  origin. A region the frame does not cover (status-bar band, navigation band)
  **fails** with both rectangles and the origin in the diff: a frame cannot
  prove pixels it does not contain.
* Region masks are display pixels and are subtractive: a mask outside the frame
  excludes nothing (dropped), one straddling the edge is clipped.
* A passing run repeats the mapping in `verdict.notes` with the run's concrete
  origin.

Why display coordinates for assertions, not PNG pixels: they are the space
`View.getLocationOnScreen`, `uiautomator dump` and `adb shell input tap` use, so
one number works for "read the tree, tap it, assert it" with no arithmetic. They
are also the space taps already used, so the product has one agent-facing space
instead of two. A mistake in the other direction (writing a PNG pixel) fails
loudly with a diff that shows both rectangles — never a silent 128-px shift.

### 3.2 Where the origin comes from (no constants in the verifier)

`crates/acos-verify/src/display.rs`:

1. `acos_runtime::display_override()` when set (`acos launch --display/--density/
   --reference`, `ACOS_DISPLAY_OVERRIDE`) → `origin = (0, status_bar_top)`,
   `display_size = (width, height)`;
2. otherwise `acos_runtime::wms_java::reference_frames()` — the runtime's own WMS
   frames: display `[0,0][1080,2400]`, app window `[0,128][1080,2337]`;
3. **cross-checked against the produced frame**: geometry is published only when
   the frame size equals the application area. A frame of another size keeps
   `display_origin: None` (identity) instead of a plausible-looking wrong offset
   — the guard is tested (`a_frame_of_an_unexpected_size_gets_no_origin`).

Because the ART verify path builds its frames in `engine/art.rs` (W55's file),
`acos-verify` also **signs** frames at its own boundary
(`display::signed_frame`): the tree artifact, step results and the verdict note
carry `display_origin` today, and a frame that already declares geometry is
never overridden. When W55 applies §7 the engine becomes the source and the
signer is a no-op for it.

### 3.3 Why not the full-display PNG (the alternative)

Rejected on three pieces of evidence:

1. **It would fabricate pixels.** ACOS has no SystemUI surface for the status or
   navigation bar; those 191 rows were never drawn by any layer. Filling them
   with "a defined colour" is a fake pixel in host-observed evidence, against the
   never-fake rule.
2. **It breaks the checked-in evidence.** `content_hash` is over the frame
   buffer, so every frame hash changes; every frame-sized `equals_png` baseline
   (`scenarios/suite/baselines/T03-hello-views-top.png` is region-sized, but the
   fixture reference PNGs and screenshot baselines are frame-sized) and every
   recorded `frames/*.png` identity would need regeneration, with no gain over
   publishing the origin.
3. **It is outside this task's files.** The composite is `acos-services`
   (W56/W54) and the frame store is `acos-runtime`; the verifier cannot change
   frame height honestly.

The metadata route costs 2 JSON fields, is additive (old artifacts deserialize
unchanged, verified by `display_geometry_serde_is_additive`), and keeps the PNG
exactly the pixels the guest drew.

## 5. Scenario hash changes: **none**

The contract moves the *coordinates*, not the pixels. For every existing region,
`y_new = y_old + 128` and the frame crop is identical, so every hash is
unchanged. Proved twice:

1. recomputed independently from the orchestrator's frame
   (`.cache/shot2/r/frames/34.png`): frame y=910 → `e753006d…`, y=1000 →
   `a72e0518…`, y=1306 → `e90ad15e…` — exactly the checked-in values;
2. the re-run asserts the same hashes through the new display coordinates, e.g.

## 7. Patch for `crates/acos-cli/src/engine/` and `serve.rs` (W55 — read-only here)

The engine builds the agent-facing frame objects. Three edits; `acos-cli` already
depends on `acos-verify`, so no new dependency.

**(a) `crates/acos-cli/src/engine/art.rs`, `fn frame_meta` (~line 1283)** — the
source of the truth for both `verify --engine art` and `serve`:

```rust
    fn frame_meta(&self, seq: u64, md5: &str) -> FrameMeta {
        let meta = FrameMeta::new(
            seq,
            acos_verify::clock::rfc3339_from_unix_ms(
                std::time::SystemTime::now()
                    .duration_since(std::time::UNIX_EPOCH)
                    .map(|d| d.as_millis() as i64)
                    .unwrap_or(0),
            ),
            "art",
            self.width,
            self.height,
            self.density,
            md5,
            true,
        );
        // W58: the ART frame is the display's application area; publish where it
        // sits on the display so a tree bound can be mapped onto a PNG pixel.
        match acos_verify::frame_display_geometry(meta.width, meta.height) {
            Some(geometry) => geometry.apply(meta),
            None => meta,
        }
    }
```

**(b) `crates/acos-cli/src/engine/serve.rs`, new helper next to `label_frame`**:

```rust
/// W58: the display geometry of the frames this session produces, as JSON
/// fields for a reply's `frame` object.
///
/// `{}` when the frame is not the display's application area (then the frame is
/// the whole display and the mapping is the identity).
fn frame_display_fields(width: u32, height: u32) -> serde_json::Map<String, Value> {
    let mut fields = serde_json::Map::new();
    if let Some(geometry) = acos_verify::frame_display_geometry(width, height) {
        fields.insert("display_origin".into(), json!(geometry.origin));
        fields.insert("display_size".into(), json!(geometry.display_size));
    }
    fields
}
```

**(c) `crates/acos-cli/src/engine/serve.rs`, the four frame objects** — add the
fields to the object (keys `display_origin`, `display_size`):

* `fn label_frame` (~:913): after `object.entry("frame")...`, when the frame
  object has `frame_seq` but no `display_origin`:
  ```rust
        if let Some(frame) = object.get_mut("frame").and_then(Value::as_object_mut) {
            if !frame.contains_key("display_origin") {
                let width = session.width();
                let height = session.height();
                for (key, value) in frame_display_fields(width, height) {
                    frame.insert(key, value);
                }
            }
        }
  ```
  (`label_frame` is also what `launch`/`observe_tree`/`tap` replies use, so every
  reply that names a frame then names its origin.)
* `fn observe` tree branch (~:1040) and capture branch (~:1064): extend the
  `"frame": { ... }` literal with the same fields, using the frame's own size —
  the tree branch from `tree.frame.width/height` (the frame the tree is bound
  to), the capture branch from `session.width()/session.height()`.
* `fn observe_tree` (~:1010) returns no frame object today; add
  `"frame": {"frame_seq": tree.frame.frame_seq, "width": tree.frame.width,
  "height": tree.frame.height, "display_origin": …, "display_size": …}` when the
  session has a bound tree, so a tree-only reply also says where the PNG starts.

Suggested regression test for W55 (`crates/acos-cli/tests/w50_serve_art.rs`):
observe with `tree:true` and assert `result.frame.display_origin == [0,128]`,
`display_size == [1080,2400]`, and that `result.tree.nodes[0].bounds` still starts
at `[0,128,...]` while the capture frame is 1080x2209.
