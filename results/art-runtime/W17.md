## 1. What was fixed

### 1.1 Live view-tree probe (`LaunchMain.appendViewJson`)

* **`hint`** — `TextView.getHint()` is now a node field. `text` falls back to
  the hint when `getText()` is empty (uiautomator-compatible), so the four W15
  fixtures that assert an EditText's hint match. A consumer that wants the
  literal text can read `text` + `hint` separately.
* **`content_description`** — `View.getContentDescription()`.
* **`checked`** — `instanceof Checkable && isChecked()`; **`selected`** —
  `View.isSelected()`; `enabled`/`focused`/`clickable` already existed.
* **Bounds are reported twice**: `bounds` = `getLocationInWindow` (host
  InputChannel space, unchanged) and `bounds_on_screen` =
  `getLocationOnScreen` (display space, the reference-scenario convention).
  The probe never guesses: both come from stock getters.
* Nothing is invoked; only getters. Budget/per-node caps unchanged.

**Engine gap (for S8, not edited here):** the engine's probe reader
(`crates/acos-cli/src/observe_tree.rs`) and the tree normaliser drop the new
fields, and `assert_text` compares `nodes[].bounds` only. The probe now carries
`hint`/`content_description`/`checked`/`selected`/`bounds_on_screen`; the engine
must pick which bounds space `Selector::bounds` and `assert_text` compare
against. Until then the four full W15 scenarios stop at their bounds assertion
with the text already matched (see §2).

### 1.2 APK native libraries installed into the per-run app lib dir

New `crates/acos-services/src/native_libs.rs` (one flagged `pub mod` line in
`lib.rs`) + `acos-art/src/launch.rs`:

* Before the guest starts, `acos_services::native_libs::install` opens the APK,
  and if it has native code: `check_native_abi("x86_64")` → if absent, returns a
  structured `UnsupportedAbi` (the guest keeps its honest
  `UnsatisfiedLinkError`; an arm64-only APK is still UNSUPPORTED_ABI by design).
  Otherwise it extracts `lib/x86_64/*.so` into **this run's own**
  `<run>/app-lib/x86_64` using `acos-apk`'s hardened extractor (single path
  components, zip-slip re-check, declared-size verification, 256 MiB per entry)
  plus a 512 MiB aggregate cap.
* The run tree is bind-mounted **read-only** at `/data/app-lib`; the guest's
  `ApplicationInfo.nativeLibraryDir` (bind request, PMS reply and the
  instrumentation info) is `/data/app-lib/x86_64`, i.e. the stock
  `lib/<abi>` shape `LoadedApk`/`SoLoader` expect. `nativeloader` now logs
  `library_path=/data/app-lib/x86_64`.
* No shared/global state: one extraction per run, Landlock still sees it
  read-only (writable roots unchanged), seccomp/namespaces unchanged.

### 1.3 The real `<application>` class and theme

`launch.rs` parses the manifest through the already-installed `PmsState` and
passes the **fully-qualified application class** and `android:theme` resource
id to the guest; `LaunchMain.buildAppInfo` sets
`ApplicationInfo.className`/`.theme`, and `buildActivityInfo` sets
`ActivityInfo.theme`. This is what stock `PackageParser` writes into the
installed `ApplicationInfo`/`ActivityInfo`, and what `LoadedApk.makeApplication`
uses to instantiate the app's own `Application`.

Effect on rn-hello: `application=dev.acos.fixtures.rnhello.MainApplication`
(before: `android.app.Application`), `SoLoader.init(this, 0, …)` runs,
`activity-resumed` is reached, and a `ReactRootView` is attached. The
`SoLoader.init() not yet called` gate is **gone**. The first wall is now
application-level (the app's own `Application.onCreate`/JS content), not the
guest.

## 6. Residuals / next walls (precise)

1. **Bounds space (S8).** The probe emits `bounds` (window-local) and
   `bounds_on_screen`. `crates/acos-cli/src/observe_tree.rs` keeps only
   `bounds`; the four full scenarios stop at
   `expected bounds [42,317][1038,435], got [42,189][1038,307]` with the text
   already matched. Engine must choose `bounds_on_screen` for scenario bounds
   (or normalise in the emitted tree). Also surface `hint`,
   `content_description`, `checked`, `selected` in the normalised node JSON.
2. **native-hello public NDK libs.** First error:
   `UnsatisfiedLinkError: dlopen failed: cannot locate symbol
   "AAssetManager_fromJava" referenced by "/data/app-lib/x86_64/libnativehello.so"`.
   The `.so` has no `DT_NEEDED libandroid.so`; the image's `libandroid.so`
   exports the symbol (`@@LIBANDROID`), so the app namespace's public-library
   set (nativeloader `clns-2`) is the gap, not the extraction. This is a real
   fidelity increase: W15's "weak pass" never ran `NativeHelloApp.onCreate`.
3. **rn-hello JS content.** Launch/activity/ReactRootView are live; the tree is
   empty. The engine's `wait_for` returned in 1 ms (does not wait), so the JS
   instance has no proven observation window; diagnosing `ReactInstanceManager`
   / Hermes bundle init is the next step (logger currently not surfaced).
4. **service-provider** still needs the `IntentFilter` parcelable codec
   (`IActivityManager.registerReceiverWithFeature` arg 5).
5. **Logs/reset** remain `UNSUPPORTED_BACKEND` on the ART engine (blocks the
   full form-validation/todo-list/multi-activity/hello-views scenarios after
   their first assertions and the two lifecycle negatives).
6. `native_libs::install` extracts on every launch (no cache); the per-run
   directory is removed with the run. A launch of a very large native APK pays
   one read + write of its x86_64 libs (measured: rn-hello 6 libs, hello-jni
   1 lib; both sub-100 ms).
7. Tooling: `wait_for` returning immediately is an engine issue (S8), recorded
   here because it changed how the rn-hello result must be read.

## 7. Handoff to S8 (engine/probe consumer; files not edited here)

1. `crates/acos-cli/src/observe_tree.rs` drops the new probe fields. The guest
   emits `hint`, `content_description`, `checked`, `selected` and
   `bounds_on_screen` on every node; the normaliser should carry them into
   `ObservedNode` (the tree JSON schema already has `content_desc`/`checked`),
   so scenarios can select/assert them.
2. `assert_text`/`Selector::bounds` still compare `nodes[].bounds`
   (window-local). To unblock form-validation, hello-views, multi-activity,
   todo-list and hello-jni, compare display-space bounds (`bounds_on_screen`)
   or normalise `bounds` to screen coordinates at ingest. Both are present, so
   no probe change is needed. Every affected failure is exactly +128 px in y.
3. `wait_for` returned after 1 ms in the rn-hello run (no wait). If it is meant
   to poll, it needs the engine-side fix; otherwise RN's asynchronous content
   cannot be observed at all.
4. The shared `target/debug/acos-art` was rebuilt with the verified W17 changes
   (no `acos-cli` build was run, so S8's working tree is untouched).
