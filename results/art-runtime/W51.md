# W51 — product policy: opt-in untrusted (2026-11-12)

Owner decision (taken 2026-11-12): untrusted APKs are **opt-in only** and, with
the sandbox at CERTIFIED-WITH-LIMITS (`docs/SANDBOX_CERTIFICATION.md` §8.6,
limits §8.7), an explicit opt-in is **allowed in the product without any
environment variable**. Trusted stays the default; nothing is auto-detected.

Work window: `date -u` **2026-11-12T04:42:43Z → 04:56Z**. No commit, no push.
All builds/tests under `CARGO_TARGET_DIR=.cache/w51-target`, every command via
`tools/guarded.sh --mem 8G`, live runs via
`tools/art-runtime/run-exclusive.sh --task W51-*`.

Unchanged on purpose: `TrustGuard` (untrusted `observe`, `logs_since`,
`capabilities.logs/crash_reports` still fail closed with
`INSUFFICIENT_HOST_EVIDENCE`), trust resolution (trusted default, flag wins,
unknown scenario value is an error), `acos-protocol` (error code stays
registered).

### The downgrade flag

`trust::CERTIFICATION: Certification` is the single switch. Today
`CertifiedWithLimits` → `untrusted_gate` returns `None` and
`UNTRUSTED_APK_NOT_CERTIFIED` is unreachable. A future re-audit sets it to
`Certification::NotCertified` and the S8 refusal returns with no other change.
Unit test `certification_flag_flips_the_untrusted_gate` (trust.rs) calls the
gate with both values and asserts the code, the `not-certified` label and
`override_required: false`.

## 4. Changed and new tests (and why)

New — `crates/acos-cli/tests/w51_untrusted_policy.rs` (5 tests, real CLI over a
scripted ART session; `ACOS_ALLOW_UNTRUSTED_FOR_TESTS` removed from the child
env, scratch under `.cache/w51-tests`, removed on drop):

1. `untrusted_without_the_env_var_runs_and_labels_the_verdict` — untrusted +
   `assert_region` passes with no env var; verdict **and** envelope `result`
   carry `trust`/`certification`/limits/policy pointers.
2. `untrusted_tree_only_assertion_still_fails_closed` — untrusted +
   `assert_text`: `INSUFFICIENT_HOST_EVIDENCE`, `evidence_provenance.tree =
   guest-asserted`; the failure is **not** `UNTRUSTED_APK_NOT_CERTIFIED`.
3. `trusted_is_still_the_default_and_tree_evidence_still_counts` — no trust key
   keeps a tree assertion passing (trusted); explicit `trust: trusted` identical.
4. `the_test_override_alias_is_accepted_and_redundant` — with the alias set the
   run passes the same way and labels are unchanged.
5. `an_unclassified_scenario_is_labelled_unresolved` — invalid `trust:` value
   still `INVALID_SCENARIO`; envelope carries `trust: "unresolved"` + the
   certification record.

Rewritten — `crates/acos-cli/tests/sandbox_s8.rs`. These encoded the old
refusal policy, so they had to change **because the code they test changed
deliberately**:

* `untrusted_run_without_the_test_override_is_refused_before_art_starts` →
  `untrusted_run_without_the_test_override_is_allowed_and_labelled`: the ART
  session now *does* start (marker file exists), the verdict is labelled, and
  the tree-only step still fails closed.
* `untrusted_flag_also_refuses_without_the_override` →
  `untrusted_flag_is_allowed_without_the_override`: `--untrusted` with no env
  var starts the session, never returns `UNTRUSTED_APK_NOT_CERTIFIED`, and fails
  the tree-only assertion with `INSUFFICIENT_HOST_EVIDENCE`.

Unchanged: `crates/acos-cli/tests/w44_trust.rs` (4 tests) still passes — it
already set the alias and asserts the guest-asserted evidence rules, which did
not move.
