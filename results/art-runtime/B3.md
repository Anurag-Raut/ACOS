# B3 — arm (b): a shared boot image without fork (opt-in seam + verification)

Owner task: arm (b) of the approved three-way comparison
(`docs/decisions/2026-11-12-zygote-shared-art.md`). Input: `results/art-runtime/B2.md`.
Time box: 60 min (ran long: 90 min). Branch `b3-shared-image-flag`, worktree
`/home/Qui/.paseo/worktrees/3oxa6xao/b3-shared-image`.

**Bottom line.** The B2 memory win is real *through the product's served path*: an
uncompressed boot image plus `-Xnorelocate` cuts the boot-image private-dirty share
from **26.29 to 13.81 MiB/session** and makes **30.65 MiB/session Shared_Clean**,
for **−12.08 MiB/session** on the D-M2 metric (`memory.stat` anon+shmem) at N=5
and **−12.75** at N=1. Correctness is unchanged: the counter scenario passes
11/11 both ways, every captured frame is **0 px different** (5/5 frames,
2 385 720 px each, SSIM 1.0), dialog-menu passes 3/3 with the flag on and
form-validation 28/28 both ways. The seam is **off by default**, fails closed on a
bad value, and requires a **fixed image base (no image ASLR)** — trusted workloads
only, still an open owner decision.

## 1. The flag

| | |
|---|---|
| name | `ACOS_SHARED_BOOT_IMAGE` |
| value | host directory containing `x86_64/boot.art` (an **uncompressed** boot image) |
| unset | nothing changes: the guest argv is byte-for-byte the pre-B3 argv (no image flag, no extra bind) |
| set | the launch `--ro-bind`s that dir to `/data/img` and prepends `-Ximage:/data/img/boot.art` **and** `-Xnorelocate` to the guest argv — exactly the pair B2 measured |
| bad value | **fails the launch** (`Error::Layout`: `ACOS_SHARED_BOOT_IMAGE=…: no x86_64/boot.art (unset it for the default LZ4 image)`). No silent fallback to LZ4, so a typo cannot masquerade as a measurement |
| recorded | every launch with it on pushes `shared-boot-image: <dir> (-Ximage:/data/img/boot.art -Xnorelocate; fixed base, no image ASLR)` into `LaunchResult.notes` and logs the same line on stderr |
| scope | it is an **environment** seam, not a CLI flag: `acos serve` inherits it and passes it to every `acos-art launch` child, so `verify`, `serve`, `observe`/`session` and `bench` all see it without touching their own surfaces |

Canonical documentation lives in the doc comment on
`crates/acos-art/src/launch.rs::ENV_SHARED_BOOT_IMAGE`.

The image is built with B2's own recipe, unchanged (no new download, no new tool):
`tools/art-runtime/b2/build-uncompressed.sh --out <dir>` — the sysroot's stock
`dex2oat64`, the device `BOOTCLASSPATH`, `--image-format=uncompressed`,
`--base=0x70000000`. Its output (`.cache/b2/image`, **not** in git) was reused
verbatim: `.art` 50.64 MiB, `.oat` 120.87 MiB, 173 MiB per image on disk (2.9× the
LZ4 `.art`). ART appends the ISA to an `-Ximage` location
(`image_space.cc:136` → `GetSystemImageFilename`), which is why the path is
`/data/img/boot.art` while the file is `/data/img/x86_64/boot.art`.

## 4. M2 (per extra session), OFF vs ON

Same method, harness and binary as D-M2: `tools/art-runtime/dm2/measure.py`
(`acos serve --engine art`, N `counter.apk` sessions, settle **60 s** after the
last first frame, `memory.stat` anon+shmem of the job + session cgroups minus the
harness, `sum(Pss)` over the session processes, `/proc/PID/smaps` groups).
`--settle 60`, `--mem 14G` (N=5) / `10G` (N=1); host had 47–49 GiB available
before every run; **0 survivors** in every run.

|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| OFF, N=1 | 1 | 102.82 MiB | **101.355** | — | 215.64 | 87.11 | 40.40 | **26.34** | 0.00 |
| ON, N=1 | 1 | 90.07 | **88.609** | **−12.75** | 248.80 | 74.55 | 78.33 | **13.95** | 0.00 |
| OFF, N=5 | 5 | 521.67 | **104.042** | — | 566.72 | 434.57 | 146.28 | **131.70** | 70.17 |

This reproduces B2 to within 0.1 MiB (B2: 26.29 → 12.71 private, 25.74 shared per
session; here 26.29 → 13.81 private, 30.65 shared — the difference is B2's probe
class vs this counter and the `.oat`/extension images that come along).

Reading the two metrics honestly:

* **M2 metric (`memory.stat` anon+shmem)** — the one D-M2/O2 use — improves by
  **12.1–12.8 MiB per session** (≈ −11.6 % of 104 MiB at N=5): the 26.3 MiB of
  LZ4 decompression is private anon memory; with the file-backed image only
  13.8 MiB of runtime writes stay private, and file pages are not anon+shmem.
* **Σ Pss at N=1 is *worse*** (248.8 vs 215.6 MiB) because the whole 168 MiB
  uncompressed image (`.art` + `.oat` + extension images) is counted when only
  one process maps it. The win only exists from the second session on, and it
  saturates at the image size: N=5 Σ Pss −19.4 MiB total, cgroup −60.4 MiB total.
* Whole-session **private dirty** falls 87.11 → 74.55 MiB/session (N=1) and
  86.91 → 74.17 MiB/session (N=5).

So at N=1 the feature is a memory *loss* on Pss (not on anon+shmem); it is a
per-extra-session win, exactly like a shared page cache.

## 5. Security note — the fixed base is a policy decision

The saving exists **only** with `-Xnorelocate`, i.e. **no image ASLR**: the boot
image maps at its recorded base `0x70000000` in every session (verified: all five
ON sessions mapped `0x70000000-0x70468000`). Without it ART relocates ~37 MiB of
image pages per process and the uncompressed image is **strictly worse** than LZ4
(B2: 49.84 vs 26.29 MiB private dirty/session, measured again as 50.22/49.84).
A predictable image base removes one randomisation for an attacker who can read
the address space, so this is **trusted-workloads-only**:

* the flag is **off by default** and turning it on anywhere by default was
  explicitly out of scope for B3;
* enabling it for untrusted APKs would need a security review of the ASLR loss
  (and the 2.9× larger image, 173 MiB per image on disk) against the 12 MiB/session
  win — this remains an **open owner decision**;
* a set-but-invalid value fails closed; a *valid but incompatible* image can still
  make ART fall back to imageless running (B2 §2 saw that silently). Any future
  measurement should assert the `boot.art` file mapping exists (this report's
  method) rather than trusting the flag alone.

## 6. Blockers / follow-ups

1. `acos-art build-image` still hardcodes `--image-format=lz4`; producing the
   shared image means running B2's script out-of-tree. A product `build-image
   --format uncompressed` (and a decision on shipping 173 MiB) is the natural
   next step, behind the same owner decision.
2. The `-test cleanup` integration cases cannot run from this worktree (SUN_LEN on
   the socket path); they are unrelated to `launch.rs` and were not weakened.
3. N=1 pays more Pss with the flag on; the crossover is N≥2. Any adoption
   argument should quote cgroup anon+shmem (the M2 metric) *and* Σ Pss at both N=1
   and N=5, as above.
