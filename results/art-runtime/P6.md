# P6 — stock Android emulator baseline (M1–M8 + CPU)

**Task:** measure the **stock AOSP emulator** (official emulator binary + the installed
API 34 `google_apis` x86_64 system image) on the same metrics as ACOS, so the
versioned deliverable table in `docs/TRACKS-2026-11-12.md` gets its
"Stock Android emulator" column. Not a verdict, not a comparison — a measured column.

**Result: every requested row is measured (117 timed samples plus the CPU windows),
0 failed correctness checks, and the emulator was shut down (no qemu/emulator process
left).**
Raw record: `results/bench/p6-emulator-20261112T092011Z.json` (every sample, host
before/after, per-rep logs under `.cache/p6/run-20261112T092011Z/`).
Harness: `tools/art-runtime/p6/p6_emulator.py`, driver `tools/art-runtime/p6/run-p6.sh`
(holds the host-wide ART lock for the whole run). Diagnostics that fixed two
measurement bugs: `tools/art-runtime/p6/diag_frames.py`.

## 4. What the numbers mean (and where they must not be over-read)

1. **M1 is the whole emulator, not one app.** 3410.7 MiB host anon+shmem for one
   idle emulator with one app open, of which the guest itself accounts for
   1084.5 MiB used and the counter app's own PSS is 23.1 MiB. The rest is the
   guest RAM allocation (2048 MiB), qemu's device/GL model and swiftshader's
   allocations. It is the right number for "what does one emulator cost this
   host", and it is *not* comparable with a per-app figure.
2. **M2 is a formula, not a second measurement.** One emulator per session ⇒
   per-session cost = one full emulator = M1. N=1 only; the scaling curve
   (N=2…20) does not exist for this isolation model at 2 GiB/session × host RAM.
3. **M3 vs M4 differ by design.** M3 is cold boot + the *first* app launch after
   boot (TotalTime 1.1–1.4 s, visible app frame ~1.9 s, settled correct frame
   4.6–5.0 s). M4 is the same launch with a warm system (TotalTime 0.42 s,
   correct frame 1.24 s). The 3.4 s difference is post-boot system work plus the
   first-launch path, not a measurement artefact — the same polling method and
   the same reference frame are used in both.
4. **M7 is the honest cost of the standard tool.** `uiautomator dump` starts a
   fresh `app_process`/instrumentation per call; that is 1.9 s on this emulator
   (spread 0.8 %). It is the tool the instructions name, and it is what an agent
   using plain adb pays. No persistent-tree route is claimed.
5. **M8's 2.33 s is M7's cost, not the tap's.** The tap command is 39.7 ms and the
   count text visibly changes at ≤ 257 ms; the *verified* state confirmation
   needs a tree dump, so tap→verified-state ≈ tap + M7. Treated correctly, a
   tap acknowledgement (257 ms) is never a success signal here.
6. **M5 PNG vs raw: the encode is not the cost.** 201.0 ms with PNG encoding vs
   205.4 ms raw — both are dominated by the emulator's screencap path (the raw
   frame is 10.4 MB over adb). 20/20 PNGs were valid and non-black; 20/20 raw
   frames were pixel-identical to the reference.
7. **Noisy rows are labelled noisy:** M8 tap-command (28.0 % spread) and M8
   tap→changed-frame (18.0 %) exceed the 15 % spread gate; M6's command chain is
   14.0 %, just inside. The other rows are 0.0–10.0 %.
8. **Host load 4.0 loadavg1 during the run** (other agents). The emulator is
   single-instance and CPU-bound in swiftshader, so absolute numbers carry that
   load; the lock was held, so no other ART measurement ran concurrently.

## 5. Not measured, and why

| Item | Why |
|---|---|
| M2 at N≥2 (per-session marginal curve) | One emulator per session and ADR-0015 forbids a second instance; 2 GiB guest per session also exceeds the host RAM guard at small N. Reported as the formula instead. |
| M9–M11 (concurrency, end-to-end verify wall time, verified tasks/GiB-min) | Not part of the P6 request (M1–M8 + CPU). They need an agent loop and an assertion suite on this emulator; not attempted here. |
| Guest-side PSS **per app process tree** as an M1 type | The instruction fixes M1's type to the host qemu anon+shmem; the guest `dumpsys meminfo` numbers are reported as context only. |
| Persistent/event-driven UI tree (the 4.1 ms ACOS research route) | That is an ACOS capability, not something stock adb exposes; the standard `uiautomator dump` is reported as instructed. |
| Tap acknowledgement at the input layer | `input tap` only reports that the command was delivered; the emulator exposes no per-touch ack, and the project rule forbids treating an ack as success anyway. |
| `policy_control immersive` / hidden system bars | Tried; no effect on this image (`userdebug`, API 34). Instead the compare region excludes the status bar and nav strip, which is stated per row. |
| Anything needing a download | Nothing was downloaded; the AVD, image and APK already existed. |

## 6. Shutdown verification

```
qemu process tree after the run : []            (no qemu-system-x86_64 for acos-oracle-34)
adb devices                     : (empty)       (no emulator-55xx)
host MemAvailable after         : 48468 MiB (48229 MiB before -> no leak)
shutdown path                   : adb -s emulator-5554 emu kill, then process-tree check,
                                  SIGKILL fallback armed; graceful kill took 1.5 s
```

`run-p6.sh` re-checks this after the driver exits (and force-kills if needed), so a
timeout in `guarded.sh` cannot leave the emulator running.

## 7. Reproduce

```sh
# full run (holds the ART lock for the whole emulator run; ~7.5 min here)
tools/art-runtime/p6/run-p6.sh

# unit checks, no emulator
python3 -I tools/art-runtime/p6/p6_emulator.py --self-test      # 13 checks, 0 failed

# frame-level diagnosis (why a "correct frame" appears when it does)
tools/art-runtime/run-exclusive.sh --task P6-diag -- \
  tools/guarded.sh --mem 6G --time 600 -- \
  python3 -I tools/art-runtime/p6/diag_frames.py --out .cache/p6/diag
```

The diagnostic run is what found the two measurement bugs fixed before the
reported numbers: `RssAnon`/`RssShmem` are not in `smaps_rollup` (they are in
`/proc/<pid>/status`; the first smoke read 0.0 MiB), and the first "correct
frame" was being delayed ~1.4 s by the status-bar clock and by the nav gesture
pill at rows 2363–2373 that is drawn for ~2 s after every launch (both are now
cropped out of the compare).
