# W54 — the dialog card is drawn at `frame − surfaceInsets`, not `frame`

**Verdicts.**

| item | result |
|---|---|
| root cause | **`LayoutParams.surfaceInsets` ignored by WMS**: the window's `SurfaceControl` was the bare frame (1024x513) and the layer sat at the frame origin, while the guest's `ThreadedRenderer` renders a `frame + insets` surface and translates the canvas by `(insetLeft, insetTop)`. The dialog card was therefore drawn 126 px (`84` insets + `42` layout) inside a buffer 168 px too small, with its right/bottom rounded corners cut by the buffer edge. |
| fix (AOSP-first, no dialog special case) | surface size = `frame + insets`; layer position = `frame − insets`; C1 clips the composite to the display viewport |

## 1. Root cause

The tree was right and the pixels were wrong: `form-validation` passed 26/26 and
the dialog window root was the stock **`[28,976][1052,1489]`**, but the frame
showed a 898x387 card at frame `(154, 974)` with flat right/bottom edges.

Measured, not guessed. With `ACOS_W6_DUMP` C1 dumps the *stored guest buffer* of
every layer (raw RGBA + meta). The dialog's BLAST child buffer was:

| | pre-fix | post-fix |
|---|---|---|
| buffer (frame 5, `layer=6`) | **1024x513** = the bare frame | **1192x681** = 1024+2·84 × 513+2·84 |
| opaque content bbox | `(126,126)…(1023,512)` — **cut by the buffer edge** | `(126,126)…(1065,554)` — the full 940x429 card |
| card colour sample | `(240,240,243)` inside, transparent in the 126 px top/left band | same, band is now the 84 px shadow inset |

So C1 was not blitting a stale crop: **the guest had already clipped the card**.
The offset is `84 + 42`:

* `84` = `LayoutParams.surfaceInsets` per side — stock `ViewRootImpl` computes it
  from the DecorView elevation (`WindowManager.LayoutParams.setSurfaceInsets`:
  `ceil(view.getZ() * 2)`), and `ThreadedRenderer.setup` makes the drawing
  surface `width + insets` and translates the canvas by `(insetLeft, insetTop)`
  (`base/core/java/android/view/ThreadedRenderer.java:515-535`, `:741`).
* `42` = the dialog's own layout inset (`[28,976]` frame → `[70,1018]` parentPanel).
* ACOS's WMS answered the relayout with `SurfaceControlInfo { width: 1024,
  height: 513 }` and placed the layer at `(28,976)`, so the client's 1276x681-ish
  drawing was truncated to the frame-sized buffer and the visible card landed at
  `28+126, 976+126`.

AOSP's other half of the contract is `SurfaceView.java:1180-1181`, which converts
a frame into the window layer's coordinate space by `offset(surfaceInsets.left,
surfaceInsets.top)`: the window layer *is* `frame − insets`, so content drawn at
`+insets` lands on the frame.

This predates W47. The W35 evidence `W35-dialog-composite-crop.png` (dialog frame
776x513 crop) already shows the card offset by 126 px and cut at the right/bottom;
W47 only made it glaring by widening the dialog from 776 to the stock 1024 px.

## 2. Fix

`crates/acos-wm/src/wms.rs`

* `WindowRecord::surface_insets()` / `surface_size()` — the window surface is
  `frame + insets` (stock `WindowState.getSurfaceWidth/Height`).
* `relayout_with_requested` returns that size in `SurfaceControlInfo` (the client
  turns it into the BLAST buffer geometry) and sets
  `RELAYOUT_RES_SURFACE_RESIZED` when the *surface* size changes, not only the
  frame (stock behaviour).

`crates/acos-services/src/wms.rs`

* `publish_layer_placement` places the layer at
  `frame.left − insets.left, frame.top − insets.top` — the window layer lives in
  the surface's coordinate space (`SurfaceView.java:1180`), so the client's
  `+insets` canvas translation lands the content on the frame.

`crates/acos-services/src/surface_client.rs`

* `placed_rect()` — one function for a layer's display-space rectangle; C1's
  canvas union and the per-pixel blend use it. It clips to the display viewport,
  which is what SurfaceFlinger does for every layer: a surface-inset window
  deliberately overhangs the display, and the frame must stay display-sized
  (1080x2209 here, not 1136x…). No ad-hoc offsets, no dialog special case.
* trace instrumentation (`ACOSC1_TRACE`): every `layer_state_t` now logs position,
  matrix, `crop`, `buffer_crop`, `destination_frame`, buffer dimensions, corner
  radius and the GraphicBuffer geometry; the composite line logs each layer's
  buffer size, crop, drawn region, placement and name.

`crates/acos-services/src/wms.rs`/`window_session.rs` also log
`surfaceInsets=` and `surface=WxH` on relayout under `ACOS_WMS_TRACE`.

Effects on existing behaviour: the only test that changed is W35's
`layers_far_apart_are_refused_before_a_canvas_is_allocated`. With display
clipping, two layers 8185 px apart are no longer a `CanvasTooLarge` refusal — the
off-display layer draws nothing and the canvas is the on-display layer
(`layers_far_apart_are_clipped_to_the_display_not_a_huge_canvas`). The memory
bound got *tighter* (the display), not looser; the per-buffer/byte caps are
unchanged.
