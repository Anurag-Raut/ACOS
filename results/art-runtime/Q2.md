# Q2 — the content-provider peer: `IActivityManager.getContentProvider` + a real `Settings` provider

**Status: done for the `acos-services` half.** `ServiceHost` now answers
`IActivityManager.getContentProvider/getContentProviderExternal/removeContentProvider/
refContentProvider` from a registry of Rust providers and hands back a real
`ContentProviderHolder` (local `android.content.IContentProvider` binder + a real
`ContentProviderConnection` token), and the `settings` provider answers
`IContentProvider.call` (`GET_*`/`PUT_*`/`GET_config`/`LIST_config`) and
`IContentProvider.query` (real `BulkCursorDescriptor` + `CursorWindow`).
`cargo test -p acos-services` passes (87 tests, 8 of them new and byte-exact).
Nothing committed; no `acos-art`/`acos-binder-peer` file touched; no
`acos-art`/`dalvikvm` process was run.

Resumed from the OOM-killed predecessor: `cursor.rs` existed but was not linked
into the crate, `provider.rs` had the defaults/`query`/`SettingsDefaults` work
without its helpers or the registry, and `host.rs` referenced
`ProviderLookup`/`AtmsService::provider_lookups` that did not exist. All of that
is now complete, and `Uri` decoding in `QueryRequest` (field 0 vs 1) was fixed —
it would have failed on the first real `query`.

## 3. Wire layouts (what the framework reads)

`ContentProviderHolder.writeToParcel` (API 34, `core/java/android/app/ContentProviderHolder.java`):

```text
ProviderInfo.writeToParcel(dest, 0)     // bare payload, NO presence marker
writeStrongBinder(provider)             // android.content.IContentProvider
writeStrongBinder(connection)           // ContentProviderConnection token
writeInt(noReleaseNeeded ? 1 : 0)       // writeInt, not writeBoolean
writeInt(mLocal ? 1 : 0)
```

`IContentProvider.call` reply (`ContentProviderNative.onTransact`, CALL_TRANSACTION):
`writeNoException()` + `writeBundle(responseBundle)`.

`IContentProvider.query` reply: `writeNoException()` + `writeInt(1)` +
`BulkCursorDescriptor.writeToParcel` (`writeStrongBinder(cursor)`,
`writeStringArray(columnNames)`, `writeInt(wantsAllOnMoveCalls)`,
`writeInt(count)`, `writeInt(window != null)` + `CursorWindow.writeToParcel`).

`CursorWindow` is the framework's **inline compacted frame** (name string8,
rows, columns, compactedSize, `writeInt(0)` "not an fd", heap allocations, then
the 16-byte slots with slot 0 last). No ashmem/memfd is used because the
framework's default window is the inline form and every Settings result fits;
a frame > `kInlineSize` (16384 bytes) is a structured
`UNSUPPORTED_ANDROID_API`, never a truncated window. If a future provider needs
more, the ashmem half is `memfd_create(2)` — the framework only `mmap`s the
received descriptor `PROT_READ` (`ParcelFd::memfd`, documented in `cursor.rs`).

Provider answer semantics: `noReleaseNeeded=0` with a real connection token, so
the framework's own reference counting and release path
(`ActivityThread.installProvider`/`releaseProvider`) run instead of being
short-circuited; `mLocal=1` because the provider *is* served in this process.
`removeContentProvider`/`refContentProvider` resolve the authority from the
connection token (the token is a real binder, never transacted on).

Unknown authority → `null` holder (`getContentProvider` returns `null` on a real
device) **and** a `ProviderLookup{hit:false}` record; unknown provider method →
`UNSUPPORTED_ANDROID_API`; unsupported projection column / SQL selection /
settings table → `UNSUPPORTED_ANDROID_API` (an empty cursor would read as "the
key does not exist").

Defaults: `SettingsDefaults::api34()` is a stock API-34 emulator image for
`system`/`secure`/`global`/`config` (`ime/*` DeviceConfig entries included);
`SettingsState::seed`, `seed_config` and `with_defaults` override any of them
(the harness can hand the runtime a whole map). The four
`System.{auto_caps,auto_punctuate,auto_replace,show_password}` keys from
`settings_keys.tsv` stay set; the `Global.*` keys the launch reads
(`force_resizable_activities`, …) stay absent so `Settings.getInt` uses the
caller's default exactly as on the reference.

## 4. What the ART side needs from the peer (not done here — outside this task's ownership)

Today `hello-views` never reaches the peer: P2a §4 stops at
`NullPointerException: IActivityManager.getContentProvider(...)`. Even after that
is fixed, the *runtime* still has to route two things to this service:

1. **`IActivityManager.getContentProvider` is answered by
   `acos-runtime/src/ams_java.rs:911`** (owned there, `owns_method`), not by
   `ServiceHost`. It uses the hardcoded `AmsState::get_content_provider`
   (`acos-services/src/ams.rs:1110`, `authority == "settings"` → record with
   `binder = 0`) and substitutes
   `acos_services::provider::settings_provider_binder()`
   (`ams_java.rs:925`), building the holder with `connection = null`,
   `noReleaseNeeded = true`, `mLocal = false` (`ams_java.rs:603-646`).
   Required: either stop owning `getContentProvider*`/`removeContentProvider*`/
   `refContentProvider` in `ams_java` so `acos-runtime/src/transport.rs:239-247`
   falls through to `ServiceHost` (the registry then decides), or have
   `ams_java` read the same `ProviderRegistry` instead of its hardcoded record
   — otherwise the authority list lives in two places and drifts.
2. **`IContentProvider.call`/`query` are answered by
   `ams_java::transact_content_provider` (`ams_java.rs:1005-1028`), which raises
   `UNSUPPORTED_ANDROID_API` for *every* method** (including `call`). Until the
   `IContentProvider` descriptor+matching codes are dispatched to `ServiceHost`
   (`transport.rs:211-247`), `Settings$NameValueCache.getStringsForPrefix`
   (`LIST_config`, the actual P2a §4 blocker) and the `query` fallback still
   fail. Ordering matters: the local-binder branch
   (`self.locals.contains_key(&binder.0)`, app-published providers) must stay
   first; a `settings` binder is a `ServiceHost` binder and must go to the host.
3. **Peer binder ids.** The holder's `provider` must be the *same* binder id the
   transport routes to `ServiceHost` (`host.binder_for_descriptor(
   "android.content.IContentProvider")`), and the `connection` token must be a
   registered binder id (`register_dynamic`), so the native `BinderProxy`
   written into the reply is routable back. The runtime currently builds a real
   `ContentProviderProxy` around `BinderProxy(mNativeData = binder)`; that works
   with these ids unchanged.
4. **`ContentProviderHolder` layout** (`parcelable.rs`) is now the framework's
   real 5-field form. `acos-runtime`'s holder writer is real Java object
   construction + the framework's own `writeToParcel`, so it already emits this
   layout and its tests still pass; any *hand-rolled* holder encoder elsewhere
   must drop the typed `ProviderInfo`/typed `IBinder` markers.
5. **DeviceConfig/IME shape** the framework asks for (verified from
   `Settings.Config.getStrings`): `call(authority="settings",
   method="LIST_config", arg=null, extras={"_prefix":"ime/"})` and expects
   `Bundle.value` as a `HashMap<String,String>` of `namespace/name` keys. It also
   may pass `_track_generation`; the reply simply omits the generation fields
   (the framework treats that as "no tracker").

## 5. Limits, and what is deliberately not done

- One process. The connection token is one binder per authority (shared by every
  acquire) rather than one per client; the framework keys its own refcounts by
  the provider binder, so the observable behaviour matches the single-app case.
  Per-client connections are only needed when two clients race on the same
  authority in one process.
- Provider set: `settings` (`system`/`secure`/`global`/`config`). Adding one is
  a `ProviderEntry` + a `ServiceObject` with `content_query`; no host change.
- `insert`/`update`/`delete`/`bulkInsert`/`openFile` remain structured
  `UNSUPPORTED_ANDROID_API` (`PUT_*` over `call` is supported).
- Windows > 16 KiB (a huge Settings table projection) are a structured error,
  not an ashmem window; see §3.
- Not done here: `results/art-runtime` evidence from a real ART run (task
  constraint: no `acos-art`/`dalvikvm`), and the runtime wiring in §4.
