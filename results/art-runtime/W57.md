## 2. What was built

* `tools/art-runtime/d2_warm.py` (new) — the warm harness. Two phases
  (`--phase mem --n 1|5`, `--phase latency`), an `--analyze` aggregator and a
  `--self-test`. It **imports** `tools/art-runtime/agent_loop.py`'s `Daemon`
  (W55-owned; imported, never forked) and one `acos serve` daemon per rep.
  * Memory: 100 ms sampler over the job cgroup (`acos serve`'s guarded scope) plus
    any guest cgroup outside it, with the sampler's own `RssAnon+RssShmem`
    subtracted (the W45/W52 rule); per-session attribution from the process tree
    each launch adds (pid sets diffed at launch) — the guest cgroups all live in the
    same guarded scope, so the cgroup column is the total and the process column is
    the attribution.
  * Latency: `acos_observe {png:true}` (M5), `acos_observe_tree` (M7) and
    `acos_reset` (M6) on the **already-held** session, each with warm-ups discarded.
    Freshness/correctness is part of every sample: `frame_seq > previous_seq`, PNG
    magic and bytes for M5; text nodes and no truncation for M7; for M6 the app is
    tapped to a non-zero count first and the post-reset tree must read 0, and the
    reply must carry a newer `frame_seq`.
  * Refuses a non-release binary path (exit 2) before any guest starts; records every
    rep (ok/failed/contaminated, survivors, host before/after) and prunes its scratch.
* `tools/art-runtime/bench-d2.sh` — new `--mode warm` (the default `cold` path is
  untouched): waits for a clean host (loadavg1 ≤ 4, MemAvailable ≥ 30 GiB), runs
  **one rep per `run-exclusive.sh` + `guarded.sh --mem 16G --time 1500`
  acquisition** (the host-wide ART lock is never held across reps), then aggregates.
  `--analyze-warm DIR` re-derives the table with no ART, no build and no host gate.
* `tools/tests/test-d2-warm.sh` (new) — 15 checks, no ART: the analysis self-test, a
  synthetic outdir that must aggregate to M1 PASS / M2 TIE / M5 FAIL / M6 PASS /
  M7 PASS with matching counts, a noisy M1 (NOISY) and a fully contaminated run
  (NOT_MEASURED), the bench-d2 re-derive path, and the three refusals. `15 passed,
  0 failed`.
* `BENCHMARKS.md` — §12.2 (new): method record, the five rows, verdict counts and
  residuals; §12 status + verdict-counts paragraphs now point at §12.2 and mark the
  cold-process cells for M1/M2/M5/M6/M7 as history. §3 gained a footnote resolving the
  "workset vs anon+shmem" ambiguity with the inventory's own definition.

## 4. Findings

1. **M2 is a real regression, not a state artefact.** Both the incremental
   (107.50 MiB/session vs legacy 78.7) and the marginal (107.67) say ~1.37×. The legacy
   workset type is the core cgroup's anon+shmem (inventory §2), so this is a same-type,
   same-state comparison. ~88 MiB of each session is the guest process tree.
2. **M1's PASS carries a scope caveat, stated in the row.** Legacy 206.0 MiB is a bare
   core with no app session; the ACOS row is `acos serve` (1.36 MiB alone) plus one
   idle launched session (guest tree ~87.8 MiB). ACOS is charged for a session legacy's
   number does not carry and still passes. The derived legacy core+one-session figure
   (206.0 + 130.3 = 336.3 MiB) is information only, never a verdict input.
3. **M5 FAIL is a PNG-write-inclusive warm retrieval** (80.08 ms vs 66.5): the shipped
   verb captures and writes a 9.5 MB PNG. It is a real regression on the warm route;
   no like-for-like no-write row is claimed.
4. **M7 PASS uses the shipped legacy route** (one-shot `ui --text` 538 ms); the 4.1 ms
   persistent-observe number is research and is explicitly not the bar.
5. **M6 is a TIE at a 14.1 % spread** — 681.8 ms vs 748.1, inside the noise band
   (642.4–785.5). A tie is not a pass. serve's reset is a kill + relaunch + fresh bound
   frame, so this is reset→ready, not a command-only number.
6. **Guest deaths at launch (engine issue, not W57's to fix):** N=5 rep1 lost session 2
   (2/5 reached a frame) and rep6 lost session 4 (4/5), both `GUEST_EXITED` ~12–14 s
   into the rep, one guest at a time, no host-gate violation, no OOM in our scope, no
   exit record (scratch was pruned; rep7 with `--keep-scratch` succeeded, so no sample
   of the failure's artifacts was captured). Both attempts are in the raw JSON as
   failed reps and are excluded from the rows; the failures are never re-labelled as
   app behaviour. This is the same undiagnosed death as W50 §7.3 / W39 §7.5.
7. **Harness lesson for W55/engine owners:** `benchlib.descendant_cgroups` takes a
   child→parent `ppid_map` (benchlib `_ppid_map`); a parent→child map raises
   `TypeError: unhashable type: 'list'` deep inside the sampler. No benchlib change is
   requested.

## 6. What is verified vs not

Verified on the actual binary: a held `acos serve` ART session settles 60 s and its
cgroup anon+shmem is measured with the sampler's own charge subtracted; 5 clean M1
reps and 5 clean N=5 reps (plus 2 recorded failures, 2 contaminated); 20 warm
screenshots (20/20 fresh, PNG valid), 20 warm trees (20/20 with text, untruncated),
10 warm resets (10/10 with a newer frame and count back to 0); every verdict produced
by `benchlib.verdict()`; the combined D2 table in BENCHMARKS §12.2; the harness's own
15 tests; and no process/cgroup leak.

Not verified: the cause of the `GUEST_EXITED` launch deaths; M4 (needs a warm worker
pool — a held session returns a bound frame, it does not create workers); M8 (W55 is
changing tap latency concurrently, so it was deliberately not measured); a quieter
host window for M6's 14.1 % spread; and N>5 held sessions in one daemon.
