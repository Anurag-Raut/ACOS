## 1. What changed

### 1.1 `assert_log` on the ART engine (guest logd, guest-asserted)

* **Guest (surgical, flagged):** `acos-art launch --interactive` now serves
  `{"cmd":"logs"}`: a live `Logd::snapshot()` (entries + `total`/`kept`/`dropped`/
  `cap`) from the same logd sink the launcher already runs. `reset`'s guest reply
  now says the CLI relaunches (it was "tap the app's Reset control"). This is
  ~35 lines in `crates/acos-art/src/launch.rs`, a file W21 owns. It is
  **not** in my working diff any more: W21's commit `58f02e3` swept it in. The
  content is intact at `launch.rs:1696`; I did not commit it.
* **CLI:** `SessionBackend::logs_since` (default = honest unsupported);
  `ArtSession::logs_since` maps a snapshot to `LogRecord`s. `seq` is the entry's
  **absolute logd ordinal** (`total - kept + index + 1`) plus a per-session
  `log_offset`, not an array index: the sink drops oldest first and a reset
  restarts the guest's counter, so both would collide otherwise. `timestamp_ms`
  is the host read time (the sink carries no guest timestamp): it orders records,
  it is not an emission instant. `level` maps `prio` 2/3/4/5/6-7 to
  Verbose/Debug/Info/Warn/Error.
* **Executor:** `assert_log.timeout_ms` now really waits (polls `logs_since`,
  back-off 10→100 ms, **real** `Instant` deadline — a `FixedClock` never
  advances), then evaluates; a missing line is still an `ASSERTION_FAILED`. The
  per-step flush's error is remembered: a *refused* log channel makes the step
  fail with the backend's code instead of a misleading "no line matched".
* **Provenance / untrusted:** logs are `guest-asserted` and the verdict already
  labelled them so (`steps[].provenance.logs`). `TrustGuard` now refuses
  `logs_since` and clears the `logs`/`crash_reports` capabilities on an untrusted
  run, so `assert_log`/`assert_no_crash` fail closed with
  `INSUFFICIENT_HOST_EVIDENCE` (`UNTRUSTED_LOG_ASSERTION`) or `UNSUPPORTED_BACKEND`
  — never a pass from a forged line.

### 1.2 `reset` on the ART engine (host-side, honest)

`reset` stops the guest (the same process-group teardown `close` proves) and
starts the same APK in a **fresh `acos-art` process**. `acos-art` gives every
launch its own run directory with an **empty `app-data`**: fresh process, fresh
Activity, cleared state. The app's own Reset control is never tapped. Two
sequence invariants keep post-reset evidence honest: `seq_offset` rebases the new
guest's frame sequence onto the engine's (`seen_seq` keeps increasing, so the
post-reset frame is provably newer under the stale-frame rule) and `log_offset`
does the same for log ordinals. `reset` leaves a bound live frame, and the
executor now binds that frame as the reset step's observation and treats `reset`
as frame-advancing, so a following pure `assert_text` describes the post-reset UI
(previously: `ASSERTION_FAILED observation is frame 4 but the bound completed
frame is 3`).

Live proof (`scenarios/w22-counter-reset.yaml`, `id/reset` never used): launch,
`assert_text count=0`, tap Increment, `assert_text count=1`, `reset`, assert
count=0, `capture fresh`, assert count=0 → **pass 9/9**. `scenarios/v1-reset.yaml`
(hello-views, taps Greet, resets, relaunches) → **pass 11/11**.

### 1.3 The bounded extra capabilities used by existing scenarios

* **crash reports** (`assert_no_crash`, blocked `v1-counter` + `v1-reset`): the
  guest log is scanned for a real fatal signature (`prio >= 7`, `art_aborter`,
  `abort_message`, `Check failed`, `AndroidRuntime: FATAL EXCEPTION`). An ordinary
  `E` line (RippleDrawable, …) is **not** a crash; `tests` assert both directions.
  Exposed as `SessionObservation.crashed` (guest-asserted; untrusted clears the
  capability).
* **`type.clear: true`** (next wall of `form-validation`): the ART session has no
  clear command, so the engine erases the field with real DEL key events through
  the existing input channel, measured from the selector's live text, then types
  the replacement. Proven live by `w22-key-delete` (3 DELs turn the email back
  into empty → the app logs the Name error) and `w22-type-clear` (12 DELs + valid
  email → `validation_ok name=Ada email=ada@example.com`).
* **Still unsupported, precise:** `input.rotate` (`hello-views` step 16:
  "the ART session protocol has no rotate command yet") and `environment`
  (`set_*`). Starting a second Activity via an Intent has no session channel:
  `multi-activity` step 7 (`tap Send`) kills the guest and surfaces
  `INTERNAL: the guest ended after the gesture without a settled frame`. That is
  the honest precise error for the missing `start_activity`/Intent path; the
  design request is in §6.

## 6. Residuals and the exact request for W21

1. **Dialog-window tree probe** (`form-validation` last step, `id/message`):
   the probe traverses the Activity window only; `AlertDialog` lives in another
   window. Request (guest/probe owner): include `WindowManagerGlobal` root views
   (or attach the dialog's decor) in the probe's node list, with the dialog's own
   `bounds_on_screen`; do not synthesise it.
2. **`input.rotate`** (`hello-views`): no session command. Smallest honest
   implementation: guest `{"cmd":"rotate","orientation":"landscape|portrait"}`
   that calls the real `ActivityThread` config-change path (or
   `WindowManagerGlobal`/`Display` update) and replies with a settled frame; the
   CLI already has `key`/`tap` plumbing to copy.
3. **Second-Activity Intent start** (`multi-activity` step 7): the Send tap kills
   the guest (`exit 1`, no settled frame). Needs a guest `start_activity`
   (Intent → `Instrumentation.execStartActivity`) or at minimum a structured
   `UNSUPPORTED_ANDROID_API` from the guest instead of exiting. Request: in
   `LaunchMain`/the AMS shim, return `UNSUPPORTED_ANDROID_API: startActivity` for
   a second Activity until it is implemented, so the error is not `INTERNAL`.
4. Layout/text metrics remain: `counter` `inc` width, `todo-list` "Clear all"
   +18 px, `hello-jni` title. Outside the engine capabilities.
5. The guest `logs` command has no timestamp or per-entry id; the CLI orders by
   absolute ordinal and stamps host read time. If W21 wants exact emission
   times, add `at_ms` to `LogEntry` (a `#[serde(default)]` field) — no CLI change.
6. `assert_no_crash` is a fatal-log signature, not a process watchdog: an app
   that exits silently without a fatal line is caught by the frame/step failures,
   not by this assertion. Documented, not hidden.
