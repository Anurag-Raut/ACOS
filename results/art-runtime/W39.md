# W39 — cache the remaining per-launch staging, profile the launch wall, refresh D2 (2026-11-12)

**Verdict: DONE (task accepted against its list).** `linkerconfig`,
`derive_classpath` and the static-RRO `idmap2` set — the last APK-independent
staging steps that ran on every launch — are now built **once per sysroot image
digest** into the W37 content-addressed cache and installed on later launches
with the same verify / per-key `flock` / atomic-publish rules. Cold-launch wall
(exec → `activity-resumed`, release, `counter.apk`, 20 launches each with a fresh
`ACOS_ART_DATA`, one binary): **2156.0 ms p50 cache-off → 503.0 ms p50 cache-on**
p95 504 ms, spread 0.2 %. The APK-independent staging share of the wall is now
**0–10 ms** (was ~110 ms with the W37 cache on and ~470 ms pre-W37).

**Component:** build/staging cache DONE for every APK-independent step on the
`launch` path; D2 table refreshed.
**Evidence scope:** real APK lifecycle (counter, rn-hello, native-hello) on real
ART, release build, a shared host (5 other agents ran ART suites in the window).
