## 1. What changed in the image model (all evidence, no guess)

1. **frame-rate group**: `layer_state_t::write` @`0xd0cc0` emits `writeByte` ×3 then
   `writeUint32 fixedTransformHint`; r75's 4th byte + `frameRateCategorySmoothSwitchOnly` +
   `frameRateSelectionStrategy` are absent. The reader was 8 bytes long from there on.
2. **GraphicBuffer magic**: the image's `libui` writes `31 30 42 47` (`0x47423031`), the byte
   reverse of the tag's `'GB01'`. Accepted alongside the tag value; anything else is still a
   structured rejection.
3. **AIDL parcelable size word counts itself**: `TrustedPresentationThresholds` is
   `[marker][size][size-4 payload]` (fixture body 816: size 16, 12-byte payload).
4. **`TrustedPresentationListener`**: correction of W8. The listener binder is **null**; the
   zero word after it is libbinder's 4-byte null-binder stability record. `acos-binder-peer`
   strips stability records only for table-listed objects, so it marks the imported parcel
   `wire_null_stability` and `read_strong_binder` consumes the record. Reading an extra `int32`
   (the W8 plan) put `displayCount`/`applyToken` 4 bytes late — that was the actual tail failure
   of the 700-byte transactions, not a missing field.
5. **fd transport**: an imported transaction names a received descriptor in its
   `BINDER_TYPE_FD` object but the peer's `Parcel` has no fd table (`unmarshall`). C1 now
   re-opens `/proc/self/fd/<n>` (safe duplicate of the same memfd; the peer keeps a received
   frame's fds open while it handles the frame). Closed/garbage numbers stay a structured error.
6. **obsolete gate removed** (`window_session.rs`): the I2 hold on `IWindow.dispatchAppVisibility`
   existed because the first traversal blocked in `nativeLockCanvas`. It no longer blocks, so
   visibility is delivered even with an injection plan; input and frames now coexist (W9's tap
   run drew the counter at `1`). The I2 input code itself is untouched.

## 6. Residuals and the next wall

1. **Next wall (precise)**: BLAST issues `setTransactionState` for only 4 of the 6 queued
   frames (BufferData `frameNumber` 1,2,3,6). The producer never blocks, so this is not the W7
   wall; it is BLAST's own acquire/coalesce path (`BLASTBufferQueue::acquireNextBufferLocked`
   dropping/merging queued frames) and it is why the literal "5 C1-accepted frames" clause is
   not met. Smallest next action: repeat the frame run with **two** real gestures (needs the
   injector to accept more than one gesture per launch — `input_dispatch.rs`, not in this
   packet) and/or one gdb breakpoint at `acquireNextBufferLocked` to log why frames 4/5 never
   become transactions.
2. **`read_sized_blob`** (WindowInfo's `InputApplicationInfo`) still assumes a body-only size
   word. No capture in hand contains a non-empty WindowInfo, so it is untested against the
   image; by analogy with `FrameTimelineInfo`/`TrustedPresentationThresholds` it probably also
   counts itself. Do not change it without a capture.
3. **fd transport**: the `/proc/self/fd/<n>` reopen is safe (`#![forbid(unsafe_code)]`) and
   works for memfd, but the clean fix is for `import_parcel_raw` to build an fd table for the
   imported parcel (`acos-parcel`/`acos-binder-peer`, outside this packet).
4. The tap run uses `ACOS_INPUT_TAP`; the packet asked for the frame run without it, and that run
   is reported separately (3 frames, idle). The interactive run is labelled as such.
5. No commit; `git status` at end contains only this packet's paths plus pre-existing edits by
   other agents (`results/…`, `research/…`, `out/`), recorded by `tools/own-check.sh`.
