## 1. Flake 1 — `allocator_bomb_is_oom_killed_inside_the_scope_and_the_host_is_untouched`

### 1.1 Root cause (measured, not inferred)

The hypothesis in the packet ("`memory.events` is read before the kernel publishes
`oom_kill`, or the scope is torn down first") is the second one, and it is not a
narrow window — the counter is **deleted with the cgroup**:

```
$ systemd-run --user --scope -p MemoryMax=134217728 … -- sh bomb.sh
rep=1 exit=-9 oom_kill read while alive: 1   cgroup after exit: GONE (ENOENT)
rep=2 exit=-9 oom_kill read while alive: 0   cgroup after exit: GONE (ENOENT)   <- lost
rep=3 exit=-9 oom_kill read while alive: 1   cgroup after exit: GONE (ENOENT)
```
(`results/art-runtime/evidence/W53/W53-cgroup-teardown.txt`.)

* `systemd-run --user --scope` is a **transient** unit: when the payload exits, systemd
  stops the unit and removes `…/app.slice/run-p<i>-i<j>.scope`, taking `memory.events`
  and `memory.peak` with it. After the child is reaped, `cg.sample()` reads ENOENT.
* `memory.events.local` is the same file in the same directory — no help.
* A **bounded poll after the child is reaped cannot help either**: the object being
  polled does not exist. The event is only visible in the microseconds between the
  kernel's publish and the cgroup's removal, which is why the failure is load-sensitive
  (more scheduler delay = more chances to miss the window).
* 20 probes with the *old* sampler semantics (2 ms `try_wait`/`sample` loop, break on
  exit) under 4 niced spinners: **8/20 and 3/20 missed the counter** (11/40 = 27.5 %);
  the same probe with an in-scope reader: **0/15 missed**.

### 1.2 The fix

`crates/acos-art/tests/sandbox_s5.rs` now runs the bomb behind a test-owned observer
script that **is** the scope's payload (`write_bomb_observer`):

1. `trap '' TERM INT HUP` — systemd's stop path SIGTERMs whatever is left in the cgroup
   as soon as it sees the kernel's OOM; the bomb itself is killed by the kernel with
   **SIGKILL**, so ignoring TERM changes nothing about the OOM being measured;
2. records `/proc/self/cgroup` (the product's `RunCgroup::confirm` contract), runs the
   bomb, `wait`s for it;
3. copies `memory.events` + `memory.peak` to `<info>.final.tmp` and renames it — the
   counters are read while the scope provably still exists, and the file outlives it;
4. exits with the bomb's status.

The test then asserts on `parse_snapshot(<info>.final)`: `oom_kill >= 1`,
`memory.peak <= 1.5 × memory.max`, `!status.success()`, host `MemAvailable` moved
< 512 MiB, and `cgroup.procs` empty. The live sampler is still exercised (`cg.sample()`
in the loop, `cg.peak_bytes() > 0` reported in the failure message) but is no longer
what the determinism of the assertion rests on.

Teeth: `snapshot_parser_reads_only_real_counters` (garbage/absent ⇒ `(0, 0)`), and
`scope_observer_is_the_payload_and_propagates_the_exit_status` (the observer is the
payload, a clean run records `oom_kill 0` and a real peak, the payload's exit code is
propagated unchanged).

The **same construction is now in `tests/sandbox_s6.rs`** (`write_scope_observer` wraps
the guest command in `spawn_probe`, `ProbeRun.events` carries the latched
`(oom_kill, memory.peak)`), so `memory_bomb_in_the_guest_is_oom_killed_at_the_cap` no
longer depends on the racy sampler either: it failed in one parallel run with
`peak 128 MiB, oom_kills 0` before the change and is **10/10** after it (snapshot
`oom_kills=1`). All five `sandbox_s6` tests stay green, including the escape corpus and
the fork-bomb bound (one extra `sh` in the scope does not affect `pids.max`).

### 1.4 Residual (product-side, deliberately not shipped in this window)

The *product* still samples `memory.events` from outside the scope, so a fast
OOM-killed run can report `oom_kills 0` and be classified as a plain guest exit
instead of `HOST_MEMORY_LIMIT` (`launch.rs:975`, `launcher.rs:419`, `app.rs:482`,
`session.rs:876` all branch on `cgroup.oom_kills() > 0`). I built and measured the
product fix, then **reverted it** — see §2.4. A second test of the same class is now
known to flake for the same reason:
`sandbox_s6::memory_bomb_in_the_guest_is_oom_killed_at_the_cap` failed in one parallel
run with `peak 128 MiB, oom_kills 0` (`evidence/W53/W53-flake2-parallel.txt`, run 3).

Smallest correct product fix (not done here, needs ~1 h and a launcher review):
add an `acos-art` **supervisor subcommand** that is spawned as the scope payload; it
sets `prctl(PR_SET_PDEATHSIG, SIGKILL)` (so the S3 `--die-with-parent` chain still dies
with the launcher), `waitpid`s the sandbox, writes the final counters next to the
cgroup info file, and propagates the exit status. Scope gets `KillMode=process` so
systemd's stop path cannot kill the supervisor mid-write. Both halves are measured:
`KillMode=process` alone takes snapshot survival from 9/15 to **15/15**
(`evidence/W53/W53-teardown-race.txt`).

## 2. Flake 2 — `w37_build_cache` in parallel

### 2.1 Root cause

`build_cache::cache_root()` reads the **process-global** `ACOS_ART_BUILD_CACHE`
(`src/build_cache.rs:53`). The test binary's five tests ran in parallel threads and
each rewrote it (`use_cache(&dir.join("cache"))`, and the "disabled" test
`set_var("…", "off")` + `remove_var`). Consequences, all observed as one HIT/one MISS
too many: a test could build into another test's root (a HIT it did not create — the
W48 log shows exactly that: "a HIT observed by the 'cache disabled' test"), and the
"disabled" test could be re-enabled mid-run by a sibling, publishing into a live root.
The default shared root `.cache/art/build-cache` was also reachable from any test that
did not set the env at all.

### 2.2 Fix

`tests/w37_build_cache.rs`: `static CACHE_ENV: Mutex<()>` + `isolate(tag)` which takes
the lock, creates a **per-test** root under `.cache/w37-tests/<pid>-<tag>/cache`, sets
the env to it and returns `(guard, dir, root)`. The guard lives for the whole test, so
the env cannot change under a test; the cached root is asserted
(`assert_eq!(build_cache::cache_root(), root)`) and `staged_from` is checked against
*that* root instead of re-reading the global. The "disabled" test takes the same lock
and pins `off` for its body. `tests/w39_stage_cache.rs` had the identical latent race
(same `use_cache` helper) and got the same treatment.

Test roots: `.cache/w37-tests/*`, `.cache/w39-tests/*` (never `/tmp`).

Runs that failed in the same window are all attributed, not retried away:

1. `cleanup.rs` compares a **host-wide** snapshot of ART-looking processes
   (`new_procs(before)`) and so reports *any* concurrent agent's `acos-art`/`bwrap`
   as a leak. On a shared host with W52's benchmark and another suite running, the
   two leak tests cannot pass — that is what B2/B3 show (the pids named are foreign
   runs, with their own `--out .cache/w30-suite/…` / `.cache/w52-suite/…` /
   `.cache/w50-target-wt/…` paths). The three green runs above are the same code in a
   window where no other agent had an ART job in flight; the acceptance is therefore
   "green for this worktree", and the host-wide scan remains the blocker for a
   continuously-shared host.
2. `sandbox_s6`'s bomb test was flake 1's class (A3); fixed in this window the same way
   (§1.2) and green 10/10 afterwards.
3. A2's failure was my own `cargo build -p acos-art` command line matching the old scan.

Fix applied (small, in my ownership): the scan now matches the process **name**
(`comm`), not "any cmdline that mentions acos-art", which removes the compiler/bash
false positives; the remaining host-wide scope (`new_procs`) needs the run root /
`--data` dir of *this* test to be matched, which I did **not** do (`cleanup.rs` is a
safety suite; changing its predicate needs its own review). Recommended exact change
for the owner: pass the test's own data/run root into `scan_procs` and require
`cmd.contains(&run_root)` for the launcher and its bwrap, or scope the scan to the
descendants of the test's own child pid.

### 2.4 Why no product change (the supervisor I built and reverted)

I implemented the in-scope supervisor in `src/cgroup.rs` (`SCOPE_SHELL` without `exec`,
`memory.events` snapshot, `KillMode=process`, a parser + 3 unit tests) and measured it:
bomb snapshot survival **15/15**, OOM counter read after teardown, S5 6/6. It also
passed a 20-variant T02/T12 suite run. **It was reverted** because it breaks a
host-safety guarantee that already has a test:

`sandbox_s5` → `crates/acos-art/tests/cleanup.rs:452`
`sigkill_of_the_launcher_takes_the_guest_and_bwrap_with_it` failed with the guest and
bwrap alive 3 s after the launcher was SIGKILLed: the supervisor (`sh`) sat between
`systemd-run` and `bwrap`, so `bwrap --die-with-parent` watched the shell, not the
launcher's death. `KillMode=process` additionally stops systemd from SIGTERMing the
rest of the scope on a stop. Both must be re-armed together (the supervisor must carry
`PR_SET_PDEATHSIG`), which is the subcommand design in §1.4 — not a shell. Evidence:
`evidence/W53/W53-supervisor-reverted.txt`. `src/cgroup.rs` is restored to HEAD
(`git diff --stat crates/acos-art/src` is empty).

| `suite-final.json` (`suite-final.log`) | 5 | 20 | never started: queued behind a 15-round run, which itself sat behind **W52's N=10 × 3-round gate run** on the host-wide ART lock. Killed at the hard stop so W52 keeps the lock; **not counted**. |

So the W45 flakes (2 events in 44 variants, loadavg ~4) did **not** reproduce in 20
live variants at loadavg 7–12. They are rare; the honest statement is *not
reproduced*, and the analysis below is code-level with the exact messages W45 captured.

### 3.2 Code-level root cause of the two messages

**(a) T12-wrong, `cannot write to acos-art: Broken pipe` at `assert_log`.**
`engine/art.rs:800-816`: the write path maps *every* non-ENOSPC `writeln!`/`flush`
error to `ErrorCode::Internal`. A broken pipe means the `acos-art` child is already
gone: there is nothing to assert, and the *cause* — which the launcher writes into
`session-exit.json` (W43) — is never read. So a guest/host death is reported as
`INTERNAL` even when the evidence file exists.

**(b) T02-wrong, `session exited` at `tap`.** `read_line` → `Disconnected` →
`session_lost` → `failure::classify_session_exit`; that returns `None` when there is no
`session-exit.json` (the launcher was SIGKILLed/SIGTERMed before it could write one, or
the record write itself failed), and `session_lost` then falls back to `Internal`. The
engine still holds the `Child` handle, so the child's own exit status (signal / code)
is available and unused.

Neither is a guest-behaviour bug in `crates/acos-art`; both are classification defects
in `crates/acos-cli` (W50 owns `engine/**`, W51 `trust.rs`/`verify.rs`), so per the
packet they are delivered as a patch, not an edit. The T12-wrong *scenario* itself
needs no change: `dialog_ok` can never be emitted, so the only correct outcomes are
`ASSERTION_FAILED` and, if the session dies under load, a host/guest code — never
`INTERNAL`.

### 3.3 The patch (exact; apply to `crates/acos-cli`)

`crates/acos-cli/src/failure.rs` — add next to `classify_session_exit`:

```rust
/// Classify a lost session from the harness child's own exit status, for the
/// case where the launcher was killed before it could write
/// `session-exit.json` (W53). Same evidence model as
/// `classify_facts_by_process`: the terminating signal / exit code is the
/// process evidence. A launcher killed by a signal is a host/harness event,
/// never `INTERNAL`.
pub fn classify_child_exit(status: std::process::ExitStatus) -> Option<(ErrorCode, Value)> {
    use std::os::unix::process::ExitStatusExt;
    let facts = serde_json::json!({
        "source": "acos-art child exit status (no session-exit.json)",
        "guest_exit": status.code(),
        "guest_signal": status.signal(),
    });
    if status.signal().is_some() || status.code().is_some() {
        // `GuestExited` is documented to carry "the guest exit code,
        // terminating signal and stage; inspect them to separate an app crash
        // from a host condition" — exactly this case. A dedicated
        // `HOST_SIGNAL` protocol code (W43 §6 request) is the better long-term
        // home and should replace it when acos-protocol gains one.
        return Some((ErrorCode::GuestExited, facts));
    }
    None
}
```

`crates/acos-cli/src/engine/art.rs` — `command_raw` (replaces the current
`if let Err(error) = writeln!(…).and_then(|_| stdin.flush()) { … }` block; the write is
moved into a value so the `&mut self` borrow ends before classification):

```rust
        let write_result = {
            let stdin = self.stdin.as_mut().ok_or_else(|| {
                acos_protocol::ProtocolError::new(
                    ErrorCode::Internal,
                    "the ART session stdin is closed",
                )
                .with_hint(
                    "The session was already shut down (close/shutdown/drop). Do not send \
                     commands to a closed session; start a new one.",
                )
            })?;
            writeln!(stdin, "{line}").and_then(|_| stdin.flush())
        };
        if let Err(error) = write_result {
            if crate::failure::is_disk_full(&error) {
                return Err(acos_protocol::ProtocolError::new(
                    ErrorCode::HostDiskFull,
                    format!("cannot write to acos-art: {error}"),
                ));
            }
            // EPIPE/ENOTCONN: the session is already gone. Classify it exactly
            // like a disconnected read (W53) instead of reporting INTERNAL.
            self.stdin = None;
            let detail = format!("cannot write to acos-art: {error}");
            return Err(self.session_lost_mut("command", &detail).to_protocol_error());
        }
```

`engine/art.rs` — replace `session_lost(&self, …)` with the `&mut self` version (the
only two call sites are `read_line`, which already has `&mut self`, and the write path
above):

```rust
    /// The art child's exit status, if it has already exited (never blocks).
    fn child_exit_status(&mut self) -> Option<std::process::ExitStatus> {
        self.child.as_mut().and_then(|c| match c.try_wait() {
            Ok(Some(status)) => Some(status),
            _ => None,
        })
    }

    /// A lost session is classified from its own exit record when there is one
    /// (W46) and, when the launcher died before writing it, from the child's
    /// exit status (W53): a SIGKILLed/SIGTERMed launcher must never surface as
    /// `INTERNAL`.
    fn session_lost_mut(&mut self, context: &str, detail: &str) -> BackendError {
        if let Some((code, facts)) = crate::failure::classify_session_exit(&self.artifacts) {
            return BackendError::Protocol {
                code,
                detail: format!(
                    "{context}: {detail} (classified from {}); stderr tail: {}",
                    crate::failure::session_exit_path(&self.artifacts).display(),
                    self.stderr_tail()
                ),
                hint: None,
                details: Some(serde_json::json!({"session_exit": facts})),
            };
        }
        if let Some((code, facts)) = self
            .child_exit_status()
            .and_then(crate::failure::classify_child_exit)
        {
            return BackendError::Protocol {
                code,
                detail: format!(
                    "{context}: {detail} (no {}; acos-art child exit classified instead); \
                     stderr tail: {}",
                    crate::failure::session_exit_path(&self.artifacts).display(),
                    self.stderr_tail()
                ),
                hint: Some(
                    "The launcher died before it could write session-exit.json. The signal/exit \
                     code in details.session_exit is the evidence; check the host kill paths \
                     (memcg OOM, RSS watchdog, guarded.sh wall clock)."
                        .to_string(),
                ),
                details: Some(serde_json::json!({"session_exit": facts})),
            };
        }
        BackendError::Error {
            code: acos_protocol::ErrorCode::Internal,
            detail: format!("{context}: {detail}; stderr tail: {}", self.stderr_tail()),
        }
    }
```

Acceptance for the owner: `cargo test -p acos-cli`, plus

report `GUEST_EXITED` (with `details.session_exit.guest_signal`) or the code from

## 5. Findings for other owners

1. **`systemd-run` rewrites `$$` in its argv** (`$$` → `$`): `wrap()` must not be given
   arguments containing `$$` (a payload's own shell text does not survive). Harmless
   today; it broke a test that used `sh -c 'kill -9 $$'`.
2. **`cleanup.rs`'s leak scan is host-wide and therefore unusable while another agent
   runs ART** (§2.3): it matched a concurrent `cargo build -p acos-art` (pid 126114) and
   then other agents' live launches (`acos-art launch --out .cache/w30-suite/…`,
   `--data …/art-locks/data-W53-r2-…`). Narrowed to `comm` in this window (builds can no
   longer trip it); the remaining fix is to scope the scan to *this* test's own run root
   or child pid. Until then, `cargo test -p acos-art` cannot be 3× green on a shared
   host, independently of w37.
3. **`sandbox_s6::memory_bomb_in_the_guest_is_oom_killed_at_the_cap` had flake 1's
   root cause** (evidence in §2.3 A3) — fixed with the same in-scope observer (§1.2).
4. **`crates/acos-services/src/surface_client.rs` did not compile** for ~2 minutes in
   this window (`no field 'width' on BufferData`, `Option<u64>: Display` at lines
   1657/1670), which turned one of my 20 bomb reps into a build error. Not mine; the
   release binaries above are from the last compiling tree.
