# S2 — Empirical sandbox probe of the ART bwrap argv

Status: **experimenter, hard checkpoint 45 min, nothing committed.** Scope: only
`research/art-feasibility/s2-sandbox-probe/` and this file. `crates/` was not edited (R1 owns
`crates/acos-art`). Every command ran through `tools/guarded.sh` (`--mem 2G --time 120`, except the
ART runs at `--mem 4G`); scratch under `.cache/`; no sudo; no host file outside the repo was read
(`stat`/`readlink` only, as instructed).

Settles the open questions listed in `results/art-runtime/S1-sandbox-review.md` §6, and the `(verify)`
marks in its §1–§3 and §5 #1, #8.

## Method

The probe does **not** re-implement the argv. It captures the argv `acos-art` actually builds and
replays it:

- `argv-real.txt` — the `bwrap …` command line printed by `ACOS_ART_DEBUG_ARGV=1` from a real
  `01_hello` run of the committed `target/release/acos-art` (i.e. exactly `Sandbox::command`,
  `crates/acos-art/src/lib.rs:657-773`: 182 argv elements).
- `gen.sh` → `bwrap-shape.sh` (that argv as a bash array + `guarded.sh`, with `$S2_EXTRA` injected
  right after `bwrap` and the guest program replaceable after `--`), plus `bwrap-raw.sh` (same argv
  without the `guarded.sh` wrapper, only for P6 where the wrapper's process-group cleanup would mask
  the answer).
- `probes.sh <p1|p2|p3|p4|p5>`, `p6-orphan.sh`, `p6b-pdeathsig.sh`, `p7-corpus.sh`; raw output in
  `logs/` (`p1`–`p7`, `p6b`, `p7-corpus`).

Guest program = `/system/bin/sh` (toybox from the sysroot, no shim) so the probes run *inside* the
real mount view. Host bwrap: **bubblewrap 0.13.1**.

"`plain`" = the argv as `acos-art` builds it today. "`hard`" = today's argv plus S1's proposed set:

```
--unshare-pid --unshare-net --unshare-ipc --unshare-uts --unshare-cgroup-try
--die-with-parent --clearenv --cap-drop ALL
```

## What S1 got right, and the three things it got wrong

**Right:** no seccomp filter; netns/IPC/UTS/cgroup shared; env inherited in full; `/proc` = host pidns;
no die-with-parent; whole `/data` rw; guest survives launcher death.

**Wrong 1 — `/proc/<pid>/root` is not an escape.** S1 §3 called it a "probable host-root escape" on the
theory that Yama `ptrace_scope=1` only gates `PTRACE_MODE_ATTACH`. In practice
`stat -L /proc/<same-uid-pid>/root` returns **EACCES** even with today's argv, because the reader is in
a child user namespace and `ptrace_may_access` requires `CAP_SYS_PTRACE` *in the target's* userns
(`ns_capable(tcred->user_ns, CAP_SYS_PTRACE)`), which bwrap's unprivileged userns can never hold. Same
for `/proc/<pid>/cwd` and `/proc/<pid>/fd`. What *does* work is the cheap half: `stat` of
`/proc/<pid>/cmdline` and `/proc/<pid>/environ` succeeds with size 0, and the pid list is fully
readable. So item #1 of S1 §5 is still required (a same-uid host **pid list** and **signal** channel is
bad enough), but "bypass the tmpfs root" is not one of the reasons. This lowers the severity of the
current route and should be reflected in the doc.

**Wrong 2 — `NoNewPrivs` and capabilities are already handled.** `NoNewPrivs: 1` and all five
capability sets zero, with today's argv and no flags. bwrap sets `no_new_privs` itself and its implicit
unprivileged userns zeroes `CapInh/Prm/Eff/Bnd/Amb`. S1's #8 ("set `NO_NEW_PRIVS` in `pre_exec`") is
therefore a no-op for the security posture, and `--cap-drop ALL` is redundant. Keep #8 only as
belt-and-braces; it costs nothing.

**Wrong 3 — `PR_SET_PDEATHSIG` does not survive into bwrap.** S1 §2 assumed the launcher's
`pre_exec` PDEATHSIG reaches bwrap and from there the guest. Measured (`logs/p6b.log`): the mechanism
works in the abstract (prctl → exec `/bin/sleep`, kill the parent → child **DIED**), but with bwrap in
the chain the bwrap supervisor **survived** its parent's SIGKILL and the guest kept running
(`logs/p6.log`, trial `plain kill=B`). The likely cause is bwrap's own credential changes
(`setresuid`/`setgroups` while building the userns), which clear PDEATHSIG. Consequence: today
`acos-art` has **no** orphan protection at all — neither the PDEATHSIG it sets nor anything else — which
is a better candidate for the 36 GB runaway than anything in S1 §4. `--die-with-parent` is the only
mechanism that actually works (trial `hard kill=B`: both die).

## Caveats

- Abstract-socket *connect* could not be measured positively: the sysroot toybox `nc -U '@/…'` failed in
  both modes, i.e. the negative is the tool, not the kernel. Evidence used instead is decisive —
  `@s2-abstract-canary` is listed in the host's `/proc/net/unix` (34 abstract entries) in `plain` and
  **absent** (0 entries) in `hard`, and an abstract socket lives in the netns, so `--unshare-net`
  removes reachability.
- P5 wrote into the shared `.cache/art/data` (`/data` is bound from there). The probe appended one line
  to `acos.properties` and `linkerconfig/ld.config.txt`; both were restored to their original line
  counts (52 / 456) and re-verified (`grep -c pwned` = 0). Canary and staging files were removed; no
  probe process is left running. P5's later re-run uses `test -w` instead of writing.
- P7b passes the DEX as `/data/s2probe/<name>.dex` instead of `/data/task/00_classes.dex`, because the
  argv binds one fixed per-run DEX. Same mount, same flags, same `dalvikvm64` invocation.
- `--unshare-cgroup-try` is a *try*: on this host it did not fail, and `NSpid` shows the pidns is
  active; the guest's `/proc/self/cgroup` was not re-read under `hard` (no time before the checkpoint).
- Only bwrap 0.13.1 was tested. The `--size`-on-tmpfs question from S1 §6 and `--disable-userns` /
  `--new-session` were out of scope for the requested question set.

## Exact flags that are safe to adopt

Adopt verbatim, inserted immediately after `bwrap` in `Sandbox::command` (`lib.rs:657`), **before**
`--tmpfs /`, so the namespace is created before any mount is set up:

```
--unshare-pid --unshare-net --unshare-ipc --unshare-uts --unshare-cgroup-try
--die-with-parent --clearenv --cap-drop ALL
```

Evidence for safety: entry 7 above — 01_hello byte-identical stdout/exit/stderr-log-count, and the
whole 27-program corpus 27/27 in both modes (54/54 runs, `logs/p7-corpus.log`). `--clearenv` is safe
because every variable ART needs is already an explicit `--setenv` (`lib.rs:742-747` + the
`BOOTCLASSPATH`/`DEX2OATBOOTCLASSPATH` derivation); `--unshare-net` is safe because both guest↔host
transports are *path* sockets (`/dev/socket/logdw`, `/data/acos-launch.sock`), which are unaffected —
the shim→logd path still produced the same 5 `[art]` lines.

Per-flag necessity (measured, not assumed):

| flag | needed? | what it buys |
|---|---|---|
| `--unshare-pid` | **required** | host pid list + `kill` reachability gone (2a, 2g). Requires `--proc /proc` *after* it — already the case. |
| `--unshare-net` | **required** | loopback/LAN/internet and every abstract socket gone (3a–3c): `DISPLAY`, `WAYLAND_DISPLAY`, D-Bus abstract buses. Path-based sockets are *not* affected (verified: the shim→`/dev/socket/logdw` path still produced the same 5 `[art]` lines), so nothing in ART notices. |
| `--unshare-ipc` | cheap, keep | SysV shm/sem/msg are otherwise host-wide writable. Not separately probed. |
| `--unshare-uts` | cheap, keep | host hostname/syslog identity. |
| `--unshare-cgroup-try` | cheap, keep | hides host cgroup layout; `-try` means no failure if the kernel lacks it. |
| `--die-with-parent` | **required** | the *only* thing that kills the guest when the launcher dies (6a/6b); `PR_SET_PDEATHSIG` is neutralised by bwrap. |
| `--clearenv` | **required** | ~125 host var names → 13 (4). |
| `--cap-drop ALL` | **redundant, harmless** | caps are already all-zero; keep for defence in depth / older bwrap. |

Deliberately **not** in the adopt list, despite S1 §5 #1:

- `--unshare-user` — bwrap already creates an unprivileged userns implicitly (this is *why* 2b/2e are
  already denied); asking explicitly changes nothing measured here.
- `--disable-userns` — untested (no nested-userns probe before the checkpoint). Do not adopt blind:
  if `unshare(CLONE_NEWUSER)` is denied, anything in the guest that spawns a userns (a Java runtime
  doing so, or a future seccomp-guard) fails closed with an unexpected errno. Needs its own probe.
- `--new-session` — untested; it only changes `setsid`/TIOCSTI exposure, orthogonal to 2–6.
- `PR_SET_NO_NEW_PRIVS` in `pre_exec` (S1 #8) — already 1; harmless to add, fixes nothing.

**What these flags do *not* fix — still open, and now empirically demonstrated (item 5):** the guest
can create, overwrite and truncate any file under `/data`, `/linkerconfig` and `/dev/socket`, in both
modes, and the change persists on the host (`boot.art` canary sha256 changed). Namespaces cannot fix a
rw bind. S1 §5 #2 (per-run `/data` tree: only `task/`, `app/`, `out/`, `session/<id>/`, socket dir rw;
`img/`, `linkerconfig/`, `system/environ/`, `shim/` ro or regenerated per run) is **the** remaining
blocker after this flag set, and it is a `lib.rs` bind change, not a bwrap flag. S1 §5 #3–#6 (cgroup
memory cap, host buffer caps, seccomp, Landlock) are likewise untouched by these flags — in particular
nothing here stops a memory runaway: only the cgroup does, and only if it is mandatory.
