## 4. Framework/native gaps found and their disposition

### 4.1 FIXED — per-package data directories were never created (`resources`)

**Symptom** (all three apps, every launch):

```
W ContextImpl: Failed to ensure /data/user_de/0/<pkg>/code_cache: mkdir failed: ENOENT (No such file or directory)
W ContextImpl: Failed to update user.inode_code_cache: stat failed: ENOENT (No such file or directory)
W ContextImpl: Failed to ensure /data/user_de/0/<pkg>/cache: mkdir failed: ENOENT (No such file or directory)
W ContextImpl: Failed to update user.inode_cache: stat failed: ENOENT (No such file or directory)
```

`apk_loader::stage` created only `/data/user/0/<pkg>` (to place `base.apk`) and
the VFS made `data/user/0` and `data/user_de/0`. Android's `installd` creates the
per-package `files`/`cache`/`code_cache`/`no_backup` trees at install time and
`ContextImpl.ensurePrivateDirExists` only calls `mkdir` (not `mkdir -p`), so the
device-protected tree failed and any `getCacheDir()`/`getCodeCacheDir()` use
would have no directory.

**Fix:** `crates/acos-runtime/src/apk_loader.rs` — new
`ensure_app_data_dirs(root, guest_dirs)` creates
`/data/user/0/<pkg>/{files,cache,code_cache,no_backup}` and
`/data/user_de/0/<pkg>/{…}` before `bindApplication`. Unit tests
`app_data_dirs_are_created_for_both_storage_trees` and
`app_data_dirs_ignore_paths_outside_data`.

**Verified:** the four `ContextImpl` lines are gone from every app's `acos logs`
after the fix; existing `hello-views`/`form-validation`/`counter` still reach
`first_frame`.

### 4.2 FIXED (partial) — raw style values exposed the attribute id as a resource (`resources`)

Found with a scratch auto-show probe (dialogs shown from a `post`, since taps do
not land). `DatePickerDialog` failed to inflate:

```
android.view.InflateException: Binary XML file line #18 in android:layout/date_picker_dialog:
  … Error inflating class android.widget.DatePicker
  caused by android.view.InflateException: Binary XML file line #23 in android:layout/date_picker_material:
    Binary XML file line #35 in android:layout/date_picker_header_material: Error inflating class <unknown>
    caused by android.content.res.Resources$NotFoundException:
      Resource ID #0x1010509 type #0x1 is not valid
```

`0x01010509` is `attr/pointerIcon`; `date_picker_header_material.xml` sets
`android:pointerIcon="1002"` on a `TextView`. Android 14's
`TypedArray.getResourceId` reads `STYLE_RESOURCE_ID` verbatim, and
`null_or_raw_typed_value` stored the **attribute id** in that slot for every
non-reference value, so the framework treated `attr/pointerIcon` itself as a
`@resid` and called `Resources.loadDrawable` on it. `STYLE_SOURCE_RESOURCE_ID`
(7th slot) already carries the attribute id.

**Fix:** `crates/acos-framework-natives/src/res/theme.rs` — `resource_id` is `0`
for raw values, the reference target for `@resid`/`?attr`. Tests
`raw_style_value_carries_no_resource_id`,
`reference_style_value_targets_its_resource`.

**Ladder after the two fixes** (probe, `probe_err` chain):

```
Resources$NotFoundException (attr/pointerIcon)   -> FIXED
java.lang.NullPointerException                    -> OPEN
  android.content.res.TypedArray.getString(Unknown Source:271)
  android.widget.TextView.readTextAppearance(Unknown Source:4288)
  android.widget.TextView.<init>(Unknown Source:1211)
  … LayoutInflater.createView(Unknown Source:866)
```

The `pointerIcon` `NotFoundException` no longer occurs; the next barrier is a
`TypedArray.getString` NPE inside the real `TextView.readTextAppearance`
(a `TYPE_STRING` entry whose pooled string does not resolve returns `null`,
then `.toString()` throws). This is a **distinct, open** resource-engine gap;
owner `acos-framework-natives/res`. Recorded, not fixed here (depth not known in
this wave). The probe app was scratch and has been deleted; the captured log is
`results/app-matrix/datepicker-probe-logs.json`.
