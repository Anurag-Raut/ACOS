## 1. Code changes

### 1.1 Split tap delivery: DOWN + pump + UP

`crates/acos-services/src/input.rs`, `crates/acos-runtime/src/input_java.rs`,
`crates/acos-runtime/src/session.rs`

A real tap delivers DOWN and UP in **separate** `InputEventReceiver` drains, so a
widget's posted tap/long-press scheduling runs between them. The old
`inject_tap` wrote DOWN+UP into the channel before the looper was pumped, so
`AbsListView` never posted its `PerformClick` `Runnable`. New
`InputDispatcher::inject_tap_down`/`inject_tap_up` (the DOWN pins its target so a
relayout cannot reroute the UP), and `session::do_split_tap` pumps the looper
between the halves. The tap path (`tap --text/--id/x y`) now uses `do_split_tap`.

This is a faithful-delivery fix, **not** the fix for scenario 1: the row tap
still never reaches the ListView (the DOWN reaches the Activity but not the
list; see §0). It did not regress the alert/Cancel/PopupMenu/Spinner flows, all
of which are covered by the tests below.

### 1.2 `acos scroll`

`crates/acos-cli/src/main.rs`, `crates/acos-cli/src/session.rs`

New `acos scroll <x> <y1> <y2>` — a vertical MotionEvent sequence
(DOWN, interpolated MOVEs, UP) with `--duration-ms`/`--steps`, a `--json`
envelope and `state_changed`. It forwards to the existing `acos_swipe` daemon
path; `acos` previously had no scroll intent.

### 1.3 `swipe` actually pumps

`crates/acos-runtime/src/session.rs`

`Cmd::Swipe` reported `accepted:true` but never called `Runtime::pump`, so a
swipe's events sat unprocessed in the channel and `state_changed` was always
`false`. It now takes a pre-gesture tree summary, pumps, and reports the real
`state_changed`, like tap/key.

### 1.4 Integration test

`crates/acos-runtime/tests/app_matrix_interaction.rs` (new) — 5 active tests
(§0 PASS rows) + 5 `#[ignore]`d gap tests (§0 OPEN rows). It reuses the
`counter_interaction.rs` launch/skip discipline and a bounded tap retry because
the first injected tap after launch is sometimes lost while the looper
re-enters; every assertion still requires a live-tree change.

## 5. Hand-off

1. **Scenario 1 (row tap)**: the DOWN reaches `Activity.dispatchTouchEvent` but
   the `ListView`'s `setOnTouchListener`/`onTouchEvent` is never called while a
   sibling `Button` in the same `LinearLayout` works. This isolates the bug to
   `ViewGroup.dispatchTouchEvent`'s child target selection for the
   `AbsListView`, not to input delivery. Probe patch + logs are described here;
   the probe was reverted.
2. **Popup select (4b) and Spinner select (6b)**: the popup window *renders and
   is in the tree* with correct geometry; taps inside it are not routed. The
   WMS popup-window input channel/frame is the next owner. This is likely the
   same class of bug as W179-A's re-opened-`AlertDialog` compact-frame residual.
3. **Toast (5)**: needs a structured surface — either a toast window in the
   view tree or a `toast`-tagged log record carrying the text. Today only the
   app's own `toast_shown` line exists.
4. `acos swipe` was silently non-pumping; fixed. Any wave that measured
   `state_changed` on a swipe before this should re-measure.
