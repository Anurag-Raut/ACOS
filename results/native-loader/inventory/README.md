Corpus-wide ELF facts that drive the loader work order:

* **No APS2 packed relocations, no RELR, no `textrel`** in this set: every
  library uses plain `DT_RELA` + `DT_JMPREL` (RELA). Packed/RELR support still
  matters for Play-Store (zipalign+`--pack-dyn-relocs=android`) builds and for
  the Flutter engine, so both stay implemented.
* **TLS**: `libreanimated.so` and `libworklets.so` are the only objects with
  `PT_TLS`; both use the **general dynamic** model (`TLS_DTPMOD64`), which the
  loader already supports via its per-module TLS blocks. **No `initial-exec`,
  no `TLSDESC`** anywhere in the corpus, so the pthread-key TLS design is not
  the blocker the earlier risk list feared.
* **Exception unwind**: 20 of 23 objects carry `PT_GNU_EH_FRAME` and import
  `dl_iterate_phdr`; the loader already reports guest program headers, and
  `libc++_shared.so` is present as a real dependency (`libreactnative`,
  `libhermesvm`, `libjsi`, `libfbjni` all `DT_NEEDED` it).
* **Init arrays**: up to 291 constructors (`libmlkit_google_ocr_pipeline.so`);
  ordering and SONAME de-duplication are therefore load-path critical.
* **`libc++_shared.so`** imports nothing that is now missing (157 imports).

### Interpretation

1. **`libandroid` (`AAsset_*`) and `libjnigraphics` (`AndroidBitmap_*`)** are
   the largest remaining real gaps (9 symbols, 3 libraries). Both need backing
   state that lives outside the loader crate: an APK asset registry and a
   bitmap store. Tracked as the next bionic work item; the loader reports them
   with `UNSUPPORTED_NATIVE_SYMBOL` naming the library instead of binding 0.
2. **`egl*`/`gl*`** (mlkit only) are a graphics-stack decision, not a loader
   gap — no honest stub exists.
3. **`__gcov_dump`/`__gcov_flush`** come from the profiling runtime
   (`libclang_rt.profile`); they are only reachable on process shutdown in
   instrumented builds.
4. **`_setjmp`/`_longjmp`** are deliberately *not* forwarded: bionic's
   `jmp_buf` is 64 B on x86_64 while glibc's is 200 B, so forwarding would
   corrupt the guest stack. Correct support needs a guest-side jmp_buf
   translation (structured error today).
5. **`__pthread_cleanup_push/pop`** are macros in glibc with no exported
   counterpart; a bionic-compatible implementation needs a guest cleanup stack
   in the shim crate.
6. The remaining `missing` entries are C++ internals expected from sibling
   objects that this APK does not ship (`MallocExtension_*`,
   `uprv_getICUData_*`, `absl::leak_check_internal`, `tflite::UseGemmlowpOnX86`,
   `x_cgo_init`, `stats_census_*`) — visible here because the inventory reports
   each library in isolation from its full runtime image.

## What changed in the loader as a result

| area | before | after |
|---|---|---|
| symbol versioning | `VERNEED` parsed, ignored for lookup | `VERDEF` + `VERSYM_HIDDEN` parsed; references bind only to the required version or to an unversioned default |
| APS2 packed relocations | single `RELATIVE` group only, multi-group rejected | all groups (`RELATIVE`, `SYMBOLIC`, custom) decoded |
| RELR | standard + `DT_ANDROID_RELR` | unchanged (already complete) |
| SONAME de-duplication | matched by file name only | file name **or** `DT_SONAME`; `dlopen` of an already-mapped object bumps the reference count instead of mapping a second copy |
| init ordering | `DT_INIT_ARRAY` deps-first | `DT_PREINIT_ARRAY` → `DT_INIT` → `DT_INIT_ARRAY`, dependencies first, once per object |
| `dladdr` | object base only | nearest exported symbol name + address (lazily built per-object table) |
| bionic surface | 475 entries | +67 entries (see below) |

## Still unsupported (honest list)

* `initial-exec` / `local-exec` TLS (`R_X86_64_TLS_TPOFF`, `R_X86_64_TLSDESC`)
  — impossible with the pthread-key TLS design; `UNSUPPORTED_RELOCATION`.
  Not used by this corpus (checked above).
* `R_X86_64_GOTPCREL`/`GOTOFF`/`PLT32` in shared objects → structured error.
* `dlsym(RTLD_NEXT)`, `dlerror` text, `android_dlopen_ext` flags other than
  fd/offset, `__system_property_find` (returns NULL).
* `setjmp`/`longjmp` (`jmp_buf` size differs), `__pthread_cleanup_push/pop`.
