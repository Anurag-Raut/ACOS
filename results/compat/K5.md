## 1. What is implemented (uncommitted)

1. **Guest uid = application uid, not `SYSTEM_UID`** (`crates/acos-art/src/lib.rs`).
   The guest ran as the host uid 1000, which is Android's `Process.SYSTEM_UID`.
   Runs now get `bwrap --unshare-user --uid 10192`
   (`acos_services::pms::FIXTURE_UID`), mapped 1:1 onto the caller for file
   access. This is the measured WebView wall: the API-34
   `WebViewFactory.getProvider` dex refuses uids 0/1000/1001/1027/1002 with
   "For security reasons, WebView is not allowed in privileged processes".
   `ACOS_ART_GUEST_UID=host` is the A/B seam.
2. **Software `AndroidKeyStore` provider**
   (`crates/acos-art/guest/java/dev/acos/art/SoftwareKeyStore.java`, installed
   from `LaunchMain.main` before app code, the way the zygote installs the real
   provider). Session-private storage under
   `/data/app-data/<pkg>/acos-keystore`; AES/HMAC `KeyGenerator`, RSA/EC
   `KeyPairGenerator`, alias persistence, `KeyStoreSpi`; rejects
   `setUserAuthenticationRequired(true)` and StrongBox instead of fabricating
   that protection; keys are ordinary software JCA objects (no hardware/KeyInfo
   claim). This removed the wall for element and dot.gallery.
3. **Two real services a device always publishes**
   (`crates/acos-services/src/extras.rs` + `registry.rs`):
   - `location` (`ILocationManager`, `geocoderIsPresent -> false`) — a null
     binder was `Objects.requireNonNull` NPE in `Geocoder.isPresent()`
     (dot.gallery).
   - `trust` (`ITrustManager`: not secure/not locked/no active unlock; report
     calls no-op) — `new KeyguardManager()` resolves `trust` with
     `getServiceOrThrow`, so its absence made `getSystemService(KeyguardManager)`
     null and element's biometric manager called `.getClass()` on null.
   - `restrictions` (`IRestrictionsManager`: empty application restrictions,
     no provider) — tailscale's `App.initializeApp` called `.getClass()` on the
     null `RestrictionsManager`.
4. **`PackageInfo.signatures` now carries the APK's real signing certificate**
   (`acos-apk/src/signing.rs`, `apk.rs`, `acos-services/pms.rs`,
   `parcelable.rs`). v3.1/v3/v2 APK Signing Block parsing (the
   `ApkSignatureSchemeV2/V3Verifier` layout), v1 PKCS#7 `META-INF/*.RSA`
   fallback, new `android.content.pm.Signature` parcelable spec (one
   `writeByteArray`), and `PackageInfo` encodes the array under the existing
   `signatures` typed-array slot. Verified offline: the extracted F-Droid cert
   for redreader is 832 bytes and `openssl x509 -inform der` parses it; the
   host PMS reply contains exactly those bytes (`count=1, presence=1,
   bytearray=832, DER`) — evidence in `.cache/k5/pmsreply.bin` and
   `.cache/k5/pmscalls.log`.

Temporary diagnostics used for the redreader investigation were removed again
(the tree was rebuilt clean); the only seam kept is `ACOS_ART_KEYSTORE=off`.

## 2. Unresolved: redreader DER decode

The host reply is byte-correct (valid 832-byte F-Droid X.509 DER, correct typed
array framing), yet the guest's framework still raises, in
`AndroidCommon.getPackageInfo`:

```
java.security.cert.CertificateException:
  com.android.org.conscrypt.OpenSSLX509CertificateFactory$ParsingException:
  ... error:0c00006d:ASN.1 encoding routines:OPENSSL_internal:DECODE_ERROR
```

The remaining hypotheses, none tested (no more experiments at the bound):

* the guest is decoding a **different** `PackageInfo` than the one whose reply
  was captured (e.g. an earlier/cached `getPackageInfo` path or a second class
  loader), or
* one of the `PackageInfo` fields *before* `signatures` is framed differently
  for a **non-ComponentInfo** `PackageInfo` reply, shifting the typed-array
  reader by one word in the framework only (the host writer byte dump looks
  right, but it was not replayed through the real Java
  `PackageInfo(Parcel)` constructor).

Smallest next action: feed the exact captured reply bytes
(`.cache/k5/pmsreply.bin`, minus the presence header) to the real
`PackageInfo.CREATOR.createFromParcel` in the existing
`acos-runtime/tests/parcelable_java.rs` harness with a non-empty
`signatures: vec![cert]`, and compare the re-emitted bytes + parsed certificate;
that decides "our framing" vs "guest got a different reply" in one test.
