**Tree:** `compat-k5-keystore` = `ed2ff4d`, the merge of `origin/main`
`d7dc8e2` (density / `<supports-screens>` fix) into the K5 chain. Base K4
funnel (`e1683c5`, last full corpus before K5): onCreate 21/42, first frame
16–17/42, tree 16/42, tap 9/42.

**Branch reattachment (2026-11-14).** The worktree was left detached at
`6d0fcf5` while `compat-k5-keystore` still pointed at the pre-amend checkpoint
`4918d26` (the checkpoint commit had been amended to `965f3fe`, and `b4acabf`,
`49e554c`, `6d0fcf5` were built on the amended commit), so a fast-forward was
impossible. The branch was reattached with a **merge** of `6d0fcf5` into
`4918d26` (`ed2ff4d`): no reset, no force, no commit dropped. The merge result
is byte-identical to `6d0fcf5` except
`results/aidl/{bench,coverage,subset_misses}.txt`, where the branch copy (the
newer AIDL numbers, `default_scan_ms=65.8`, `all_interfaces=1351`) was kept over
the amended copy. Everything below is measured on `ed2ff4d` with binaries built
from it (`.cache/k5-target/release`) and a reference binary built from
`d7dc8e2` (`.cache/k5-main-target/release`).

## What changed since the pre-merge checkpoint

1. **APK signing certificates (fix-first, done + tested).**
   - v1 block reads are capped: 1 MiB absolute, 200× deflate ratio, and a
     capped `read_to_end` because the zip size field is untrusted. Violations
     are `APK_SIGNING_MALFORMED`.
   - `PackageInfo.signatures` is **one leaf cert per signer**, not the first
     signer's chain; v2/v3/v3.1 iterate every signer.
   - Highest present scheme wins; a malformed higher scheme is an error, never
     a lower-scheme fallback. v1 is used only when no block scheme exists and
     the signer is found by `SignerInfo` issuer+serial.
   - `Apk::signing_certificates_error` records a rejection; PMS sees empty, not
     wrong.
   - `acos-apk` lib: **14/14** (incl. malicious oversized block, ratio and
     lying-reader caps, v3-over-v2, malformed-v3 no-downgrade, chain-vs-leaf,
     v1 sid selection).
   - RedReader's exact 832-byte F-Droid DER is decoded by the **real
     `PackageInfo.CREATOR`** in `acos-runtime/tests/parcelable_java.rs` (1/1)
     and re-emits identical bytes. The ART guest's
     `OPENSSL_internal:DECODE_ERROR` is **still unexplained**; the Rust framing
     is not the cause (hypothesis: different reply/truncation).
2. **App uid — measured** (`org.billthefarmer.editor`, real ART, 1450 ms):
   `guest_uid=10192`, `pms_uid=10192` (agreement), `uid_map=10192 0 1`,
   `Uid: 10192×4`, `Gid: 984×4`, `Groups: … 984 …`, `CapEff: 0`,
   `/data/app-data` writable and listing only the current package. Each session
   binds its own `/data/app-data`; a previous session's directory is absent.
   **Not host-level isolation:** gid/groups stay the host caller's (984) and the
   inner uid maps to host 1000. `ACOS_ART_GUEST_UID` accepts only `host`
   (explicit A/B) or 10192; anything else is `INVALID_GUEST_UID`.
3. **Services.** `trust` read paths remain; every setter/listener transaction
   now returns `UnsupportedOperationException`. `restrictions.requestPermission`
   is a **void** API-34 call (verified in the boot image), so the reply is only
   the exception header (the old null-`IntentSender` word is gone);
   `createLocalApprovalIntent` answers null. `location.geocoderIsPresent` code
   12 + `readBoolean` re-verified.
4. **Software keystore is opt-in** (`ACOS_ART_KEYSTORE=on`); default off, so
   element/dot.gallery keep the honest K4 `AndroidKeyStore not found` wall until
   **K5b** (Backlog) implements the advisor's fix list. Earlier targeted
   evidence with it on: element 1534 ms + tree, dot.gallery 2504 ms + tree.

## Gates (final tree `ed2ff4d`, real ART)

All 34 scenarios, one lock acquisition, `--engine art`. Artifacts:
`.cache/k5/final/gates/<scenario>/out.json` + `summary.tsv`; reference arm
`.cache/k5/final/gates-main/`.

- **24 pass**: 19 standard (`v2-art-counter`, `w22-counter-reset`,
  `w54-dialog-pixels`, `w42-back-frame`, `w15-dialog-menu`, `form-validation`,
  `T03-render-good`, `v1-offscreen-pager`, 11 `p11-*`) and all five Gaten flows.
- **9 fail with the expected code**: `T03-render-wrong`, five
  `negative/gaten-*-wrong`, `w7-insets-carve-negative` (ASSERTION_FAILED),
  `offscreen-pager-visible` (ELEMENT_OFFSCREEN), `p11-progress-timeout`
  (TIMEOUT).
- **1 unexpected failure: `w7-insets-report`** —
  `expected text exactly "status=128", got text "status=0"` at step 3
  (`assert_text`), rc=1.

**0 false passes** (no wrong twin passed).

**`w7-insets-report` is not a K5 regression.** The `d7dc8e2` reference binary
fails the *identical* assertion at the same step
(`.cache/k5/final/gates-main/w7-insets-report/out.json`). The K5 gate run on
`49e554c` passed this scenario, and the only main-side delta between `5cae694`
(that run's main base) and `d7dc8e2` is `0e569b5`/`00804dc` (the density /
`ApplicationInfo.flags` fix) plus the B4/S3c harness commits, so the density
change is the prime suspect and needs a revert arm on main's track. Side effect:
`w7-insets-carve-negative` still reports the expected `ASSERTION_FAILED`, but it
now fails at that same step-3 `status=128` assertion instead of the `carve`
assertion it was written for — its "expected failure" is satisfied for the wrong
reason and must be re-checked together with the fix.

The five Gaten flows now pass **without** an error code; `check_gates.py` still
expects K4's `TIMEOUT` code for them, so it prints 5 stale MISMATCH lines. (K4's
TIMEOUT disappeared with merged main, not with K5.)

**Fluffychat is unresolved but not attributable to K5.** 15 isolated runs on
the same binaries (5 interleaved per arm, 3 with `ACOS_ART_GUEST_UID=host`, 2
with the arm order reversed and only 2 apps) **all** abort identically in both
arms — Flutter `GeneratedPluginsRegister: Received exception while registering
java.lang.reflect.InvocationTargetException` → `SIGABRT` (signal 6, thread
`1.raster`), no `activity_resumed` marker — so the corpus-only one-rung delta is
not reproducible outside the corpus, and **uid is excluded** as the mechanism
(the `uid=host` arm aborts the same way 3/3). It is listed as the one
unexplained per-app difference; it changes no frame/tree/tap rung.

**`net.cozic.joplin` is NOT a K5 regression (3×3 A/B, `.cache/k5/jab/`).**
Branch 3/3 and main `d7dc8e2` 3/3 abort with exit 134 and the *same* logd
signature: `facebook::jni::JniException … JavascriptException: [runtime not
ready]: Error: Exception in HostObject::get for prop 'RNCNetInfo':
java.lang.UnsupportedOperationException: unsupported Android API:
android.net.IConnectivityManager code 42 (requestNetwork)` → RN aborts the
process on thread `mqt_v_js`. The `connectivity` service landed on main in
`a98e839` (T-38/T-39, "null IME, clipboard, … connectivity state machines"),
an ancestor of `d7dc8e2`; K4's tree rung predates it. The wall and its next
action belong to the connectivity track, not K5: implement the
`requestNetwork` / `registerDefaultNetworkCallback` path (or answer it honestly
without aborting the app).

**Expected, not regressions:** `io.element.android.x` / `com.dot.gallery` stay
at the honest `KeyStoreException: AndroidKeyStore not found` wall because the
software keystore is opt-in and off by default (element in
`MainActivity.onCreate`, dot.gallery in `GalleryApp.onCreate`);
`com.nextcloud.client` reads `inspect` only because the code-42 wall fires
before its application-created marker (K3 also only reached process start).
