## 2. R4 — the crash line had no cause chain (evidence first)

**Root cause.** `LaunchMain`'s `ACOSLAUNCH {"outcome":"crash",…}` line contained
only `String.valueOf(topException)`. The framework's own
`handleBindApplication` wraps app failures (`Unable to create application …`),
so the cause that names the first failing call (`InstanceCreationException`,
`StartupException`, the NPE site) was never on the line; the host additionally
truncated the line at 600 chars, and only `stdout_tail_last` survived.

**Fix (`6a08341`).** The guest now emits `exception`, `stack` (24 frames) and
`causes[]` (class, message, 16 frames each) in the crash line. `acos-art` keeps
the whole line (32 KiB cap instead of 600 chars), writes it as
`guest_crash_detail`, and adds `logd_tail`, `stdout_tail`, `stderr_tail` to
`session-exit.json`. `guest_crash` stays byte-identical for existing readers.
AOSP reference: `frameworks/base/core/java/android/app/ActivityThread.java`
(`handleBindApplication` wraps with `RuntimeException`),
`android.app.Instrumentation.callApplicationOnCreate`.

**Apps reclassified (targeted re-run, `.cache/k2/runs-r4`).**

## 3. R1 — a `null` where Android never returns one (13 apps)

**Root cause.** `ContextImpl.getSystemService(name)` reaches
`SystemServiceRegistry`, whose fetchers call
`ServiceManager.getServiceOrThrow(<name>)`. Android always publishes `mount`
(storage), `jobscheduler`, `shortcut`, `power`, `account` (and
`thermalservice`/`alarm`/`netstats`); ACOS published none, so the fetcher threw
`ServiceNotFoundException`, the cached fetcher returned `null`, and the app
dereferenced it. For storage, `IStorageManager.getVolumeList` had no model at
all; for JobScheduler, the app's `ParceledListSlice<JobInfo>` then exposed a
missing payload codec.

**Fix.** New `crates/acos-services/src/extras.rs`:
* `IStorageManager` (`mount`): one primary emulated volume
  `/storage/emulated/0`, primary/emulated, not removable, owner `UserHandle(0)`,
  UUID null, `state=mounted`; empty disk/volume arrays; `mkdirs`/`fixupAppDir`
  accepted (the app dirs already exist); privileged vold mutations stay
  `UNSUPPORTED`.
* `IJobScheduler` (`jobscheduler`): `schedule`/`enqueue` return
  `RESULT_SUCCESS` (1) and record the package; `cancel*` succeed; no pending
  job/empty map/empty lists otherwise.
* `IShortcutService` (`shortcut`): cap 5, icon dimension 96 dp, empty
  shortcuts/share targets, `set/add/update` accepted, remove/enable recorded.
* `IPowerManager` (`power`): awake/interactive, not power-save, not idle,
  wake locks recorded as no-ops, `isIgnoringBatteryOptimizations=false`.
* `IAccountManager` (`account`): one user, no accounts; every query empty.
* `IThermalService` (`thermalservice`) and `IAlarmManager` (`alarm`): cool
  device / queued alarms; both are fetched by `PowerManager` and by k9/wikipedia.
* `netstats` binder resolves (`TrafficStats.init` no longer logs a failure);
  `permissionmgr` is an alias of the existing `IPermissionManager`.
* Job/shortcut/channel payload lists are decoded when their element codec is
  modelled and otherwise consumed opaquely at decode time (see §5); a real
  device accepts these calls and returns success, so ACOS never rejects the
  request merely because it cannot store the payload.

AOSP references: `StorageManagerService.getVolumeList`,
`StorageVolume.writeToParcel(CREATOR)`, `SystemServiceRegistry`
(`STORAGE_SERVICE`, `JOBSCHEDULER`, `SHORTCUT`, `POWER`, `ACCOUNT`),
`JobSchedulerService.schedule`, `ShortcutService` limits,
`PowerManagerService` offline state.

## 4. R2 — notification channels (6 apps)

**Root cause.** `NotificationManager.createNotificationChannels` sends a
`ParceledListSlice<NotificationChannel>`. ACOS failed at two places: no
`ParceledListSlice` codec at all, and no `NotificationChannel` codec. Get-channel
transactions (42/53) were not implemented.

**Fix (`3484c3b`, corrected by `e3d0c47`, dispatch fallback `fab6f64`).**
* `ParceledListSlice<T>` is decoded/encoded as count + element class name +
  per-element `writeTypedObject` presence marker + payload (the AOSP
  `BaseParceledListSlice.writeToParcel` shape; only the inline case is needed
  for the small channel lists real apps create).
* `NotificationChannel` and `NotificationChannelGroup` specs were transcribed
  from the API-34 image's `NotificationChannel(Parcel)` constructor — every
  nullable member is a `writeByte` presence marker, not an int. The first
  attempt mis-ordered `AudioAttributes` (the image writes 5 ints, StringArray,
  nullable String, bundle marker, Bundle); that produced exactly K1's
  `bad string: String16 is not NUL terminated`. `e3d0c47` fixes it and adds a
  channel-with-audio round-trip test.
* `NotificationService` stores channels/groups per package and answers
  `getNotificationChannel(42)`, `getNotificationChannelGroup(53)`,
  `getNotificationChannels`, `...ForPackage`, counts and delete/update calls.
  `enqueueNotificationWithTag`/`cancelNotificationWithTag` now succeed and are
  recorded (a real NMS returns normally when there is no status bar entry to
  draw; ACOS still never displays one).

AOSP references: `NotificationChannel.writeToParcel`,
`NotificationChannelGroup.writeToParcel`,
`BaseParceledListSlice.writeToParcel`, `INotificationManager.aidl`,
`PreferencesHelper`.

**Before → after (6 apps).** All six leave the channel create call:
* `org.kde.kdeconnect_tp` — full ladder (665 ms);
* `com.github.gotify` — material button/color-state inflation
  (`InflateException` on `MaterialButton`), not notifications;
* `com.ichi2.anki` — exits 10 after create; no crash line yet (app-level exit);
* `com.tailscale.ipn` — `AndroidKeyStore not found` in `getEncryptedPrefs`;
* `org.videolan.vlc` — `PackageManager.getPackageInfo("com.google.android.gsf")`
  raises our structured "unknown service name" instead of
  `NameNotFoundException` (PMS error-class wall);
* `org.wikipedia` — `AlarmManager` resolved; now killed by signal after the
  app's Okio poller starts (next evidence run should name it);
* `org.fdroid.basic` — `canRequestPackageInstalls` (156) /
  `getIntentSenderWithFeature` (63), R3 family.

## 5. R3 — missing read-only transactions (7 apps)

**Root cause.** The decoded AIDL tables know these methods but no handler
answered them, so the guest received `UNSUPPORTED_ANDROID_API` in an app path
that assumes a real query.

**Fix (`35374c2`).**
* `IActivityManager.getMemoryInfo` (77): `MemoryInfo` from the host's real
  `/proc/meminfo` (avail/total/threshold/advertised + the four thresholds);
  `getRunningAppProcesses` (86) → empty typed list.
* `IActivityClientController.getTaskForActivity` (22) → 1 for a known ACOS
  activity token, else -1; `getRequestedOrientation` (30) → -1
  (`SCREEN_ORIENTATION_UNSPECIFIED`); `willActivityBeVisible` (20) → true.
* `IPackageManager.getPackageInstaller` (133) → a real
  `IPackageInstaller` binder (aux node; ACOS never installs);
  `getPermissionControllerPackageName` (140) →
  `com.android.permissioncontroller`; `getInstallSourceInfo` (54) → a
  null-installer `InstallSourceInfo`; `queryIntentContentProviders` (35) →
  empty slice.
* `IConnectivityManager.getNetworkCapabilities` (16) → typed null (offline:
  no network has capabilities). `requestNetwork` remains structured
  unsupported (it needs a `NetworkCapabilities` codec + callback delivery).
* Parcelable codecs: `ActivityManager$MemoryInfo`, `InstallSourceInfo`,
  `Network`, `Messenger`; `AudioAttributes` fixed for R2.

**Before → after (7 apps).**
* `com.money.manager.ex` — full ladder (459 ms) after the permission-controller
  query resolved (AppManager shares this fix and now renders).
* `net.cozic.joplin` — first frame + tree + screenshot; the tap step has no
  clickable node (`getNetworkCapabilities` no longer kills the tree).
* `appmanager` — first frame/tree/screenshot; tap has no clickable node.
* `com.termux` — `getRunningAppProcesses` resolved; now a platform layout
  inflation failure (`activity_termux` line 46, unknown class).
* `chat.fluffy.fluffychat` — `getMemoryInfo` resolved; now SIGABRT (signal 6)
  with no Java crash line, Flutter/native-side.
* `com.unciv.app` — `getRequestedOrientation` resolved; next is
  `setRequestedOrientation` (29), a mutator not in the read-only set.
* `it.niedermann.owncloud.notes` — `getTaskForActivity` resolved; next is an

* `com.aurora.store` — `getPackageInstaller` resolved; next is

## 8. Limits and rule compliance

* Only the service host and crash-evidence plumbing were changed. The sandbox,
  network policy, APKs and the ART launch path owned by other agents were not
  weakened or touched. Untrusted APKs stay on the exec path.
* The service answers are the offline single-user device state: one mounted
  emulated volume with no UUID, no accounts, no jobs pending, no network
  capabilities, cool thermal state, queued (not fired) alarms. Nothing is
  fabricated as a pass.
* Corpus APKs live only in `.cache/corpus/k1`; runs and gates in `.cache/k2`;
  no APK or full frame is committed.
* Confound: targetSdk 35–37 apps still run against an API-34 framework, the same
  condition a real Android 14 device gives them.
