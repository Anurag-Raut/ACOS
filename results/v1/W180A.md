## What changed

| Area | Change |
|---|---|
| `crates/acos-verify/src/native.rs` | `NativeBackend` now drives the **product `AgentSession`** (the `acos launch --keep` / `observe` / `tap` / `session text` / `reset` worker) instead of stopping at the M2 attach handshake. Real launch ladder → failure on any blocker; live `ViewTree`→`UiTree` conversion; frame metadata from the frame store; PNG evidence; selector→centre taps; type (focus + `InputConnection` commit, optional clear); back/key mapping; reset; crash mapping. `capture()` forces a real repaint (`render_frame_now`) so a static screen still publishes a new frame. Logs are de-duplicated by line because the session log view re-appends the constant launch block on every read (this was silently dropping the W161-A tap log). |
| `crates/acos-runtime/src/session.rs` | New `AgentSession::capture()` (`Cmd::Capture`) = render-then-observe; text state-change is a before/after tree diff including focus/enabled/checked; the guest log view no longer loses the tap log to the re-appended lifecycle block. |
| `crates/acos-runtime/src/view_tree.rs` | Empty `TextView`/`EditText` reports its `hint` as text, matching uiautomator/ART (`input` = `Enter your name`). |
| `crates/acos-runtime/src/lifecycle.rs` | Interaction pump is bounded (`run_scheduler_max(…, 2000)`): an `EditText` cursor blink would otherwise chase the 100k-turn virtual-time budget. |
| `crates/acos-vm/src/vm.rs` | `Vm::run_scheduler_max(virtual_time, max_turns)`; `run_scheduler` delegates with the existing 100k cap. |
| `crates/acos-cli/src/verify.rs` | `--scenario <file>` (in addition to positional), `--native` (enters the ADR-0022 confinement before the session worker and adds the artifacts dir to the writable surface), honest error envelope if the gate refuses. |
| `crates/acos-cli/src/native_launch.rs` | `confine_native_launch_with_writable(apk, extra_writable, extra_read)`: the verifier can write evidence and read its scenario; `ACOS_BOOT_DIR` is honoured inside the confinement. |
| `scenarios/v1-counter.yaml`, `scenarios/v1-hello-views.yaml` | The V1 core loop (launch → tree assertions → input → text assertion → fresh capture → no crash). The rotation/back steps stay in the full scenarios so they are not weakened. String reconciliation is in the file header. |
| `tools/build-negative-apps.sh` | Builds the three broken variants from the existing fixture sources with the same toolchain. |
| `crates/acos-cli/tests/negative_verify.rs` | Runs the **product command** on all three broken APKs and asserts the exact non-pass verdict, the structured error, and false-pass count = 0. |

## Exact blockers

1. **hello-views tap after type** — click handler runs and logs, but the
   following traversal does not terminate (VM watchdog at 120 s); `result`
   stays `clicks: 0` and the post-abort tree loses `result`. Product-path
   repro: `acos launch …/hello-views.apk --keep` → `acos session text --text
   World` → `acos tap --id btn` (hangs). Suspected owner: layout/measure
   (W179-A area) or the relayout-after-input path. Not worked around; the v1
   scenario is unchanged and fails honestly.
2. **Bounds offset** — live tree `count` is `[84,506][105,570]`; ART reference
   `[42,317][63,368]` (content top 422 vs 275, x doubled). Text/ids match
   exactly. V1 1.4/1.9 stay in progress.
3. **Rotation/recreate** — no orientation path in the session, so the full
   scenarios report `unsupported` at `rotate` (V1 1.7).
4. **hello-jni** — the loader path is reached (`--native`), but the VM's JNI
   binding reports `UNSUPPORTED_NATIVE_SYMBOL` for `stringFromJNI`, which **is
   exported** by `libhellojni.so`. Same gap as W3-07 (owner W93-A). No
   `JNI_OnLoad`/`RegisterNatives`/`ThrowNew` evidence yet, so V1 §2 stays open.
