## 0. Verdict

**Can the owner use ACOS to verify Gaten today: NO.**

Gaten never reaches a first frame, a tree, or a screenshot on ACOS — with either APK variant,
old or new. Two *independent* ACOS-side blockers stop it, and a third stops the interactive
ART loop that would be needed for the steps *after* launch:

| # | blocker | where it bites Gaten |
|---|---|---|
| 1 | ACOS's React Native driver is a **hand-written RN ≤ 0.81 (Paper) Java driver** (`rn-bridge-probe.dex`) that references framework-internal class names R8 strips from every release APK | both Gaten **release** APKs die at mount: `UNSUPPORTED_RN_DRIVER … Lcom/facebook/react/internal/AndroidChoreographerProvider;` — 488 ms, no frame |
| 2 | ART guest is **SIGKILLed the moment the `acos launch` connection closes** (`PR_SET_PDEATHSIG` set from the per-connection thread), so `acos launch --keep` → `acos observe/tap` from another process cannot work | kills the loop for **any** app; Gaten would hit it right after launch |
| 3 | **fbjni `alias_ref` assertion** inside the merged `JNI_OnLoad` for debug (unminified) RN builds; the W188-A fix is patch-only and **not in `main`** | Gaten **debug** APK aborts at 10.4 s: `LocalReferenceAllocator…verifyReference` (References-inl.h:424) |

What *does* work, proven in this run: `launch → tree → screenshot → tap → tree → screenshot`
on real ART for a plain framework app (`counter`, 0→1 with pixels) — but only while the
launch connection is held open (workaround for #2); and the RN renderer path end to end for
an RN 0.81 Paper app (`rn-hello`, count 0→1→2). The Gaten-specific failures are therefore
*version/artifact* walls, not "ACOS cannot drive an app at all".

## 6. What would change the verdict

Rank 1 + 2 (a driver that resolves the choreographer provider reflectively and boots a
bridgeless RN ≥ 0.82 app) would get Gaten to a JS-side tree; rank 3 (PDEATHSIG) is needed for
the post-launch steps; rank 6 (pixels) is needed for screenshots. Rank 4 matters only for
debug builds. With 1+2+3 done the owner could at least drive Gaten's first screen by
`tap --testID`/`--text` (no pixels); with 6 as well, the request in this task ("screenshots
plus a ranked list") becomes answerable for Gaten itself.
