Implements ADR-0026 decision 4: the boot-image default is `shared-fixed`, built
once per machine and cached on disk, reused across serves and sessions, rebuilt
only when its inputs change. Image ASLR is given up (owner accepted); `lz4` and
`shared-aslr` stay selectable through `ACOS_ART_BOOT_IMAGE`.

## What changed

* `crates/acos-art/src/boot_image.rs`: `Mode::SharedFixed` is the unset
  default. New content-addressed cache: `<cache>/fixed-<input-hash>/`,
  `manifest.json` (input hash, image-format version, per-file size + sampled
  checksum), atomic publish (temp dir on the same fs, `fsync` files, `rename`,
  `fsync` dir), exclusive `flock` on `<cache>/.lock` across build + publish,
  `current.json` pointer for the prewarm, prune to the newest 2 entries.
  Input hash = ACOS image-format version + `dex2oat64` flags + boot-classpath
  environ text + identity (path, size, mtime) of every sysroot boot jar
  (`system/framework/*.jar`, `system/apex/*/jars/*.jar`, 37 jars here) and of
  `dex2oat64`/`dalvikvm64`/`libart.so`/`libartbase.so`/`libnativehelper.so`.
  Cache root: `ACOS_BOOT_IMAGE_CACHE`, else `ACOS_CACHE_DIR`, else
  `$XDG_CACHE_HOME/acos`, else `~/.cache/acos`, then `art/boot-images`.
* Reply field `boot_image: {mode, cache, reason?, dir?, input_hash?, base?,
  prep_ms?}` in `LaunchResult`, in the interactive ready line, in `acos verify`'s
  `engine.timing.boot_image`, and in `acos serve`'s launch reply + session list
  (`cache` ∈ hit / built / fallback / external / none).
* Failure policy: an explicit `ACOS_ART_BOOT_IMAGE=shared-fixed` fails closed;
  the **default** falls back to the sysroot LZ4 image, logs it and reports
  `cache: "fallback"` + `reason`.
* `acos-cli` prewarm warms the cached entry named by `current.json` instead of
  the old `fixed-70000000` directory.

## H13C follow-up (2026-11-14): the serve path works — the probe fixture was wrong

The H13b handoff reported `acos serve` launches dying `GUEST_EXITED` (child exit
134) on both arms. That reproduces, but it is **not** the serve path and not
this change: the probe launched `fixtures/build/apps/acos-counter.apk`, the
47 MB **Flutter** fixture, and that app SIGABRTs in its own `1.raster` thread
on both arms. The plain counter fixture every scenario and `acos_bench.py` use
(`fixtures/build/apps/counter.apk`) launches through `acos serve` on both arms.

| arm | fixture | `acos serve` + `launch --keep` | evidence |
|---|---|---|---|
| main `3e11d9c` (`acos 5a2ea97d…`) | `counter.apk` | **pass**, `first_frame`, `boot_image: lz4/none` | `results/bench/H13b/serve/main-counter-{launch,list}.json` |
| main `3e11d9c` | `acos-counter.apk` (Flutter) | fail `GUEST_EXITED` exit **134** | `results/bench/H13b/serve/flutter-fixture-crash.md` |
| branch `0676c6f` | `counter.apk` | **pass**, `first_frame` | `…/branch-cold-*.json`, `…/branch-hit-*.json` |
| branch `0676c6f` | `acos-counter.apk` (Flutter) | fail `GUEST_EXITED` exit **134** | same file |

Abort reason (both arms, `session-exit.json`): `code:
GUEST_KILLED_BY_SIGNAL`, `guest_signal: 6`, `activity_resumed: false`,
`application_created: true`; `native-crash.txt`:
`ACOSCRASH {"signal":6,"code":-6,"fault_addr":"0x0","pid":2,"tid":19,
"thread":"1.raster","source":"acos-shim"}`; logcat tail: Flutter's
`GeneratedPluginRegistrant` `ClassNotFoundException` (harmless), then
`pid: 2, tid: 19, name: 1.raster >>> …/dalvikvm64 <<<`, `signal 6 (SIGABRT)`,
one frame `__android_log_assert+452` in `/data/shim/libartshim.so`. The shim
only interposes `__android_log_assert` (artshim.c:248) to route the message to
logcat; the assertion is Flutter's. No `scenarios/` file references
`flutter` (`grep -rl flutter scenarios/` is empty), so no gate ever ran it.

Second, independent probe mistake in the handoff: its second probe set
`XDG_RUNTIME_DIR` to a private `.cache/h13b/run`. `acos-art` gets its mandatory
memory cgroup through `systemd-run --user --scope`, which needs the **real**
XDG runtime dir's session bus: with the private dir
`systemd-run --user --scope … true` exits 1, "Failed to connect to user scope
bus via local transport", and the launch fails
`MEMORY_CGROUP_UNAVAILABLE: …/cgroup was not written yet` (visible in
`.cache/h13b/serve2-launch.json`). Keeping `XDG_RUNTIME_DIR` and pointing only
`ACOS_SESSION_SOCKET`/`ACOS_SERVE_ARTIFACTS`/`ACOS_ART_DATA` at the worktree is
what the probe scripts under `.cache/h13c/` do.

**Conclusion: no regression, no code change.** `tools/bench/acos-bench.sh` was
never affected (it leaves `XDG_RUNTIME_DIR` alone and launches `counter.apk`).
