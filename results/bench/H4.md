# H4 — idle CPU and wakeups per idle session

**Branch:** `perf-h4-idle-cpu` (off `main` `11b917c` + T1 merge `4737bb7`; H4 code in `6c3b01a`,
probe-liveness fix and watchdog thread name in the final commit)
**Date:** 2026-11-14. **Metric:** idle CPU (% of one core) and idle wakeups/s (voluntary context
switches/s, the B2 metric) per idle session at N=1/5/10, plus a latency A/B to prove the change
does not cost latency.

## 1. What changed and why

An idle session with a settled screen should cost nothing but its own guest work. Before H4 each
idle session still ran a set of periodic timers on the host and in the guest (S3/B2 attribution:
`acos` serve poll 20/s, `acos-art` launcher ~77/s, guest binder loopers 2 × 50/s, a 250 ms probe
fallback at 8/s, guest main 4/s).

| file | change |
|---|---|
| `crates/acos-art/guest/java/dev/acos/art/LaunchMain.java` | probe liveness fallback `P10_PROBE_FALLBACK_MS` 250 ms → **5000 ms**. The host `PROBE` wake and view-dirty events still produce samples; the fallback is only the missed-event bound. |
| `crates/acos-art/src/launch.rs` | interactive idle loop: `recv_timeout(100 ms)` polling → event-driven `ServeEvent` (`Line` / `ChildExited`); stdin reader thread; child exit watched with `waitid(P_PID, …, WEXITED\|WNOWAIT)` (does not reap, so `try_wait`/`wait` still own the status). The only periodic host deadline left is the 900 s `ACOSLAUNCH_SESSION_SECS` cap. Peer socket `SO_RCVTIMEO` 100 ms → 1 s (wedged-peer bound only; guest exit closes the socket). |
| `crates/acos-art/src/launch.rs` (final fix) | **required**: `wait_for_event_settled` now records an arriving probe sample in `last_requested_seq` (and resets `last_wake`) instead of leaving it stuck at the pre-request value. Without it the host stopped asking for samples after the first answer; the 250 ms guest fallback hid that, the 5 s fallback exposed it as a deterministic `w42-back-frame` strict `TIMEOUT`. Probe cadence is still the 50 ms floor from G3b — no re-ask on arrival, one bounded ask per 50 ms while the settle is unsettled. |
| `crates/acos-art/src/logd.rs` | reader timeout 100 ms → 1 s (`finish_capped` already sends a zero-length stop datagram, so this is not the stop path). |
| `crates/acos-binder-peer/native/binder_driver.c` | looper wait: `pthread_cond_timedwait` 20 ms loop (`waited < 1000`) → untimed `pthread_cond_wait(&g.cv_txn, &g.mu)`; `F_TXN` broadcasts under `g.mu`, non-loopers return before this wait. Removes ~2 × 50 wakeups/s per guest. |
| `crates/acos-cli/src/serve.rs` | idle `poll()` timeout 50 ms → up to 1 s (a connection wakes `poll` immediately; the timeout only bounds idle-exit checking). |
| `crates/acos-art/src/watchdog.rs` | memory-watchdog sampler thread is now named `acos-mem-watchdog` (attribution only; period, limit and kill behaviour unchanged). |

## 2. Method

- Real ART, release build, one session per cgroup. Host AMD Ryzen 9 9950X (32 threads, 61 908 MiB);
  `ACOS_FONT_DIR=/home/Qui/Projects/acos/.cache/boot/android-34/fonts`, `ACOS_BOOT_DIR` unset.
- Every ART run: `tools/art-runtime/run-exclusive.sh --task H4 -- tools/guarded.sh --mem <N>G --time <s> -- …`.
  One lock acquisition per rep (`memory,latency` bundle ≈ 280 s ART, well under the 10 min budget).
- **Arms, interleaved** `base rep1, fixed rep1, base rep2, fixed rep2, base rep3, fixed rep3`:
  - base: `acos` sha256 `7fb5e560…`, `acos-art` `568658342b…` (main at the merge base).
  - fixed: `acos` sha256 `740d8e54…`, `acos-art` `71c1f10f…` (checkpoint + probe-liveness fix).
    Recorded yesterday's fixed `acos` was `df1d6088…`; both are release builds of the same source
    and differ only by cargo feature unification (dev-deps of `acos-verify`), so the whole fixed
    arm above was measured on one and the same binary. The behavioural evidence that it carries the
    fix is the `w42-back-frame` canary (§5), which fails deterministically without it.
- Idle metric: `tree_delta` in `tools/bench/acos_bench.py` sums `/proc/<pid>/stat`
  utime+stime and `voluntary_ctxt_switches` over the serve tree for a 60 s idle window, per N,
  after a 10 s settle. 3 reps × N=1/5/10 per arm (`cpu_idle_n*_pct`, `wakeups_idle_n*_per_s`,
  `m1`/`m2` memory from the same run).
- Latency: `--phases latency`, 3 reps × 8 samples per arm, animations on (product default):
  M4 launch strict/fast, M5 screenshot, M6 reset strict/fast, M7 tree strict/fast,
  M8 tap counter/form strict/fast, tap ack, teardown. Agent loop: `--phases loop1`, 3 reps per arm,
  21 tasks/rep.
- Host load (load1): base memory phase **0.80 / 0.68 / 1.11**, fixed **0.78 / 0.74 / 0.69**
  (matched, low). `MemAvailable` 46.5–47.1 GiB in every rep. Loop arm load1 1.07–2.48.
  No rep was flagged noisy. Artifacts: `.cache/h4/results/ab/`, `.cache/h4/results/loop/`
  (`{base,fixed}.json|.md` merged, `ab*/` raw per-rep phase JSONs), logs `.cache/h4/logs/`.

## 6. Attribution (from the earlier profiler runs, `.cache/h4/profile_idle.py`)

Base N=10 all-thread (per session → N=10 total, 60 s): `acos-art` launcher ~77/s → 771/s;
guest `Thread-1` and `binder:2_1` ~50/s each → ~996/s; `acos-live-probe` 8/s → 80/s;
guest main 4.05/s → 40.5/s; `acos` serve 2/s → 20/s; stock ART daemons ~1.5/s → ~15/s.

After the fix the remaining per-session wakeups are the 50 ms memory watchdog (~40/s, 2 threads
that both disappear with `ACOS_ART_RSS_MAX=0` — measurement only, it removes a safety bound),
`acos` serve ~1/s total, `acos-live-probe` ~0.4/s total, guest ART daemons ~1/s. The watchdog
period is the accepted safety cost: it bounds launcher RSS overshoot and has no event source.

## 7. Risks / notes

- **Probe liveness is load-bearing.** The 5 s guest fallback is only safe with the host
  `last_requested_seq` fix; `w42-back-frame` is the canary (fails deterministically without it).
  Do not "fix" a w42 timeout by restoring the 250 ms fallback — that gives back most of the
  guest-main wakeup win (40.5 → ~8/s at N=10).
- **Binder driver untimed wait** is theoretically correct (broadcast under `g.mu`) but not
  separately gate-proven: reverting only that file to the 20 ms timed wait reproduces the same
  w42 timeout, so w42 does not isolate it. If a future binder trace shows a missed incoming
  transaction, revert just `binder_driver.c`.
- The two watchdog-lifetime 20/s threads are not fully attributed (one is the named 50 ms
  sampler, the second shares its lifetime). Not a behavioural concern at the measured numbers.
- Base arm is `main` at the T1 merge (`4737bb7` second parent), not B2's `main 4958703`; the
  idle rows are B2-compatible (34.06 / 90.22 / 160.52 wakeups/s vs B2's 34.1 / 90.8 / 161.7).
