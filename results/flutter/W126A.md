## 1. `sem_*`: the counter lives in the guest word (crates/acos-native-loader/src/bionic/shims.rs)

The old implementation boxed a host `libc::sem_t` behind an address-keyed handle
table and zeroed 32 guest bytes on `sem_init`. Any lookup that missed — a
different address, a copied/moved `sem_t`, a never-initialised object, or a
poisoned table (`sem_ref` used `.lock().ok()?`, which silently returns `None`) —
made every entry point return `-1` with no diagnostic. `fml::Semaphore`, the
engine's only user, is exactly the "moved/embedded object" shape: it embeds a
`sem_t` in a heap object and coalesces frame requests with
`sem_trywait`. A silent `-1` there means "a frame is already in flight", which
is how W119-A measured `Animator::RequestFrame` dropping *every* request.

The rewrite is now POSIX/bionic in the guest object:

* the **value is the 32-bit counter word in the guest `sem_t`** (`atomic_int`
  semantics, `EM_BYTES = 4`, alignment-checked with `EINVAL` otherwise), so it
  survives copies/moves and cannot be lost by a table lookup;
* `sem_init` stores the value and creates the per-address blocking state;
  `sem_trywait` is a pure CAS decrement (`EAGAIN` when zero); `sem_post` is a
  CAS increment with `EOVERFLOW` at `SEM_VALUE_MAX`;
* blocking (`sem_wait`, `sem_timedwait`) uses a host table keyed by the guest
  address, created eagerly by `sem_init` **and lazily** on first use, so a
  never-initialised or copied handle degrades to POSIX semantics (a zero
  counter) instead of `-1`. `sem_destroy` removes it and wakes/detaches parked
  waiters with `EINVAL`;
* `sem_timedwait` takes a `CLOCK_REALTIME` **absolute** deadline (POSIX);
* no call can fail because of internal bookkeeping: the only `-1`s are POSIX
  argument/value errors (`EINVAL`, `EAGAIN`, `EOVERFLOW`, `ETIMEDOUT`);
* `ACOS_TRACE_SEM=1` traces every call and `bionic::shims::sem_call_counts()`
  exposes `(init, trywait, post, wait)` for the harness (inert otherwise).

Unit tests (6, `bionic::shims::sem_tests`): the exact `fml::Semaphore`
sequence (`init(1)` → trywait `0` → trywait `-1/EAGAIN` → post → trywait `0`),
moved/copied handle, never-initialised object, `CLOCK_REALTIME` absolute
`timedwait` (300 ms deadline, and an expired one), cross-thread
`post` unblocking a blocked `wait`, and `getvalue`/error paths.

## 2. One engine, one `JNI_OnLoad` (crates/acos-native-loader/src/loader.rs, crates/acos-jni/src/load.rs)

`dlopen` already de-duplicated against the process-wide `OBJECTS` registry, but
the JNI loader's `System.loadLibrary` mapped bytes unconditionally, so
`libflutter.so` was mapped twice: the harness's phase-A engine and the engine
`System.loadLibrary("flutter")` produced. The engine-side breakpoints of
W119-A only ever fired on the second copy.

* `Loader::find_loaded(names)` consults `OBJECTS` (display name, `DT_SONAME`,
  full path, file name), takes a reference and returns the existing
  `LibraryHandle`.
* `load_named` now resolves to an existing mapping first, and every published
  label/path is the existing object's own (this also fixed
  `hello_jni_runs_through_the_vm`, which asserts the APK label survives).
* `NativeLibrary::jni_on_load_done()/note_jni_on_load()` make `JNI_OnLoad` run
  once per mapping; a repeat `System.loadLibrary` of the same object is a
  no-op, exactly as bionic behaves.

Measured: the harness summary reports `libraries: ["libflutter.so"]`, and the
gdb driver's base derivation now finds a single engine copy.

## 4. Remaining blocker (named): no GL surface is ever created, so the draw has nowhere to go

Honest status: **no frame has been presented, no PNG exists.**

* The harness's own drive loop (`FlutterProbe.requestFrame()` every ~320 ms,
  added so frames are requested *after* the first coalesced one) makes Dart
  draw 33 scenes, but the engine never posts raster work for them: the
  raster queue (`qid=2`) shows only the 3 tasks posted during startup,
  regardless of how many frames Dart draws.
* EGL is never entered at all. With `ACOS_TRACE_EGL=1` instrumenting
  `eglGetDisplay` / `eglInitialize` / `eglCreateWindowSurface` /
  `eglCreateContext` / `eglMakeCurrent` / `eglSwapBuffers`, **zero** calls are
  recorded in a full confined run (`/tmp/w126a-run5.log`). So this is *not* yet
  a Skia/GLSL-reject or unsupported-GL-call problem: the rasterizer never gets
  as far as asking for a context (the engine does not even call
  `eglGetDisplay`).
* Consistent with that: `ANativeWindow_lock`/`unlockAndPost` are never called,
  `presented_frames()` is empty, and no `results/flutter/w126a-frame-*.png` was
  produced.
* Second, independent gap: `FlutterJNI.dispatchPointerDataPacket` returns
  (`phase=pointerDispatched bytes=576`), but Dart's `onPointerDataPacket` never
  runs (`ACOS_DART_POINTER` is never printed); with `tapIncrement()` driven
  from the harness the counter therefore never becomes 1.

Most likely cause of the missing surface, for the next wave:
`FlutterJNI.onSurfaceCreated(surface)` must reach
`PlatformViewAndroid::SurfaceCreated` → `AndroidSurface::Create` →
`ANativeWindow_fromSurface` + EGL on the **raster** runner. Note the raster
runner does execute early tasks (3 early `PRIMARY` on the raster thread), so the
failure is inside the surface/EGL creation step or in the
`ANativeWindow`-from-`Surface` resolution, not in the raster thread's loop.
Start there with a breakpoint on the engine's surface-create path and a trace
on `ANativeWindow_fromSurface`.
