## 1. Root causes (all four had to fall)

### 1.1 `setSemanticsEnabled` raced the Dart isolate start

`FlutterSession::launch` called `enableSemantics` immediately after
`vm.run(FlutterProbe.main)` returned, but `runBundleAndSnapshotFromLibrary` is
asynchronous: the Dart isolate had not run `main` yet, so
`onSemanticsEnabledChanged` was not installed when the engine's posted
`_updateSemanticsEnabled(true)` fired. `sSemanticsSeq` stayed 0 forever.

**Fix:** `FlutterSession::pump` requests semantics only once a frame has been
presented (proof the isolate ran), and the fixture's `_onDrawFrame` re-publishes
the node whenever `PlatformDispatcher.semanticsEnabled` is true, so the state
cannot be missed.

### 1.2 JNI `Call<Type>Method` missed a private method

The engine delivers the tree by calling the **private**
`FlutterJNI.updateSemantics(ByteBuffer,String[],ByteBuffer[])` through JNI.
`acos_jni_va_invoke` used `Vm::call_method` (virtual dispatch only), so the call
failed with `no method …updateSemantics`. **Fix:**
`crates/acos-jni/src/jni.rs` falls back to `Vm::call_method_direct` on
`MethodNotFound` (the same fallback `GetMethodID` already used).

### 1.3 `NewDirectByteBuffer` over a caller-owned host pointer

The engine wraps its native semantics buffer with `NewDirectByteBuffer(addr,cap)`.
ACOS's `Unsafe`/`libcore.io.Memory` reads are bounded to synthetic
`native_mem` regions, so `buffer.duplicate()` threw
`IllegalStateException: native memory: address does not name a live region`.
**Fix:** `jni_NewDirectByteBuffer` copies a caller-owned region into a fresh
synthetic region (and records the original pointer); `GetDirectBufferAddress`
still returns the original host pointer. Java reads the copy, native keeps its
pointer.

### 1.4 Fixture set the wrong action bit

`dart:ui`'s `SemanticsAction.tap.index` is **1** in Flutter 3.47, but the engine
wire uses the Java `AccessibilityBridge$Action` **mask** (`TAP = 1 << 0`). The
probe's `1 << tap.index` therefore set the `LONG_PRESS` bit and the node decoded
as `clickable = false`. **Fix:** `actions: 1 << 0` in the fixture, and
`tap_text`'s node lookup no longer depends on the bit (it matches `text()`).

## 3. Honest boundary

* `tap --text` resolves the node from the semantics tree, then dispatches a
  `nativeDispatchSemanticsAction` TAP=1 (`FlutterProbe.dispatchSemanticsTap` +
  Dart `onSemanticsAction` are wired). In this raw `dart:ui` fixture the engine's
  `Shell::OnPlatformViewDispatchSemanticsAction` is reached (verified with the
  W119-A in-engine gdb harness) but the probe's `onSemanticsAction` handler does
  not fire, so `tap_text` falls back to the proven W130-A pointer packet at the
  node centre. The counter increment is therefore the pointer path; a framework
  app that handles the accessibility action would take the action path.
* The semantics buffer copy is one-way (native → Java): a native caller that
  creates a direct buffer, lets Java write it, then reads the original pointer,
  would not see the writes. No such path is exercised today.
* Frame pixels after the tap are byte-identical to the pre-tap frame (the
  software GLES sink re-publishes the first buffer); the counter change is
  proven by the Dart log and the new frame sequence, as in W149-A.
