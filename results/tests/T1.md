## What was actually wrong

The failures were **not** all stale goldens. Three shared-code/wire bugs and
three test/environment issues were hiding behind the golden-looking diffs.

1. **`SurfaceControl` native reader consumed only an i64 handle, while the WMS
   Rust codec emitted the full libgui body.** `addToDisplayAsUser`'s reply and
   `IWindow.insetsControlChanged` were therefore left with 796 unread bytes;
   the framework's `IWindow$Stub` threw `BadParcelableException` /
   `InsetsSource` NPE and `ViewRootImpl.setView` never added a root. Fixed in
   `crates/acos-vm/src/natives/fwk_surface.rs`: `nativeReadFromParcel` consumes
   `client, handle, layerId, layerName, transformHint, width, height, format`
   and `nativeWriteToParcel` writes the same body. This unblocked
   `counter_interaction`, `m2`, `wms`, `app_matrix` launch, toasts, and the
   notification path.
2. **`KeyCharacterMap.nativeReadFromParcel` assumed `[keyboardType, String8]`.**
   The image/`acos-services` payload is `deviceId, hasMap, cstring loadFile,
   keyboardType, overlay, key records with behaviour lists, three remap tables`
   (`libs/input/KeyCharacterMap.cpp`). The short reader desynchronised the
   enclosing `InputDevice` parcel; `CheckBox` inflation then hung the test in
   `PathParser`.
3. **`render_views` hang: non-reentrant mutex double-lock.**
   `gfx_vector::pp_can_morph` evaluated `(path_data().get(a), path_data().get(b))`
   in one expression: the first `MutexGuard` was alive when the second
   `path_data()` tried to lock the same mutex. `widget-gallery`'s `CheckBox`
   triggers a vector path-morph query during inflation, so the test hung
   forever (44+ min, ~1 min CPU). Fixed by taking one guard; added a 180 s
   `HostGuard` around the VM run so a future guest loop fails loudly.
4. Stale goldens: PMS `app.flags` now includes `FLAG_DEBUGGABLE` (0x2) and
   `FLAG_ALLOW_CLEAR_USER_DATA` (0x40) → `0x3000_0046`; framework bool true is
   AOSP's `0xFFFF_FFFF` sentinel, not `1`.
5. Test/environment: arm64 test skipped when qemu is absent; protocol scenario
   skipped when its APK fixture is absent; native-loader semaphore test now
   uses a real mapping (the product `check_sem` correctly rejects stack
   pointers); `services_t38` was updated to K2/K5's faithful "notification post
   is recorded, not rejected" behaviour.
