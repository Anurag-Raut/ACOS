# ACOS v0.4.0 — release notes (DRAFT, 2026-11-18)

**Android building blocks.** v0.4.0 lets an agent attach the Android system
pieces an app needs, and detach them again. A piece that is not attached
answers with a named error. It never gives a fake success.

Status: **draft.** v0.4.0 is not released. The release gate has not run on
this tree. See "Gate results" at the end.

Install: `tools/release/install.sh --prefix ~/.local --register-mcp`
(unconfirmed for v0.4.0; this is the v0.3.0 command).

## New

### Service modules

Each module owns some Android system pieces. It has a manifest and one or
more profiles:

- `off`: the framework takes the real missing path. The reply says the module is off.
- `stub`: fixed, documented answers.
- `scripted`: the agent drives the state.
- `real`: a real implementation.

An app that calls a service with no module attached gets `UNSUPPORTED_ANDROID_API`,
and the error names the module. (Model: `docs/PLAN_2026-11-16.md` §3.1.)

Modules on `modules` today, by profile (from the module source):

| Module id | Profiles | Notes |
|---|---|---|
| `accessibility` | real | accessibility service, bind, gestures, screenshot |
| `network` | real | offline and scripted are control ops on the real arm, not profiles (per code comment) |
| `webview` | real | WebView provider; see WebView below |
| `system.permissions` | real | permission dialog as a guest system app |
| `system.notifications` | real | notification shade as a guest system app |
| `hw.biometric` | stub, scripted | |
| `hw.bluetooth` | stub, scripted | |
| `location` | stub, scripted | |
| `sensors` | stub, scripted | |
| `net.telephony` | stub, scripted | |
| `feedback.vibrator` | stub, scripted | |
| `hw.usb`, `system.dropbox` | stub | tail modules |
| `hw.nfc`, `system.wallpaper`, `system.print`, `system.search`, `system.usage`, and 3 more tail modules | off | tail modules (8 in `tail_stubs.rs`) |

Attach in a launch: `services: [{id, profile, config}]`, in `acos_launch` or in
scenario YAML. Live attach and detach use `acos_services`. Scripted state uses
`acos_service_ctl`. (Names taken from module doc comments and the CLI serve path;
unconfirmed against this build's MCP tool schema.)

### Permissions and system UI

- **Permission dialog is a guest system app** (`com.android.permissioncontroller`,
  staged by the `system.permissions` module). Allow and deny work. A request for
  a permission that is already granted
  returns at once. The result follows AOSP ordering. (SYSUI1, SYSUI2, SYSUI4.)
  The "don't ask again" path is listed in SYSUI1 but its pass is unconfirmed.
- **Real permission labels.** The 42 dangerous platform permissions and 16
  permission groups have AOSP labels. App-declared `<permission>` labels are read
  from the manifest. The dialog shows the real label. (SYSUI3B.)
- **Notification shade** (`com.android.systemui`). Agents can open it with
  `open_shade`, read the rows, and tap one to fire its content intent. Scenario
  `sysui1-shade`: 12 of 12 steps pass. (SYSUI2, SYSUI3A.)

### App broadcasts and accessibility

- **App broadcasts reach their receivers.** Filter matching and package targeting
  work. A manifest `<receiver>` runs in the app's own process. (GATENBOOT2 §1.)
- **The accessibility service binds on the enable set.** A `Settings.Secure`
  write binds it. `service_ctl enable` and `disable` bind and unbind it. Removing
  the component unbinds it. (GATENBOOT2 §2.)
- **Paced gestures.** A swipe is a stream of MOVE events on a real timeline.
  A 400 px swipe scrolls 649 px (400 px plus fling). (A11YPACE §1.)
- **`tap` with `expect_change: false`.** Use it for a tap that should change
  nothing. (A11YPACE §2. See Behaviour changes.)
- **`takeScreenshot` no longer crashes.** It returns a HARDWARE bitmap of the
  screen. Drawing that bitmap is a known limit. (A11YPACE §3.)

### WebView

- **Two WebViews do not starve each other.** Frame pulls are fair across views.
  (WVFAIR, from `results/handoff/WVFAIR/REPORT.md`; no README in that directory.)
- **The WebView provider APK ships in the image.** A fresh install needs no
  separate build step. (WVFAIR.)
- **Taps on web content land.** `webview-probe` passes 10 of 10 (WVTAP). In
  `webview-fair`, a tap reaches its click in under 1 s on 20 of 20 runs. The worst
  run took 529 ms (WVTAIL).
- **One input rule.** A touch is routed by its point. A key is routed by focus.
  (WVTAP.)
- **An engine restart is named.** When the shared engine restarts, the broker
  reports `ENGINE_RESTARTED` with the exit status and stderr. It no longer shows
  `NO_VIEW`. (WVTAIL.)

### Launch intent extras

- The launch Intent reaches `getIntent()`. That covers the action, the data URI
  and the typed extras. (LAUNCHEXTRAS.)
- Plain scalars are sent as plain JSON values. `long` and `float` have explicit
  type tags, so the Activity reads the right Java type.
- **Parcelable extras are refused** with `UNSUPPORTED_ANDROID_API`, and the error
  names the type.
- Scenario `launch-extras.yaml` passes on ART 34. (LAUNCHEXTRAS.)

### Per-app uids and caller identity

- **Each installed package has its own uid.** The fixture package is 10192. Each
  further package gets the next free uid. A process runs under its package's uid.
  This follows AOSP's package manager. (PROCUID.)
- `getNameForUid` and `checkPermission(perm, pid, uid)` answer per uid. (PROCUID.)
- **Binder frames carry the sender's pid and uid** (protocol v4).
  `Binder.getCallingPid()` and `getCallingUid()` answer with the caller. (BINDERPID.)

### Binder callbacks are released

- Module callbacks are stored and released. Biometric callbacks release on
  detach. Autofill callbacks release at session teardown. IME callbacks release
  at process teardown. (BINDERREF3.)

### Not yet in `modules` (on other branches; confirm before release)

- **Software GL is the default** (`glship`). ANGLE on SwiftShader is used on every
  launch when it is installed. `ACOS_GUEST_GLES=off` turns it off. With no
  provider installed, the guest runs as before. An app that never uses EGL costs
  nothing that the measurement can see: launch p50 154 ms with it on and 154 ms
  with it off (5 reps). The provider is staged locally by `tools/art-gles.sh`. It
  is not an official release. Its manifest records hashes and upstream URLs.
- **Optional AMD GPU** (`gpuspike`, spike). Waydroid's Mesa runs on the host GPU
  with `ACOS_GUEST_GLES=mesa-host`. It is off by default. In the spike, a heavy
  1080×2400 shader took 2.8 ms on the GPU and 17.4 ms on SwiftShader (6.2×).
  Results must not depend on the GPU (owner direction 2026-11-18, item 5).
- **The shared WebView broker outlives its session** and refuses a stale build
  (`wvscope`). Its engines are forked by one process-lifetime thread, so a
  finished session no longer kills the shared engine (`wvkill`: 5 of 5 `webview-probe`
  runs and 5 of 5 `webview-fair` runs, zero engine restarts).

## Behaviour changes (read this)

- **A declared dangerous permission is not granted.** A permission in the
  manifest is not an install-time grant. The permission dialog or an explicit
  grant is needed. (MERGE040B, `c7236c42`.)
- **`tap` with `expect_change: false`** is the way to claim that a tap changed
  nothing. The verdict records `input.expect_change: false` and
  `change_claimed: false`. `expect_change: true` still fails honestly.
  (A11YPACE §2.)
- **Strict settle has a new bound: `window-reshown`.** When a window is removed
  and shown again, the step can settle with `settle.bound: "window-reshown"`.
  Evidence is in `settle.window_reshown` (a token) and
  `settle.window_reshown_frame`. A `fast` settle never reports this bound.
  (BACKSETTLE.)
- **`hello-views` and `multi-activity` now pass.** Both used to end in
  `TIMEOUT … no-draw-after-action` at `back`. The first Back goes to the soft
  keyboard. Then the finish Back closes the window. Their scenario headers now
  say so. If you treated these as known failures, remove that. (BACKSETTLE.)
- **Scenario expectations use a fixed vocabulary.**
  - `expectation: unsupported` means the engine refuses with an `UNSUPPORTED_*`
    code, and the run must match that code.
  - `needs_env: [pasta]` means the scenario needs a host tool that is missing.
    The matrix counts it under `skipped_needs_env`, not as a failure.
  - Sixteen scenarios that used to fail for known reasons now declare their real
    outcome, with a pinned `expect_error`. (SCENHYG.)
- **Launch extras are typed.** Use `long` and `float` explicitly when the app
  reads them as those types. A `Parcelable` extra is refused.
  (LAUNCHEXTRAS.)
- **A binder frame carries sender pid and uid** (protocol v4). A v3 peer reads as
  "unknown sender" (pid 0). A v4 peer still serves a v3 driver. (BINDERPID.)
- **Each package has its own uid.** Code that assumed one app uid for every
  process will now see a different uid for a second package. (PROCUID.)
- **WebView taps follow one rule.** A touch goes to the view under its point.
  A key goes to the focused view. (WVTAP.)

## Known limits

- **v0.4.0 is not done.** The plan's exit rule is that every module passes its
  conformance kit and its real-app proof, and that the Gaten floating bubble runs
  end to end on ACOS. The bubble does not run end to end yet (see below).
- **`gaten-bubble-overlay` fails at its screenshot step** on the merged tree
  (MERGEFIX2 §6). Its earlier 24-of-24 run (GATENBOOT2) was on a branch before the
  merge.
- **A HARDWARE bitmap cannot be drawn into a View.** The image has no OpenGL ES
  driver. `libEGL` aborts the RenderThread (A11YPACE §5.2). Software GL on
  `glship` may fix this. That is unconfirmed.
- **The bubble drag cannot run in the single-app scenario model.** A gesture has
  to come from a bound service, and only the app's own process can launch the app.
  The drag proof is in the `a11y-probe` probe app instead (A11YPACE §1b).
- **Real-network scenarios need `pasta`.** `net-check`, `net-network-real` and
  `net-network-offline` are skipped with `needs_env` when pasta is absent
  (SCENHYG, MERGE030).
- **The ANGLE/SwiftShader provider is a local build, not an official one**
  (glship, not in `modules`).
- **Rust VM engine: binder callback roots leak.** The leak is documented, not
  fixed. BINDERREF4 recommended keeping it and documenting it (option A3). Whether
  that was adopted is unconfirmed.
- **`gaten-backstack` fails on this base.** It is a settle-layer defect that
  already exists on the base commit. It is not from the per-app uid change
  (PROCUID §6).
- **Warm launch is 0.8 % slower than the stock emulator** (see Emulator comparison).
- **Not covered by a README in this draft (unconfirmed):** the conformance kit;
  the `network` module's real-HTTPS proof; the second app and intents (media pause,
  share sheet); rotation and multi-window; sensors, location and camera proofs;
  telephony and biometric proofs; the long tail; docs generated from the module
  registry (plan track D).
