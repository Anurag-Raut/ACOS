# ACOS v0.3.0 — release notes (2026-11-16)

**Trustworthy, agent-sized replies.** v0.3.0 is built from the v0.3.0 agent
feedback: a reply you can parse, that says what the app did with your input, that
is small enough to read, and that never claims a pass the engine did not see.
Every new fact is backed by evidence in the reply itself, and every claim that
cannot be backed fails closed with a code.

Install: `tools/release/install.sh --prefix ~/.local --register-mcp`
(see `docs/INSTALL.md`).

## New

- **Settle is an observation rule, not just an input option (REL3A).**
  `wait_for` and `assert_text`/`assert_visible`/`assert_not_visible`/`assert_state`
  accept `settle: strict|content`. Without one they are **auto**: strict first,
  then content-stable once strict proves it cannot settle (the step JSON then
  says `mode: content`, `fallback_from: strict`, `pixels_evidence: false`). A
  screen that animates forever (React Native `Animated`, a spinner, an endless
  `ProgressBar`) no longer spends the whole timeout on a rule that can never win.
  `settle: fast` is rejected on a wait or an assertion (`INVALID_SCENARIO` /
  `INVALID_ARGUMENT`). `timeout_ms` on a tree/text/state assertion is now a real
  poll (it used to be read once, ~1 ms after the previous step).
- **Every step and every action reply states the settle outcome**:
  `settle: {mode, settled, waited_ms, reason}` plus the rule's own evidence
  (`bound`, `window_ms`, `traversals`, `pixels_changed`, `probe_seq`,
  `fallback_from`, `waited_ms_source`).
- **Input is reported as *handled*, not just as sent (REL3E/REL3H2/REL3I3).**
  `acos_tap`/`acos_key`/`acos_text`/`acos_swipe` and every scenario input step
  carry `input.handled` (the app window's own `finishInputEvent(handled)` bit,
  `null` when it did not ack), `input.handled_evidence`
  (`{source: guest|host_window_removed|none, published, acked, unhandled}`),
  `input.target` (the resolved node, the injected point and the tree-geometry
  **hit-test**: `node`, `clickable`, `consumer`, `suggest`), `input.expect_change`
  (`true` / `false` / `"auto"` for a tap) and a one-line `input.handled_hint`
  that names the clickable control to tap instead when the point missed one.
- **`expect_handled` (scenario) — say whether the press must be consumed.** A
  tap/key/text/swipe step can declare `expect_handled: true` (an unconsumed
  gesture is `INPUT_NOT_HANDLED`, class `assertion`, never a pass and never
  "unknown") or `expect_handled: false` (a deliberate no-op, and it silences the
  warning). An unverifiable claim (no complete ack set) is
  `UNSUPPORTED_ASSERTION`.
- **Unhandled input is a settled observation, not a timeout (REL3H).** When every
  published event came back `handled: false`, the strict rule no longer sits out
  the whole settle deadline waiting for a draw: the step settles with
  `bound: "unhandled-input"`, `reason: unhandled_input`, and a **pass** carrying
  the step-level and verdict-level `INPUT_UNHANDLED` warning. Nothing else
  changes: any draw, or any `handled: true`, takes the normal rule.
- **Agent-sized replies (REL3C, PERF3, INTEG030).** Every reply — MCP tool and
  CLI `--json` — obeys one rule in `acos_protocol::reply`:
  - the default tree is the **compact screen** (every visible `text` /
    `content_desc` node in reading order with id, resource id, class, bounds,
    clickable and the state flags `focused`, `password`, `enabled`, `scrollable`,
    `checked`, `selected`), ~1–3 KB for a phone screen; `{"full": true}` gives the
    inline tree back;
  - a bigger compact list is **paged**, never head/tail-cut: `next_cursor` /
    `tree_next_cursor` + `{"cursor": N}`;
  - the full tree is always written and named: `tree_path`
    (`artifacts/tree/<frame_seq>.json`); live logs are named by `log_path`;
  - a hard **20 KiB** cap per reply (`reply::MAX_REPLY_BYTES`); a long string is
    bounded in place (head + tail + marker + artifact path, an identical repeat
    becomes a back-reference) before anything is replaced; a launch ladder keeps
    every rung, its `status` and `blocker.code`; if the bulk still cannot be
    bounded the reply becomes a pointer object that still answers did-it-pass
    (`verdict_status`), which step failed (`failed_step`) and what produced it
    (`provenance`, `evidence_provenance`). `_meta.acos_mcp.reply_capped` says so.
    `ACOS_MCP_MAX_TEXT` bounds one string; `0` disables both bounds.
- **New error codes (all documented in `docs/ERROR_CODES.md` and
  `acos_help {"topic":"errors"}`):**
  - `END_OF_LIST` (assertion) — a bounded `scroll_until` search reached the end:
    two **consumed** gestures in a row moved nothing. `details` names
    `attempts`, `unchanged_gestures`, `gesture_consumed` and
    `last_tree_texts`.
  - `INPUT_NOT_HANDLED` (assertion) — `expect_handled: true` and the app window
    answered `handled: false`.
  - `DAEMON_VERSION_MISMATCH` (harness) — the daemon answering is a **different
    build** than the caller (see below).
- **Two new verdict warnings** (`provenance.warnings[]`, and `step.warnings[]`
  where the fact is a step fact): **`INPUT_UNHANDLED`** and
  **`SCENARIO_ENGINE_MISMATCH`** (`engine:` in the document vs the engine that
  ran; the engine that runs is still the request's — nothing switches engines),
  plus **`INPUT_CHANGED_DURING_RUN`** when an input file is rewritten under the
  run (size/mtime/inode differ from the pre-run capture).
- **Provenance on every run (REL3B).** `provenance` names the APK and scenario by
  SHA-256 (12 hex), size and path, the engine, the build id and the warnings; the
  shared summary line ends with `warnings: N [CODE]`. Input digests are captured
  **before** the first step and cached process-wide (a warm launch in a
  long-lived daemon pays no hash: 3.16 s cold → 22 µs warm on Gaten).
- **`scroll_until` and swipe are real gestures on ART (REL3S/REL3H/REL3H2).**
  `acos_swipe` and the scenario `swipe`/`scroll_until` steps publish a paced
  DOWN/MOVE/UP stream on the real `InputChannel` with real event timestamps and
  per-event acks. `scroll_until` is bounded (`max_attempts`), takes one fresh
  settled traversal per attempt, and distinguishes the three outcomes that used
  to look identical: found, `END_OF_LIST`, and
  `ELEMENT_NOT_FOUND … "gesture not consumed (swipe missed the scroller?)"`.
- **`StepResult.attempts` (MERGEINTEG).** A step that took more than one attempt
  carries the history (`attempts[]`: status, reason, settle) next to the final
  `status`. A retried attempt never becomes a second step, so a passing run's
  `verdict.json` and its inline `result.verdict` are the same document; a
  `scroll_until` stop reason travels in the final attempt's `reason`.
- **Back / dialog / IME semantics (REL3K, REL3K2, REL3I, REL3I2, REL3I3).** Back
  pops in AOSP order (Pause B → Start/Resume A → Stop B → Destroy B), a Back on
  the root Activity finishes the task and settles on `bound: "window-gone"` with
  `task_finished: true` (no PNG is published for a screen that no longer exists),
  and Back closes a dialog before it touches the IME. The IME is a real **bound**
  IME: `startInputOrWindowGainedFocus` is answered with a session binder, a
  session id and a real `InputChannel` pair; Back hides the soft input
  (`FINISHED(handled=true)`) and the app sees the hide through the framework's own
  insets path. A dialog-dismissing Back that the guest cannot ack reports
  `handled: true` with `handled_evidence.source: "host_window_removed"` and
  `settle.bound: "host-window-removal"` — the delivered window's own removal is
  the consumer's proof.
- **The daemon must be the same build as the caller (REL3D).** `acos serve`
  reports an `Identity` in `hello`/`ping`: crate version, git sha, a digest of the
  workspace sources, the running binary's hash and a single `build_id`
  (`<git_sha>.<source8>.<exe8>`). The client compares **before any request** and
  never reads a foreign daemon's answer: an idle auto-started daemon is replaced,
  otherwise this build starts its own private socket and emits the structured
  `DAEMON_VERSION_MISMATCH` warning. `acos doctor`'s `session_daemon` check prints
  the running daemon's identity next to the CLI's.
- **One front door (REL3F).** `acos guide [workflow|cli|scenarios|errors|limits|mcp|all]`
  prints exactly the text the MCP `acos_help` tool serves (no second copy, no
  checkout needed); `acos session list` says what is running in text; session ids
  may be given positionally; selectors accept the human spellings the guide uses;
  and the stream contract is stated once (with `--json`, stdout is the JSON
  document and nothing else; the human summary goes to stderr).
- **CLI/MCP parity (REL3A, REL3B, MERGEINTEG).** `acos_verify` (MCP) gains
  `animations: on|off` and `native: bool`, relayed to `--animations`/`--native`;
  `acos_observe` honours `png`/`screenshot` on every route that can produce
  pixels; `acos_launch` accepts `flutter`/`rn`; the four session-addressed
  protocol tools accept `session_id`; `acos_verify`/`acos_observe` accept
  `full`/`cursor`; `acos_tap`/`acos_key`/`acos_text`/`acos_observe_tree` accept
  `settle_timeout_ms` (and `acos_observe`, the tree-carrying protocol route).
  Advertised and
  enforced schemas come from one helper, so they cannot drift, and a test checks
  every call written in the docs against the real schema (§Breaking changes).

## Fixed

- **`GET_SIGNATURES` returns certificates again (REL3P).** The APK signing-block
  parser read the signers *sequence* length as a signer length, so every
  `PackageInfo.signatures` was `[]`. A reply now carries the real DER (`[]` → one
  791-byte certificate on the fixtures); this also unblocks
  `WebViewFactory.verifyPackageInfo`.
- **Parcel String8 arrays (REL3P/REL3P2).** Sixteen `android.content.pm` fields now
  use the framework's String8 array encoding (the `getPackageInfo(…, 0x100024c0)`
  desync), `ProviderInfoList` is a typed list, the typed-array *reader* consumes
  the per-element presence marker the writer emits, and the two `android.net`
  codecs (`NetworkCapabilities`, `LinkProperties`) are rewritten from the image's
  own `writeToParcel`. The parcelable oracle now scans the image's whole boot
  classpath (83 dex dirs) and inlines `write*` helpers, so this class of defect
  is caught instead of passing as "class not found".
- **"Adding window failed" launch flake (FLAKEWIN).** Not a framework
  disagreement: the binder driver's transaction-buffer allocator had **no lock**,
  and two guest threads allocate at once by design (a reply for a synchronous
  transaction and a peer-initiated `BR_TRANSACTION`). Both memcpy'd into the same
  block, so a reply kept its object table and lost its data — the guest read an
  interface token as an exception code. The heap now lives in
  `txn_heap.{c,h}` behind a leaf mutex (AOSP's `binder_alloc` mutex, for the same
  reason): 800/800 launches at concurrency 1 and 4.
- **A no-op tap is no longer a red `TIMEOUT`** (`no-draw-after-action`), and a
  `pass` can no longer come with `settled: false`.
- **A settle that timed out is never a pass.** Scenario step → `status: timeout`,
  `error.code: TIMEOUT`; live action → `status: timeout`, `ok: false`,
  `details.reason: "settle_timeout"`, with the delivered facts (`accepted`,
  `state_changed`, `frame`, `changes`, `timing`) kept in `details.delivery` and
  in `result` so the screen is not lost.
- **Pixel and geometry claims still fail closed** on a content settle
  (`content_settle_pixel`, `content_settle_geometry`), and an explicit
  `settle: content` whose backend returns no content record fails closed
  (`content_settle_unhonored`).
- **A failing input step still says what the app did with the gesture** — a
  failing `expect_change` used to report `input.handled: null`, `published: 0`
  even though the acks existed.
- **Full-tree artifacts are cached (PERF3).** Writing the same tree under a new
  sequence on every reply was the M8 form-fast regression (REL3C); identical
  content now reuses its artifact, a different tree for a used sequence gets its
  own `tree/<seq>-<hash>.json` so a named artifact is never replaced, and writes
  are temp+rename.
- **`acos-mcp` discovery and the launch ladder keep working with the cap**: the
  ladder's rungs, `status` and `blocker.code` survive a 88 KB → 18.7 KB cut, and
  the compact node keeps `focused`/`password` so live typing still has its signal.
- **`acos_verify` no longer silently drops `animations`** (it was missing from
  `VerifyRequest` although the hints recommended it).

## Breaking changes (read this)

- **Unknown MCP arguments are rejected, not ignored (REL3B).** Every tool schema
  is closed: an argument the route does not honour is `INVALID_ARGUMENT` with the
  valid names in the message (`details.valid`). Every documented call in `docs/`
  is checked against the real schema by a test, so this cannot silently bite the
  docs. If you were passing an ignorable extra key, remove it.
- **Unhandled input is now a pass with a warning, not a `TIMEOUT` (REL3H).** Code
  that treated a no-op tap as a failure must either read
  `status`/`warnings` (`INPUT_UNHANDLED`) or declare `expect_handled: true` to
  keep the strict claim. `expect_change: true` still fails honestly
  (`ASSERTION_FAILED`, `details.reason: expect_change`).
- **`handled_evidence.source` values are `guest`, `host_window_removed`, `none`.**
  The ack case is spelled `guest` (a v0.3.0 pre-release spelled it
  `finishInputEvent`); the field is new in this release, so no released spelling
  changes, but anything written against a pre-release build needs the new value.
- **The default tree reply is the compact screen, not the full tree.** Parsers
  that read `result.tree` as a recursive node tree must read the compact node
  shape (or pass `{"full": true}`, or read `tree_path`). `acos_launch` returns the
  stage ladder; `tree_path` always names the complete tree.
- **`scroll_until` reports `END_OF_LIST`** where it used to report
  `ELEMENT_NOT_FOUND` after burning every attempt. A search that ends at the end
  of the list is no longer indistinguishable from a selector that never renders.
- **`StepResult.attempts` is additive but changes the step count rule**: one step
  is one entry (the final status), and a retried attempt is in `attempts[]`, not
  in `steps[]`.
- **`VerifyRequest.engine` semantics are stated, not implied**: `art` by default,
  `rust-vm` when `reference` is set without `engine`; an explicit `engine: art` +
  `reference` is `INVALID_ARGUMENT`, and `--reference` without `--engine` reports
  `explicit: false` in `engine.json`.
- **A different-build daemon is refused** with `DAEMON_VERSION_MISMATCH`. Rerun
  the command (the client replaces an idle auto-started daemon or starts a
  private one); an operator-started `acos serve` must be restarted after an
  upgrade.
- **Boot-image caches from v0.2.x are invalid** — the cache key and the header
  both carry the ACOS version. The first launch after the upgrade rebuilds it.

## Known limits

- **The settle horizon is the step, not the app.** A step settles on the screen its
  action produced; a change the app makes **later** (a delayed post, a worker
  thread, a timer) can land after the step settled. Check such an effect with
  `assert_text` + `timeout_ms` (a real wait), not with the action step's result —
  the action step's evidence is the screen its own injection produced.
- **`scroll_until` takes no `settle:`** — every attempt is one real gesture plus
  its own fresh settled traversal. A gesture that moves nothing twice **while
  consumed** is `END_OF_LIST`; a gesture nobody consumed is `ELEMENT_NOT_FOUND`
  with the "swipe missed the scroller?" hint, and a list that is still loading can
  look like an end for one gesture — which is why two consumed gestures in a row
  are required.
- **Dialog Back** settles on host window removal
  (`handled_evidence.source: "host_window_removed"`), not a guest ack — the
  receiver is disposed with the window, so there can be no ack.
- **Flutter fixtures are still incomplete**: the shared Flutter fixture has no
  `libapp_probe.so`, so the semantics tree is empty and
  `acos-jni/tests/flutter_hello.rs` / `acos-mcp/tests/flutter_session.rs` stay
  fixture-gated failures (the argument-gate half is covered by
  `documentation_args.rs`).
- **The `android.net` codecs were a gap in two steps.** REL3P found
  `NetworkCapabilities` (5/18 fields) and `LinkProperties` (2/17) wrong in the
  same class but out of its scope; REL3P2 rewrote both from the image's own
  `writeToParcel` and proves them byte-for-byte against the real framework.
  `SigningInfo`/`SigningDetails` (`writeArraySet` + two typed arrays) is still a
  curated gap, so a `SigningInfo` reply is never non-null today.
- **`INPUT_UNHANDLED` needs a complete ack set.** A short ack list is *unknown*
  (`handled: null`), never "not handled" — a 300 ms swipe publishes ~20 events and
  the guest may ack fewer.
- **`acos text` on a live session** needs a focused editor; `UNSUPPORTED_BACKEND`
  means the route has no `InputConnection` path, and the same interaction as a
  scenario `type:` step does work.
