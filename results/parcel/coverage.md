# Parcelable codec coverage vs the API-34 framework DEX

Generated by `cargo test -p acos-services --test parcelable codec_field_orders_match_the_framework_dex` (W155-A).
Source: `.cache/boot/android-34/dex/framework` (5 boot DEX files).

A spec is **Full** only when every `Parcel.write*` in the real `writeToParcel` is
represented and no spec field is left over. **Prefix** means the leading fields
match the real order with a documented gap; **Curated** means an ACOS-owned value
whose Java reader is not on the V1 path. 59 of the 67 shipped specs are
visible to the scanner; 34 are Full (the other 8 are ACOS-owned values with no
`writeToParcel` on the boot classpath).

W155-A added Full specs for the `PackageInfo` member arrays + intent resolution:
`ServiceInfo`, `InstrumentationInfo`, `PermissionInfo`, `ResolveInfo` (plus the
already-Full `ProviderInfo`/`PackageInfo`). The `ServiceInfo` DEX confirms the
field order is `permission, flags, mForegroundServiceType`.

## Documented gaps on the new specs

- `ServiceInfo`: none (the DEX `writeString8/writeInt/writeInt` tail is `permission, flags, mForegroundServiceType`).
- `InstrumentationInfo`: `splitDependencies` is a `SparseArray` — only the null encoding is modelled.
- `PermissionInfo`: `knownCerts` is a `Parcelling.ForStringSet`; only its leading `writeInt` (`-1` for null) is modelled.
- `ResolveInfo`: the component marker is modelled as the activity branch (`1`); the service (`2`) and provider (`3`) branches share the slot. A present `IntentFilter` is a structured `UnsupportedParcelable` (no codec yet).
