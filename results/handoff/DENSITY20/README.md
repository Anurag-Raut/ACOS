## 1. Audit: the N=1 to N=2 marginal of -14.5 MiB is a measurement artifact (method fix)

Cause. PSS divides a shared file page by *every* process on the host that maps it, not just
this daemon's tree. The cohorts ran in shared slots next to other agents' ART guests, which
map the same boot image / framework / fonts inodes (hardlinked cache). During the N=2 reps
(load 7.8-8.7) the file-backed classes were diluted about 2x: framework-dex 25.3 -> 12.9,
fonts 15.4 -> 8.3, apk-dex 13.8 -> 7.2, hwui 8.5 -> 4.5, shared-lib 44.6 -> 31.0 (total over the whole tree
at N=2 is *smaller* than one solo guest, which is impossible without foreign sharers). N=1 ran
with no foreign sharers (`Shared_*` 5 MiB), so its numbers are the clean solo cost.

Check. Fit `T(N) = pool + slope*N` on N=5/10/20 (`attribution_v2.md`): exec pool 190 MiB,
slope 37.2 MiB/session; residuals N=5 +0.7, N=10 -1.0, N=20 +0.3, N=1 +6.4, **N=2 -45.2**.
Independent cross-check: the *private* (unique-page) MiB per session at N=20 sums to 37.0 for exec
and 23.2 for zygote, equal to the fitted slopes 37.2 / 24.2. Private pages cannot be diluted by
other mappers, so the slope is trustworthy and the N=2 row is the outlier.

Fix to the method (adopted for the table above and BENCHMARKS.md): (a) report the marginal as the fitted slope /
private-per-session (37 MiB exec, 24 MiB zygote), (b) mark any cohort whose file-class PSS falls
below the N=1 solo value as foreign-diluted, (c) N=2 is flagged and its density figure carries an asterisk.
D3 marginals: N=2->5 52.5 is the same artifact (N=2 low), 5->10 36.9, 10->20 37.3 are valid. N=2 was
**not re-run**: disk is 88 % (>= 85 % stop rule) and a clean N=2 needs an `--exclusive` slot. Smallest next
action: `run-density.sh --n 2 --reps 3 --exclusive` when disk < 85 %.
Caveat that remains: other cohorts' absolute PSS (N=5..20) are *also* a lower bound on a quiet host
(the model fit says their dilution was about zero, i.e. the pool of 190 MiB is plausible vs N=1 solo 234 - 37 - host).

Reading: 73 % of a session's real cost (unique 37.0) is three things: boot-image CoW 10.2,
malloc/GC anon 9.8, managed heap 7.1 (= 27.1), then odex 3.8, shared-lib CoW 4.5. The shared pool
(boot image, framework, fonts, libs, ~190 MiB) is already well shared: framework-dex, fonts, apk-dex
have ~0 unique cost. At N=1 the whole 234 MiB is paid once; the emulator pays 3300 MiB for *each*.
N=20 total: ACOS exec 935 MiB (0.91 GiB), zygote 645 MiB; 20 emulators ~64.5 GiB (does not fit this 61 GiB host).

Emulator density (bounds, not measured here): 3 tasks per 3.22 GiB instance; at the same
~4.5 s wall (warm, favourable to the emulator) 12.4 tasks/GiB-min; with its 25.2 s cold boot per
instance 1.9. ACOS: 863-1116 at N=10, 881-1116 at N=20, i.e. 70-90x (warm bound) and 450-590x (cold).
Citation note: BENCHMARKS.md line 103 cites `EXPERIMENTS.md` E1.1 for the emulator figure, but E1.1 in
that file is the dexdump differential; the source of 25.2 s / 3300 MiB should be re-pointed.

Zygote warm-fork costs (same cohorts): CPU 164 % vs 94 % of one core at N=20 (sampled window), reset p50 493 vs 407 ms at N=20
(345 vs 341 ms at N=10), tap p50 unchanged 931 ms, wall unchanged (5.66 vs 5.70 s). Reps for zygote N=20: 2 (r3 absent).

| 3 | **KSM / `madvise(MADV_MERGEABLE)` on guest anon (scudo, dalvik heap)** | **est. 60-150 MiB, high uncertainty** | medium (needs host `/sys/kernel/mm/ksm/run=1`, root; ksmd CPU; madvise in launch) | host KSM is 0 now. Not worth it first: shared-boot-image mapping for the exec path (the 14 MiB/session CoW is the same win
as rank 1, but costs a medium ART/linker change; only do it if the owner rejects zygote default); lazy services (framework-dex/fonts/apk-dex/hwui are already ~0 unique).
Owner decision (ADR-0026 gate): rank 1 is a default flip, so it is the owner's call after Z7.
