## 1. The guest's constraints, measured

The guest is **not** an emulator: it is the image's own bionic `dalvikvm64`
(ART APEX) running as a real Linux process inside `bwrap`
(`crates/acos-art/src/lib.rs`, `Sandbox::command`), with a mini-Android root:

* `/system` = `<sysroot>/system` (real `/system/bin/linker64`, real
  `ld.config.txt` generated by the staging step), `/apex/*` bound per module,
  `/data` + `/vendor` + `/product` + `/system_ext` **empty** (`--dir`), `/data`
  per-run.
* image: `google/sdk_gphone64_x86_64/emu64xa:14/UE1A.230829.050/12077443:userdebug/dev-keys`,
  `ro.product.cpu.abi=x86_64`, API 34, bionic (`/system/lib64/libc.so`), so a
  driver must be a **bionic x86_64 ELF** — a host glibc `.so` cannot be loaded.
* properties come from `crates/acos-art/src/props.rs` (`/data/acos.properties`,
  served by the freestanding `artshim`): `ro.hardware=acos` and **none** of
  `ro.hardware.egl`, `persist.graphics.egl`, `ro.board.platform`.

### 1.1 The loader's own path (the seam)

`/system/lib64/libEGL.so` is the framework's EGL **loader** (227,584 B,
sha256 `b40c4c4cfbe26064ab296ca98ba25ab5c5460d3700cf79d7a94832e50d27d65a`).
Its strings carry the whole contract:

```
persist.graphics.egl   ro.hardware.egl   ro.board.platform
/egl/libEGL_   libEGL_angle failed!   _angle.so   /system/lib64/egl
couldn't find an OpenGL ES implementation, make sure one of %s, %s and %s is set
```

AOSP `frameworks/native/opengl/libs/EGL/Loader.cpp` (android-14.0.0_r75,
fetched for this spike, not vendored) spells the order out:

1. `shouldUseAngle()` → `attempt_to_load_angle()` (`libEGL_angle.so`, fatal if
   ANGLE is selected and fails);
2. updated driver APK;
3. `attempt_to_load_system_driver(cnx, <prop>, exact=true)` for the first
   non-empty of `HAL_SUBNAME_KEY_PROPERTIES` = `persist.graphics.egl`,
   `ro.hardware.egl`, `ro.board.platform` — `findLibrary` opens
   `/vendor/lib64/egl/libEGL_<prop>.so` (and `libGLESv1_CM_<prop>.so`,
   `libGLESv2_<prop>.so`);
4. the unsuffixed `libEGL.so` in the same directories;
5. `LOG_ALWAYS_FATAL_IF(!hnd, "couldn't find an OpenGL ES implementation, …")`.

### 1.2 Why nothing is there today

* no `/system/lib64/egl`, no `/vendor/lib64/egl` in the sysroot;
* no `egl.cfg` anywhere in the sysroot;
* all three `HAL_SUBNAME_KEY_PROPERTIES` empty (§1) → the search cannot even
  start, and step 5 aborts whatever thread touched EGL.

### 1.3 What hwui dlopens, and where the abort comes from

`libhwui.so` has `DT_NEEDED libEGL.so libGLESv1_CM.so libGLESv2.so
libGLESv3.so libvulkan.so` — so libEGL is mapped at load, and its `Loader` runs
on first use. Measured abort (unmodified tree, A11YPACE §4 and reproduced by
this spike's default arm):

```
?/libEGL: assertion failed: !hnd couldn't find an OpenGL ES implementation,
          make sure one of persist.graphics.egl, ro.hardware.egl and ro.board.platform is set
Fatal signal 6 (SIGABRT) … Thread: "RenderThread"        (A11YPACE)
Thread: 26 "GrallocUploadTh"                             (this spike, HARDWARE bitmap upload)
#00 pc 000013f4 /data/shim/libartshim.so (__android_log_assert+452)
```

Two different hwui threads reach it (RenderThread for `TextureView`-style
surfaces, `GrallocUploadTh` for a HARDWARE bitmap), which is why the fix has to
be the driver the loader looks for, not a call-site hook.

### 1.4 The namespace detail that decides the on-disk layout

`<data>/linkerconfig/ld.config.txt` (generated at staging):

```
namespace.default.search.paths  = /system/${LIB} … /vendor/${LIB} /odm/${LIB}
```

* there is **no `sphal` namespace** at all (`/vendor` is empty, no vendor
  linkerconfig fragment) — `android_load_sphal_library` falls back to a plain
  `dlopen`, and its internal `dlerror()` consumed the message, which is why the
  loader prints `load_driver(…): unknown` instead of the linker's text;
* the default namespace's search paths have **no** `/vendor/${LIB}/egl`.

Consequence: `libEGL_<tag>.so` must be reachable at `/vendor/lib64/egl/` (what
`findLibrary` opens by absolute path) **and** its `DT_NEEDED`
(`libGLESv2_<tag>.so`) must be resolvable from `/vendor/lib64/` (a namespace
search path). The provider therefore carries the same inodes twice —
`lib64/egl/*` + `lib64/*` — and one bind of `lib64` at `/vendor/lib64` covers
both. No linkerconfig change; the image's config is untouched.

### 2.3 Why Mesa is not a drop-in (measured from its own source, 24.0.9)

* `-Dplatforms` has no `surfaceless` choice in 24.0.9
  (`auto, x11, wayland, haiku, android, windows`); the only bionic-viable one is
  `android`.
* `-Dgallium-drivers=softpipe` no longer exists (`swrast` is the only software
  driver), so the CPU rasteriser is llvmpipe (needs LLVM; `-Dllvm=disabled`
  leaves nothing to build) — a bionic LLVM build is out of spike budget.
* `-Dplatforms=android` stops in configure on `libdrm` (no pkg-config for the
  NDK sysroot) and needs AOSP-only headers (`hardware/gralloc.h`,
  `grallocusage/GrallocUsageConversion.h`, `system/window.h`).
* At runtime `src/egl/drivers/dri2/platform_android.c`:
  `droid_open_device()` opens a **DRM node** (render node, or the primary node
  in `swrast` mode) and `droid_create_image_from_native_buffer()` imports
  buffers through `u_gralloc` (a **gralloc HAL/mapper**), and
  `EGL_ANDROID_image_native_buffer` is exported on that path.
  This guest has no `/dev/dri` node and **no gralloc HAL module**: ACOS's
  gralloc is an `LD_PRELOAD` C++ *interposer* (`crates/acos-art/shim/gralloc_shim.c`)
  that answers `GraphicBufferMapper::*`, which a GL driver never calls.

So "drop in Mesa" is really "write a DRM-node stand-in **and** a gralloc5 module
**and** an EGLImage path over the memfd", i.e. the graphics track A11YNATIVE2
estimated at weeks. The measurement above is what makes that estimate concrete.

## 3. The mechanism (flag off by default)

`ACOS_GUEST_GLES=<tag>` (absent/empty = off):

1. `Props::for_launch()` adds `ro.hardware.egl=<tag>` and `acos.guest.gles=<tag>`
   to the per-run property table (`crates/acos-art/src/props.rs`);
2. `Sandbox::command()` bind-mounts `<sysroot>/gles/<tag>/lib64` (or
   `$ACOS_GUEST_GLES_DIR/<tag>/lib64`) **read-only** at `/vendor/lib64`;
3. `gles::verify()` checks every manifest file's size+sha256 (measured 44 ms for
   18,276,896 B across 6 files, once per launch, only with the flag on);
4. nothing else happens. `libEGL.so` is dlopened by libhwui when it first needs
   GL; only then does the loader dlopen `libEGL_<tag>.so`. A process that never
   touches EGL pays **zero** resident bytes (the bind is one mount entry).

`tools/art-gles.sh --tag <t> --from-dir <dir>` or
`--from-emulator-vendor <vendor.img>` installs a provider
(`<sysroot>/gles/<t>/`, `manifest.json` with provider/source/version/licence and
per-file sha256/size) — the same add-on shape as `<sysroot>/shim/`, which is
**not** per-run (every run gets a fresh `ACOS_ART_DATA` from
`run-exclusive.sh`, so a provider under the data dir would vanish with the run).
A provider whose bytes drifted from the manifest is a structured
`sysroot layout error … sha256 … != manifest …`, never a different library.

Files: `crates/acos-art/src/gles.rs` (5 unit tests: verified provider,
drift, missing provider, path-shaped flag values, manifest validation),
`crates/acos-art/src/lib.rs` (bind), `crates/acos-art/src/props.rs` (property),
`tools/art-gles.sh`, `fixtures/apps/a11y-probe/…/A11yProbeService.java`
(the three draw probes, gated on `acos.guest.gles`),
`scenarios/gles-software.yaml` (the arm), `scenarios/a11y-screenshot-wrap.yaml`
(asserts the default arm's `gles_draw skipped=no_software_gles`).

* **Laziness: Δ(on − off) = −0.5 MiB, i.e. 0 within noise** — the staged
  provider costs nothing in a session that never touches EGL, which is the
  property the brief asked for (and it is the `counter.yaml` M8 run, 24/24
  steps pass in both arms). The timed M8 fast-tap A/B is the bench owner's
  (COMMON_RULES: no self-run exclusive A/B); no latency number is claimed here.
* A GL-touching session costs **63.6 MiB peak** on this image *without* a
  working driver — that number is the app + the 9 MB of mapped driver pages,
  **not** a working-GL number. A real per-session GL cost cannot be measured
  until a driver initializes (§6.1).
* First-EGL-init latency: **not measurable** — `eglInitialize` fails, so there
  is no successful init to time; the launch-side cost that *is* measured is the
  provider verify, 44 ms for 18.3 MB, paid once per launch and only with the
  flag on.
* Per-frame cost: **not reachable** (no frame is drawn).
* Disk: the provider is 8.8 MiB on disk (18.3 MiB of manifest entries for 6
  hardlinked names, one inode each), shared by every session; the guest sees
  one read-only bind.

## 6. Options for the owner

### 6.1 In-guest lazy software GL (what this spike built, and what is missing)

* **Done, cheap, and mergeable**: the staging + loader mechanism (§3), 0 MiB
  when unused, 8.8 MiB shared on disk, no architecture change, no default
  behaviour change.
* **Missing, expensive**: a software GLES that *initializes* on this guest.
  Measured blockers, in order:
  1. ANGLE (prebuilt, Apache-2.0) needs a **Vulkan ICD + transport**: the guest
     has `libvulkan.so` but no ICD, and the emulator's Vulkan path is
     gfxstream/virtio-gpu on the host. Cost: option 6.2.
  2. gfxstream's guest encoders (`libGLESv2_enc`, `libvulkan_enc`, …) need the
     emulator's goldfish/address-space device — a host process (6.2).
  3. Mesa (MIT) needs a **DRM node** or a non-DRM EGL platform *and* a
     **gralloc HAL module** for `EGL_ANDROID_image_native_buffer` (ACOS's
     gralloc is an interposer, not a HAL), *plus* an EGLImage-over-memfd path
     for the screenshot buffer. This is the graphics track ("weeks").
* Recommendation if the goal is "a wrapped screenshot can be drawn": the
  smallest honest step is **not** a GL stack. A11YPACE §5.2 option 2 (drop
  `USAGE_GPU_SAMPLED_IMAGE` from the screenshot buffer so
  `wrapHardwareBuffer` refuses cleanly and apps take their software path) is
  days, and it is a *documented* image deviation the owner has to accept.

### 6.2 Per-host shared renderer (gfxstream/virgl style, one host process)

Measured sizes on this box (host side, reuse candidates):

| Host piece | Size | Licence |
|---|---|---|
| emulator `lib64/gles_swiftshader/` (`libEGL.so` 59 KB, `libGLESv2.so` 6.8 MB, `libGLES_CM.so` 6.2 MB) | **13 MB** | Apache-2.0 (SwiftShader) |
| emulator `lib64/gles_angle/` (`libEGL.so` 260 KB, `libGLESv2.so` 6.6 MB, `libvk_swiftshader.so` 4.5 MB, `libvulkan.so` 0.5 MB) | **12 MB** | Apache-2.0 |
| `lib64/libgfxstream_backend.so` (the renderer that speaks the guest encoder protocol) | **15 MB** | Apache-2.0 |

Guest side (bionic, from the same vendor image): the encoder set
`libGLESv1_enc.so` 226,296 + `libGLESv2_enc.so` 591,968 + `libvulkan_enc.so`
4,308,584 + `libOpenglSystemCommon.so` 107,216 + `libOpenglCodecCommon.so`
213,760 + `libandroidemu.so` 104,896 + `lib_renderControl_enc.so` 67,752 +
`libGoldfishProfiler.so` 2,347,800 ≈ **8.0 MB** (5.6 MB without the profiler).

What AOSP code is reusable: gfxstream itself (the 15 MB backend + the encoders,
Apache-2.0, the same code the emulator uses) and AOSP's `libvulkan` loader.
What is **new code**: the transport. gfxstream's guest encoders expect the
goldfish pipe / address-space device or virtio-gpu; ACOS has neither, so the
renderer has to be reached the way the **WebView broker** already is — a host
process + a `LocalSocket` (`crates/acos-art/src/webview_socket.rs`,
`acos-webview`) and a guest-side shim that turns the encoders' device writes
into socket frames. That transport adapter plus the same
gralloc/`ANativeWindow`/EGLImage contract as §6.1 is the cost. Per-session
guest RSS: the encoder set is mapped per process (~8 MB of file pages, shared
page cache) versus 0 today.
