## 1. What was wrong (E13.8 re-verification)

`ArtSession::bind_first_frame` re-traversed while the launch tree was still the bare window
skeleton (≤ 40 nodes, no text), bounded by `ACOS_ART_FIRST_FRAME_MS` (900 ms) **and** 4
traversals. A Gaten strict traversal costs ~0.8 s, so the budget was exhausted after the first
retry: 9/30 launches bound the 10–15-node skeleton and were published as labelled placeholders
(`first_frame.placeholder: true`, `meaningful: false`, `waited_ms` ≈ 1.63 s) although the same
sessions had 243 nodes 2 s later.

Measured again on this branch/host before the fix, the *binding shape* of the failure is
sharper than E13.8 recorded: Gaten's launch traversal is **unsettled** (the welcome screen runs
a 10 s Reanimated timeline and never reports `settled`; `acos observe --tree` 2 s later also
reports `settle.bound: "timeout"` with 243 nodes). So:

* ~2/3 of launches: the first traversal is an *unsettled content frame* (243 nodes). P9 already
  hands that back (`traversals: 1`, `waited_ms: 0`) — content, no wait.
* ~1/3 of launches: the first traversal **settles on the 10-node skeleton** (the timeline has
  not started). No later sample is ever `settled`, so a settle-gated retry can only time out.
  That is the placeholder class.

A wait that requires `settled` therefore cannot reach Gaten's content frame at any budget.
The event that *is* observable on such a screen is the app's next **draw commit**: a probe
sample whose tree differs from the one the host holds and whose draw has been stored by C1.
That is the draw half of the strict settle rule (a probe after a draw, same draw for the 24 ms
confirmation, store at/after request entry) without the "framework is idle" half.

## 2. The change

### Guest (`crates/acos-art/src/launch.rs`)

`{"cmd":"tree"}` accepts an optional `baseline_tree` (the raw probe tree the caller already
holds). With it, the strict settle's candidate sample must satisfy:

1. tree ≠ baseline (exact `serde_json::Value` comparison — the caller hands back the reply's own
   tree, so no re-serialisation can make them differ by accident);
2. the draw behind it is committed: `probe_usable_for_fast_tree` (store generation at/after
   request entry, sample newer than the entry floor).

The 24 ms "same draw stayed newest" confirmation is deliberately **not** part of the change rule:
on a screen that keeps animating the draw changes every frame, so that rule can never converge
(measured: a change-gated wait built on it never validated a single sample in 10 s and the launch
fell back to the placeholder every time). The change rule is what `settle:fast` already uses for
freshness; the reply labels it `change-draw` and keeps `settled:false`, so it is never presented as
a settled frame. The *settled* path (`baseline_tree` absent) is byte-identical.

The reply's settle block states exactly which rule bound it: `bound: "strict-event"` when the
sample was also fully settled, `bound: "change-draw"` with `settled: false` +
`awaited: "tree-change"` when only the draw commit was proven. `reason: "tree-unchanged"` is the
timeout reason when the app never committed a different state. Existing callers send no
`baseline_tree` and are byte-identical.

### CLI (`crates/acos-cli/src/engine/art.rs`)

`bind_first_frame` keeps its first traversal. Only when that traversal **settled on an unmounted
skeleton** does it wait, and the wait is one request per committed state, not a traversal count:

* `ACOS_ART_FIRST_FRAME_MS` is now the wall-clock budget of the *content wait* (default 5000 ms,
  measured from the end of the launch's own traversal) and is passed as the request's
  `settle_timeout_ms` (a caller `settle_timeout_ms` stays a ceiling). Measured on Gaten the wait
  ends in ~0.23 s (3–4 committed states), so the budget is only a ceiling — it is spent only by an
  app that never gains content;
* the skeleton's raw probe tree is the baseline; each committed, still-unmounted state re-arms
  the wait with the new baseline until the budget expires;
* `FIRST_FRAME_MAX_ATTEMPTS` (8) remains only as a runaway guard.

Guarantees kept:

* **content first → zero extra traversals**: no second request is sent (unit-tested by request
  count);
* **never gains content → labelled placeholder**: the last *settled* traversal is restored, the
  frame is published with `first_frame.placeholder: true` and `frame.meaningful: false`;
* **settle verdict rollback**: a timed-out or errored wait restores the last settled traversal's
  frame *and* settle block, so the wait can never turn a passing launch into a `TIMEOUT`;
* **P9 untouched**: `SessionBackend::launch` still restores the pre-launch settle block, so the
  launch step is judged exactly as before. `result.settle` therefore stays the pre-launch block
  (null for a fresh session) and the truth about the bound frame is in
  `result.first_frame.{settled, bound, event_waits, traversals, waited_ms, nodes, placeholder}`;
* **a `change-draw` frame is never assertion evidence**: its settle block says
  `settled: false`; only the *launch* (whose P9 contract is a fresh frame) uses it. A frame that
  is not fresh at all is still a placeholder.

### Prelaunch guest death (`crates/acos-cli`, `serve`)

A launch whose guest dies before its first frame now:

1. closes/reaps the launcher first (bounded, idempotent) so its `session-exit.json` — guest exit
   status, `logd_tail`, stdout/stderr tails, native-crash record — is on disk;
2. writes a consolidated `<session>/art-frames/launch-failure.json` (classification, last 12 logd
   lines, session-exit facts, and the list of evidence files that exist);
3. classifies the death in the failure envelope (`details.launch_failure.classification`:
   `guest-exited-before-first-frame` / `guest-signal-crash` / `guest-signal` /
   `guest-exited-zero` / `unclassified-guest-death` / `no-death`) and points the hint at the kept
   evidence.

The pre-fix shape (a bare `GUEST_EXITED` exit 1 with `session_exit: null`, the race between the
reply and the record) is a unit test: the fake launcher answers `GUEST_EXITED`, *then* writes its
exit record, then exits 1.

## 4. Open / next

- The `change-draw` frame is fresh but not settled (no `settled: true` claim). SE2 (ADR-0026 #3,
  content-stable settle) would let a launch frame on a forever-animating screen also be *settled*;
  until then the launch reply says `settled: false, bound: "change-draw"`.
- `resource` defence: the wait only fires where the launch frame settled on the skeleton, so a
  genuinely empty screen pays the budget once (3 s default, `ACOS_ART_FIRST_FRAME_MS` to tune).
