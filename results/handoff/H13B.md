# H13B handoff — `shared-fixed` boot image default + on-disk cache

Status: **core done and measured; M1/M2 memory and the N=10 loop are not yet
re-measured** (see "Remaining"). Branch `perf-h13b-shared-image` off `main`

## What landed

* ADR-0026 §4 implemented: `ACOS_ART_BOOT_IMAGE` unset now means
  `shared-fixed` (fixed base `0x70000000`, `-Xnorelocate`, no image ASLR —
  owner-accepted). `lz4` and `shared-aslr` remain selectable; the B3
  `ACOS_SHARED_BOOT_IMAGE` directory still works and still fails closed when
  unusable.
* Content-addressed disk cache (`crates/acos-art/src/boot_image.rs`): key =
  ACOS image-format version + `dex2oat64` flags + boot-classpath environ text +
  identity (path, size, mtime) of all 37 sysroot boot jars and of
  `dex2oat64`/`dalvikvm64`/`libart.so`/`libartbase.so`/`libnativehelper.so`.
  Atomic (`temp dir` → `fsync` → `rename` → `fsync` dir), concurrent-safe
  (exclusive `flock` around check+build+publish: two serves build once),
  validated by `manifest.json` (per-file size + sampled checksum) so a
  truncated/partial entry is rebuilt. Cache root: `ACOS_BOOT_IMAGE_CACHE`, else
  `ACOS_CACHE_DIR`, else `$XDG_CACHE_HOME/acos`, else `~/.cache/acos`, then
  `art/boot-images` (0700 dir, 0444 files, never `/tmp`).
* Reply surface: `boot_image: {mode, cache, reason, dir, input_hash, base,
  prep_ms}` in `LaunchResult`, the interactive ready line, `acos verify`
  (`engine.timing.boot_image` in the artifact `engine.json`) and `acos serve`
  launch reply + session list.
* `acos-cli` prewarm warms the entry named by `<cache>/current.json`.

## Decision made here (needs orchestrator awareness, not a new owner gate)

**Failure policy is split.** Explicit `ACOS_ART_BOOT_IMAGE=shared-fixed` fails
the launch closed (no fallback), as every explicit knob has since H13. The
*default* (knob unset) falls back to the sysroot LZ4 image and reports
`cache: "fallback"` + `reason` in the reply and the log.

Why: the default must not be less available than the old default. A machine
without `dex2oat64`, with a full disk or a broken sysroot would otherwise fail
every launch where LZ4 worked, turning a performance decision into an outage.
Silence is what the old H13 statement forbade ("no silent fallback"); this is a
*reported* fallback in a field a benchmark and a gate can assert on, and the
explicit knob keeps the fail-closed contract.

## Evidence

* `results/bench/H13b.md` — cold build vs warm hit (3.58 s → 153/151 ms
  `session_start_ms`), interleaved 3-rep A/B on the recorded release binary vs
  lz4 (166 vs 174 ms median; 175/166/162 vs 174/176/169 per rep), gates 11/11
  expected, Gaten 5/5 flows pass + 5/5 negatives `ASSERTION_FAILED`.
* Unit tests (14 in `boot_image::tests` + the pre-existing launch tests): cold
  miss builds, second run hits without calling the builder, input change is a
  new entry, truncated file rebuilds (size mismatch named), same-size
  corruption rebuilds (checksum named), two concurrent builders build exactly
  once (one `Built`, one `Hit`), a failed build is a structured error and
  leaves no entry, pruning keeps 2 entries.
* `cargo test --release -p acos-art` (with the known `sandbox_s5` order flake
  run separately and passing), `-p acos-cli`, `-p acos-services`,
  `-p acos-verify`: all green.
* **Serve-path end-to-end not proven here.** A `acos serve` daemon in this
  worktree (isolated `XDG_RUNTIME_DIR` + `ACOS_SESSION_SOCKET`, `--engine art`)
  fails its first `acos launch --keep` with `GUEST_EXITED` (child exit 134) on
  **both** arms — `ACOS_ART_BOOT_IMAGE=lz4` and the new default — so it is a
  pre-existing daemon/guest-environment issue, not this change. What *is*
  proven: the ready line carries `boot_image`, `ArtSession` parses it, and
  `acos verify` publishes it (`engine.timing.boot_image`); `launch_reply` /
  `list_sessions` read the same accessor (code + compile only). Re-check when
  the daemon path is green on main.
