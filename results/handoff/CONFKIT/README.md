## 2. Conformance kit — every registered module

The kit (ADR-0029 item 7) runs six checks per module: `manifest` (validates),
`attach` (attach → detach twice, every provided name resolves; an `off`-only
module instead refuses every non-off profile), `detach-restores` (process fds +
threads and host binders + names back to baseline), `honest-report` (each name
answers what it answered before the attach — `null`, a tombstone name, or
`core`'s answer — and the report says `off`), `negative` (unimplemented profile,
unknown control op, unknown module id all refused), `budget` (declared RAM +
startup non-zero).

All 22 modules PASS, each in a quiet child process (fds/threads are
process-wide): `evidence/kit/<module>.txt`.

## 5. What failed on this tree

1. **`gaten-bubble-overlay` step 21** (`service_ctl accessibility status`
   expecting `screenshots: [{display_id: 0, status: 0}]`): reproducible twice,
   the reply has `screenshots: []` and the module's own report says the
   interaction surface ("getWindows, node queries, gestures, screenshot") is not
   implemented yet (`modules/accessibility.rs:365`). The bubble itself, its
   drag/clamp/fade and the tap on "Screen lookup" all pass (steps 0–20). This is
   a **pre-existing v0.4.0 gap**, not a regression from this track: the
   module's `status` has no screenshot record at all. Smallest next action: none
   here — it is part of the accessibility interaction-surface work.
2. **`net-network-real` / `net-network-offline`**: not runnable on this host
   (no `pasta` binary). The scenario declares `needs_env: [pasta]`; the runner
   recorded `GUEST_EXITED guest_exit 127`. The tree-side evidence for the module
   is the kit row and `tests/network_module.rs`.

## 6. Commands (this tree, all under the shared lock + guard)

```text
# conformance kit over every registered module + the generated docs
tools/art-runtime/run-exclusive.sh --task CONFKIT -- tools/guarded.sh --mem 22G --time 900 -- \
  env CARGO_TARGET_DIR=$PWD/.cache/confkit-target ... cargo test --offline -p acos-services \
  --test module_kit --test modules_doc
  -> module_kit 20 passed / 0 failed (the 22 kit children are spawned by the two
     registry-wide tests; `evidence/kit/` holds one log per module)
  -> modules_doc 2 passed / 0 failed

# acceptance gate
... cargo test --offline -p acos-services   -> 84 suites, 695 passed, 0 failed, 2 ignored
... cargo test --offline -p acos-art        -> 16 suites, 254 passed, 0 failed, 1 ignored

# the generated document
cargo run -p acos-services --example gen-modules-docs > docs/MODULES.md

# one proof run (`results/handoff/CONFKIT/run-batch.sh <scenario>`, which sets a private
# ACOS_RUNTIME_DIR/ACOS_SESSION_SOCKET, ACOS_VIEW_TEST_DIR, ACOS_ART_BIN and
# ACOS_WEBVIEW_CACHE, and writes evidence/<name>/{verdict.json,steps/,logs/})
tools/art-runtime/run-exclusive.sh --task CONFKIT -- tools/guarded.sh --mem 16G --time 900 -- \
  results/handoff/CONFKIT/run-batch.sh gaten-bubble webview-probe sysui1-shade sensors-scripted
```

Prerequisites that are easy to miss: `fixtures/build` must be built
(`tools/build-apps.sh`, `tools/build-webview-provider.sh`), and the WebView proof
needs `acos-webview` on `PATH` plus the pinned engine
(`ACOS_WEBVIEW_CACHE=<checkout>/.cache/webview`).

## 7. Verdict rows for every run

Every `evidence/<name>/verdict.json` carries the `modules` array, e.g.
`tail-telephony`: `core:real, net.telephony:scripted`; `webview-probe`:
`core:real, webview:real`; `tail-detached`: `core:real` only, with every other
module `state: off` and its reason. A pass that relied on `stub`/`scripted` says
so in that row (ADR-0029 item 5).
