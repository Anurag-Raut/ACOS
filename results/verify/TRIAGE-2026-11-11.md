## Log native check (brief item)

- `crates/acos-vm/src/natives/os_log.rs` `install()` registers `println_native`, `isLoggable`, and `logger_entry_max_payload_native` on `Landroid/util/Log;`. The file's only commit is `2ca97a9`. It has not changed since, so registration did not break.
- `Log.i(String,String)I` is ordinary Java bytecode in the framework boot classpath. It is not a native. It is missing only when the Bootstrap corelib is used. That is what happened here.

## Verification runs (at dbaf79b, worktree with `fixtures/build` symlink)

- Build: `cargo test -p acos-runtime -p acos-verify -p acos-sandbox -p acos-render --no-run` exit 0.
- Render, with `ACOS_FONT_DIR=<main>/.cache/boot/android-34/fonts`, no boot symlink needed: 8/8 PASS (`triage-render-env.log`).
- Render control, font env removed and no boot symlink: 8/8 FAIL with the gate's exact numbers (`triage-render-control.log`).
- Runtime, with `.cache/boot/android-34` symlink in the worktree and `ACOS_BOOT_DIR` unset: 3/3 PASS (`triage-runtime-env2.log`).
- Runtime, with `ACOS_BOOT_DIR` set to the main dir: 3/3 FAIL (`triage-runtime-env.log`). That is the sessions-dir Permission denied, and it is an artifact of setting `ACOS_BOOT_DIR` to a path outside the worktree.

## Recommendations

1. Do not treat the 11 failures as regressions. The gate's numbers match the clean-worktree-without-env signature exactly.
2. Add a worktree bootstrap step to the gate script. It should symlink `fixtures/build`, symlink `.cache/boot/android-34`, and set `ACOS_FONT_DIR` to the android fonts. Without the boot symlink, the RN tests silently fall back to Bootstrap and fail with misleading `UNSUPPORTED_*` errors.
3. Code-level hardening (optional): make the font tests fail, not skip or fall back to host fonts, when `ACOS_FONT_DIR` is unset and the repo's android fonts are missing. That would have surfaced this immediately.
4. Stop creating worktrees under `<main>/.cache/wt-*`. The walk-up in `default_boot_dir` and `workspace_root` then resolves to the main checkout.
