# V1 — tree visibility means *visible to the user* (GR2 W3/W4 fix)

Branch `verify-v1-visibility`, worktree `/home/Qui/.paseo/worktrees/3oxa6xao/v1`, off `main`
`2f9bf4a` (GR2 merged). Task: kill the GR2 W4 false-pass class and the W3 mis-target at their root —
the guest tree reported `visible: true` for a warm-mounted pager page parked at `x = +displayWidth`.

**One-line verdict: `visible` now means what Android means by `View.isVisibleToUser()`, each node
carries its clipped `visible_bounds`, and every selector used by `assert_visible`/`assert_text`/
`wait_for`/`tap` matches only user-visible nodes by default; a selector that matches only an
off-screen node fails with `ELEMENT_OFFSCREEN` naming its bounds. `scenarios/gaten-home.yaml`
passes 14/14 and its Analytics `wait_for` now matches a node that is really on screen (its bound
frame is the Analytics frame, different from the Home frame). Zero false passes in every re-run
artifact, and the class is pinned by a new fixture plus two negative scenarios.**

## 1. What changed (where)

| Layer | Change |
|---|---|
| **guest probe** `crates/acos-art/guest/java/dev/acos/art/LaunchMain.java` | Each node now carries `visible` and `visible_bounds`. `visible` is the framework's own `View.isVisibleToUser()` (reflection on the `public @hide` method; fallback reproduces it through `isShown()` + `getAlpha()` + `getGlobalVisibleRect()`), which is exactly what `AccessibilityNodeInfo.setVisibleToUser`/UiAutomator publish: attached with a visible window, it **and every ancestor** `VISIBLE` with alpha > 0, and the **global visible rect** (clipped by every ancestor via `ViewGroup.getChildVisibleRect`, i.e. scroll/pager clip) non-empty. `visible_bounds` is that same `getGlobalVisibleRect()` rect converted from root-view space to display pixels (root's `getLocationOnScreen()`), then clipped to the display bounds from `DisplayMetrics`; empty when nothing is visible. Off-screen/clipped nodes stay in the tree (agents may need them) and are `visible:false`. |
| **host mapping** `crates/acos-cli/src/engine/mod.rs` | `ui_node_from_json` copies the probe's `visible` and `visible_bounds` verbatim (a probe that predates the field keeps the old `visibility == VISIBLE` reading — it never claims more than it knew). |
| **protocol** `crates/acos-protocol/src/ui.rs` | `UiNode.visible_bounds: Option<Bounds>` + `UiNode::visible_rect()` / `UiNode::tap_point()` (centre of the visible rect). `Selector.include_invisible: bool` (default false) + `Selector::accepts_node()`; `UiTree::find_all`/`find_one` apply it, `UiTree::find_invisible()` returns the structural match that is not visible. |
| **error code** `crates/acos-protocol/src/error.rs` | New `ELEMENT_OFFSCREEN` (class `assertion`, status `fail`). Names the off-screen node: text/content_desc, full `bounds`, `visible_bounds`, window. |
| **verify** `crates/acos-verify/src/assertions.rs`, `executor.rs` | `assert_text`/`assert_visible` match visible nodes only; when only an invisible node matches they fail `ELEMENT_OFFSCREEN` (diff carries the node). `assert_not_visible` looks *including* invisible nodes, so a present-but-off-screen node passes with the honest message "present in the tree but not visible to the user (bounds …)" rather than "node absent". `assert_state {visible:false}` can reach an invisible node. `wait_for` polls visible matches only and, on timeout, adds `offscreen_match` (bounds) plus a message saying it *did* match a node the user cannot see. |
| **tap** `crates/acos-verify/src/native.rs`, `crates/acos-cli/src/engine/{mod,serve,art}.rs` | A selector tap resolves a **visible** match first (a visible match always wins), refuses an invisible-only match with `ELEMENT_OFFSCREEN`, and taps the centre of the **visible rect**, never a point outside it (this is W3: the old full-bounds centre of a clipped/overlapped label landed in the neighbouring tab). |
| **Rust VM** `crates/acos-runtime/src/view_tree.rs`, `crates/acos-verify/src/native.rs` | Same flag rule via the framework's `isVisibleToUser()` (fallback `isShown`), plus `ViewNode.visible_bounds` = bounds clipped to the root window rect (`None` when not visible). Honest limit: the VM rect is window-clipped, not ancestor-scroll-clipped — the boolean is the framework's, the rect is the window clip (the ART probe has both from `getGlobalVisibleRect`). |

Probe cost: the walk adds one `getGlobalVisibleRect` + one reflected `isVisibleToUser` per node; the
same probe line keeps its measured `emit_us` field, and no gate regressed visibly (all 7 gate walls
unchanged, counter gate still rc=0 in 0.8–2 s territory).

### 4.1 The one regression my change exposed, and its fix

`p11-delay1000` waits for `{id: delay1000_done}`. In `fixtures/apps/settle-lab` that marker is a
`TextView` with `android:layout_width="0dp"`, `visibility="gone"`, made `VISIBLE` after 1 s — so its
laid-out width is **0** and `bounds` came back `[1059,676][1059,792]`. The old tree called it
`visible` (the `VISIBLE` flag was set) and the scenario passed on a node with zero visible area; a
real device's `isVisibleToUser()` would say false for it too. Fix: the marker is now
`layout_width="wrap_content"` (a fixture layout bug, not a product one); `p11-delay1000`,
`p11-delay200` and `p11-delay40` re-run **pass**.

## 7. Limits / open items

* W5 (a tap step that may "pass" with no change) is untouched — it is `acos-verify` scenario
  semantics owned elsewhere; this change removes the *visibility* half of that false-pass pair.
* W6 (intermittent `+1080 px` fragment layout / a launch that never paints) is untouched and is
  still why a green Gaten run is luck-dependent (run 1 above).
* `wait_for`'s invisible-only match is reported as `TIMEOUT` + `offscreen_match` (not
  `ELEMENT_OFFSCREEN`) because the wait genuinely timed out; both channels name the node's bounds.
* Rust VM `visible_bounds` is window-clipped, not ancestor-scroll-clipped (the boolean is the
  framework's `isVisibleToUser`, which does account for ancestor clipping).
* The `acos-protocol` scenario test's 400 dpi failure for `gaten-home` is pre-existing (GR2 commit)
  and left as-is rather than "fixed" by editing the Gaten scenario's display.
