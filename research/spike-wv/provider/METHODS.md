# Provider surface the framework requires (API 34, from the image's own dex)

Generated by `research/spike-wv/broker/sigs.py` over
`.cache/spike-wv/dex/classes4.dump` (`dexdump -d` of `framework.jar`), i.e. the
method set the pinned API-34 framework will actually call. Hidden-API level for
each class is in the dex dump; `WebViewFactoryProvider`, `WebViewProvider`,
`WebViewProvider$ViewDelegate` and `WebViewDelegate` are framework classes an
app cannot reference, so the provider is compiled against the *image* stubs, not
against the SDK's `android.jar`.

Load path (see `../LOG.md` §1): `WebViewFactory.getProvider()` →
`getUpdateService().waitForAndGetProvider()` → `PackageManager.getPackageInfo` →
`Application.createApplicationContext` → `WebViewLibraryLoader.loadNativeLibrary`
(skippable: omit `com.android.webview.WebViewLibrary`) →
`Class.forName("com.android.webview.chromium.WebViewChromiumFactoryProviderForT")`
→ static `create(WebViewDelegate)`.
