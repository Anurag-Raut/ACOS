# LAUNCHER2 Plan — Minimal Guest Launcher & Settings System Apps (v0.4.1)

## Step 0 Findings

- **(a) HOME key (`key home` / `CATEGORY_HOME`)**: `acos-cli` / `acos-mcp` / `acos-protocol` map `"home"` to `KEYCODE_HOME = 3`, and `crates/acos-art/src/launch.rs` dispatches `(_, Some(code))` straight to `live.input.key(3, ack_wait)` on the focused window's `InputChannel`, where normal apps ignore it. No `CATEGORY_HOME` activity is installed today.
- **(b) `android.settings.*` intents**: `AmsState::start_activity_origin` resolves intents via `ManifestDb::resolve_activity` (which already checks action, `CATEGORY_DEFAULT`, and `data` scheme such as `package:` for `ACTION_APPLICATION_DETAILS_SETTINGS`). Unmatched intents fall through to `intents.rs::IntentState::capture` (which only captures `SEND`, `VIEW`, `PICK`, `GET_CONTENT`) and otherwise return `Err(IllegalState)` → `ams::START_NOT_FOUND`. **Bug found**: `ams::START_NOT_FOUND` is currently `4` (a non-fatal AOSP `START_*` code), so `Instrumentation.checkStartActivityResult` silently returns instead of throwing `ActivityNotFoundException`. Setting `START_NOT_FOUND = -91` (`ActivityManager.START_INTENT_NOT_RESOLVED = FIRST_START_FATAL_ERROR_CODE + 9`) restores honest `ActivityNotFoundException`.
- **(c) System/fixture app build & session install**: Framework-only Java APKs (`fixtures/apps/<name>`) are compiled by `tools/build-apps.sh` into `fixtures/build/apps/<name>.apk`. Under ADR-0029 (`system.permissions`, `system.notifications`, `webview`), modules declare `system_apps` in `ModuleManifest`, resolved via `modules::system_app_apk` → `module::system_apks`, staged as `ExtraApk`s in `acos-art`, and lazily spawned by `SecondaryPool`.
- **(d) Package resolution (`PMS queryIntentActivities`)**: `ManifestDb` matches filters, but `PmsService::call` `"resolveIntent" | "queryIntentActivities"` currently only caches matches for `acos-runtime` and returns `Parcelable::Null` to ART. Meanwhile `parcelable.rs` already has a `Verification::Full` `ResolveInfo` spec and `parceled_list_of`, and `ManifestLabels` already parses `<application>`/`<activity>` labels (`labelRes` and literal `nonLocalizedLabel`).

## Design Choices (Reuses ADR-0029 + MPROC7; No New Architecture)

1. **System Apps & Build (`fixtures/apps/`)**:
   - `fixtures/apps/launcher` (`com.acos.launcher`, `fixtures/build/apps/launcher.apk`): `LauncherActivity` (`MAIN`/`HOME`, `launchMode="singleTask"`, `exported="true"`). Queries `PackageManager.queryIntentActivities(new Intent(ACTION_MAIN).addCategory(CATEGORY_HOME | LAUNCHER) -> ACTION_MAIN + CATEGORY_LAUNCHER, 0)`, filters out self (`com.acos.launcher`), sorts deterministically by label/package, renders a `ListView` / clickable rows with real `ResolveInfo.loadLabel(pm)` text (`row_0`, `row_1`, … / label text), and launches the tapped package via `pm.getLaunchIntentForPackage(pkg)` (`FLAG_ACTIVITY_NEW_TASK`).
   - `fixtures/apps/settings` (`com.android.settings`, `fixtures/build/apps/settings.apk`): `SettingsActivity` (`exported="true"`, `launchMode="singleTask"`) declaring `<intent-filter>`s with `CATEGORY_DEFAULT` for:
     - `android.settings.SETTINGS`
     - `android.settings.WIFI_SETTINGS`
     - `android.settings.APPLICATION_DETAILS_SETTINGS` with `<data android:scheme="package" />`
     Displays honest action title + detail (for `APPLICATION_DETAILS_SETTINGS`, extracts and renders `getIntent().getData().getSchemeSpecificPart()`). Unhandled actions (e.g. `LOCATION_SOURCE_SETTINGS`) are **not** declared and continue to fail with `START_NOT_FOUND = -91` → `ActivityNotFoundException`.
2. **Opt-in ADR-0029 Modules (`system.launcher`, `system.settings`)**:
   - Both use `profiles: &[Off, Real]`, `default_profile: Off`, `attach_mode: AtLaunch`, `services: &[]`, `system_apps: &["com.acos.launcher"]` / `&["com.android.settings"]`, keeping zero cold-start impact on existing scenarios and preserving honest errors when unattached (`key home` → error, settings intents → `ActivityNotFoundException`).
   - Update `TOMBSTONES` `"launcherapps"` module target to `"system.launcherapps"` so attaching `system.launcher` never falsely marks `ILauncherApps` as attached.
3. **PMS `queryIntentActivities` / `resolveIntent` & Labels (`pms.rs`)**:
   - Return real `ResolveInfo` / `ParceledListSlice<ResolveInfo>` (with `ActivityInfo`, `priority=0`, `system=1` for system apps, `nonLocalizedLabel`/`labelRes`), while keeping `cache_intent_activities` intact for `acos-runtime`.
   - Thread `ManifestLabels` (`nonLocalizedLabel` + `labelRes`) into `AppInfo` and `ActivityInfo` parcelables so `ResolveInfo.loadLabel(pm)` and `ActivityInfo.loadLabel(pm)` return real labels.
4. **`key home` Routing & Cross-Process Task Switching (`launch.rs`, `ams.rs`, `atms.rs`, `peer.rs`, `acos-wm`)**:
   - Intercept `KEYCODE_HOME` (`code == 3`) in `acos-art/src/launch.rs` before `live.input.key` (matching `PhoneWindowManager`), routing `ACTION_MAIN` + `CATEGORY_HOME` (`FLAG_ACTIVITY_NEW_TASK | FLAG_ACTIVITY_RESET_TASK_IF_NEEDED`) via `AtmsState::start_activity_from_host`. If no HOME handler is installed, return an honest error (`HOME_UNAVAILABLE`) without falling back to `InputChannel`.
   - Record `caller_tag` on `PendingLaunch` so `tag 0` skips host delivery **only** when `tag 0` launched locally; launches from `Launcher` (`tag != 0`) or `Host` into `tag 0` are delivered or brought to front.
   - Support bringing an existing alive `Stopped`/`Paused` task/activity to the front (`START_TASK_TO_FRONT` / `ResumeActivityItem` + optional `NewIntentItem`), pausing/stopping the displaced foreground activity via `top_of_task`, updating `top_process`, and raising the re-shown window in `acos-wm` (`relayout` visibility + layer stack focus/z-order) so `assert_windows`, input focus, hit-testing, and compositor C1 agree.
