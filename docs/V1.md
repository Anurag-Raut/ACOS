# ACOS V1 — version 1 definition

**Owner definition, 2026-11-10.** This is the accepted definition of "V1". It is
a checklist; every item names its verification command and the metric it must
satisfy. Status values: `not started`, `in progress`, `done`. Only `done` with a
reproducible artifact counts.

> **V1 = an AI agent can run**
> ```
> acos verify --apk <apk> --scenario <file> --json --artifacts <dir>
> ```
> **on the two fixture APKs with NO Android boot, and get a correct, evidenced
> verdict.**

No Android boot, no emulator, no system_server, no Binder, no SurfaceFlinger on
the execution path. Reference captures come from the ART oracle (ADR-0015) and
are used only for comparison, not execution.

## Out of scope for V1 (explicit)

Compose, Flutter, React Native, WebView, GMS, ARM translation, multi-process
apps, isolation level `sandbox` hardening beyond process separation, and JIT.

---

## Critical path

```
VM interpreter (in progress)
  → boot real core library (println natives)
  → boot framework + in-process service layer
  → Activity launch
  → bind acos-render to graphics natives
  → input + UI tree
  → acos-jni + native loader
  → verify/scenario runner
  → snapshot/restore
  → concurrency
  → benchmarks
```

Each arrow is a gate: the next stage may not claim progress while the previous is
unverified. The honest progress metric is **the first `unsupported` native hit
per fixture**, not a raw class count (per `research/framework-dex/REPORT.md` §e).

## W180-A status (2026-11-11): `acos verify` on the native backend

The native backend behind `acos verify` now drives the **product session**
(`AgentSession`: the same worker as `acos launch --keep` / `observe` / `tap` /
`session text` / `reset`), instead of stopping at the M2 attach point. Evidence
lives in `results/v1/w180a/` and the run log in `results/v1/W180A.md`.

Reproduce (from a clean worktree at this commit, `ACOS_BOOT_DIR` pointing at
`.cache/boot/android-34`):

```bash
acos verify --apk fixtures/build/apps/counter.apk \
  --scenario scenarios/v1-counter.yaml --json --artifacts out/v1-counter
# verdict pass, backend=acos-native, fidelity=native-runtime,
# 13/13 steps, capture frame_seq 10, hash e3cd0a18…b1e, wall 16.8 s

acos verify --apk fixtures/build/apps/hello-views.apk \
  --scenario scenarios/v1-hello-views.yaml --json --artifacts out/v1-hello-views
# launch/assert/type pass; tap after type spins >120 s and the VM watchdog
# aborts it -> assert_text ELEMENT_NOT_FOUND (blocker, see 1.5)

acos verify --apk fixtures/build/apps/broken-wrong-text.apk \
  --scenario scenarios/v1-counter.yaml --json --artifacts out/neg-text
# fail / ASSERTION_FAILED ("expected text exactly \"0\", got \"5\"")
# etc. for broken-crash and broken-missing-symbol; zero false passes

tools/build-negative-apps.sh   # builds the three broken APKs
cargo test -p acos-cli --test negative_verify
cargo test -p acos-verify
```

**Exact blockers (not marked done):**

1. **hello-views tap after typing** — the click handler runs
   (`AcosFixture: greet name=World clicks=1` is logged) but the following
   framework traversal does not complete: the pump spins until the 120 s VM
   watchdog, `result` still reads `clicks: 0`, and the post-abort tree no longer
   exposes `result`. Reproduced on the product path
   (`acos launch --keep` → `session text` → `tap --id btn`). Not worked around
   in a scenario. Likely owner: the layout/measure work (W179-A) or the
   input/relayout path.
2. **View bounds** — live tree `count` bounds `[84,506][105,570]` vs ART
   `[42,317][63,368]` (content top 422 vs 275, x doubled). Text/ids are exact;
   V1 1.4/1.9 stay in progress until the layout-offset work lands.
3. **Rotation / recreate** — the session has no orientation-change path, so
   `scenarios/hello-views.yaml` / `counter.yaml` (V1 1.7) still report
   `unsupported` at `rotate`. The core V1 loop lives in
   `scenarios/v1-hello-views.yaml` / `v1-counter.yaml`.
4. **hello-jni** — `verify --native …` reaches the loader but reports
   `UNSUPPORTED_NATIVE_SYMBOL` for `stringFromJNI`, which **is exported** by
   `libhellojni.so`: the VM's JNI symbol binding does not find it (same gap as
   W3-07, owner W93-A). V1 §2 is therefore not done.
